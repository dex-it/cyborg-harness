# ADR-CH-0002 Манифест плагина читается до запуска кода; API плагинов, контракты и разделы config и state версионируются семантически

> Решение составителя по запросу владельца, не согласовано; ждёт приёмки. Редакция 2026-11-05 записывает решение, принятое в [SAD](../design/sad.md#33-версии-и-миграции) и реализованное в `core/`; решение первой редакции (2026-11-02) - в рассмотренных вариантах. Основано на [ресёрче](../../research/README.md): [bb](../../research/bb.md), [DeepSeek Harness](../../research/deepseek-harness.md), [сравнение](../../research/comparison.md).

## Decision Drivers

- Ядро должно знать о плагине **до** запуска его кода: что он даёт и требует, какие права просит, какие виды и сочетания вносит.
- Обновление Cyborg или плагина не должно ломать остальных и терять данные ([SAD, 3.3](../design/sad.md#33-версии-и-миграции)).
- Пользователь правит файл воркспейса руками и ошибается; это не должно ронять плагин или окно.

## Context

bb: блок `bb` в `package.json`, строгая схема (`plugin-manifest.ts`), `engines.bb` и `engines.bbPluginSdk`, префикс `experimental_` на каждом публичном члене и реестр `api_to_audit.md`. dsh: блок `dsh`, `engines.dsh`, исключения `acceptRisk`, `upgrade-guide` на каждое внешнее ломание, форматы данных версионируются отдельно ([bb 5.1](../../research/bb.md), [dsh 5](../../research/deepseek-harness.md)).

## Decision

1. **Манифест - JSON, его разбирает ядро до запуска кода.** Поля: `id`, `version`, `engines.cyborg`, `provides`, `requires`, `optional`, `consumes`, `commands`, `keybindings`, `permissions`, `config`, `state`, `ui`, `documents`, `host`, `activation`, `lock`, а также `$schema` для редактора. Незнакомое поле верхнего уровня, как и во вложенных блоках `provides.<контракт>`, `ui`, `lock`, `documents`, `permissions`, - ошибка с его именем: опечатка (`keybinding`, `lok`) не отключает функцию молча, а ужесточить разбор после появления сторонних плагинов значило бы сломать уже выпущенные. Ошибки собираются все сразу; плагин с ошибкой манифеста не загружается, причина в журнале. Если при ошибках разбора `engines.cyborg` не принимает версию API ядра, причина одна - «нужен API Cyborg `<диапазон>`, есть `<версия>`»: поле новой версии API старое ядро не знает, и называть его бесполезно. Файл лежит в каталоге плагина; в playground это `manifest.json`. Проверка: `core/test/semver-manifest.test.ts` («манифест: ошибки собираются все сразу и id сохраняется для журнала», «манифест: незнакомое поле верхнего уровня…», «манифест под другой API…»), `core/test/loader.test.ts` («журнал: невалидный, выключенный…», «манифест с полем новой версии API…»).
2. **Совместимость и граф - до импорта кода.** Несовместимый `engines.cyborg`, недостающий `requires`, два поставщика при кратности `one`, цикл - плагин не загружается, отказ каскадом уходит на тех, кто его требует ([SAD, 3.2](../design/sad.md#32-загрузка-плагинов)). Проверка: `core/test/graph.test.ts` («отказ по engines каскадирует на зависимых, optional переживает» и соседние), `core/test/loader.test.ts` («хуки: граф до кода…»).
3. **Версия API плагинов семантическая.** `engines.cyborg` - диапазон (`^1`) против версии API приложения. API плагинов - это `ctx` и элементы ядра; в пределах мажорной версии член `ctx` не удаляется, а элемент ядра не удаляется и не меняет атрибуты. Проверка: диапазон - `core/test/graph.test.ts`, `core/test/semver-manifest.test.ts` («диапазоны: каретка, тильда, префикс и звезда»); стабильность в пределах мажорной версии автоматически не проверяется.
4. **Контракты версионируются семантически.** Минорная версия добавляет необязательный член, поле или значение в объединении событий, и потребитель пропускает незнакомое. Мажорная - удаление, переименование, новое обязательное поле аргумента, смена смысла. Поставщик может дать две мажорные версии сразу (`"provides": { "cyborg.files": ["1.4", "2.0"] }`), потребитель получает ту, что просил. Проверка: `core/test/graph.test.ts` («поставщик с двумя мажорными версиями обслуживает старого и нового потребителя», «несовместимая мажорная версия поставщика - как отсутствие»), `core/test/registry.test.ts` («потребитель получает свою мажорную версию…»); правило минорной версии держат автор контракта и ревью.
5. **Устаревание через `@deprecated`.** Член с пометкой живёт минимум до следующей мажорной версии; ядро пишет в журнал, кто его вызывает. Проверка: журнала вызовов пока нет - см. расхождения.
6. **Пространства имён.** `cyborg.*` закреплено за этим репозиторием и пакетом `@cyborg/contracts`; сторонние контракты называются по автору (`acme.*`) и публикуются своими пакетами объявлений. Команды плагина лежат в пространстве его `id`; `id` `cyborg` и `cyborg.window` заняты командами окна. Проверка: `core/test/semver-manifest.test.ts` («команды: схема с ошибкой не проходит разбор» - команда вне пространства `id`), `core/test/window.test.ts` («манифест: id, в пространстве которого лежат команды окна, занят»); закрепление `cyborg.*` за репозиторием автоматически не проверяется.
7. **Разделы `config` и `state` версионируются отдельно от плагина.** Манифест объявляет `version` и, по желанию, схему `./<файл>.json` в каталоге плагина. Версия раздела ниже - ядро до активации вызывает `migrate(fromVersion, data)` плагина и записывает результат. Версия выше (плагин откатили) - плагин не активируется, раздел не трогается. Раздел не прошёл схему или `validate` - отказ только этому плагину; правка файла извне не по схеме оставляет прежнее значение. Проверка: `core/test/config.test.ts`, `core/test/loader.test.ts` («откат версии плагина…», «миграция config идёт в хосте…», «схема раздела из манифеста…»), `core/test/json-schema.test.ts`, `playground/src/main/plugins.test.ts` («схема раздела: файл из каталога плагина…»).
8. **Схема раздела - подмножество JSON Schema без зависимостей.** Ключ вне подмножества - ошибка схемы, а не пропуск: автор не должен считать проверенным то, что ядро не проверяет ([SAD, 3.3](../design/sad.md#33-версии-и-миграции)). Проверка: `core/test/json-schema.test.ts` («схема раздела: ключ вне подмножества и неверный ключ - ошибка схемы, а не пропуск»).

## Consequences

- Positive: каркас окна, таблица сочетаний, граф контрактов и права словами строятся до активации; конфликт сочетаний виден при загрузке; несовместимый или откаченный плагин не запускается и не портит данные.
- Negative: манифест - ещё одно, что автор поддерживает рядом с кодом; объявления контракта в манифесте и в коде (`provide`) должны совпадать, расхождение ядро ловит только при вызове.
- Risks: манифест разрастается с каждой целью ядра. Новое поле - только под цель SAD, с разбором в `core/src/manifest.ts` и тестом.

## Alternatives Considered

- **Блок `cyborg` в `package.json`, строгая схема (первая редакция).** Готовил распространение плагинов через npm. Why rejected: установки в первом этапе нет, источник установки - открытый вопрос 8 [SAD](../design/sad.md#8-открытые-вопросы); плагин - каталог, а не npm-пакет ([ADR-CH-0001](ADR-CH-0001-core-and-plugins.md)). Строгость верхнего уровня - открытый вопрос ниже.
- **Целочисленная версия API (первая редакция).** Why rejected: `engines.cyborg` - тот же диапазон semver, что у контрактов, и мажорная часть делает то же, что целое число; минорная часть отмечает добавления без ломания.
- **Префикс `experimental_`, реестр аудита и журнал ломающих изменений (первая редакция).** Why rejected: свободу ломать нестабильное даёт мажорная версия контракта, а переход - две мажорные версии у поставщика сразу и `@deprecated` с журналом ([SAD, 3.3](../design/sad.md#33-версии-и-миграции)). Вывод составителя: снятие префикса при стабилизации само ломало бы всех потребителей члена.
- **Миграция данных «рядом» - новый файл, прежний не трогается (первая редакция).** Why rejected: разделы плагинов живут в общем файле воркспейса и в `state`, отдельного файла у плагина нет; откат защищён отказом активации при разделе новее манифеста. Старый формат воркспейса `{projects, lastProjectId}` при переводе сохраняется копией `.v1.bak` (`core/test/workspace.test.ts`).
- **Манифест как код (экспорт из модуля).** Cons: ядру нужно выполнить код, чтобы узнать вклад. Why rejected: ломает ленивую активацию, каркас до кода и проверку графа.
- **Пропуск незнакомого поля верхнего уровня.** Pros: манифест с полем новой версии ядра загружается в старой без этой функции. Cons: опечатка молча отключает функцию, а `lock` с опечаткой - замок окна при старте. Why rejected: новое поле идёт с новой минорной версией API, и старое ядро и так откажет по `engines.cyborg`; ужесточить разбор позже - сломать сторонние плагины, ослабить - нет.
- **Общая библиотека схем (zod, ajv).** Pros: полная JSON Schema. Cons: зависимость ядра. Why rejected: подмножества хватает, а незнакомый ключ - ошибка (пункт 8).

## Расхождения с текущим кодом

- Пункт 5: журнала вызовов члена с `@deprecated` нет ([дорожная карта](../../05-plans/roadmap.md#2-остаток-этапа-1)).
- Пункт 3: стабильность `ctx` и элементов ядра в пределах мажорной версии держится ревью; теста, сверяющего API с предыдущей версией, нет.
