# ADR-CH-0013 UI плагина: свой iframe, origin по группе рендера, мост через preload, CSP

> Решение сведено из [SAD2, 3.8](../design/sad2.md#38-изоляция-рендера) и проверено замерами [ресёрча-2](../../research/sad2-validation.md#3-замеры-окно-iframe-и-мост); не согласовано, ждёт приёмки. Заменяет [ADR-CH-0007](ADR-CH-0007-ui-slots-and-commands.md).

## Decision Drivers

- Один плагин не должен ломать DOM, стили и фокус другого; каркас окна должен появляться до кода плагинов.
- Стоимость кадра: отдельный origin на кастомной схеме даёт отдельный процесс рендера.
- Страница плагина не должна обходить права `net` шлюза.

## Context

ADR-CH-0007 монтировал вклады плагинов в слоты общего DOM. Замеры в Electron 45: пустой кадр со своим origin - около 17 МБ против примерно 3 МБ при общем; десять кадров - 190 МБ рендереров и 11 процессов против 45 МБ и 2; десять `<iframe>` с xterm - 335 МБ против 106 МБ. Кадр с `sandbox="allow-scripts"` живёт в одном процессе, но без хранилищ origin.

## Decision

1. **Каждый вид и тип документа плагина - свой `<iframe>`**; плагин экспортирует `mount(root, ctx: UiContext): Disposable`. У `UiContext` нет `ctx.os`: доступ к ОС только у главной части.
2. **Origin по группе рендера:** `cyborg-plugin://<группа>/`. Автор плагина рекомендует группу в манифесте (`ui.group`), владелец переопределяет в `plugins.uiGroups` config пользователя или воркспейса. Плагин без группы получает группу со своим id; сторонний по умолчанию один, в общую группу попадает только волей владельца с предупреждением. Внутри группы правило «не трогать чужой DOM» проверяется статически ([ADR-CH-0011](ADR-CH-0011-isolation-stages.md)). Мост узнаёт вид по origin, поэтому граница доверия - группа, а не плагин.
3. **CSP по умолчанию:** `default-src 'none'; script-src 'self'; style-src 'self' 'unsafe-inline'; connect-src 'self'; img-src 'self' data:`. Проверено: встроенный скрипт не выполняется, интернет и другие origin закрыты, `parent.document` и мост оболочки недоступны.
4. **Мост - preload в подфреймах** ([спайк](../../04-verification/spike-iframe-ui.md)): главный процесс узнаёт плагин по origin фрейма-отправителя, а не по словам вида; вывод идёт во фрейм мимо документа окна. Preload выдаёт мост по origin документа: вид - свой, окно - свой, чужая страница внутри вида - ничего.
5. **Общего UI-фреймворка нет:** токены темы (CSS-переменные) и веб-компоненты ядра, версионируются вместе с API плагинов.
6. **Чужой UI не встраивается - «задача, а не виджет»:** плагин вызывает команду или член контракта владельца, тот показывает свой документ или диалог.
7. **Скрытая область не отмонтируется.** Блокировка окна `ctx.ui.lock` - механизм в ядре, политика и проверка пользователя - в плагине.
8. Каркас рисуется по манифестам: ядро знает только роды областей; расстановка = манифесты + изменения пользователя (`state`).

## Consequences

- Positive: изоляция DOM между группами даёт браузер; число процессов рендера равно числу групп, а не плагинов.
- Negative: UI переносится из одного документа в кадры плагинов; ключи `localStorage` (`cyborg.*`) теряются при смене origin и переносятся в `state`; `webUtils.getPathForFile` и drop требуют перехвата в оболочке.
- Negative: внутри группы изоляции DOM нет; плагины одной группы для моста неразличимы.
- Risks: клавиши при фокусе в кадре на macOS, Monaco и xterm под `sandbox` не проверены (вопрос 11); HTML5-перетаскивание между группами Chromium блокирует, его ведёт ядро через `startDrag`.

## Alternatives Considered

- **Слоты в общем DOM (ADR-CH-0007).** Cons: нет изоляции стилей и фокуса. Why rejected: изоляцию рендера даёт `<iframe>`.
- **Origin на плагин для всех.** Cons: свой процесс рендера на каждый плагин (+13 МБ PSS на Linux, ~17 против ~3 МБ на macOS). Why rejected: близким по смыслу плагинам граница не нужна; владелец может развести их по группам.
- **Origin по классу (`builtin` для всех встроенных, свой у стороннего).** Cons: класс не отражает смысл; владелец не может развести встроенные. Why rejected: заменён группами.
- **Мост без preload** (`MessageChannelMain`, порт через страницу оболочки, круг 45 мкс). Cons: порт, переданный через документ окна, не говорит главному процессу, чей это кадр. Why rejected: preload с проверкой origin отправителя говорит.
- **`sandbox` без `allow-same-origin` для всех.** Pros: изоляция DOM по цене общего origin. Cons: нет хранилищ origin, Monaco не проверен. Why rejected пока.
- **Общий UI-фреймворк.** Cons: его версия стала бы частью API, мажорное обновление ломало бы все сторонние плагины. Why rejected.
- **Встраиваемые чужие виды.** Why rejected: в изученных системах прецедента нет.
