## Что это

Приложение, которое растёт функциями, рано или поздно превращается в один большой главный процесс: агент, сессии, файлы, проекты, трекеры лежат рядом и знают друг о друге. Добавить функцию значит править всё, а сбой одной функции роняет окно.

Cyborg Harness переворачивает это. В ядре нет ни агента, ни файлов, ни проектов, ни трекеров: только то, что нужно любому набору плагинов. Всё остальное - плагины на одних и тех же правилах, а поставка приложения - это список встроенных плагинов.

:::note[Статус]
Ранняя версия. Ядро и стенд запускаются из исходников, подписанных сборок нет. Работает на macOS и Linux, проверяется в CI на обеих системах. Описание на этом сайте - ядро в том виде, в каком его завершает [эпик микроядра](https://github.com/dex-it/cyborg-harness/issues/15); что уже сделано, показывает [дорожная карта](/development/roadmap/).
:::

## Возможности

<CardGrid>
  <Card title="Плагины как равные" icon="puzzle">
    Агент, сессии, дерево файлов, просмотрщик, git и трекеры - плагины на общих правилах. Манифест разбирается до запуска кода, активация ленивая, безопасный режим не стартует ни одного плагина.
  </Card>
  <Card title="Контракты вместо сервисов" icon="random">
    Плагин объявляет, что даёт и что ему нужно. Ядро строит граф заранее и видит циклы, пропавших поставщиков и несовместимые версии, а не падает на первом вызове.
  </Card>
  <Card title="Сбой изолирован" icon="shield">
    Плагины работают в отдельных процессах-хостах под сторожем. Зависший или упавший плагин получает страйк, а после трёх подряд выключается; окно и терминалы продолжают работать.
  </Card>
  <Card title="Терминалы переживают всё" icon="laptop">
    pty - ресурс ядра в отдельном процессе. Он переживает перезапуск плагина, хоста и окна, а вывод идёт прямо к виду, мимо хоста плагина.
  </Card>
  <Card title="Виды во фреймах" icon="pencil">
    Каждый вид - свой iframe со строгой CSP. Мост узнаёт плагин по origin, а не по словам вида; набор элементов `cy-*` держит тему приложения.
  </Card>
  <Card title="Права словами" icon="approve-check">
    Файлы, процессы, сеть и окружение - только через ядро и только в объявленных областях. Человек читает права обычными словами, а не флагами.
  </Card>
  <Card title="Единые клавиши и меню" icon="rocket">
    Реестр сочетаний без конфликтов между плагинами, меню и акселераторами работает и тогда, когда фокус внутри фрейма вида.
  </Card>
</CardGrid>

## Быстрый старт

<Steps>

1. Установите Node.js 24 и подключите пакеты в приложение на Electron 45:

   ```bash
   npm install @cyborg-harness/core @cyborg-harness/electron @cyborg-harness/contracts
   ```

2. Или посмотрите ядро вживую на стенде:

   ```bash
   git clone https://github.com/dex-it/cyborg-harness.git
   cd cyborg-harness
   npm ci
   npm start
   ```

3. Скопируйте шаблон плагина и запустите его тесты (в клоне из шага 2 пакеты уже стоят):

   ```bash
   cp -R templates/plugin my-plugin
   cd my-plugin
   npm test
   ```

   Пакеты в клоне собирает `npm run build` (или `npm run build:packages`): после него в копии работают `npm run check`, `build` и `test`. `npm run typecheck` копии берёт `tsc` корня клона (TS 6 из алиаса), а по TS 7 шаблон проверяет `npm run typecheck` в корне.

</Steps>

:::caution[Пакеты ещё не опубликованы]
Пакеты `@cyborg-harness/*` и команда `cyborg-plugin` ещё не в реестре. `@cyborg-harness/contracts` готов к выпуску ([P-01](https://github.com/dex-it/cyborg-harness/issues/29): собирается, упаковывается и ставится в пустой проект из tarball), его выпуск - [P-10](https://github.com/dex-it/cyborg-harness/issues/11); остальное публикуется задачами [P-02](https://github.com/dex-it/cyborg-harness/issues/34), [P-05](https://github.com/dex-it/cyborg-harness/issues/39), [P-09](https://github.com/dex-it/cyborg-harness/issues/9). Пакеты scope `@cyborg` на npmjs.com к проекту не относятся. До выпуска работайте из репозитория (`npm ci`, `npm start`).
:::
