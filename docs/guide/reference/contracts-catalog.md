Каталог перечисляет контракты, которые объявляет репозиторий Cyborg. Тип каждого лежит в пакете `@cyborg-harness/contracts`; контракт предметной области описывает плагин-владелец по правилу 11 из [модели контрактов](/concepts/contracts-model/). Пространство `cyborg.*` занимают только плагины из поставки.

## Сводка

| Контракт | Версия | Кратность у потребителя | Объявляет и опрашивает | Поставщики |
|---|---|---|---|---|
| `cyborg.agent` | 1 | `many` | `sessions` | `agent-claude-code`, `agent-shell` и другие агенты |
| `cyborg.agent-tool` | 1 | `many` | `sessions` | Плагины, дающие агенту инструменты (`next-actions`) |
| `cyborg.session-prompt` | 1 | `many` | `sessions` | Плагины с фрагментами промпта (`session-isolation`, `next-actions`) |
| `cyborg.sessions` | 1 | `one` | `sessions` | `sessions` |
| `cyborg.projects` | 1 | `one` | `projects` | `projects` |
| `cyborg.project-settings` | 1 | `many` | `projects` | `trackers` и другие |
| `cyborg.tree-decoration` | 1 | `many` | `files` | `git` и другие |
| `cyborg.editor` | 1 | `one` | `viewer` | `viewer` |
| `cyborg.git` | 1 | `one` | `git` | `git` |
| `cyborg.secret-source` | 1 | по схеме ссылки | Источник секретов | Плагины внешних хранилищ |

## cyborg.agent

Описывает запуск агента и переводит его следы в события. Процесс не создаёт: терминал запускает потребитель по своему праву `pty`.

| Член | Что делает |
|---|---|
| `facts()` | `id`, `title`, `found` (программа найдена), `version?` и `capabilities`: `resume`, `history`, `events` |
| `launch(request)` | Возвращает готовый вход `ctx.os.pty.spawn`: `program`, `args`, `cwd`, `env` |
| `watch(sessionId, listener)` | Подписка на события сессии; у агента без следов молчит |
| `ended(sessionId, exit)` | Убирает файлы поставщика и называет причину по коду выхода: `notFound`, `authRequired`, `rateLimited`, `resumeFailed`, либо `null` |
| `history(cwd)` | Прошлые сессии каталога: `id`, `cwd`, `title`, `updated`; без `capabilities.history` пусто |

`LaunchRequest`: `sessionId` (устойчивый), `cwd`, `extraDirs?`, `prompt?`, `resumeId?`, `promptFragments?`, `tools?` (`url` и `token` сервера MCP потребителя).

События `watch`:

| Тип | Поля | Смысл |
|---|---|---|
| `cwd` | `cwd` | Рабочий каталог сессии изменился |
| `session` | `resumeId` | Сессия агента началась или сменилась; `launch({ resumeId })` её продолжит |
| `activity` | `tool?` | Агент работает |
| `prompt` | - | Человек отправил запрос: прошлые предложения агента не к месту |
| `turnEnd` | `text?`, `background` | Ход закончен; `background` - агент проснётся сам |
| `waiting` | `reason` | Агент ждёт вопрос, разрешение или лимит |

Права: поставщик объявляет `launch` с теми же правилами, что `pty` у потребителя; ядро пропускает запуск, только если он подходит под оба. Программой может быть `$SHELL` с закреплённым скриптом.

## cyborg.agent-tool

Инструменты, которые агент вызывает по MCP. Сервер держит потребитель по праву `serve` и отвечает JSON-RPC по Streamable HTTP.

| Член | Что делает |
|---|---|
| `tools()` | Список `{ name, description, inputSchema }`; имя `[A-Za-z0-9_-]` до 64 знаков, схема - объект JSON Schema |
| `call(name, input, { sessionId })` | Ответ `{ text, isError?, actions? }` |

Поставщик действует с правами агента: описание инструмента попадает в контекст агента до вызова. Поэтому контракт отдают только плагины из поставки (сторонний плагин с ним отклонён), а агент зовёт эти инструменты без вопроса. Правило - в [границах доверия](/concepts/trust/#агент). При одинаковом имени у двух поставщиков берётся поставщик с меньшим id плагина. `actions` - кнопки под сессией: до шести, подпись до 40 знаков, управляющие символы удаляются; новый запрос человека их снимает. Кнопка: `label`, `text`, `submit?`; реплика `text` видна на кнопке второй строкой. С `submit` нажатие отправляет реплику с Enter, только когда агент ждёт новой реплики: ход кончился без фоновой работы, и агент с тех пор не брался за инструмент и не спрашивал. В остальных состояниях и без `submit` реплика встаёт в строку ввода, Enter нажимает человек.

## cyborg.session-prompt

| Член | Что делает |
|---|---|
| `fragment()` | Строка-вклад в системный промпт сессии; пустая строка - вклада нет |

Потребитель собирает фрагменты всех поставщиков по порядку id плагинов, пустые и упавшие пропускает и передаёт в `launch({ promptFragments })`. Фрагмент читает агент, поэтому поставщик действует с правами агента и отдают контракт только плагины из поставки ([границы доверия](/concepts/trust/#агент)).

## cyborg.sessions

Реестр сессий агентов.

| Часть | Что в ней |
|---|---|
| Члены | `create`, `send`, `paste`, `reveal`, приём броска пути |
| События | `onChange` |
| Метки | Владелец сущности даёт метки с ключом по плагину; хранятся только в памяти |
| Команда | `sessions.new` |

## cyborg.projects

Поставщик `projects`, кратность `one`.

| Член | Что делает |
|---|---|
| `list()` | Все проекты: `id`, `name`, `description`, `repos` (абсолютные пути) |
| `get(id)` | Проект или `null` |
| `active()`, `activate(id)` | Активный проект окна; хранится в `ctx.state` |
| `ownerOf(path)` | Проект, которому принадлежит путь: самый длинный совпавший корень |
| `onChange(listener)` | События `added`, `updated` (с `changed`), `removed`, `activated` |

Изменения идут не через контракт: записи меняет владелец через свой диалог, остальные вызывают команды `projects.new` и `projects.edit`. Корни проектов `projects` передаёт ядру через `ctx.security.setRoots` по праву `security.roots`.

## cyborg.project-settings

Секция формы настроек проекта от стороннего плагина; диалог рисует `projects`, значения хранит поставщик в своём разделе.

| Член | Что делает |
|---|---|
| `fields()` | Описание полей секции |
| `load(draft)` | Загрузка значений в форму |
| `validate(draft, values)` | Проверка |
| `save(projectId, values)` | Сохранение |

Значений секретов в форме нет: хранится выбор «локально» или «ссылка» и сама ссылка.

## cyborg.tree-decoration

Отметки в дереве файлов, например статус git. Объявляет владелец дерева, `files`; поставщики отдают отметки, рисует владелец.

## cyborg.editor

Редактор документов у `viewer`. Плагин, которому нужен редактор, не встраивает его, а вызывает контракт и получает данные. Пример из руководства - `editJson({ title, value, schema })`: возвращает текст или `undefined`, если человек отменил.

## cyborg.git

| Член | Что делает |
|---|---|
| `root`, `branch`, `status`, `headContent`, `branches`, `switch`, `remotes`, `files` | Сведения о репозитории и переключение ветки |

Плагин `git` имеет право `process` на программу `git`.

## cyborg.secret-source

Источник секретов (Vault, 1Password, `pass`) - плагин. Выбирается по схеме ссылки: два поставщика одной схемы - отказ при загрузке.

| Элемент | Описание |
|---|---|
| Манифест поставщика | `"provides": { "cyborg.secret-source": { "version": "1.0", "schemes": ["vault"] } }` |
| `resolve(ref)` | Возвращает `{ value, expiresAt? }` |
| `list(prefix)` | Необязательно: пути без значений для выбора ссылки в форме |
| Права | Потребитель - `secrets.ref` с масками; источник видит запрос, но не знает, кто спросил |

Ядро значение не кэширует и не пишет в журнал.

## Сторонние контракты

Контракт стороннего автора называется по автору (`acme.*`) и публикуется в собственном пакете объявлений, который дополняет карту `Contracts` через `declare module '@cyborg-harness/contracts'`.
