Права объявляются в поле `permissions` манифеста. Нет права - нет объекта в `ctx.os`, а вызов в обход формы отклоняет шлюз ядра. Неизвестное право в манифесте - ошибка манифеста, а не молчаливое «нет права».

## Перечень прав

| Право | Значение | Что открывает в `ctx.os` |
|---|---|---|
| `fs.read` | Список областей путей | Чтение файлов, каталогов, `stat`, `readSlice`, `watch` |
| `fs.write` | Список областей и `workspace.git` | `writeText`, `mkdir`, `remove` |
| `shell` | Области путей и схемы URL | `shell.openPath` по путям, `shell.openExternal` по схемам |
| `process` | Список программ | `process.run` |
| `pty` | Список программ | `pty.spawn`, `list`, `attach` |
| `launch` | Список программ | Ничего: описывает запуск, который выполнит потребитель |
| `net` | Список хостов | `net.fetch` |
| `env` | Список имён переменных | `env.get` |
| `notify` | `true` | `notify.show`, `notify.close` |
| `clipboard` | `["read"]`, `["write"]` или оба | `clipboard.readText`, `clipboard.writeText` |
| `secrets.ref` | Маски ссылок | Разрешение ссылок на внешний источник секретов |
| `security.roots` | `true` | `security.setRoots` |
| `ui.lock` | `true` | `ui.lock` |
| `serve` | `true` | `serve.http` |

## Что доступно без права

| Возможность | Ограничение |
|---|---|
| `paths.data`, `paths.temp`, `paths.home` | Пути своих каталогов и домашнего каталога |
| `fs.*` в своих каталогах `plugin-data` и `plugin-temp` | Только внутри них |
| `secrets.get`, `set`, `delete` | Только свои ключи; без шифрования ОС - `Unavailable` |
| `dialog.open` | Выбор человека сам становится областью `granted` этого плагина |
| `ctx.commands`, `ctx.contracts`, `ctx.documents`, `ctx.config`, `ctx.state` | Только своё |

## Области путей

Применяются в `fs.read`, `fs.write` и `shell`.

| Запись | Что значит |
|---|---|
| `workspace` | Репозитории проектов и рабочие каталоги живых сессий; их задают плагины с правом `security.roots` |
| `plugin-data` | Свой каталог данных |
| `plugin-temp` | Свой временный каталог |
| `granted` | Пути, выбранные человеком в `dialog` |
| `workspace.git` | Только в `fs.write`: запись в `.git` корней воркспейса |
| `any` | Только в `shell`: любой существующий документ или каталог, например ссылка из вывода сессии. Программы, скрипты и файлы не из списка документов не открываются, защищённые пути и чужие каталоги закрыты. Там, где пишет сам плагин или вызывающий его через контракт, - только документы |
| Абсолютный путь | Каталог с поддеревом; `~` - домашний каталог |
| Маска | `*` - один сегмент, `**` - любая глубина и только целым сегментом |

Правила масок: первый сегмент не содержит `*`, `.` и `..` не допускаются, так что маска не начинается с корня файловой системы. Каталог, попавший под маску, - корень своей области, и `fs.remove` его не удалит.

## Правила шлюза

- Вызывающего ядро определяет по каналу, а не по словам плагина.
- Путь проверяется после `realpath` на открытом дескрипторе. Вне области - всегда `PermissionDenied`, никогда `NotFound`.
- Всегда закрыты: данные приложения, файл воркспейса и замок, каталоги других плагинов, запись в `.git` без `workspace.git`. Исключение - корни проектов, которые задаёт само приложение.
- `fs.remove` не удаляет корень области и каталог, внутри которого есть `.git`.
- Права через чужой контракт не передаются, действует `guard` поставщика.
- Каждый отказ пишется в [журнал](/reference/journal/) записью `denied`; одинаковые отказы за пять секунд склеиваются.

## process и pty

Элемент списка - строка с именем программы или объект `{ "program", "args", "env" }`.

| Форма | Смысл |
|---|---|
| `"git"` | Программа с любыми аргументами |
| `{ "program": "npm", "args": ["test"] }` | Программа с закреплёнными первыми аргументами |
| `{ ..., "env": ["CI"] }` | Дополнительно можно передать названные переменные окружения |
| `{ "program": "$SHELL", "args": ["-lc", "скрипт", ...] }` | Оболочка входа человека; путь подставляет ядро |

`$SHELL` допустим только с закреплёнными флагом и скриптом: не меньше двух аргументов. Оболочка без скрипта запустила бы что угодно. Запущенная программа получает базовое окружение (`PATH`, `HOME`, локаль, `TERM` и системные переменные) и только переменные из `env` правила. Рабочий каталог проверяется как чтение.

`pty.spawn` принимает `persist: true`: процесс переживает перезапуск хоста, и владелец забирает его через `attach`. Чужого терминала для плагина не существует (`NotFound`).

## net

Список хостов (`api.github.com`) или `config:<поле>`: хост берётся из своего раздела `config`. Правила:

- без порта разрешён только порт схемы по умолчанию, переадресация не выполняется;
- хост берётся из слоя пользователя: значение того же поля в файле воркспейса хоста не даёт, `net.fetch` на него получает `PermissionDenied`, причина названа в журнале;
- плагин сам не может записать в поле `config` значение, которое расширило бы сеть: в слой пользователя допустимо только значение, уже заданное в нём;
- запрос вместе с телом ответа по умолчанию ждёт не дольше 30 секунд, затем `Timeout`; тело ответа больше 16 МиБ обрывается ошибкой `Remote`.

## shell

В `shell` помещаются области путей и схемы URL с двоеточием (`https:`, `mailto:`). Схемы `file:`, `javascript:`, `data:`, `vbscript:` манифест не примет. `openPath` не открывает исполняемый файл: ни по расширению (`.sh`, `.exe`, `.app`, `.desktop` и подобные), ни по биту `x`. В областях, куда плагин пишет (`fs.write`, а также `plugin-data` и `plugin-temp`), он открывает только документ: `.txt`, `.md`, `.log`, `.csv`, `.json`, `.pdf`, `.rtf`, `.odt`, `.ods`, `.odp`, `.docx`, `.xlsx`, `.pptx`, `.epub`, картинки, звук и видео. HTML и SVG там не открываются: браузер выполнил бы их скрипт.

## serve

`serve.http(handler)` поднимает сервер HTTP на `127.0.0.1` с портом от ОС. До четырёх серверов на плагин; выгрузка и падение хоста их закрывают. Ядро отвечает само, не обращаясь к плагину: чужой `Host` - 421, заголовок `Origin` - 403, тело больше 1 МиБ - 413, нет ответа за 30 секунд - 504, падение обработчика или чужая форма ответа - 502. Кто звонит, ядро не знает: вызывающего проверяет плагин, например токеном.

## Права словами

Окно управления плагинами и `cyborg-plugin check` описывают права одними и теми же строками.

| Право | Строка |
|---|---|
| `fs.read` | читает файлы: проекты воркспейса, свои данные, выбранное человеком в диалоге |
| `fs.write` | пишет файлы: те же области |
| `shell` | открывает в системе: области и схемы |
| `process` | запускает программы: список - полный доступ через программу |
| `pty` | запускает в терминале: список - полный доступ через программу |
| `launch` | предлагает запуск в терминале: список - его выполнит потребитель |
| `net` | ходит в сеть: хосты; для `config:<поле>` - хост из настройки |
| `env` | читает переменные окружения: имена |
| `notify` | показывает системные уведомления |
| `clipboard` | буфер обмена: чтение, запись |
| `secrets.ref` | читает секреты по маскам ссылок |
| `security.roots` | задаёт корни проектов, доступные другим плагинам |
| `ui.lock` | может закрыть окно Cyborg |
| `serve` | принимает запросы HTTP на 127.0.0.1 - от программ этого компьютера |
