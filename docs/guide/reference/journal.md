---
title: "Журнал"
description: "Записи журнала плагинов: когда ядро их пишет, какие поля несут и как по ним вычисляется состояние плагина."
---

Журнал плагинов - то место, где ядро объясняет, почему плагин не загрузился, остановился или получил отказ. Он виден в окне управления плагинами. Каждая запись относится к плагину (`pluginId`) или к хосту целиком. Записи описаны словами для человека, а поля ниже нужны тому, кто читает журнал программой.

## Записи по плагину

| Запись | Уровень | Когда пишется | Поля |
|---|---|---|---|
| `disabled` | инфо | Плагина нет в `plugins.enabled` | - |
| `not-found` | ошибка | Плагин включён, но не найден в каталогах плагинов | - |
| `invalid` | ошибка | Манифест не разобран | `errors` - список причин |
| `rejected` | ошибка | Граф контрактов отказал | `reasons` - см. ниже |
| `safe-mode` | предупреждение | Безопасный режим: код не запускается | - |
| `skipped` | предупреждение | Поставщик из `requires` не активен | `reason` |
| `config`, `state` | инфо или ошибка | Раздел не прошёл проверку или миграцию, либо плагин откатили | `result` - см. ниже |
| `waiting` | инфо | Ленивый плагин ждёт пробуждения | - |
| `activated` | инфо | Плагин поднят | `hostId`, `ms` - время запуска |
| `failed` | ошибка | Хост не запустился или `activate` упал | `hostId`, `error` |
| `deactivated` | инфо или предупреждение | Плагин снят; с ошибкой - предупреждение | `error?` |
| `unloaded` | инфо или предупреждение | Выключен человеком или вместе с поставщиком, которого требовал | `by`, `error?`, `keptPty?` |
| `uninstalled` | инфо или ошибка | `kernel.uninstall`: что стёрто и что осталось словами; с `error` - какие шаги не удались, повтор доделает | `erased`, `left`, `error?` |
| `revived` | инфо | Включён снова | - |
| `unhandled-rejection` | предупреждение | Промис плагина отклонён без обработчика; хост держится, плагину страйк | `error` |
| `switched-off` | ошибка | Выключен сторожем после череды сбоев: зависаний, падений, необработанных отклонений. С `reason: 'log-flood'` - выключен за поток строк `ctx.log` и вывода хоста выше предела частоты дольше 10 с (сбоев не было, `strikes` равен 0) | `strikes`, `affects`, `reason?` |
| `log-summary` | предупреждение | Плагин написал строк больше предела за интервал (по умолчанию 100 за 1 с): по одной они в журнал не идут, в конце интервала пишется эта запись. Состояние плагина не меняет | `skipped`, `errors`, `lastError?` - последняя пропущенная строка уровня `error` |
| `denied` | предупреждение | Шлюз `ctx.os` отказал: вызов вне прав; с `reason: 'window'` - окно не пустило вид на чужой адрес | `method`, `detail`, `reason?`, `repeats?` |
| `pty-expired` | предупреждение | Терминал без владельца не взят через `attach` за льготное время и завершён: после падения хоста или после активации плагина, в том числе вернувшегося к оставленным человеком процессам | `id`, `program`, `graceMs` |
| `key-conflict` | предупреждение | Сочетание уже занято другим плагином | `key`, `command`, `winner` |
| `host-isolated` | предупреждение | Сторонний плагин назван в группе, но получил отдельный хост | `group`, `hostId` |
| `group-isolated` | предупреждение | Сторонний плагин назван в группе рендера с другими (`reason: 'third-party'`): плагин получил свою группу (`renderGroup` - его id, origin его видов - `solo_<id>`) | `group`, `renderGroup`, `reason` |
| `third-party` | предупреждение | Загружен плагин не из поставки: на первом этапе это плагин из каталога пользователя, включённого флагом `--user-plugins`. Код не проверен; запись состояния не меняет. Пишется, только когда приложение передало ядру список поставки `bundled` | - |
| `host-own-grouped` | предупреждение | Плагин поставки просит `"host": "own"`, а группа `plugins.hosts` сажает его к соседям: действует группа | `group`, `neighbours` |

## Записи по хосту и настройкам

У этих записей нет `pluginId`, они касаются хоста или записей `plugins.keybindings`.

| Запись | Уровень | Когда пишется | Поля |
|---|---|---|---|
| `host-down` | предупреждение | Хост завис или упал; у pty-хоста `hostId: pty-host` | `hostId`, `reason` (`hang` или `crash`), `culprits`, `plugins`, `affects`; у pty-хоста `lostPtys` - владельцы потерянных pty, они получили выход `{ code: -1 }` |
| `host-restart` | инфо | Хост перезапускается | `hostId`, `plugins` |
| `host-abandoned` | ошибка | Хост падает без виновника несколько раз подряд и больше не перезапускается; pty-хост поднимет снова следующий `spawn` | `hostId`, `failures`, `plugins` |
| `key-ignored` | предупреждение | Привязка `plugins.keybindings` не применена | `key`, `command`, `reason` |
| `trace-args` | предупреждение | Приложение запущено с `--trace-args`: записи трассы несут аргументы операций, в файле диагностики и выгрузке будут пути и данные человека; пишется один раз при запуске | `limit` - предел длины аргументов в записи, байт |

## Причины отказа графа (rejected)

| Причина | Смысл |
|---|---|
| `duplicate` | Два манифеста с одним id: ядро отвергает оба. Приложение второй манифест ядру не передаёт, поэтому из каталогов поставки и пользователя эта причина не приходит |
| `engines` | `engines.cyborg` не принимает версию API; поля `range` и `api` |
| `missing` | Нет поставщика для `requires`; поля `contract`, `range` |
| `ambiguous` | Несколько поставщиков при кратности `one`; поля `contract`, `providers` |
| `cycle` | Цикл зависимостей; поле `members` |
| `command` | Одну команду объявили два плагина (например, `a` и `a.b` оба объявили `a.b.run`): отказ обоим, а если один из них встроенный - только остальным; поля `command`, `with` |
| `reserved` | Сторонний плагин занял пространство поставки (`cyborg.`): `what` - `id` или `provides`, поля `name`, `prefix` |

Отказ каскадом переходит на плагины, которые требовали отказавшего.

## Результат раздела (config, state)

| Статус | Смысл |
|---|---|
| `ok` | Раздел прочитан, `migrated` называет слои, где выполнена миграция |
| `newer` | Версия раздела выше известной плагину: похоже, плагин откатили. Данные не тронуты |
| `migrate-error` | `migrate` бросил исключение; поля `layer`, `from`, `error` |
| `invalid` | Значение не прошло схему или `validate`; `errors` - список |

## Отказы шлюза: denied

Поле `method` называет вызов (`fs.readText`, `config.set`, `ui.lock` и другие), `detail` - причину. `reason: 'via-contract'` означает, что право проверялось у вызывающего через `guard` поставщика. `reason: 'command-callers'` - главная часть плагина позвала чужую команду, которую исполнитель не открыл плагинам (`callers`); `method` - имя команды, запись лежит у вызывающего. `reason: 'window'` с `method: 'navigate'` - вид пытался увести свой или чужой фрейм либо окно с адреса плагина; в `detail` - адрес, обрезанный до 200 символов. `reason: 'csp'` с `method: 'csp'` - CSP не пустила на странице вида запрос или стиль; в `detail` - что отклонено и директива, для инлайн-стиля ещё и подсказка про флаг `ui.inlineStyles` манифеста (текст обрезан до 200 символов). Одинаковые отказы одного плагина за пять секунд склеиваются: первый пишется сразу, повторы - одной записью с полем `repeats`. В журнале хранится не больше тысячи записей `denied`; при переполнении уходит старейший отказ самого шумного плагина, так что поток отказов одного плагина не вытесняет чужие. Так же ограничены записи `log-summary` (тысяча, вытесняется старейшая самого шумного плагина). Прочие записи не вытесняются: из них выводится состояние плагинов.

Значения секретов в журнал не попадают.

## Состояние плагина по журналу

Состояние вычисляется по последней записи жизненного цикла. Записи `key-conflict`, `key-ignored`, `trace-args`, `denied`, `deprecated-call`, `unhandled-rejection`, `pty-expired`, `host-isolated`, `group-isolated`, `host-own-grouped`, `third-party` и `log-summary` о работе плагина ничего не говорят и состояние не меняют: они приходят и после снятия плагина, но запись снятия не перекрывают. По той же последней записи жизненного цикла зависимого `enable` поставщика решает, поднимать ли его: поднимается зависимый, снятый вместе с этим поставщиком (`unloaded` с `by` поставщика), или пропущенный (`skipped`).

| Запись | Состояние | «Включить снова» |
|---|---|---|
| `activated` | Работает | - |
| `waiting` | Ждёт | - |
| `disabled` | Выключен в настройках | - |
| `host-down`, `host-restart`, `revived` | Перезапускается | - |
| `switched-off`, `failed`, `skipped`, `host-abandoned` | Остановлен | Есть |
| `unloaded` (выгружен сам) | Остановлен | Есть |
| `unloaded` (вместе с поставщиком), `uninstalled`, `invalid`, `not-found`, `rejected`, `safe-mode`, `config`, `state`, `deactivated` | Остановлен | Нет: причина в манифесте, настройках или у поставщика |

## Уровни

- **инфо:** `activated`, `waiting`, `disabled`, `revived`, `host-restart`; `unloaded`, `deactivated` и `uninstalled` без ошибки.
- **предупреждение:** `denied`, `key-conflict`, `key-ignored`, `trace-args`, `safe-mode`, `skipped`, `unhandled-rejection`, `pty-expired`, `host-down`, `host-isolated`, `group-isolated`, `host-own-grouped`, `third-party`, `log-summary`; `unloaded` и `deactivated` с ошибкой.
- **ошибка:** все остальные, а также `config` и `state`, если статус не `ok`, и `uninstalled` с `error`.
