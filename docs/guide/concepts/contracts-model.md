Плагины не знают друг друга по имени. Поставщик отдаёт реализацию контракта, потребитель просит контракт, а ядро передаёт вызовы между ними. Обе стороны знают только имя, версию и тип контракта.

## Четыре строки манифеста

| Поле | Роль плагина | Кратность | Если поставщика нет |
|---|---|---|---|
| `provides` | Поставщик: отдаёт контракт | - | - |
| `requires` | Потребитель, поставщик обязателен | `one` | Плагин не загружается |
| `optional` | Потребитель, поставщик желателен | `one` | Плагин работает, `ctx.contracts.get` вернёт `undefined` |
| `consumes` | Потребитель вкладов от многих поставщиков | `many` | Список пуст |

Кратность объявляет потребитель. При `one` два поставщика - отказ при загрузке, и выбор остаётся за пользователем. При `many` ядро собирает всех поставщиков в список, и они приходят и уходят во время работы.

```jsonc
// манифест потребителя
"requires": { "cyborg.sessions": "^1" },
"optional": { "cyborg.projects": "^1" },
"consumes": { "cyborg.tree-decoration": "^1" }
// манифест поставщика
"provides": { "cyborg.tree-decoration": "1.0" }
```

Тип контракта не задаётся вызывающим: он выводится из имени и мажорной версии по карте `Contracts` пакета `@cyborg-harness/contracts`. Потребитель получает `Remote<T>`, у которого каждый метод асинхронный.

```ts
const sessions = ctx.contracts.get('cyborg.sessions', 1);
const all = ctx.contracts.all('cyborg.tree-decoration', 1);
ctx.subscriptions.add(ctx.contracts.onChange('cyborg.tree-decoration', refresh));
```

Компилятор ловит опечатки в имени и версии. Ядро ловит остальное: контракт не объявлен в манифесте, мажорная версия вне диапазона - вызов получает `NotDeclared`.

## Версии

Версии семантические. Минорное изменение добавляет необязательный член или поле либо новое значение в объединении событий, и потребитель обязан пропускать незнакомое. Мажорное - удаляет или переименовывает член, добавляет обязательное поле аргумента, меняет смысл.

Поставщик может отдавать две мажорные версии сразу, и каждый потребитель получает ту, что просил:

```jsonc
"provides": { "cyborg.sessions": ["1.4", "2.0"] }
```

Член, помеченный как устаревший, живёт минимум до следующей мажорной версии. Ядро пишет в журнал, кто его вызывает.

Пространство `cyborg.*` принадлежит репозиторию Cyborg и пакету `@cyborg-harness/contracts`, и объявлять такие контракты могут только плагины из поставки. Сторонние контракты называются по автору, например `acme.*`, и публикуются в собственных пакетах объявлений.

## Команды

Команда - вторая связь без зависимости: «пусть сделает кто-нибудь». Исполнитель объявляет её в `commands` манифеста вместе со схемой аргументов, ядро сверяет аргументы до обработчика, откуда бы ни пришёл вызов. Имя команды лежит в пространстве имён плагина (`<id>.`). Виды аргументов: `string`, `number` (конечное), `boolean`, `array`, `strings`, `record`, `any` (не `undefined`). Обработчик получает `unknown[]`, поэтому схема - проверка во время работы, а не тип для компилятора.

Третий вид связи - тип данных при перетаскивании и в буфере обмена, например `application/x-cyborg-path`.

## Одиннадцать правил

| № | Правило |
|---|---|
| 1 | Связь через контракты, а не друг через друга: поставщик не знает потребителей, потребитель - поставщика |
| 2 | Кратность объявляет потребитель: `one` или `many` |
| 3 | Помимо контрактов есть команды по имени и типы данных при перетаскивании |
| 4 | Общей шины событий нет: событие - часть контракта того, кто владеет предметом |
| 5 | API контракта асинхронный и только с данными; обратный вызов - только подписка с `Disposable` |
| 6 | Подписки привязаны к вызывающему: ядро снимает их при выгрузке или падении любой из сторон |
| 7 | Раздел `config` - не канал связи: плагин видит только свой раздел |
| 8 | Версии контрактов семантические |
| 9 | Тип контракта выводится из имени и мажорной версии, а не задаётся вызывающим |
| 10 | Аргументы команды описывает манифест исполнителя, ядро сверяет их до обработчика |
| 11 | Контракт вклада объявляет владелец сущности или вида; вкладчик зависит от владельца, а не наоборот |

### Как работает правило 5

Функция-колбэк остаётся в хосте потребителя, через границу идёт её номер. Вызовы возвращаются сообщениями через ядро, а `dispose()` снимает подписку у поставщика. Если поставщик не вернул `Disposable`, колбэк живёт только до ответа.

### Как работает правило 11

Общий ресурс предметной области получает плагин-владелец с контрактом, а не место в ядре. Следствия:

- **Общий ресурс** - свой плагин с контрактом. Например, `git` даёт `cyborg.git`, и ему не нужно знать ни дерево, ни просмотрщик.
- **Данные одного плагина в виде другого.** Владелец вида объявляет вклад с кратностью `many`, вкладчики отдают данные, рисует владелец. Так `files` объявляет `cyborg.tree-decoration`, а `git` поставляет отметки.
- **Состояние у чужой сущности.** Владелец сущности даёт метки с ключом по плагину, только в памяти. Цикла между плагинами при этом нет: оба зависят от владельца, а не друг от друга.
- **Меню** - вид ядра, вклады в него плагины объявляют по тому же правилу.

Чужой интерфейс в свой не встраивается. Если плагину нужен редактор, он вызывает контракт владельца редактора, а тот сам показывает документ или диалог и возвращает данные.

## Права при вызове через контракт

Поставщик, который по чужой просьбе читает или пишет путь, объявляет в `provides` блок `guard`: какие аргументы его членов являются путями или ссылками и по какому праву их проверять. Ядро сверяет аргумент с правом вызывающего до передачи вызова, а отказ записывает как `denied` с причиной `via-contract`. Дальше поставщик работает своими правами, поэтому действует пересечение: право вызывающего поставщика не расширяет.
