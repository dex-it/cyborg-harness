Слово «изоляция» в ядре означает три разные вещи. Они стоят по-разному и вводятся по-разному, поэтому их полезно различать.

| Вид | Чем даётся | Что защищает |
|---|---|---|
| Сбоев | Хосты плагинов и сторож | Зависание или падение плагина не трогает другие хосты, окно и терминалы |
| Рендера | Свой `<iframe>` с CSP на вид, группы рендера | Плагин рисует только у себя и не получает сеть в обход прав |
| Доступа | Процесс на плагин, ограничения Node, окна согласия | Плагин физически не может сделать ничего сверх объявленного |

Первые два вида действуют для всех плагинов уже на первой ступени. Третий вид относится ко второй ступени и вводится по поводу: плагин от стороннего автора, который нужно дать установить пользователю, или каталог плагинов. До этого доступ держат шлюз и дисциплина, о которых сказано ниже.

## Изоляция сбоев

Главные части плагинов работают не в главном процессе, а в хостах (`utilityProcess`). Плагины одного хоста делят процесс и цикл событий: зависание одного останавливает соседей, падение хоста роняет все его плагины. Поэтому группировкой по хостам управляет пользователь:

```jsonc
"plugins": {
  "enabled": ["sessions", "agent-claude-code", "files", "trackers", "search"],
  "hosts": {
    "builtin":  ["sessions", "agent-claude-code", "files"],
    "trackers": ["trackers", "search"]
  }
}
```

- `plugins.hosts` - часть `config` на уровнях пользователя и воркспейса.
- Плагины из поставки по умолчанию идут в хост `builtin`. Манифест может попросить отдельный хост (`"host": "own"`); пользователь вправе переопределить, но окно управления плагинами покажет предупреждение.
- **Сторонний плагин всегда один в своём хосте.** Признак поставки определяет каталог установки, а не манифест: автор может написать в манифест что угодно. Если пользователь назвал стороннего в группе с другими, ядро всё равно даёт ему отдельный хост и пишет в журнал `host-isolated`.
- Исключение внутри хоста ловит сам хост: отказывает один плагин, а не все.

### Сторож

Ядро пингует каждый хост раз в секунду. Нет ответа дольше пяти секунд - хост перезапускается. Пороги выбраны замером: обход 230 тысяч записей без `await` занимает две секунды, а порог равен самой долгой синхронной работе, которую плагин вправе сделать подряд. Виновник - при зависании плагин, чей код хост выполнял (хост называет плагин ядру до входа в его код: вызов, событие, таймер, продолжение после ответа ядра), при падении - плагин, чей код завершил процесс (`process.exit`, необработанное исключение в его цепочке); хост виновника не назвал, например процесс убит сигналом, - плагин первого вызова, принятого после последнего отвеченного пинга. Отметка ставится на входах хоста, в его глобальных таймерах и `queueMicrotask`: зависание кода, запущенного мимо них, и кода самого хоста после плагина записывается на плагин, вошедший последним. Необработанное отклонение промиса плагина хост не роняет: запись `unhandled-rejection` и страйк плагину, с чьего входа началась цепочка. Три сбоя подряд - зависания, падения, отклонения - выключают плагин с записью в журнале.

Перезапуск не трогает другие хосты, окно и терминалы. Цена изоляции - память на процесс: замер на Linux показал около 56 МБ на первый хост и около 34 МБ на каждый следующий, плагины в одном хосте добавляют мало. На macOS замеры дают другие цифры, потому что и ОС, и способ измерения другие.

## Изоляция рендера

Каждый вид и тип документа живёт в своём `<iframe>` с собственным DOM, CSS и `window`. Origin кадра задаёт группа рендера: кадры одной группы делят origin `cyborg-plugin://<группа>/` и процесс рендера, у каждой группы свой процесс.

```jsonc
// манифест - рекомендация автора
"ui": { "group": "terminal", "views": { "terminal": "./ui.js" } }
// config пользователя - решение владельца (поле воркспейса не действует)
"plugins": { "uiGroups": { "terminal": ["sessions", "agent-claude-code"], "workspace": ["files", "viewer"] } }
```

Группы устроены как хосты. Плагин без группы получает группу со своим id, то есть свой origin и свой процесс. Сторонний плагин всегда один в своей группе, из любого слоя config и из манифеста: если его назвали в группе с другими, ядро даёт ему группу с его id, пишет в журнал `group-isolated`, а окно предупреждает в строке плагина. Его origin - `cyborg-plugin://solo_<id>`: такого имени у групп поставки нет, поэтому группа поставки с именем, совпавшим с id стороннего плагина, не получит ни его origin, ни его веб-хранилище, и в следующем запуске тоже. Итог для плагина: `plugins.uiGroups` файла пользователя, затем `ui.group`, затем группа со своим id. Группы из файла воркспейса не действуют: группа делит мост плагинов, а присланный файл такого права не имеет. Адрес вида - `cyborg-plugin://<группа>/<плагин>/`.

Выбор группы - компромисс по цене: свой процесс рендера стоит около 13 МБ на вид (замер на Linux; около 18 МБ на macOS при десяти видах), поэтому процесс на каждый вид дорог, а один origin на всё стирает границы между несвязанными частями.

### Что запрещает CSP вида

CSP вида строгая: `default-src 'none'` и явные источники - скрипты, соединения, стили и шрифты только со своего origin, картинки ещё и `data:`; `<base href>` адреса вида не меняет, форма ничего не отправляет (`base-uri 'none'`, `form-action 'none'`). Стили инлайн (`<style>` и атрибут `style` в разметке) разрешены только виду плагина, который объявил в манифесте `ui.inlineStyles: true`, потому что их вставляют, например, xterm и Monaco; запись через CSSOM и элементы `cy-*` флага не требуют. Следствия:

- встроенный скрипт не выполняется;
- запросы в интернет и на чужие origin блокируются;
- `parent.document` и мост оболочки недоступны;
- фреймы закрыты: вид не встраивает в себя ни соседа по группе, ни чужую страницу;
- сеть виду не нужна: всё, что выходит наружу, идёт через главную часть и шлюз `ctx.os.net`, иначе страница обошла бы права.

CSP не граница между плагинами одной группы: они делят origin, и вид читает и правит документ соседа (`parent.frames`) при любой CSP соседа. Граница доверия - группа; сторонний плагин всегда один в своей группе.

Код вида - браузерный бандл без Node. Пакеты npm в нём разрешены, встроенные модули Node и `electron` - нет, это проверяется при сборке.

### Мост видов

Главный процесс узнаёт плагин по адресу кадра-отправителя, а не по словам вида: группа берётся из origin, плагин из первого сегмента пути, и плагин обязан состоять в этой группе. Вид может сменить путь своего кадра и стать соседом по группе, но не плагином вне её. Внутри группы плагины друг друга подменяют, как плагины одного хоста, поэтому граница доверия проходит по группе. Мост выдаётся по схеме документа: виду - свой, окну - свой, чужой странице внутри вида - ничего.

### Окно и навигация

Вид не открывает новых окон и не уводит окно на чужую страницу: иначе внутри Cyborg появилась бы, например, поддельная форма входа в GitHub. Свой фрейм вид может перевести только на адрес своего плагина. Попытку уйти главный процесс отменяет, вид остаётся на месте, а в журнал плагина пишется отказ `denied` с `reason: 'window'`. Ссылку наружу вид открывает через главную часть: `ctx.os.shell.openExternal` по праву `shell`.

## Изоляция доступа

Для главных частей действует правило: к системе только через `ctx.os`. Шлюз сверяет каждый вызов с правами манифеста, и нет права - нет объекта. Пока код плагина работает в обычном процессе Node, шлюз делает права видимыми и ловит ошибки, но плагин, который захочет, может обратиться к `node:fs` напрямую. Поэтому дисциплина проверяется тестами и командой `cyborg-plugin check`, а не ревью:

- члены контрактов асинхронные, аргументы и результаты переживают `structuredClone`;
- главная часть импортирует только `@cyborg-harness/contracts` и свои модули: ни чужих плагинов, ни `node:*`, ни `electron`;
- вид общается с главной частью и ядром только через `ctx`;
- вид не трогает DOM соседей по группе.

Гарантию «ничего сверх объявленного» для стороннего кода даёт следующая ступень, и она уже есть для плагинов не из поставки: процесс Node на плагин с ограничениями Node (`--permission`), поверх него ограничитель ОС. Одного `Compartment` недостаточно (общая виртуальная машина пробивается), и вторым слоем он пока не добавлен. Флаг `--permission` `utilityProcess` принимает, но не применяет, поэтому сторонний плагин запускается в отдельном процессе Node, а не в `utilityProcess`. Если дисциплина выше соблюдена, переход меняет среду выполнения хоста, а не код плагинов.

### Уровни изоляции процесса

Каждый запуск хоста называет уровень от 0 до 3 и причину словами; «Плагины Cyborg» показывают «Изоляция N из 3» в строке плагина, журнал - запись `isolation`.

| Уровень | Что это | Что закрыто | Что открыто |
|---|---|---|---|
| 0 | Хост без явного окружения и запретов | Ничего | Всё |
| 1 | `utilityProcess` с явным окружением (плагины поставки; сторонний, если включён возврат или нет отдельного Node) | Токены главного процесса не в окружении, хост получает только своё | Файлы, программы и сеть мимо `ctx.os`: запретов ОС нет. Для плагина поставки это доверие к нашей сборке и проверке, для стороннего - прямое предупреждение |
| 2 | Процесс Node под `--permission`, ограничителя ОС нет | Чтение только каталога плагина и кода хоста, нет запуска программ, потоков и аддонов, окружение пусто | **Сеть и сокеты:** плагин может открыть соединение мимо `ctx.os.net` |
| 3 | То же и ограничитель ОС (Seatbelt на macOS; Landlock и seccomp на Linux) | Дополнительно сокеты не создаются, `fork` и чужие программы отказаны на уровне ОС | Метаданные файлов (`stat`) на macOS; на Linux - то, что разрешает Landlock вашего ядра |

Хост доказывает заявленное сам при каждом запуске, пробуя запрещённое. Не доказал - плагин не запускается, в журнале `sandbox-ineffective`. Ядро Linux без Landlock (до 5.13) оставляет сеть закрытой (seccomp), но файлы держат только запреты Node: это уровень 2, и причина называет ядро. Возврат сторонних плагинов на `utilityProcess` - одна настройка приложения.

:::caution[Честная граница]
Права `process` и `pty` дают программе все права пользователя ОС. Списки аргументов смягчают риск, но не защищают. Полную гарантию получают плагины-интеграции, которым нужны только сеть к своему хосту и свой токен. Подробнее - [границы доверия](/concepts/trust/).
:::

## Что дороже, а что дешевле

| Мера | Цена | Что покупает |
|---|---|---|
| Хосты по группам | Память на процесс | Сбой одной группы не трогает другие |
| Группы рендера | Память на процесс рендера | Граница DOM между несвязанными частями |
| pty-хост | Один процесс | Терминалы переживают хост плагина |
| Процесс на плагин (доступ) | Около 28-39 МБ PSS на Linux (замер пустого плагина), отдельный бинарник Node в поставке (около 120 МБ), обмен через главный процесс и кодек типов канала | Запреты файлов, программ, потоков и аддонов, а с ограничителем ОС и сети, для чужого кода |
