Плагины не знают друг друга: поставщик и потребитель называют контракт по имени и мажорной версии, а тип берут из пакета объявлений. Ядро сводит их до запуска кода и передаёт вызовы между хостами.

## Объявить в манифесте

```jsonc
// поставщик
"provides": { "cyborg.files": ["1.4", "2.0"] }
// потребитель
"requires": { "cyborg.files": "^2" },
"optional": { "cyborg.projects": "^1" },
"consumes": { "cyborg.tab": "^1" }
```

`requires` и `optional` - кратность one (один поставщик), `consumes` - many (все поставщики списком). Два поставщика при кратности one - отказ при загрузке, выбор за пользователем. Недостающий `requires`, цикл и несовместимая версия мешают плагину загрузиться, и причина попадает в журнал.

## Отдать и взять

```ts
// поставщик: версия берётся из provides, тип - из карты Contracts
ctx.contracts.provide('cyborg.files', '2.0', {
  readText: async (path: string) => {
    const text = disk.get(path);
    return text === undefined ? undefined : { path, text, size: text.length };
  },
});

// потребитель кратности one
const files = ctx.contracts.get('cyborg.files', 2); // Remote<FilesV2> | undefined
const file = await files?.readText('/notes.txt');

// потребитель кратности many
const tabs = ctx.contracts.all('cyborg.tab', 1);    // Provider<Remote<Tab>>[]
ctx.subscriptions.add(ctx.contracts.onChange('cyborg.tab', () => refresh()));
```

Мажорная версия в `get` и `all` обязательна: по ней компилятор выводит тип, а ядро сверяет её с диапазоном манифеста. Версия вне диапазона - `NotDeclared`. Результат `get` - `Remote<T>`: каждый метод возвращает `Promise`, даже если в типе он синхронный, а поле данных приходит снимком на момент `provide`.

## Свой контракт

Контракты вашего пространства (`acme.*`) объявляет ваш пакет: он дополняет карту, ничего не меняя в `@cyborg/contracts`.

```ts
// @acme/contracts/index.ts
declare module '@cyborg/contracts' {
  interface Contracts {
    'acme.clock': { 1: Clock };
  }
}

export interface Clock {
  now(): Promise<number>;
}
```

Пространство `cyborg.*` закреплено за пакетом `@cyborg/contracts` и за встроенными плагинами: поставщиком контракта `cyborg.*` сторонний плагин стать не может.

## Правила типов

| Правило | Почему |
|---|---|
| Методы асинхронные, аргументы и результат - данные | Вызов идёт через границу хоста; функцию, класс и `Map` она не пропустит (`NotCloneable`) |
| Единственный обратный вызов - подписка, возвращающая `Subscription` с `dispose()` | Колбэк остаётся в хосте потребителя, ядро снимает подписку при выгрузке или падении любой стороны |
| Член, добавленный в минорной версии, объявляется необязательным | Поставщик 1.0 удовлетворяет тому же типу; потребитель проверяет, что член есть |
| Новая мажорная версия - новый ключ карты и новый тип | Поставщик отдаёт обе версии сразу, потребитель получает ту, что просил |
| Минорное изменение: новый необязательный член или значение в объединении событий | Потребитель обязан пропускать незнакомое |
| Мажорное изменение: удаление, переименование, новое обязательное поле, смена смысла | Ломает потребителей |

Член с пометкой `@deprecated` живёт минимум до следующей мажорной версии, а ядро пишет в журнал, кто его вызывает.

## Ограничить вызывающего: guard

Если поставщик по чужой просьбе читает или пишет путь, он посредник: без проверки вызывающий без `fs.read` прочитал бы файл правами поставщика. Объявите в `provides`, какой аргумент члена какому праву соответствует:

```json
"provides": {
  "cyborg.files": {
    "version": "1.0",
    "guard": { "read": { "fs.read": 0 }, "open": { "fs.read": "0.path" } }
  }
}
```

Ключ - член контракта, значение - право (`fs.read`, `fs.write`, `shell`, `secrets.ref`) и номер аргумента или `"номер.поле"`. Ядро проверяет аргумент по праву вызывающего до передачи вызова, из главной части и из вида. Отказ - `PermissionDenied` с записью `denied` и причиной `via-contract`. Дальше поставщик работает своими правами, то есть действует пересечение. Член без `guard` ядро не проверяет.

## Вид и контракты

Вид берёт контракт через `ctx.contracts.get` и получает `UiRemote<T>`: только методы с данными. Подписки и колбэки остаются у главной части, поэтому вид опрашивает методы, а главная часть пользуется подписками.

## Отмена запросов

Долгий запрос к другому плагину можно отменить: ядро передаёт поставщику сообщение об отмене с идентификатором запроса. Форма вызова отмены в API относится к решениям проекта, список которых - на странице [Решения](/development/decisions/).
