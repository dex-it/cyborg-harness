## Запустить программу

Право `process` называет программу и, при необходимости, закрепляет первые аргументы. Ядро запускает её без оболочки и с урезанным окружением (`PATH`, `HOME`, локаль) плюс переменные, названные в `env` правила.

```json
"permissions": {
  "process": ["git", { "program": "npm", "args": ["test"], "env": ["CI"] }]
}
```

```ts
const result = await ctx.os.process?.run('git', ['status', '--short'], { cwd });
```

Знайте границу: ядро видит, какую программу и с какими флагами запускает плагин, но не то, что сделает сама программа. Право `process` на `git` или `claude` по сути даёт доступ ко всему, что умеют эти программы.

## Запустить агента через оболочку входа

Агент часто лежит в `PATH`, который задаёт оболочка человека. Правило `pty` может называть `$SHELL`, но только с закреплённым флагом и скриптом:

```json
"pty": [{
  "program": "$SHELL",
  "args": ["-lc", "exec claude --settings \"$CYBORG_SETTINGS\" \"$@\"", "cyborg"],
  "env": ["CYBORG_SETTINGS"]
}]
```

Оболочка без закреплённого скрипта запустила бы что угодно, поэтому такой манифест не примут. Путь оболочки подставляет ядро.

## Терминал, переживающий хост

```ts
const alive = (await ctx.os.pty.list()).find((p) => p.persist && !p.exit);
const pty = alive
  ? await ctx.os.pty.attach(alive.id)
  : await ctx.os.pty.spawn({ program: '/bin/sh', persist: true, cols: 80, rows: 12 });
```

С `persist: true` процесс ждёт, пока плагин вернётся через `attach`, и отдаёт хвост вывода в `backlog`. Виду отдайте билет `pty.share()` ответом своей команды: вывод пойдёт мимо хоста.

## Хранить секрет

Значение секрета не лежит ни в `config`, ни в `state`, ни в журнале. В файле допустима только ссылка:

```json
{ "token": { "$secret": "github-token" } }
```

```ts
await ctx.os.secrets.set('github-token', value);       // в хранилище ядра
const { value: token } = await ctx.secrets.resolve({ $secret: 'github-token' });
```

Ключи видны только своему плагину. Если система не умеет шифровать (`safeStorage` недоступно), хранилище отвечает `Unavailable`, а не пишет открытым текстом. Ссылка со схемой (`vault://kv/data/jira*`) относится к внешнему источнику и должна подходить под маску права `secrets.ref`. Аренду значения (`expiresAt`) соблюдайте: после неё значение спрашивают заново.

## Ходить в сеть

```json
"net": ["api.github.com", "config:baseUrl"]
```

`config:baseUrl` - хост из своего раздела `config`, так пользователь может направить плагин на свой сервер, не меняя манифест. Значение берётся только из файла пользователя: адрес, лежащий в файле воркспейса, плагин увидит в `ctx.config`, но запрос на него отклонится. Не переписывайте слитое `ctx.config.get()` целиком в слой пользователя: значение воркспейса в поле хоста вернёт отказ. По умолчанию запрос ограничен 30 секундами, а тело ответа - 16 МиБ. Страница вида сама в сеть не ходит: делайте запрос в главной части.

## Защитить член контракта правом вызывающего

Поставщик, чей метод принимает путь, объявляет в манифесте `guard`: ядро проверит у вызывающего право на этот аргумент, прежде чем передать вызов (`via-contract`). Без него чужой плагин с правом на ваш контракт, но без права на файл, читал бы файлы вашими правами.

```json
"provides": { "acme.files": { "version": "1.0", "guard": {
  "read": { "fs.read": 0 },
  "open": { "fs.read": "0.path" }
} } }
```

`0` - сам нулевой аргумент должен быть строкой-путём; `"0.path"` - поле `path` объекта в нулевом аргументе. Не строка - отказ `Invalid`, а не пропуск. Право проверяется по правам вызывающего; отказ пишется ему в журнал с `reason: 'via-contract'`. То же для команд, открытых чужим плагинам: `callers: "plugins"` и `guard` в описании команды ([Манифест](/reference/manifest/#commands)). Источники: [SAD, 3.7](https://github.com/dex-it/cyborg-harness/blob/master/docs/04-architecture/design/sad.md#37-безопасность-данных-и-контроль-плагинов); [ADR-CH-0016](https://github.com/dex-it/cyborg-harness/blob/master/docs/04-architecture/adr/ADR-CH-0016-command-callers.md); код - `core/src/via-contract.ts`, `core/src/call-check.ts`.

## Сменить формат настроек

Поднимите `version` раздела в манифесте и добавьте `migrate`:

```ts
const plugin: PluginModule = {
  config: {
    defaults: { pageSize: 50 },
    migrate: (from, data) => (from < 2 ? { ...data, pageSize: Number(data.limit ?? 50) } : data),
    validate: (value) => (Number(value.pageSize) > 0 ? [] : ['pageSize должен быть больше нуля']),
  },
  activate() { return undefined; },
};
```

Ядро вызывает `migrate` до `activate` для каждого слоя старше и сохраняет результат. Слой новее плагина (его откатили) ядро не трогает, а плагин не активируется с понятной причиной. Бросок из `migrate` или значение не по схеме - отказ только вашему плагину.

## Не блокировать хост

Сторож пингует хост раз в секунду и считает его зависшим, если ответа нет пять секунд. Ответ хоста приходит не раньше, чем кончится самая долгая синхронная работа в нём, и соседи ждут столько же, поэтому правило такое: не дольше секунды без `await`. Зависание даёт плагину страйк, три сбоя подряд (между соседними не больше десяти минут) выключают его. Тяжёлое вынесите в `worker_threads`, а чтение и запись делайте асинхронными. В записи `host-down` виновники названы в `culprits`: хост сам сообщает, чей код выполнялся.

## Принимать запросы программ

```json
"permissions": { "serve": true }
```

`ctx.os.serve.http(handler)` поднимает сервер на `127.0.0.1` с портом от ОС. Ядро само отвечает 421 на чужой `Host`, 403 на заголовок `Origin`, 413 на тело больше 1 МиБ и 504, если вы не ответили за 30 секунд. Кто звонит, ядро не знает: проверяйте вызывающего сами, например токеном в заголовке, и не передавайте токен в аргументах процесса.

## Закрыть окно

Право `ui.lock`, экран `ui.overlay` и `ctx.os.ui.lock()`. Экран нужен обязательно, иначе человек не смог бы открыть окно. Замок защищает экран от случайного взгляда, а не данные на диске.

## Найти причину

Подробно - [Отладка](/authors/debugging/). Коротко:

1. Откройте журнал плагинов: там `invalid`, `rejected`, `failed`, `denied`, `switched-off`, `key-conflict`.
2. Пишите `ctx.log`: строки видны виду и вкладке сообщений.
3. Для отказа права смотрите `denied`: в нём метод и деталь вызова.
4. Повторные одинаковые отказы склеиваются в одну запись с `repeats`, не ищите их по одному.
