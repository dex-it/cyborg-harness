Ядро связывает плагины с окном и операционной системой. Плагин узнаёт о фокусе, сне и простое, показывает уведомления, добавляет пункты в меню и может закрыть окно своим экраном.

## События окна и системы

Все подписки возвращают `Disposable` и снимаются вместе с плагином. Слушатель, который бросил исключение, пишет в журнал плагина и соседям не мешает.

| Событие | API |
|---|---|
| фокус окна | `ctx.window.onFocusChange` |
| сон и пробуждение | `ctx.system.onSuspend`, `ctx.system.onResume` |
| блокировка экрана ОС | `ctx.system.onScreenLock` |
| простой пользователя | `ctx.system.onIdle(seconds, listener)` |
| завершение приложения | `ctx.system.onBeforeQuit` |
| видимость своей области (вид) | `ctx.onVisibilityChange` |
| смена темы (вид) | `ctx.theme.onChange` |
| правка своего раздела настроек | `ctx.config.onChange` |

Приложение сообщает факт ядру, ядро рассылает его хостам один раз, хост раздаёт слушателям. `onIdle` срабатывает один раз на каждый простой от `seconds` секунд и снова после активности; ОС опрашивается, только пока есть подписчики. `onBeforeQuit` ядро ждёт не дольше бюджета приложения; зависший слушатель сбоем плагина не считается.

## Уведомления

С правом `notify` плагин показывает системное уведомление через `ctx.os.notify`. Уведомление принимает клик: он поднимает окно, закрывает уведомление и запускает команду плагина, а само уведомление плагин может закрыть, когда повод исчез. Решает ли плагин показывать уведомление, зависит от фокуса окна: об открытой в фокусе работе напоминать незачем (`ctx.window.onFocusChange`).

```ts
const id = await ctx.os.notify.show('Сборка упала', 'core: 3 теста', { onClick: { command: 'ci.open', args: ['core'] } });
await ctx.os.notify.close(id);
```

Команда клика - своя, из `contributes.commands`; ядро сверяет её и аргументы при `show`, поэтому ошибка видна сразу, а не в момент клика. Пределы: заголовок до 120 символов, текст до 1000, живых уведомлений у плагина до 10 - одиннадцатое отклоняется, пока прежние не закрыты.

- Под чужим замком окна клик только поднимает окно: команду плагина за экраном замка ядро не запускает.
- Хост плагина упал - уведомления остаются; клик дождётся перезапуска и дойдёт до команды. Выключение или выгрузка плагина его уведомления закрывают.

## Заголовок окна

Заголовок окна собирает ядро: имя файла воркспейса, фрагменты плагинов и имя приложения через « - », например `team.cyborg.json - Проект X - Cyborg`. Плагин ставит свой фрагмент вызовом `ctx.window.setTitle(segment)`, права не нужно; фрагменты разных плагинов идут по порядку их id. Фрагмент - до 80 символов, `undefined` его снимает. Под замком окна в заголовке видны только фрагменты владельца замка: заголовок виден в панели задач и поверх экрана замка. Форма вызова - в [руководстве по главной части](/authors/main-api/).

## Меню окна

Плагины добавляют пункты в меню окна через `contributes.menus` в манифесте. Меню - вид ядра, а вклад в него подчиняется тому же правилу, что и остальные вклады: ядро владеет меню, плагины вкладывают пункты. Состояние пунктов (доступен, отмечен) определяет плагин-вкладчик.

Акселераторы пунктов меню и сочетания плагинов живут в одном реестре: конфликт между ними виден в журнале ([Клавиши](/features/keys/)). Точная форма записи пункта - в [справочнике манифеста](/reference/manifest/).

## Диалоги плагина

| Что | Кто показывает |
|---|---|
| `ask` и `menu` | слой ядра, по одному, поверх всех фреймов |
| выбор файла (`ctx.os.dialog.open`) | системный диалог; выбор становится областью `granted` |
| модальное окно плагина с формой | окно плагина поверх остальных |

Диалог чужого плагина под замком окна отвечает `Unavailable`, чтобы системное окно не встало поверх экрана замка.

## Замок окна

Механизм замка в ядре, политика - в плагине: пин, отпечаток или пароль ОС - разные плагины на одном механизме. Плагин с правом `ui.lock` и экраном `ui.overlay` закрывает окно:

```ts
const lock = await ctx.os.ui.lock({ hideNotifications: true });
// ... человек подтвердил себя
await lock.release();
```

Пока окно заблокировано:

- чужие `<iframe>` скрыты и неактивны: ни мышь, ни фокус до них не доходят; виден только экран владельца замка;
- системные сочетания отключены, кроме сочетаний владельца;
- чужие диалоги ждут в очереди; с `hideNotifications` уведомления идут без текста: «Cyborg: новое событие»;
- управление плагинами недоступно: выключить плагин замка из-под замка нельзя;
- главные части работают дальше, процессы живы: замок закрывает экран, а не работу.

Снять замок может только тот, кто его поставил. Два замка от двух плагинов - окно открывается, когда сняты оба. Состояние «заблокировано» держит ядро: хост владельца упал - окно остаётся закрытым, сторож поднимает хост, плагин снова показывает экран. С `"lock": { "onStart": true }` в манифесте окно закрыто с первого кадра.

:::caution[Замок не защищает данные]
Замок защищает экран от того, кто подошёл к столу. Безопасный режим выключает все плагины, а с ними и замок; файлы и состояние доступны любому, кто вошёл в ОС под этим пользователем. Защита данных - шифрование диска и блокировка ОС.
:::

## Безопасный режим

Безопасный режим выключает все плагины без исключений: код плагинов не запускается, в журнале у каждого запись `safe-mode`, управление плагинами остаётся доступным. Включается флагом `--safe-mode` или пунктом окна. Это выход, если плагин замка не открывает окно.
