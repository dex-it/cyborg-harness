Ядро - маленький хост плагинов. Оно открывает воркспейс, загружает плагины, связывает их, изолирует их сбои, следит за правами и даёт экран, клавиши и хранение. Всё предметное - агенты, сессии, файлы, проекты, трекеры - живёт в плагинах, а не в ядре.

## Что умеет ядро

| Возможность | Что гарантирует | Страница |
|---|---|---|
| Плагины | сломанный граф виден до запуска кода; окно без плагинов работает | [Плагины](/features/plugins/) |
| Контракты и команды | плагины знают друг друга только через контракт | [Контракты](/features/contracts/) |
| Хосты и сторож | зависание или падение плагина не трогает соседние хосты и окно | [Хосты](/features/hosts/) |
| Терминалы | процесс переживает перезапуск плагина и окна | [Терминалы](/features/terminals/) |
| Виды | плагин рисует только у себя, в своём `<iframe>` | [Виды](/features/views/) |
| Раскладка окна | каркас рисуется по манифестам до кода плагинов | [Раскладка](/features/layout/) |
| Сочетания клавиш | сочетание срабатывает одинаково из любого фрейма | [Клавиши](/features/keys/) |
| Права | плагин делает только объявленное | [Права](/features/permissions/) |
| Настройки и состояние | плагин видит только свой раздел; ошибка ломает только его владельца | [Настройки и состояние](/features/config-state/) |
| Воркспейсы | один файл воркспейса - один владелец, замок и согласованное состояние | [Воркспейсы](/features/workspaces/) |
| Окно и система | события окна и ОС, уведомления, меню, замок экрана | [Окно и система](/features/window-system/) |
| Версии | обновление Cyborg или плагина не ломает остальных и не теряет данные | [Версии](/features/versions/) |

## Чего в ядре нет

Задача попадает в ядро, только если выполнены оба условия:

1. она нужна всем плагинам или окну без плагинов;
2. плагин не может решить её сам, не нарушив гарантию, которую ядро даёт остальным.

Поэтому проекты - плагин, а терминальный процесс - у ядра: он должен пережить перезапуск своего плагина, и плагин сам этого не гарантирует. Список того, чего в ядре нет:

- агента и его запуска, сессий и их восстановления;
- дерева файлов, просмотрщика, проектов, трекеров;
- уведомлений о сессиях и источников секретов;
- общей шины событий и реестра сервисов по произвольным ключам.

:::note[Центральных плагинов нет]
Ядро не выделяет ни один плагин, в его коде нет имён плагинов. Окно без плагинов - нормальное состояние: в нём доступно управление плагинами. Поставка приложения - это список встроенных плагинов и больше ничего. Чистоту ядра проверяет тест: в исходниках `@cyborg/core` нет предметных имён, импортов Electron и npm-зависимостей.
:::

## Как читать возможности

Каждая страница раздела отвечает на три вопроса: что это даёт, как выглядит для человека и для автора плагина, где граница возможности. Устройство целиком описано в разделе [Устройство](/concepts/), точные перечни - в [Справочнике](/reference/manifest/), пошаговые руководства - в разделе [Автору плагина](/authors/).

## Где что живёт

| Пакет | Что в нём |
|---|---|
| `@cyborg/core` | ядро: загрузчик, граф контрактов, реестры, хосты со сторожем, шлюз прав, журнал, воркспейс |
| `@cyborg/electron` | адаптер Electron: хосты, адаптер ОС, схема `cyborg-plugin://`, мост видов, оболочка вида |
| `@cyborg/contracts` | типы контрактов и API плагина |
| `@cyborg/testing` | тест-кит автора плагина |

Пакеты и их версии перечислены в [справочнике](/reference/packages/).
