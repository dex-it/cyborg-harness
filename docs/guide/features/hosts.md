---
title: "Хосты и сторож"
description: "Главные части плагинов живут в отдельных процессах; зависший хост перезапускается."
---

Главные части плагинов работают не в главном процессе Electron, а в **хостах** - отдельных процессах (`utilityProcess`). Плагины одного хоста делят процесс и цикл событий. Адаптер хостов входит в пакет `@cyborg-harness/electron`.

## Зачем это нужно

| Что случилось | Что происходит |
|---|---|
| плагин бросил исключение в активации или вызове | хост ловит его, отказывает только этому плагину, в журнале запись |
| хост завис | сторож перезапускает его; другие хосты, окно и терминалы не затронуты |
| хост упал | то же, плагины хоста активируются заново |
| плагин зависает снова и снова | после нескольких зависаний подряд плагин выключен, запись в журнале |

Необработанное исключение вне вызова - в таймере или фоновом промисе - роняет процесс хоста. Ядро называет в журнале плагин, чей код завершил процесс, засчитывает страйк ему и перезапускает хост; соседи по хосту активируются заново, остальные хосты, окно и терминалы не затронуты.

## Что видит человек

Пока хост перезапускается, виды его плагинов остаются на месте под плашкой ядра «Перезапуск» и не принимают ввод. Если плагин не поднялся или выключен, вид заменяет заглушка: имя плагина, причина из журнала, кнопки «Включить снова» и «Журнал». Плагин без видов при выключении даёт одно уведомление ядра с перечнем плагинов, которые брали его контракты.

Потребители из других хостов узнают о пропаже и возврате поставщика из `ctx.contracts.onChange`.

## Группы хостов

Группировкой плагинов по хостам управляет пользователь. Раздел `plugins.hosts` лежит в настройках пользователя и воркспейса:

```jsonc
"plugins": {
  "enabled": ["sessions", "agent-claude-code", "files", "trackers"],
  "hosts": {
    "builtin":  ["sessions", "agent-claude-code", "files"],
    "trackers": ["trackers"]
  }
}
```

- Плагины поставки по умолчанию идут в хост `builtin`; плагин, не названный ни в одной группе, - тоже.
- Манифест может попросить отдельный хост: `"host": "own"`. Пользователь вправе переопределить группой `plugins.hosts`: действует группа, а если в ней есть соседи, ядро пишет `host-own-grouped` с их списком, и окно управления плагинами показывает предупреждение.
- **Сторонний плагин всегда один в своём хосте.** Если пользователь назвал его в группе с другими, ядро всё равно даёт ему отдельный хост и пишет `host-isolated` с именем группы.

:::caution[Почему сторонний плагин один в хосте]
Граница доверия ядра - процесс хоста. Ядро проверяет, что сообщение пришло из хоста, где живёт названный в нём плагин, а внутри хоста плагины неразличимы. Плагин в общем хосте мог бы писать от имени соседа - в его настройки, команды и контракты. Цена - процесс на каждый сторонний плагин.
:::

## Сторож

Ядро регулярно спрашивает хост, отвечает ли он. Нет ответа дольше порога - хост перезапускается. Виновник - при зависании плагин, чей код хост выполнял (хост называет плагин ядру до входа в его код: вызов, событие, таймер, продолжение после ответа ядра), при падении - плагин, чей код завершил процесс (`process.exit`, необработанное исключение); хост виновника не назвал, например процесс убит сигналом, - плагин первого вызова, принятого после последнего отвеченного пинга. Отметка ставится на входах хоста и в его глобальных таймерах: код, запущенный мимо них, и зависание кода самого хоста после плагина записываются на плагин, вошедший последним.

| Параметр | Значение |
|---|---|
| пинг | раз в 1 с |
| порог | 5 с без ответа |
| выключение плагина | после трёх зависаний подряд |
| перезапуск хоста | около 70-85 мс |

Падение хоста идёт тем же путём. Сторож следит и за отдельным процессом терминалов ([Терминалы](/features/terminals/)). Выгруженный человеком плагин сторож не поднимает.

## Правило для авторов

Пока синхронный код выполняется, хост не отвечает на пинг. Порог сторожа - 5 с, но дольше секунды без `await` работать не стоит: длинное переносите в асинхронные шаги, читайте файлы кусками, тяжёлое выносите в `ctx.os.process`. Подробности - в [рецептах](/authors/recipes/).

## Цена

| Платформа | Память на хост | Перезапуск хоста |
|---|---|---|
| Linux | первый хост около 56 МБ PSS, каждый следующий около 34 МБ | около 70 мс |
| macOS | около 27 МБ физического следа на хост | около 85 мс |

Меры на платформах разные, сравнивать их можно по порядку величины. Плагины внутри одного хоста почти ничего не добавляют, поэтому встроенные плагины собраны в общий `builtin`. Замеры - в [справочнике платформ](/reference/platforms/).
