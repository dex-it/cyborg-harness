Доступ к ОС разбит на пространства имён. Нет права в манифесте - нет члена в `ctx.os`: ни чтения, ни записи, ни запуска. Все вызовы идут через **шлюз** ядра, который проверяет их по манифесту.

## Что видит человек

Окно управления плагинами показывает права каждого плагина словами: «читает файлы воркспейса», «запускает программу `git`», «ходит на хост из настройки `baseUrl`». Право `process` или `pty` показано как «полный доступ через программу»: программа получает все права пользователя ОС. Каждый отказ шлюза пишется в журнал плагина.

## Права

| Право | Что даёт | Значение в манифесте |
|---|---|---|
| `fs.read` | чтение файлов, `fs.watch`, `readSlice`, `realpath` | области путей |
| `fs.write` | запись, создание и удаление | области путей, `workspace.git` |
| `shell` | открыть путь или URL программой ОС | области путей и схемы (`https:`, `mailto:`) |
| `process` | запуск программы и ожидание результата | список программ и закреплённых аргументов |
| `pty` | программа в псевдотерминале | то же |
| `launch` | запуск, который поставщик `cyborg.agent` описывает потребителю | то же; члена в `ctx.os` не даёт |
| `net` | HTTP-запросы | список хостов, `config:<поле>` |
| `env` | чтение переменных окружения | список имён |
| `notify` | системные уведомления | `true` |
| `clipboard` | буфер обмена | `read`, `write` |
| `secrets.ref` | ссылки на секреты внешнего источника | маски `vault://kv/data/jira*` |
| `security.roots` | задать корни проектов | `true` |
| `ui.lock` | закрыть окно своим экраном | `true` |
| `serve` | сервер HTTP на `127.0.0.1` | `true` |

Свои каталоги `paths.data` и `paths.temp`, своё хранилище секретов `ctx.os.secrets` и выбор файла через `ctx.os.dialog` права не требуют: выбранное человеком становится областью `granted` этого плагина и хранится в состоянии воркспейса. Выбор одного плагина не право другого.

## Области путей

| Область | Что это |
|---|---|
| `workspace` | репозитории проектов и рабочие каталоги живых сессий; корни задают плагины с `security.roots` |
| `plugin-data`, `plugin-temp` | всегда свои |
| `granted` | выбор человека в `dialog` |
| `any` | только в `shell`: любой существующий документ или каталог; программы, скрипты и файлы других типов - нет |
| абсолютный путь | каталог с поддеревом; `~` - домашний |
| маска | `*` - часть имени, `**` - любые каталоги; маска не начинается с корня ФС |

## Правила шлюза

- Вызывающего ядро определяет по каналу, а не со слов плагина.
- Путь проверяется после `realpath` на открытом дескрипторе. Вне области - всегда `PermissionDenied`, никогда `NotFound`.
- Закрыто всегда: данные приложения, файл воркспейса и замок, каталоги других плагинов, запись в `.git/` (кроме области `workspace.git`).
- Права через чужой контракт не передаются: поставщик объявляет `guard`, и ядро сверяет аргумент с правом **вызывающего**.
- Корень области не удаляется, как и каталог с `.git` внутри.
- Программа получает только базовое окружение и переменные, названные в `env` её правила.
- `shell.openPath` исполняемый файл не открывает: ни по расширению (`.sh`, `.exe`, `.app` и подобные), ни по биту исполнения. Там, где плагин пишет сам (`fs.write` и свои каталоги), он открывает только документы - текст, `.pdf`, офисные файлы, картинки, звук и видео: файл другого типа плагин мог подготовить для запуска. Схемы `file:`, `javascript:`, `data:`, `vbscript:` манифест не примет.

## Пределы

Ядро ограничивает ресурсы, которые плагин может занять. Превышение отвечает `Invalid` с причиной; приложение может поменять значения при загрузке ядра.

| Что | Предел |
|---|---|
| запрос `net.fetch` | 30 с по умолчанию, ответ до 16 МиБ |
| чужой метод контракта | предел ожидания ответа ядра, дальше `Timeout` |
| `fs.watch` | до 64 наблюдений на плагин, события склеиваются за 50 мс |
| `fs.readText` | файл до 5 МиБ, крупнее - `fs.readSlice` |
| `fs.readSlice` | кусок от 4 байт до 1 МиБ |
| `process.run` | до 16 программ одновременно; вывод до 16 МиБ на `stdout` и на `stderr` (опция `maxOutputBytes` - до 64 МиБ), больше - программа остановлена, в ответе `truncated: true` |
| pty | до 32 живых, ввод до 1 МиБ за вызов |
| подписки через контракты | до 256 у потребителя |
| `onIdle` | до 64 слушателей |
| `serve.http` | до 4 серверов, тело до 1 МиБ |
| диалоги | очередь до 8, до 12 пунктов |
| документы | до 200 на плагин, данные до 64 КБ |

Превышение отвечает `Invalid` или `Timeout`. Выгрузка плагина закрывает его наблюдения, серверы, запросы и диалоги.

## Секреты

Значение секрета не пишется в настройки, состояние и журнал. Подробнее - в [Настройках и состоянии](/features/config-state/#секреты).

## Два класса плагинов

| Класс | Примеры | Что гарантирует изоляция |
|---|---|---|
| широкий | агенты, файлы, git, поиск | известно, какую программу плагин запускает; что сделает сама программа, ядро не знает |
| узкий | интеграции по HTTP API, блокировка по пину | сеть к своему хосту и свой токен: полная гарантия |

Поэтому для интеграций выбирайте HTTP API, а не CLI: обёртка над `gh` или `glab` требует `process` и попадает в широкий класс.

:::caution[Честная граница]
Шлюз делает права видимыми и ловит ошибки, но в одном процессе хоста плагин, который захочет, достанет `node:fs` в обход шлюза. Для встроенных плагинов это дисциплина, которую проверяют тесты: плагин импортирует только `@cyborg-harness/contracts` и свои модули. Для стороннего кода гарантию «ничего сверх объявленного» даёт изоляция доступа (процесс на плагин), которая не входит в ядро. Подробности - в [границах доверия](/concepts/trust/).
:::
