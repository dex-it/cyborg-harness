title: "Раскладка окна"
description: "Какие области знает ядро и как плагины занимают их через манифест."
---

Ядро не знает, что показывают плагины, но знает **роды областей** окна. Плагин объявляет в манифесте, в какую область встаёт его вид и в каком порядке. Каркас окна рисуется сразу по манифестам, до запуска кода плагинов.

## Роды областей

| Род области | Что это |
|---|---|
| боковая колонка | колонка с заголовком; в ней видов может быть несколько |
| основная область | группа документов: вкладки, которые открывают плагины |
| панель инструментов основной области | полоса над документами |
| всплывающий слой | окна и меню поверх остального |
| слой замка | экран `overlay` плагина с правом `ui.lock` ([Окно и система](/features/window-system/)) |

Предустановленной раскладки нет. Расстановка складывается из манифестов и изменений пользователя.

## Что объявляет плагин

Для каждого вида и типа документа манифест называет род области (`sidebar`, `main`, `toolbar`, `popup`) и `order`. Короткая запись, где вид задан одной строкой с путём к модулю, остаётся допустимой: такой вид встаёт в боковую колонку с `order` 1000. Неизвестный род области или нечисловой `order` отвергают манифест с именем поля в сообщении (`ui.views.<имя>.area`).

```jsonc
"ui": { "views": {
  "tree": "./ui/tree.js",
  "sessions": { "module": "./ui/sessions.js", "area": "main", "order": 100 }
} },
"documents": { "note": { "restorable": true, "area": "main", "order": 200 } }
```

У плагина может быть несколько видов, в разных областях. Плагины из поставки занимают `order` от 0 до 1000 с шагом 100; остальные идут после них. Все поля - в [справочнике манифеста](/reference/manifest/).

## Как ядро упорядочивает

- Ядро отдаёт приложению упорядоченный снимок раскладки (`kernel.layout`): сначала по `order`, при равенстве - по `id` плагина, затем вид раньше типа документа и по имени. Результат детерминирован.
- В снимке выключенные плагины и плагины вне графа помечены, чтобы окно показало заглушку, а не пустое место.
- Приложение рисует области по снимку и не называет плагины по именам. Какие именно области и в каком виде показывает окно, решает приложение; ядро задаёт роли и порядок.

## Что делает человек

Человек двигает вкладки, меняет ширины областей, раскрывает узлы. Эти изменения - состояние воркспейса, они не попадают в манифесты. Закрепить расстановку для команды можно явным сохранением в настройки воркспейса.

## Документы и вкладки

Документ - вкладка, которую открывает плагин в основной области: файл, терминал сессии, заметка. Ядро держит документы в порядке окна.

| Метод `ctx.documents` | Что делает |
|---|---|
| `open(type, { title, data? })` | открывает документ, отдаёт `id` |
| `save(id, { title?, data? })` | меняет названное поле; `data: undefined` забывает данные |
| `close(id)` | закрывает |
| `list()` | свои документы, после перезапуска - сохранённые прошлой работы |
| `onClose(listener)` | вкладку закрыл человек |

Тип документа объявлен в манифесте. Тип с `restorable` переживает перезапуск: ядро сохраняет его строки в состоянии воркспейса, а после перезапуска владелец получает свои документы из `list()` и поднимает их. Владелец сам отдаёт данные, когда они меняются (`save`): после падения окна или хоста опрашивать некого. Если владельца нет, вкладка показывается как недоступная, а не пропадает.

Пределы: заголовок до 200 символов, данные - JSON до 64 КБ, документов на плагин до 200. Тип не из манифеста отвечает `NotDeclared`, чужой `id` - `NotFound`.

## Фокус

Порядок фокуса между областями задаёт ядро: `F6` ведёт вперёд, `Shift+F6` назад, по кругу через области и видимые фреймы, мимо скрытых и неактивных. При открытом диалоге ядра фокус не двигается.

:::note[Чужой UI не встраивается]
Один вид не монтирует другой. Если одному плагину нужно показать данные другого, он вызывает контракт владельца, а владелец рисует у себя ([Виды](/features/views/)).
:::
