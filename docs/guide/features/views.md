Интерфейс плагина - **вид**: браузерный модуль, который живёт в собственном `<iframe>`. Общего фреймворка нет: внутри фрейма плагин пишет UI на чём угодно. Ядро даёт только токены темы, набор элементов `cy-*` и мост к главной части.

## Что видит человек

Окно показывает вид в области, которую выбрал плагин или человек ([Раскладка](/features/layout/)). Свёрнутый вид не размонтируется: прокрутка, выделение и DOM сохраняются. Тема и шрифт приходят из ядра, при смене темы вид обновляется сам. Меню и диалоги выходят за рамки фрейма только через слой ядра, поэтому поверх всех видов и без обрезки.

Пока хост плагина перезапускается, вид закрыт плашкой «Перезапуск». Если плагин выключен, на его месте заглушка с причиной ([Хосты](/features/hosts/)).

## Как вид устроен для автора

Манифест называет вид и его модуль, а модуль экспортирует `mount`:

```jsonc
"ui": { "views": { "tree": "./ui/ui.js" } }
```

```ts
export function mount(root: HTMLElement, ctx: UiContext): Disposable | undefined { /* ... */ }
```

`mount` вызывается один раз на документ вида, `dispose` - когда ядро снимает вид. Код вида - браузерный бандл без Node: npm-пакеты разрешены, встроенные модули Node и `electron` - нет.

`UiContext` - урезанный `ctx` главной части:

| Член | Что даёт |
|---|---|
| `commands.run` | команды своего плагина; чужую ядро отклонит |
| `contracts.get` | контракт из `requires` или `optional` своего плагина; ответ - только данные |
| `theme` | токены `--cy-*` и `onChange` |
| `visible`, `onVisibilityChange` | видимость вида; фрейм об этом не знает |
| `logs`, `onLog` | сообщения своего плагина |
| `terminal.open(ticket)` | pty по билету своей главной части ([Терминалы](/features/terminals/)) |
| `state` | память вида в состоянии воркспейса, JSON до 64 КБ |
| `dialogs.show` | вопрос `ask` или меню `menu` в слое ядра |
| `keys.of` | сочетание своей команды для подсказки |
| `drag` | перетаскивание файла через ядро |

`ctx.os` в виде нет: всё, что выходит наружу, идёт через главную часть и шлюз прав. Память вида лежит в состоянии воркспейса, а не в `localStorage`: у origin плагина он один на все воркспейсы.

## Канал с главной частью

Вид и главная часть обмениваются сообщениями по каналу, который ядро связывает по имени вида. Сообщения доходят только до видов своего плагина, размер ограничен, при выгрузке плагина канал закрывается. Тот же слой даёт плагину модальные окна. Формы вызовов - в [руководстве по виду](/authors/view-api/).

## Элементы ядра

Оболочка вида определяет элементы до `mount`: имя `cy-*` плагину не занять, а CSP `'self'` их пропускает. Стили идут на токенах темы.

| Тег | Что это |
|---|---|
| `cy-button` | кнопка, варианты `primary` и `danger` |
| `cy-field` | поле ввода: `text`, `search`, `password` |
| `cy-list` | список с выбором и активацией |
| `cy-tree` | дерево с раскрытием ветвей |
| `cy-tabs` | вкладки |
| `cy-empty` | пустое состояние |
| `cy-spinner` | индикатор загрузки |

Клавиши работают по WAI-ARIA. В пределах мажорной версии API элемент не удаляется и не меняет атрибуты. Набор минимален по замыслу: так версия фреймворка не становится частью API плагинов.

## Изоляция вида

- **Фрейм на вид.** Каждый вид и тип документа живёт в своём `<iframe>` со своим DOM, CSS и `window`.
- **Группы рендера.** Origin задаёт группа, адрес вида - `cyborg-plugin://<группа>/<плагин>/`. Кадры одной группы делят origin и процесс рендера, у каждой группы свой процесс. Манифест рекомендует группу полем `ui.group`, владелец переопределяет её разделом `plugins.uiGroups` файла пользователя; поле воркспейса не действует. Плагин без группы получает группу со своим id.
- **Сторонний плагин всегда один в своей группе.** Если его назвали в группе с другими, он остаётся в своей группе (origin `solo_<id>`), окно предупреждает в строке плагина, а в журнал идёт запись `group-isolated`.
- **Строгая CSP.** `default-src 'none'` с явными источниками: скрипты и данные - только `'self'`, сеть вида закрыта, `<base href>` и отправка формы отклонены. Инлайн-стили вид получает только по флагу `ui.inlineStyles: true` в манифесте плагина; xterm и Monaco вставляют `<style>`, и им он нужен. Без флага вставленный `<style>` не применяется, а консоль фрейма вида и журнал плагина называют причину и флаг. CSP не защищает плагин от соседа по группе: граница доверия - группа.
- **Мост.** Главный процесс узнаёт плагин по группе из origin кадра-отправителя и плагину из пути его адреса, а не по словам вида; плагин должен состоять в группе кадра. Страница, вставленная внутрь вида, моста не получает.

:::note[Чужой UI в свой не встраивается]
Плагин не монтирует вид другого плагина. Нужен чужой интерфейс - вызывайте команду или метод контракта владельца: он сам покажет свой документ или диалог и вернёт данные. Так редактор кнопок просит JSON у просмотрщика, а не встраивает Monaco.
:::

## Диалоги и фокус

Диалоги `ask` и `menu` показывает слой ядра поверх всех фреймов, по одному; остальные ждут в очереди (до 8 на плагин). В описании не больше 12 пунктов, подписи до 80 символов. Ответ - `id` пункта; Escape, клик мимо меню и выгрузка плагина дают `undefined`. Клавиши `F6` и `Shift+F6` переводят фокус между областями окна; фокус, пришедший во фрейм снаружи, ложится на `[autofocus]` или первый фокусируемый элемент.
