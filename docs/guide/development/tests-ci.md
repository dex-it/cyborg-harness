Изменение считается готовым, когда зелёные пять проверок: сборка, типы, линтер, тесты и дымовой тест окна. Первые четыре идут на любой машине, пятому нужен дисплей.

| Команда | Что проверяет |
|---|---|
| `npm run build` | собирает стенд playground в `playground/dist` |
| `npm run typecheck` | строгие типы ядра, браузерной части элементов `cy-*` и стенда; в том числе файлы, где строка под `@ts-expect-error` обязана не компилироваться |
| `npm run lint` | ESLint со `strictTypeChecked`, ноль предупреждений |
| `npm test` | модульные, сценарные и стресс-тесты на встроенном `node:test` |
| `npm run smoke` | дымовой тест окна по DevTools Protocol |
| `npm run demo` | сценарии ядра в консоли с пошаговым режимом `--step` |
| `npm run spike`, `npm run spike:hosts`, `npm run spike:gateway` | замеры фреймов, хостов и шлюза, не тесты; `spike:gateway` - проверка бюджета для CI по медиане трёх прогонов |

## Типы и линтер

Проверка типов использует TypeScript 7 из алиаса `typescript7`, а пакет `typescript` - это TS 6 под API `typescript-eslint`. Поэтому `npx tsc` - не тот компилятор: запускайте `npm run typecheck`.

Отключить правило линтера можно только директивой с причиной после `--`. Параметры-свойства конструктора и `enum` не пишут: Node снимает только стираемый синтаксис. Импорты пишутся с расширением `.ts`, потому что тесты идут на Node без сборки.

## Тесты

`npm test` запускает файлы `core/test/*.test.ts`, `playground/src/**/*.test.ts` и `playground/test/*.test.ts` с общим сроком 120 секунд на тест. Зависший тест падает под своим именем и не снимает всю задачу.

| Что покрыто | Где |
|---|---|
| Загрузка: разбор манифеста, граф контрактов, версии, ленивая активация, журнал, безопасный режим, выгрузка с зависимыми | `loader`, `graph`, `registry`, `lifecycle`, `status`, `semver-manifest` |
| Хосты и сторож: падение, зависание, перезапуск, три страйка | `hosts`, `stress-hosts`, `stress-restart` |
| Границы доверия: подделка сообщений хоста, недоверенный ввод, шлюз `ctx.os`, права через контракт и команду, значение секрета вне журнала, `config` и `state` | `trust`, `untrusted-input`, `security-gateway`, `via-contract`, `command-callers`, `os`, `secrets-journal` |
| Данные: разделы `config` и `state`, миграции, схема, воркспейс | `config`, `json-schema`, `workspace`, `stress-sections`, `stress-workspace` |
| Терминалы | `pty`, `stress-pty` на поддельном pty |
| Окно и вид: оболочка вида, слой диалогов и замок, элементы `cy-*`, документы, события | `ui-shell`, `window`, `elements`, `documents`, `events`, `subscriptions` |
| Канал и данные вызова: клонируемость, подписки | `rpc` |
| Сторож импортов плагинов: плагин импортирует только `@cyborg-harness/contracts` и свои модули | `plugin-imports` |
| Чистота ядра: нет предметных слов, Electron, импортов вне `core/src` и зависимостей npm | `purity` |
| Пакет ядра и публичный API: состав пакета, установка в пустой проект, хосты на собранном пакете, перечень имён по точкам входа, окно без `node:*`, граница playground | `package`, `consumer`, `hosts-dist`, `public-api` |
| Стенд: поиск плагинов, схема `cyborg-plugin://`, мост видов, перетаскивание, билеты терминала, замеры памяти, общий набор тестов `cyborg.agent` | `playground/src/main/*.test.ts`, `playground/test/` |

:::note[Проверки чистоты]
Ядро не знает предметной области, не импортирует Electron и не тянет зависимости из npm. Это проверяют тесты, а не ревью. Отдельные тесты закрепляют, что секрет не попадает в журнал, `config` и `state`, и сверяют публичные экспорты пакетов и снимок API плагина.
:::

## Дымовой тест окна

`npm run smoke` запускает собранный стенд с временным каталогом данных и ведёт его по DevTools Protocol. В нём проверяется то, что без настоящего Electron не проверить:

- плагины в нескольких хостах `utilityProcess`, перехват сочетаний и конфликт, обмен сообщениями через три хоста;
- виды во фреймах: мост, лента журнала, чужая команда отклонена, тема до `mount` и при смене;
- права `ctx.os`: отказ вне прав с записью в журнале, права словами, псевдотерминал;
- терминал вида по билету: вывод и ввод идут мимо хоста и переживают зависание хоста и его перезапуск;
- сторож: падение и зависание хоста;
- слой окна: диалоги `ask` и `menu`, замок, порядок фокуса по `F6` и `Shift+F6`;
- элементы `cy-*`: определены до `mount`, работают под строгой CSP, клавиши и события;
- воркспейс: замок с pid, второй запуск отдаёт фокус первому, «Недавние».

Проверка с настоящим `claude` пропускается, если не задана переменная `CYBORG_SMOKE_CLAUDE`. Сочетания в тесте подбираются под платформу: на macOS это `Shift+Meta+<клавиша>`, на Linux `Ctrl+Shift+<клавиша>`.

## CI

Workflow `.github/workflows/ci.yml` запускается на каждый pull request и на пуш в `master`.

| Шаг | macOS (`macos-latest`) | Linux (`ubuntu-24.04`) |
|---|---|---|
| `npm ci` на Node 24 | да | да |
| `npm run build`, `typecheck`, `lint`, `npm test` | да | да |
| Дымовой тест | `node playground/scripts/smoke.mjs` | `xvfb-run --auto-servernum node playground/scripts/smoke.mjs --no-sandbox` |

Лимит - 15 минут на каждую ОС, права токена - только чтение. Действия закреплены по SHA коммита, новая сборка той же ветки отменяет прежнюю. Матрица идёт с `fail-fast: false`: падение на одной ОС не прячет результат другой.

Кроме `ci.yml` есть `docs-site.yml` для сайта, см. [Сайт документации](/development/docs-site/).

## Релизы, бюджеты и ссылки

Для выпуска пакетов, бюджетов и проверки ссылок эпик заводит отдельную задачу P-10. Она добавляет:

- релизный workflow по тегу: сборка `@cyborg-harness/contracts`, `@cyborg-harness/core` и `@cyborg-harness/electron`, сверка версии в теге с версией пакета и `CHANGELOG`, публикация;
- задание бюджетов: замеры хостов и задержки шлюза сравниваются с порогами из файла в репозитории, PR с ухудшением красный;
- проверку ссылок и якорей в `docs/`;
- `npm audit` и обновление зависимостей, кэш сборки нативного `node-pty`;
- запуск тест-кита и проверки плагина на шаблоне плагина.

Замеры на общих раннерах шумят, поэтому у порогов есть запас, а память и задержка сторожатся по-разному. Раннер Windows в матрицу не входит.
