# Cyborg Harness: идея на одной странице

## Идея

Ядро плагинов для рабочего места, где человек ведёт несколько сессий агентов. Ядро не знает предметной области: агент, сессии, дерево файлов, просмотрщик, проекты и трекеры - равные плагины на одном API. Поставка приложения - список встроенных плагинов; сторонний плагин и другой агент подключаются тем же путём. Устройство - [SAD](../04-architecture/design/sad.md).

## Проблема

- Приложение, где каждая возможность вшита в общее целое, дорожает с каждой функцией: новая функция правит общие файлы и может сломать соседнюю ([как это выглядит в Cyborg](../research/cyborg-today.md)).
- Агент зашит в приложение: другой CLI-агент без правки приложения не подключить.
- Сбой одной функции роняет окно, а с ним и процессы агентов.
- Права функций не видны и не ограничены: любая читает любой файл и запускает любую программу. Чужое расширение нельзя ни поставить, ни ограничить.

## Решение

Своё маленькое ядро с десятью целями ([SAD, раздел 3](../04-architecture/design/sad.md#3-цели-ядра)):

- плагины знают друг друга только через контракты в манифесте; граф проверяется до запуска кода, окно без плагинов работает;
- главные части плагинов - в хостах `utilityProcess` со сторожем: зависание или падение не трогает другие хосты, окно и агентов;
- pty держит ядро: перезапуск хоста или окна не убивает процессы агентов;
- доступ к ОС - только через шлюз `ctx.os` по правам из манифеста; права видны словами;
- UI плагина - в своём `<iframe>`; каркас окна рисуется по манифестам до кода плагинов;
- агент - обычный плагин, поставщик `cyborg.agent`; Claude Code остаётся нативным `claude` в pty.

Строится в [два этапа](../04-architecture/design/sad.md#6-этапы): первый даёт все цели, кроме гарантии доступа; второй - `Compartment` в хостах, окна согласия и установку сторонних плагинов, когда появится повод.

## Почему так

- Оба изученных проекта ([bb](../research/bb.md), [DeepSeek Harness](../research/deepseek-harness.md)) держат ядро минимальным и проверяют манифест до загрузки кода - это берём.
- Оба исполняют сторонний плагин без изоляции. Рядом с сессиями агента с правами пользователя этого мало: у нас сбои и рендер изолированы для всех плагинов с первого этапа, а доступ - во втором.
- Интерактивный CLI в pty не встраивает ни один образец: контракт `cyborg.agent` спроектирован свой.
- Реестр сервисов с `inject` и шину событий не берём: связь идёт через контракт владельца предмета ([SAD, раздел 7](../04-architecture/design/sad.md#7-расхождения-с-первой-редакцией-пакета)).

## Кому и что даёт

| Кто | Что получает |
|---|---|
| Пользователь | окно, которое переживает сбой плагина; агенты, которые переживают перезапуск плагина и окна; видно, что каждый плагин может |
| Автор встроенного плагина | новая функция - новый плагин, без правки ядра и соседей |
| Автор стороннего плагина | тот же API и `@cyborg-harness/contracts`; во втором этапе - установка с согласием на права |
| Автор поставщика агента | новый агент - плагин `cyborg.agent` рядом с Claude Code |
| Владелец продукта | предсказуемая цена новой функции; сторонние плагины и агенты без форка |

## Меры успеха

| Мера | Цель | Чем проверяется |
|---|---|---|
| Имена плагинов в коде ядра | нет; окно без плагинов работает | [SAD, раздел 2](../04-architecture/design/sad.md#2-что-есть-ядро) |
| Правки ядра ради нового плагина | ноль | сценарий [автор встроенного плагина](../02-use-cases/maintainer-adds-feature/scenario.md) |
| Второй агент без правки ядра | да: `agent-shell` рядом с `agent-claude-code` | `playground/test/agents.test.ts` |
| Зависший плагин | обнаружен за порог плюс интервал сторожа (5 с + 1 с), хост перезапущен за ~70 мс; другие хосты, окно и pty не затронуты | [замер хостов](../05-verification/spike-hosts.md), дымовой тест |
| Процессы агентов при падении хоста и при выключении плагина с оставлением процессов | живы, плагин подключается к ним через `attach` | `core/test/pty.test.ts`, дымовой тест |
| Вызов к ОС без права в манифесте | всегда `PermissionDenied` и запись в журнале | `core/test/os.test.ts` |
| Импорт плагином чего-то, кроме `@cyborg-harness/contracts` и своих модулей | тест падает | `core/test/plugin-imports.test.ts` |
| Переход ко второму этапу | меняет среду хоста, а не код плагинов | [SAD, 6.2](../04-architecture/design/sad.md#62-этап-2-изоляция-доступа-по-поводу) |
| Накладные расходы: старт, память на хост и вид, задержка шлюза | в бюджете от базовой линии; числа не заданы | [SAD, открытый вопрос 9](../04-architecture/design/sad.md#8-открытые-вопросы) |

## Риски

Главные: `ses` с `lockdown()` может не заработать в `utilityProcess`; цена RPC через шлюз на горячих путях; `process` и `pty` дают программе все права пользователя ОС. Полный список и меры - [SAD, раздел 9](../04-architecture/design/sad.md#9-риски).
