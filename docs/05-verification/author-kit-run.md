# Проверка набора автора человеком со стороны

Критерий приёмки задачи [P-04](https://github.com/dex-it/cyborg-harness/issues/38) и норма [NFR-CH-1008](../03-requirements/07-author-kit/srs.md#nfr-ch-1008-набор-автора): человек, не участвовавший в разработке, по руководству за один заход собирает и запускает плагин с видом, командой, контрактом и разделом `config`.

**Статус: не проверено - нужен человек.** Этот документ - шаблон протокола и точная инструкция. Прогона не было, строк результата нет: заполненный протокол без человека был бы выдумкой. Критерий NFR-CH-1008 остаётся открытым, пока в разделе 5 нет подписанной записи прогона.

## 2. Условия прогона

- Участник: разработчик на TypeScript вне команды Cyborg Harness, не читавший код ядра, SAD и ADR этого репозитория и не участвовавший в разработке. Один человек на прогон; повторный прогон тем же человеком не засчитывается.
- Наблюдатель: человек из команды, который готовит стенд, молчит и записывает. Подсказывать нельзя; вопрос участника записывается, ответа он не получает.
- Машина: чистая учётная запись или контейнер; Node 24 и git; доступ к сети не нужен после подготовки; Electron для запуска окна (шаг 7) или проверка окном наблюдателя.
- Материалы выпуска: руководство (сайт `docs/guide`, раздел «Автору плагина» и «Первый плагин»), шаблон `templates/plugin`, архивы пакетов. Пакеты `@cyborg-harness/*` в реестре ещё не опубликованы ([P-10](https://github.com/dex-it/cyborg-harness/issues/11)), поэтому подготовка ниже ставит их из архивов; когда пакеты выйдут, шаг 2 подготовки заменяется `npm install`, а в протоколе фиксируется выпуск.

## 3. Подготовка (наблюдатель, до прихода участника; время не засчитывается)

```bash
git clone https://github.com/dex-it/cyborg-harness.git && cd cyborg-harness
git rev-parse HEAD                              # записать в протокол, раздел 5
npm ci && npm run build:packages
mkdir -p ../packages
npm pack --workspace=contracts --workspace=core --workspace=testing --workspace=tools/cyborg-plugin --pack-destination ../packages
cd site && npm ci && npm run dev                # сайт руководства на http://localhost:4321/cyborg-harness/
```

Участнику выдаётся: адрес сайта руководства (страница «Первый плагин»), каталог `packages/` с архивами, клон репозитория только ради каталога `templates/plugin` и стенда `playground`. Закрыть участнику: каталоги `core/src`, `docs/04-architecture` (не запрещать открывать, а записывать каждое открытие как обращение к коду ядра).

## 4. Задание и ход прогона

Задание участнику, дословно: «Соберите плагин `greeter` по руководству на сайте: у него должны быть команда, контракт (метод, который вызывает другой плагин), раздел настроек `config` со схемой и вид с кнопкой, которая вызывает команду. Плагин должен пройти проверку, тест, сборку и открыться в окне стенда. Работайте по руководству, начните со страницы «Первый плагин». Прервитесь, только если вы застряли».

Наблюдатель запускает секундомер, когда участник открывает страницу, и останавливает, когда выполнено последнее условие успеха или участник сдался. Прерывание на еду и перерывы записываются отдельной строкой и вычитаются.

**Условия успеха (проверяет наблюдатель после остановки секундомера, на каталоге участника):**

| № | Условие | Команда |
|---|---|---|
| 1 | Манифест и состав в порядке | `npx cyborg-plugin check` |
| 2 | Тест на тест-ките проходит | `npm test` |
| 3 | Сборка и упаковка проходят | `npx cyborg-plugin build && npx cyborg-plugin pack dist` |
| 4 | Плагин активен в стенде, вид виден, команда отвечает, раздел `config` проходит схему | положить результат сборки в `plugins/` каталога данных стенда, добавить `greeter` в `plugins.enabled` и запустить `cd cyborg-harness && npm start -- --user-plugins`; в журнале `activated` для `greeter`, `denied` и `failed` нет; нажатие кнопки вида возвращает ответ команды |
| 5 | Контракт вызывает другой плагин | в тесте участника потребитель получает метод контракта через границу (`Remote<T>`) |

**Условия неуспеха:** обращение к коду ядра (открытие файла в `core/src`, SAD, ADR, чтение исходников чужого плагина стенда ради ответа, которого не было в руководстве); вопрос, на который в руководстве и справочниках нет ответа (в том числе заданный наблюдателю); остановка на шаге дольше 15 минут без продвижения.

## 6. Что делать с результатом

1. Каждый вопрос без ответа в руководстве заводится в трекере репозитория; ответ дописывается в руководство (норма [FR-CH-7006](../03-requirements/07-author-kit/srs.md#fr-ch-7006-руководство-под-api-10)), участник возвращается к шагу, на котором остановился. Канал вопросов и метка - открытый вопрос 1 SRS фичи 07 ([FR-CH-7008](../03-requirements/07-author-kit/srs.md#fr-ch-7008-канал-вопросов-автора)); пока метки нет, вопросы идут в задачу P-04 комментарием.
2. Запись раздела 5 кладётся в этот файл отдельным коммитом, статус в шапке меняется на `review`.
3. Если неуспех - критерий приёмки P-04 и NFR-CH-1008 остаются открытыми; повторный прогон делает другой участник после правки руководства.
4. Если успех - в SRS фичи 07 у NFR-CH-1008 «Ещё нет» заменяется ссылкой на этот протокол с датой прогона.
