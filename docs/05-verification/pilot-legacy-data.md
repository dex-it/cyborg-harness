## 1. Таблица «поле старого файла - куда уходит»

Файл воркспейса Cyborg `e4beb72`: `{projects, lastProjectId, commands?}`; `ProjectStore.save` пишет `{...state, ...own}` с `OWN_FIELDS = ['commands']` (`src/main/projects.ts:112`), `validateProjectsState` сохраняет неизвестные поля проекта (`{...p, trackers, jira}`).

| Поле старого файла | Куда в новом файле | Состояние до PL-06 | Решение |
|---|---|---|---|
| `projects[].id`, `name`, `description`, `repos` | `settings.projects.items[]` | переносилось | без изменений; `repos` берётся из устаревшего `path`, если `repos` нет |
| `projects[].trackers` (`github`, `gitlab` и любые другие ключи как есть) | `settings.trackers.byProject.<id>` | переносилось | без изменений |

| `projects[].<неизвестное>` (в фикстуре `color`, `notes`) | `settings.projects.items[]`, рядом с известными полями, значение как есть | **терялось** | перенос (D-01) |
| запись в `projects[]` не объект или без строкового `id` | `settings.projects.skipped[]` как есть | **терялась** | отказ с записью (D-02): ключа `id` нет, привязать трекеры и активный проект не к чему, но данные остаются в файле, а не только в `.v1.bak` |

| `commands` (список) | `settings.command-buttons.commands`, кнопки как записаны, включая поля, которых нет в схеме кнопки | **не читалось ни одним разделом** (оставалось наверху файла) | перенос (D-03); не список остаётся наверху файла |

| канонизация путей `repos` через `realpath` при чтении (`canonicalRepo`) | не переносится | не переносилась | пути остаются как записаны; нормализацию делает плагин `projects` при чтении, потерь значений нет |

## 2. Что было потеряно и как закрыто

| Файл только для чтения переводился: `rename` проверяет права на каталог, а не на файл, и заменял файл `0444` новым с обычными правами | тест «файл только для чтения…» | не переводится, запись отменена, права и байты на месте |

## 3. Ключи `localStorage` окна -> `ctx.state` видов

Окно Cyborg пишет в `localStorage` только через `src/renderer/prefs.ts`; закрытый список проверяет `test/static-guards.test.ts`. Ключи читает только старое окно (сессия Chromium `userData/workspaces/<хеш>/`, ADR-0014 п. 11), поэтому оно **отдаёт** их плагину: команда `legacy-prefs.import` принимает объект «ключ -> строка» со всеми ключами `cyborg.*`.

**Путь данных.** Старое окно -> `legacy-prefs.import` (главная часть: `readLegacyPrefs` раскладывает ключи по видам, результат ждёт в памяти) -> вид забирает своё командой `legacy-prefs.pending` при открытии (канал сообщений не хранит, [K-13](https://github.com/dex-it/cyborg-harness/issues/60)) или толчком канала, если он уже открыт -> `ctx.state.set` -> раздел `$views` state воркспейса -> главная часть получает `legacy-prefs.done`. Пишет память вида только сам вид (у главной части такого API нет).

| Ключ окна | Вид | Поле памяти вида | Значение |
|---|---|---|---|
| `cyborg.fontSize` | `terminal` | `fontSize` | целое 8-32 |
| `cyborg.notifications` | `notifications` | `enabled` | любое значение, кроме `off`, - `true` (как читало окно) |
| `cyborg.tasks.assigned` | `tasks` | `assigned` | `1`/`0` -> булево |
| `cyborg.tasks.sort` | `tasks` | `sort` | строка |
| `cyborg.mrs.filter`, `cyborg.mrs.sort` | `mrs` | `filter`, `sort` | строки |
| `cyborg.search.mode` | `search` | `mode` | строка |
| `cyborg.extensions.tab`, `cyborg.extensions.view` | `extensions` | `tab`, `view` | строки |
| `cyborg.extensions.size` | `extensions` | `size` | `ширина,высота` -> `{width, height}`; пустая строка (сброс окна) - не переносится |
| семейство `cyborg.search.<флаг>` | `search` | `regex`, `caseSensitive`, `wholeWord` | `1`/`0` -> булево |
| семейство `cyborg.extensions.<флаг>` | `extensions` | `regex`, `caseSensitive` | `1`/`0` -> булево |
| семейство `cyborg.tasks.labels:<id проекта>` | `tasks` | `labels.<id>` | список пар `[имя, "+"/"-"]`, как `serializeLabelFilter` |

Правила:
- Выбор из списка допустимых значений (`sort`, `filter`, `mode`, `tab`, `view`) проверяет владелец вида, как проверял `readChoice`; перенос проверяет только форму (непустая строка). Значение не по форме, неизвестный ключ `cyborg.*` и значение не строкой не переносятся и **названы в ответе `legacy-prefs.import` (`skipped`) и в журнале плагина** с ключом и причиной; чужие ключи (не `cyborg.`) игнорируются. Окно и раньше читало такое значение как умолчание, так что поведение то же.
- Память вида ограничена 64 КБ JSON. Фильтры меток растут с числом проектов: сверх бюджета (63 КБ) лишние проекты названы в `skipped` и не пропадают молча.
- Метка `legacyImported: true` в памяти вида делает повторный перенос пустым: старое окно отдаёт ключи при каждом запуске, пока `localStorage` живёт, и правка человека в новом окне не затирается. Значение человека, заданное в новом окне до переноса, сильнее перенесённого (вложенные записи - метки, размер - сливаются так же, поле за полем).
- Имена видов (`terminal`, `notifications`, `tasks`, `mrs`, `search`, `extensions`) в пилоте - видов одного плагина; у настоящих владельцев (sessions, session-notifications, trackers, search, claude-extensions) память вида та же по форме, перенос копируется вместе с модулем вида. Это допущение (D-07).

Проверено тестами `playground/test/pilot-legacy-prefs.test.ts`: десять ключей и три семейства дают значения, равные исходным; запись идёт в настоящий файл state воркспейса; повторная отдача файл не меняет (побайтно); память пережила перезапуск ядра и воркспейса.

## 4. Повреждённые, пустые, новые и защищённые от записи файлы

Тесты - `core/test/workspace.test.ts` (поведение ядра, файл любой формы).

| Исход | Что делает ядро | Закреплено |

| Пустой файл (0 байт), JSON не по форме, корень не объект (`[1]`, `null`) | не стирается и не переводится, хук не зовётся, рядом копия `<файл>.corrupt-<время>`, причина в `problems`, запись разделов в него отменена | «пустой файл и корень не объект…», «битый файл воркспейса…» |
| `cyborg` больше известного (`3` при известном `2`) | читается (`plugins`, `settings` доступны плагинам, у которых версия раздела подходит), запись отменена, файл побайтно прежний, копий нет, в `problems` - «формат cyborg 3 новее известного 2» | «файл новее известного формата…» |
| Файл без права записи (`0444`) | не переводится (копии `.v1.bak` нет), запись отменена с причиной, права и байты прежние | «файл только для чтения…» |
| Каталог без права записи | `openWorkspace` отказывает ошибкой `EACCES` (замок `<файл>.lock` не создаётся), файл не тронут. Текст ошибки называет путь замка, а не причину «воркспейс только для чтения»; перевод в понятное сообщение - дело приложения | «каталог только для чтения…» |
| Сбой записи state при переводе | файл остаётся прежним, перенос повторится при следующем открытии | «сбой записи state…» |

Под `root` проверки прав пропускаются (доступ проверкой не закрывается).

## 5. Откат: что видит старая версия Cyborg

`npm run build:packages && node --disable-warning=MODULE_TYPELESS_PACKAGE_JSON playground/scripts/pilot-legacy-rollback.mjs <путь к ai-cyborg на e4beb72>`. Скрипт копирует во временный каталог `projects.ts`, `jira-keys.ts`, `jsonfile.ts` старого приложения, переводит копию фикстуры хуком и читает её настоящим `ProjectStore`. Итог запуска 2026-11-11:

| Действие | Что делает старая версия |
|---|---|
| `ProjectStore.load()` на переведённом файле | **проекты: ноль, `lastProjectId` пусто.** Файл `{cyborg, settings, ...}` не имеет поля `projects`, `shapeProblem` называет его повреждённым («поле projects не массив»), рядом ложится `<файл>.corrupt-<UTC>` с байтами переведённого файла; сам файл пока не тронут. В окне - пустой перечень проектов и замечание о повреждении |
| `loadCommands()` | `undefined`: поле `commands` ушло в `settings` (D-03), кнопки пользователя в окне старой версии не видны, остаются встроенные |
| `save()` (любое сохранение проектов, например создание проекта) | файл **заменяется** на `{projects, lastProjectId}`: `cyborg`, `settings`, `plugins` и все неизвестные поля **стираются** (старая версия сохраняет только `commands`); правки, сделанные в новой версии после перевода, теряются, если их не вернуть из `.corrupt-*` |
| Что остаётся | `<файл>.v1.bak` - прежний файл побайтно (скрипт проверяет); `<файл>.corrupt-*` - переведённый файл на момент первого открытия старой версией |
| Ручной откат | вернуть `<файл>.v1.bak` на место файла: старая версия читает все три проекта, `lastProjectId` и три кнопки без замечаний (скрипт проверяет) |

Вывод: откат **не безопасен без копии**: старая версия показывает переведённый файл как повреждённый, а первое сохранение стирает формат 2. Пользователю, откатывающемуся на старую версию, нужен `.v1.bak`; правки, сделанные в формате 2, придётся переносить руками. Шаг 0 плана (`ProjectStore` сохраняет неизвестные поля) **не сделан и требует правки ai-cyborg**: он не отменяет того, что старая версия не прочитает проекты из `settings`, но не даст ей стереть чужие поля. Данные не дублируются в старых полях (D-05): два места правды разошлись бы при первой же правке.

## 6. Решения

Все решения - принято по поручению владельца 2026-11-11 по предложению составителя; владельцу подтвердить.

| № | Решение | Основание |
|---|---|---|
| D-01 | Неизвестные поля проекта остаются в его записи в `settings.projects.items[]`, значения как есть | Приложение `e4beb72` их сохраняет (`validateProjectsState`); отдельный раздел «лишнее» дал бы два места на проект. Обратимо: плагин `projects` может их игнорировать |
| D-02 | Записи `projects[]` без строкового `id` (не объект, `null`, строка) переходят в `settings.projects.skipped[]` как есть | «Потеря данных недопустима»; ключа для `trackers.byProject` и `lastProjectId` нет, поэтому полноценной записью проект не становится. Исходник и так хранит `.v1.bak`, но запись в файле видна пользователю |
| D-03 | `commands` (список) -> `settings.command-buttons.commands`; не список остаётся наверху | Идентификатор плагина `command-buttons` - из [инвентаря](../research/cyborg-migration-inventory.md), раздел 3.1; код плагина вне задачи. Слой кнопок воркспейса - ADR-0015 п. 10 (ai-cyborg): третий слой после встроенных и `userData/commands.json` |
| D-04 | Подстановка из `userData/trackers.json` проекту без `trackers` не переносится | Это файл каталога приложения, а не воркспейса; в новом файле у проекта без `trackers` источники по умолчанию задаёт плагин `trackers` |
| D-05 | Старые поля (`projects`, `lastProjectId`, `commands`) в переведённом файле не дублируются для старой версии | Копии расходились бы; откат - копией `.v1.bak` |
| D-06 | `.v1.bak` - побайтная копия; порядок записи: копия, state, файл последним; файл новее известного формата читается, но не записывается; файл без права записи не переводится | Раздел 2. Поле `cyborg` - точка фиксации перевода |
| D-07 | `localStorage` переносит приложение (плагин приложения), ядро ключей не знает; вид забирает своё при открытии и по толчку канала; имена видов пилота - допущение | SRS фичи 05, вопрос 10 (предложение: приложение); K-13: канал сообщений не хранит. Ядро не менялось |
| D-08 | Перенос ключей идёт при каждом отдавании старым окном, пока метка `legacyImported` не стоит; человек сильнее перенесённого | Нет надёжного «момента перехода» (раздел 7), поэтому перенос идемпотентен |
| D-09 | Тесты хука лежат в `playground/src/main/legacy-workspace.test.ts`, а не в `core/test/workspace.test.ts`, как предлагала задача | Ядро не импортирует playground, а хук - код приложения; в `core/test` лежат проверки механизма (копия, порядок, файлы) на хуке-заглушке |
| D-10 | Результат записан в `docs/05-verification/` | Каталога `docs/04-verification/` нет |

## 7. Не проверено и зависимости

- **Правка ai-cyborg (шаг 0 плана: `ProjectStore` сохраняет неизвестные верхние поля) не сделана.** Внешняя зависимость: пока старая версия жива, откат и открытие нового файла стирают чужие поля (раздел 5).
- **Момент и канал передачи `localStorage`.** Старому окну нужна кнопка или шаг при первом запуске новой версии, который прочитает ключи `cyborg.*` из своей сессии и вызовет `legacy-prefs.import` (в playground - команда плагина; как она доходит из старого окна, не решено и в ai-cyborg не сделано). В тесте старое окно изображено вызовом `kernel.run`. Живого Cyborg с настоящим `localStorage` в работе не было. **Что должен сделать человек:** на машине с рабочим профилем Cyborg выгрузить `Object.entries(localStorage).filter(([k]) => k.startsWith('cyborg.'))` из окна (DevTools) в JSON и прогнать через `readLegacyPrefs` (`playground/plugins/legacy-prefs/prefs-map.ts`), сверив `skipped`; так проверяются настоящие значения, в том числе `cyborg.tasks.labels:<id>` с реальными метками.

## Открытые наблюдения

- Если `.v1.bak` уже есть, а файл без `cyborg` появился снова (вручную вернули старый), перевод **перезапишет** прежнюю копию. Копия отражает файл, который переводили, но предыдущая теряется. Не менялось: нужно решение о нумерованных копиях.
