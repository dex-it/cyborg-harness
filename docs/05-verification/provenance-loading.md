# Загрузка плагина из проверенных байтов: способ, проверка на macOS и Linux, цена

Результат задачи TR-11 ([#247](https://github.com/dex-it/cyborg-harness/issues/247), критерий 5) по [исследованию доверия](../research/trust-and-isolation/README.md), [раздел 5.4](../research/trust-and-isolation/05-decision.md#54-слой-происхождение-плагинов) и открытый вопрос «Загрузка из проверенных байтов» ([7.2, п. 6](../research/trust-and-isolation/07-open-questions.md)). Решение - [ADR-CH-0017](../04-architecture/adr/ADR-CH-0017-plugin-provenance.md), п. 4-5. Дата замеров 2026-11-13.

## Задача

Ядро читает каталог плагина один раз, проверяет подпись и хеши этих байтов и должно заставить хост исполнить **именно их**. Если хост откроет файл по пути второй раз (`import(entry)`), процесс того же пользователя успеет подменить файл между проверкой и открытием.

## Способы и итог

| Способ | `import.meta.url` и относительные импорты | Закрывает гонку | Итог |
|---|---|---|---|
| `import()` из `data:` URL | ломаются: адрес `data:`, относительные импорты не находят соседей | да | отвергнут (бандл `cyborg-plugin build` - один файл, но плагины со вспомогательными модулями и `import.meta.url` в нём встречаются) |
| Копия во временный каталог ядра (0700, файлы 0400), `import` оттуда | работают | нет: тот же пользователь подменяет и копию, окно гонки остаётся | отвергнут |
| `vm.SourceTextModule` | свои правила, нужен флаг `--experimental-vm-modules` | да | отвергнут (экспериментальный флаг в хосте, не публичный API) |
| **Хук загрузки модулей `module.registerHooks` (Node 24)**: `load` для адреса под каталогом плагина возвращает проверенные байты из памяти | работают: адрес остаётся `file:` | да | **выбран** |

Устройство: ядро присылает хосту в `activate` адрес каталога и байты загружаемых файлов (`.mjs`, `.cjs`, `.js`, `.json`; base64 - чтобы одинаково доехали по structuredClone и по JSON); `core/src/verified-sources.ts` один раз на процесс ставит хук. Для адреса под каталогом плагина хук отдаёт байты (формат по расширению; для `.js` - по ближайшему проверенному `package.json`), для адреса, которого нет среди проверенных, бросает ошибку; прочие адреса (`node:*`, другие плагины) идут как обычно. Проверенные байты забываются при `deactivate` и при ошибке активации.

## Что проверено

Опыт на отдельном скрипте (плагин из двух модулей, подмена обоих на диске после регистрации хука, лишний файл рядом):

| Среда | Результат |
|---|---|
| macOS 27.2 arm64, Node 24.20.0 | загружен проверенный код, `import.meta.url` - `file:`, относительный импорт отдал проверенный соседний модуль, неназванный файл отклонён, файл, появившийся на диске после проверки, отклонён |
| Linux arm64 (Docker OrbStack, `node:24-bookworm-slim`, ядро 7.2.12), Node 24.22.3 | то же |

Тесты репозитория, в которых подмена файла делается сразу после проверки и до `import()` (с контролем: без проверенных байтов та же подмена исполняется):

| Среда | Тест | Результат |
|---|---|---|
| Node, настоящий дочерний процесс хоста (`forkHosts`), macOS | `core/test/provenance.test.ts` («подмена файла между проверкой и запуском…») | зелёный |
| Тот же набор тестов ядра на Linux (Docker, Node 24.22.3): `integrity`, `trust-store`, `provenance`, `delivery` | 51 тест | зелёные |

## Цена

Замер `createProvenance().check` на macOS, ноутбук, пакет из `index.mjs`, `manifest.json` и ресурсов вида (медиана семи запусков; чтение каталога, sha256 всех файлов, проверка подписи):

| Пакет | Проверка, мс | Хосту уходит (base64) |
|---|---|---|
| бандл 0,2 МБ | 1,1 | 0,27 МБ |
| бандл 2 МБ | 2,5 | 2,67 МБ |
| бандл 2 МБ и 40 МБ ресурсов видов | 26,8 | 2,67 МБ |

Ресурсы видов хешируются (они входят в подпись), но в хост не едут. Проверка идёт на каждой активации, в том числе при перезапуске хоста. Бюджеты шлюза `ctx.os` (`npm run check:budgets`) загрузка не затрагивает: она единожды на активацию, горячий путь вызовов не меняется.

## Ограничения и что не проверено

- `module.registerHooks` в Node 24 имеет статус «активная разработка»: canary на каждый релиз Electron и Node - сами тесты выше (CI на macOS и Linux).
- Хук действует на весь процесс хоста: в общем хосте он обслуживает всех плагинов, адреса других плагинов проходят мимо. Модуль, уже загруженный в хост (кэш `import()` по адресу), повторная активация не перечитывает: пока хост жив, кэш держит прежние проверенные байты.
- **Не проверено:** хук в процессе Node под `--permission` и под ограничителем ОС (этап В, TR-20/TR-21: способ загрузки там проверяется отдельно, как записано в [плане](../research/trust-and-isolation/06-work-plan.md), TR-20, критерий 4); `utilityProcess` на Linux с дисплеем локально (в CI шаг «доверие» идёт под `xvfb-run`; локально агент Linux с Electron не запускал, только Node в Docker); процесс Node на Windows (вне охвата).
