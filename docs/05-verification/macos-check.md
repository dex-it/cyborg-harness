# Проверка ядра на macOS

Результат задачи [#2](https://github.com/dex-it/cyborg-harness/issues/2): замеры хостов и фреймов, клавиши, терминал. Linux-таблицы - [spike-hosts.md](spike-hosts.md) и [spike-iframe-ui.md](spike-iframe-ui.md).

## Среда

MacBook Pro 16" (MacBookPro18,1), Apple M1 Pro, 10 ядер; macOS 27.2 (сборка 26B123); Electron 45.2.2, Chromium 156.0.8078.80, Node 24.22.2. Замеры сняты на рабочем компьютере с открытыми Telegram, Chrome и другими приложениями: load average 20-29. Для задержек и порогов это шум в худшую сторону, для памяти - нет.

**Память мерили иначе, чем на Linux.** Там PSS из `/proc/<pid>/smaps_rollup`; на macOS такого файла нет, и скрипты печатали в этих колонках прочерки. Теперь на macOS столбец «PSS» - физический след процесса из `footprint -p <pid>`, RSS - из `ps -o rss=` (`playground/src/main/proc-memory.ts`). Это другая мера: она не делит общие страницы по тому же правилу, поэтому память macOS и Linux сравнивается порядком величины, а не цифрой в цифру.

Нажатия посылались через `System Events` (`key code` по физической клавише; `keystroke "буква"` зависит от раскладки и для проверки сочетаний не годится) в окно playground, когда оно было на переднем плане. Проверено:

| `F2` | работает: `bob.status`, в поле вида ничего не напечатано |

Первая попытка дала `Shift+Meta+A`: `keystroke "b"` в `System Events` зависит от раскладки (на этом Mac русская), а `key code 11` идёт по физической клавише. Это ограничение способа нажатия, не ядра: ядро получило `key: A, code: KeyA`, то есть уже искажённое ОС нажатие |

**Не удалось проверить:** обычные буквы в поле вида (текст через `keystroke` ушёл бы в раскладку, а во фрейм не попал: `document.hasFocus()` был `false`), `Cmd+C`/`Cmd+V`, `Cmd+Shift+L` и замок, `Cmd+Backspace` и `Option+стрелки` в терминале. Причина в среде проверки, а не в ядре: macOS возвращала фокус другому приложению (терминалу, из которого запущен тест) через ~0,3 с после активации окна, `document.hasFocus()` в окне и во фрейме оставался `false`, и текст во фрейм не попадал. Эти пункты нужно пройти человеку за чистым сеансом.

## Меню Edit в меню приложения (K-08, 2026-11-10)

С K-08 у playground есть настоящее меню приложения (`bindAppMenu`, `playground/src/main/main.ts`): `appMenu`, `editMenu` с ролями `copy` и `paste`, меню плагинов. Шаг smoke «буфер обмена» теперь нажимает роли в `Menu.getApplicationMenu()`, а не в отдельно собранном шаблоне.

Результат на этом Mac (macOS 27.2, Electron из `package-lock.json`, `node playground/scripts/smoke.mjs` с пропущенным шагом фокуса F6, который падает на чистой базе): `copy` и `paste` во вложенном кадре работают в Monaco и xterm через `webContents.copy()/paste()` (вывод «copy/paste в Monaco и xterm работают»); сама роль меню под CDP не сработала (`{"copy":false,"paste":false}`), как и в прошлой проверке: на macOS роль шлёт действие первому ответчику AppKit, а окно под управлением CDP не ключевое. Нажатие настоящего пункта «Правка > Копировать» живой мышью или клавиатурой не снималось: среда проверки возвращает фокус терминалу (см. выше). Критерий «роли Edit работают во вложенном кадре на macOS» закрыт частично; остаток - пройти человеку за чистым сеансом.

### Попытка настоящих нажатий в этом запуске

Нажатия `System Events` `key code` отправлять в окно можно, только если оно надёжно получает фокус. Проверка без отправки клавиш: playground запущен под CDP (`--remote-debugging-port`), процесс выведен на передний план `set frontmost of (first process whose unix id is <pid>) to true`, 12 секунд (60 опросов по 200 мс) опрашивались `document.hasFocus()` страницы и процесс на переднем плане. Итог: `document.hasFocus()` ложен в 60 из 60 опросов, Electron на переднем плане в 0 из 60 - как и в прошлой проверке (раздел «Клавиши настоящими нажатиями»): macOS возвращает фокус запускающему терминалу. Клавиши не посылались: они ушли бы в приложение, у которого фокус, то есть в терминал, из которого идёт сессия. Вторая попытка (активация по `tell application id "com.github.Electron" to activate`) ответа не дала и была прервана по таймауту. Поэтому в графе «не проверено» ниже стоит причина «окно не получает фокус надёжно», а не «не сделано».

### Что должен пройти человек за чистым сеансом

Условия: чистый сеанс без фоновых приложений (Telegram, Chrome, терминал со сторонним фокусом закрыты), английская раскладка (`ABC`: Cmd+буква не зависит от раскладки при `key code`, но поле вида печатает символ раскладки), окно приложения в фокусе кликом.

```sh
git checkout it4-pl03   # после слияния - master
npm ci && npm run build
UD="$(mktemp -d)/cyborg-pl03"
# 1. Первый запуск создаёт cyborg.json. Запускать через LaunchServices (open), а не из терминала: так приложение сохраняет фокус.
open -n -W ./node_modules/electron/dist/Electron.app --args "$PWD" --user-data-dir="$UD"   # закрыть окно после запуска (Cmd+W)
# 2. Включить пилот keys-pilot:
node -e 'const f=process.argv[1],fs=require("fs"),c=JSON.parse(fs.readFileSync(f,"utf8"));c.plugins.enabled.push("keys-pilot");fs.writeFileSync(f,JSON.stringify(c,null,2))' "$UD/cyborg.json"
# 3. Рабочий запуск:
open -n -W ./node_modules/electron/dist/Electron.app --args "$PWD" --user-data-dir="$UD"
```

В боковой колонке появится вид `keys-pilot` (поле и лента «что дошло до страницы»); на вкладке «Клавиши» панели слева - таблица реестра. ### Колесо с модификатором и бросок файла ОС: решение PL-03

Принято по поручению владельца 2026-11-11 (риск задачи #19: «нужно отдельное решение»).

- **Колесо с `Cmd`/`Ctrl`** (масштаб шрифта в Cyborg: `app.ts`, слушатель `wheel` в фазе захвата) в реестр сочетаний не входит. Реестр клавиатурный: ключ записи - клавиша и модификаторы, `before-input-event` колесо не видит (событие `input-event` вебконтента о колесе в кадрах других процессов этим запуском не проверялось). Масштаб - функция слоя окна приложения: слушатель `wheel` в документе окна и в оболочке вида (она загружается в каждый кадр вида), который зовёт команду приложения. Это отдельная задача переноса окна Cyborg; здесь заведена как открытое наблюдение. Проверка колеса на macOS - человеку, строка в таблице выше. Обратимо: если колесо потребует ядро, команда окна с областью приложения добавляется поверх, не меняя реестр.
- **Бросок файла ОС в кадр** (`webUtils.getPathForFile` в кадре с целью броска) - как в задаче: вне #19, см. «Что осталось», п. 3.

## Дымовой тест на этом Mac

`npm run build`, `typecheck`, `lint`, `npm test` (248 тестов) проходят. `node playground/scripts/smoke.mjs` на этом компьютере нестабилен (зелёными были единицы из полутора десятков прогонов): падал на шаге F6 -> «фокус вида лёг на его элемент, а не на body» (`document.hasFocus()` ложен: то же возвращение фокуса приложению-запускателю) и на шагах выключения `echo` с вопросом о процессах терминала. Второй вид падений причиной фокуса не объяснён; на `macos-latest` в CI тест проходит. Версия `sh` на macOS - bash 3.2: интерактивный `/bin/sh` игнорирует `SIGTERM`, а `SIGHUP` и `SIGKILL` завершают его; ядро шлёт `SIGHUP` группе (`killGroup`), поэтому расхождения с Linux здесь нет.
