# Спайк: UI плагинов во фреймах

Ответ на [открытый вопрос 11 SAD2](../03-architecture/design/sad2.md#8-открытые-вопросы): что стоит вид плагина в своём `<iframe>` с origin `cyborg-plugin://<id>` ([SAD2 §3.8](../03-architecture/design/sad2.md#38-изоляция-рендера)) по памяти, задержке вывода, клавишам и перетаскиванию, и какой мост к главному процессу брать.

## Как мерили

- Код - `playground/`: схема `cyborg-plugin` (`standard`, `secure`) в `src/main/views.ts`, мост вида в `src/main/preload.ts`, замер в `src/main/spike.ts`, запуск - `npm run spike` (на Linux - `xvfb-run --auto-servernum node playground/scripts/spike-iframe.mjs --no-sandbox` после сборки).
- Пробный вид - минимальная страница: поле ввода, два перетаскиваемых пути (страницей и через ядро), зона сброса (`src/renderer/probe/`). Вид с xterm или Monaco весит больше, но эта цена одинакова при любом мосте и любом origin.
- Окно - `contextIsolation`, `sandbox`, `nodeIntegrationInSubFrames`. Ядро плагинов в замере не запускается: числа - только UI.
- Среда: Electron 45.2.2, Chromium 156, Linux x64, Xvfb. macOS не мерили.

## Мост: preload в подфреймах

- **Вид не может назваться чужим.** Главный процесс узнаёт плагин по `event.senderFrame.origin`, а не по словам вида: `view:run` выполняет только команды из манифеста этого плагина, чужую отклоняет (кнопка `alice.hello` в виде bob). При `postMessage` плагин называет документ окна по `event.origin`, и код окна оказывается на пути доверия.
- **Документ окна не на горячем пути.** Вывод терминала идёт прямо во фрейм; занятое окно его не задерживает.
- **Каналы окна закрыты для видов.** `plugins:*` принимают только главный фрейм окна (`fromWindow`): вид, обошедший свой preload, не выключит соседа.
- **Цена.** `nodeIntegrationInSubFrames` запускает preload в каждом фрейме, включая чужую страницу, встроенную в вид. Preload выдаёт мост по origin документа: вид получает `cyborgView`, окно - свой API, остальные - ничего.

## Перетаскивание: через ядро

Chromium не пускает перетаскивание, начатое страницей, во фрейм другого процесса той же страницы (`WebContentsViewAura::IsValidDragTarget`, защита от подмены сброса между сайтами). Над чужим фреймом события перетаскивания не получает никто: ни фрейм, ни окно. Это касается и вида, и документа окна. Перехват CDP (`Input.dispatchDragEvent`) шлёт события прямо во фрейм и проверку обходит - поэтому замер через CDP показывает, что `application/x-cyborg-path` переходит, а мышь - нет.

Как работает обход (`src/main/view-drag.ts`, виды alice и bob):

- Вид гасит `dragstart` и зовёт `cyborgView.startDrag(path)`. Ядро запоминает путь и плагин-источник по origin фрейма и запускает перетаскивание ОС через `webContents.startDrag`. Такое перетаскивание идёт не от страницы, и проверка его не касается.
- Приёмник видит тип `Files`, на сбросе зовёт `cyborgView.drop()` и получает `{ from, path }` один раз. Сброс файла из ОС - `null`.
- На Linux `startDrag` держит главный процесс до отпускания кнопки, а `view:drop` приходит через десятки миллисекунд после. Ядро забывает путь через секунду после возврата - иначе забытый путь достался бы следующему сбросу файла из ОС.
- Цена: путь уходит в ОС как `file://`, его можно сбросить в файловый менеджер или терминал. Для файлов проекта это полезно, но ядро должно проверять путь по правам плагина, как при чтении. Playground проверяет только форму пути.

## Запасной путь: общий origin для встроенных

На десяти видах он экономит ~80 МБ PSS, но встроенные плагины начинают видеть DOM друг друга (`window.parent.frames[i].document`), и origin больше не называет плагин - мосту понадобится другое удостоверение. При сегодняшних числах этот путь не нужен; возврат к нему - если видов станет заметно больше десяти или бюджет памяти (открытый вопрос 9) окажется ниже.

## Что замер не проверяет

- **Ввод в тестах.** `webContents.sendInputEvent` отдаёт клавишу виджету главного фрейма: `before-input-event` срабатывает, но во фрейм с фокусом клавиша не попадает. CDP `Input.dispatchKeyEvent` идёт во фрейм мимо `before-input-event`. Клавиши во фреймах проверяются только настоящим вводом: `playground/scripts/xtest.py` (нужен `python-xlib`), путь к нему - в `CYBORG_SPIKE_XTEST`.
- **Перетаскивание без XTest.** Без `CYBORG_SPIKE_XTEST` замер делает только перехват CDP, а он обходит проверку Chromium (см. выше). Настоящая мышь - `xtest.py drag`. Строки `html5` и `kernel` в выводе замера.
- **Перетаскивание в другие приложения и из них.** Не проверено: сброс пути ядра в файловый менеджер и файла из ОС в вид.
- **macOS.** Процессы и память там могут отличаться; замер запускается той же командой.
