# Проверка ядра на macOS

Результат задачи [#2](https://github.com/dex-it/cyborg-harness/issues/2): замеры хостов и фреймов, клавиши, терминал. Linux-таблицы - [spike-hosts.md](spike-hosts.md) и [spike-iframe-ui.md](spike-iframe-ui.md).

## Среда

MacBook Pro 16" (MacBookPro18,1), Apple M1 Pro, 10 ядер; macOS 27.2 (сборка 26B123); Electron 45.2.2, Chromium 156.0.8078.80, Node 24.22.2. Замеры сняты на рабочем компьютере с открытыми Telegram, Chrome и другими приложениями: load average 20-29. Для задержек и порогов это шум в худшую сторону, для памяти - нет.

**Память мерили иначе, чем на Linux.** Там PSS из `/proc/<pid>/smaps_rollup`; на macOS такого файла нет, и скрипты печатали в этих колонках прочерки. Теперь на macOS столбец «PSS» - физический след процесса из `footprint -p <pid>`, RSS - из `ps -o rss=` (`playground/src/main/proc-memory.ts`). Это другая мера: она не делит общие страницы по тому же правилу, поэтому память macOS и Linux сравнивается порядком величины, а не цифрой в цифру.

## Клавиши настоящими нажатиями

Нажатия посылались через `System Events` (`key code` по физической клавише; `keystroke "буква"` зависит от раскладки и для проверки сочетаний не годится) в окно playground, когда оно было на переднем плане. Проверено:

| Что | Результат |
|---|---|
| `Cmd+Shift+A` | работает: ядро забирает сочетание, команда `alice.hello` выполнена, в поле вида `bob` ничего не напечатано |
| `F2` | работает: `bob.status`, в поле вида ничего не напечатано |
| `Cmd+Shift+B` | работает: `bob.hello`, запись `Shift+Meta+B` в ленте. Первая попытка дала `Shift+Meta+A`: `keystroke "b"` в `System Events` зависит от раскладки (на этом Mac русская), а `key code 11` идёт по физической клавише. Это ограничение способа нажатия, не ядра: ядро получило `key: A, code: KeyA`, то есть уже искажённое ОС нажатие |
| `F6` / `Shift+F6` | работает: фокус уходит между панелью «Плагины» и видом `sessions`, обратно - `Shift+F6` |

**Не удалось проверить:** обычные буквы в поле вида (текст через `keystroke` ушёл бы в раскладку, а во фрейм не попал: `document.hasFocus()` был `false`), `Cmd+C`/`Cmd+V`, `Cmd+Shift+L` и замок, `Cmd+Backspace` и `Option+стрелки` в терминале. Причина в среде проверки, а не в ядре: macOS возвращала фокус другому приложению (терминалу, из которого запущен тест) через ~0,3 с после активации окна, `document.hasFocus()` в окне и во фрейме оставался `false`, и текст во фрейм не попадал. Эти пункты нужно пройти человеку за чистым сеансом.

## Дымовой тест на этом Mac

`npm run build`, `typecheck`, `lint`, `npm test` (248 тестов) проходят. `node playground/scripts/smoke.mjs` на этом компьютере нестабилен (зелёными были единицы из полутора десятков прогонов): падал на шаге F6 -> «фокус вида лёг на его элемент, а не на body» (`document.hasFocus()` ложен: то же возвращение фокуса приложению-запускателю) и на шагах выключения `echo` с вопросом о процессах терминала. Второй вид падений причиной фокуса не объяснён; на `macos-latest` в CI тест проходит. Версия `sh` на macOS - bash 3.2: интерактивный `/bin/sh` игнорирует `SIGTERM`, а `SIGHUP` и `SIGKILL` завершают его; ядро шлёт `SIGHUP` группе (`killGroup`), поэтому расхождения с Linux здесь нет.
