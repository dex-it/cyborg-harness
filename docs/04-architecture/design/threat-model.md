# Модель угроз Cyborg Harness

Отсюда выводятся задачи безопасности: у каждой угрозы есть защита в коде, статус и задача, которая её закрывает. Как устроена защита, описывают [SAD 3.7](sad.md#37-безопасность-данных-и-контроль-плагинов) и [3.8](sad.md#38-изоляция-рендера). Этот документ отвечает на другой вопрос: от кого защищаемся, что бережём и где защиты нет.

Статусы указаны на 2026-11-08 по ветке `master` после слияния PR #78 - #97. У-46 и У-47 добавлены 2026-11-08, когда выводились нормы наблюдаемости.

## 1. Предмет и граница

Предмет - ядро плагинов (`core/`) и его адаптер Electron (`playground/src/main`), а также встроенные плагины. Встроенные плагины ведут себя как образец для сторонних и сами дают агенту права пользователя.

В модель не входят:

- **Вредоносный код под тем же пользователем ОС.** Он может всё, что может Cyborg: читать файлы, keyring, память процессов. Cyborg от него не защищается.
- **Уязвимости Electron, Chromium, Node и ОС.** Защита - своевременное обновление, а не архитектура ядра.
- **Поведение программ, которые плагин запускает по праву `process` или `pty`.** Это честная граница ([6](#6-допущения-и-честные-границы)).

## 4. Границы доверия

| ID | Граница | Кто проверяет | Чем |
|---|---|---|---|
| Г1 | Хост плагина → главный процесс | ядро | вызывающий определяется по каналу, форма каждого сообщения сверяется (`core/test/trust.test.ts`) |
| Г2 | Вид → главный процесс | preload и мост | плагин определяется по origin фрейма; чужая страница во фрейме моста не получает |
| Г3 | Плагин → плагин | ядро | граф контрактов, схема аргументов команд, `guard` у членов контракта |
| Г4 | Плагин → ОС | шлюз `ctx.os` | права из манифеста, `realpath`, защищённые пути, лимиты |
| Г5 | Плагин → сеть | шлюз `net` | список хостов, без переадресации, предел тела |
| Г6 | Программа плагина → ОС | **никто** | честная граница: у программы права пользователя |
| Г7 | Внешний текст → агент | **никто в ядре** | права агента задаёт сам агент (режим разрешений Claude Code) |
| Г8 | Браузер → локальный сервер | ядро в `serve` | 421 на чужой `Host`, 403 на `Origin` |
| Г9 | Файл воркспейса → ядро | ядро | схема; значения файла считаются решением человека |

## 5. Угрозы

Статусы:

- **закрыто** - защита в `master` под тестом;
- **частично** - защита есть, но названная часть угрозы остаётся;
- **открыто** - защиты нет;
- **открыто до этапа 2** - защиты нет, закрывается этапом 2;
- **принято** - честная граница, описанная человеку;
- **принято, граница не описана** - владелец принял границу, человеку она ещё не описана;
- **вне этапа 1** - угроза относится к этапу 2.

### 5.4. Агент

Агент работает с правами пользователя, а текст в его контекст попадает из многих мест. Поэтому всё, что пишет агенту, по силе равно праву `pty` на агента.

| ID | Угроза | Кто | Актив | Защита | Статус | Задача |
|---|---|---|---|---|---|---|
| У-27 | Плагин без прав вписывает текст в системный промпт агента (`cyborg.session-prompt`) и управляет агентом | Н2 | А4 | поставщики `cyborg.*` - только встроенные (#71); само правило «текст агенту равен праву на агента» нигде не записано | частично | K-23 #83 |
| У-28 | Описание или ответ инструмента агента (`cyborg.agent-tool`) несёт инструкции (tool poisoning); описание попадает в контекст агента ещё до вызова | Н2, Н3 | А4 | как У-27; инструмент стороннего плагина в сервер `cyborg` не попадает, а его собственный сервер MCP агенту не показывается вовсе, пока не объявлен в манифесте (FR-CH-3017; решение владельца, 2026-11-08; K-23) | частично | K-23 #83 |
| У-29 | Prompt injection через внешние данные: файл репозитория, MR, тикет, вывод команды | Н3 | А4, А2, А5 | ядром не закрывается; права агента задаёт сам агент | принято, граница не описана | K-23 #83 |
| У-30 | Cyborg разрешает агенту больше, чем человек в своём Claude Code: агент под инъекцией зовёт инструмент Cyborg и выводит данные наружу без вопроса, хотя тот же вывод через `curl` или `WebFetch` Claude Code показал бы вопросом | Н3 | А1, А2, А5 | токен MCP на сессию; настройки claude, которые пишет `agent-claude-code`, заранее разрешают все инструменты сервера (`allow: ["mcp__cyborg"]`); сервер отдаёт только инструменты встроенных плагинов, они проверены в поставке, сторонний поставщик `cyborg.agent-tool` не загрузится (K-15). ## 6. Допущения и честные границы

- **Этап 1 защищает от ошибки, а не от умысла.** Шлюз делает права видимыми и ловит ошибки встроенных плагинов (Н1). От стороннего плагина (Н2) он не защищает, пока главная часть - обычный Node (У-04). Поэтому на этапе 1 сторонний код не грузится (У-38), а гарантию даёт этап 2.
- **`process` и `pty` - права пользователя.** Плагин с этими правами ограничен только тем, какую программу он запускает (У-10). Узкий класс, где изоляция даёт полную гарантию, - интеграции по HTTP API.
- **Агент - самый широкий плагин.** У него права пользователя и контекст из внешнего мира. Ядро не решает, что агенту можно: это делает режим разрешений самого агента. Ядро отвечает только за то, чтобы плагин без прав не получил агента в посредники (У-15, У-27, У-28).
- **Замок закрывает экран, а не данные** (У-26).
- **Файл воркспейса - решение человека** (У-40). Это допущение верно, пока воркспейс создан самим человеком.

## 8. Как вести документ

- Новая возможность ядра с правом, каналом или данными извне добавляет строку угрозы или ссылается на существующую.
- PR, закрывающий угрозу, меняет её статус здесь. Задача безопасности ссылается на ID угрозы.
- Задача, которая закрывает угрозу хотя бы частично, несёт метку `type: security`, даже если её основной тип другой.
- Пересмотр - при переходе к этапу 2 и перед заморозкой API (K-21 #62).
