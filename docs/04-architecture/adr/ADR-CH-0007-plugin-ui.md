# ADR-CH-0007 Интерфейс плагинов: ядро знает роды областей, вид плагина живёт в своём `<iframe>`, сочетания объявлены в манифесте и перехватываются ядром

> Решение составителя по запросу владельца, не согласовано; ждёт приёмки. Редакция 2026-11-05 записывает решение, принятое в [SAD](../design/sad.md#38-изоляция-рендера) и реализованное в `core/` и playground; решение первой редакции (2026-11-02) о слотах на общем DOM - в рассмотренных вариантах. Редакция 2026-11-06 переносит из бывшего ADR-CH-0013 группы рендера и закрытую CSP по замерам [ресёрча-2](../../research/sad2-validation.md#3-замеры-окно-iframe-и-мост). Основано на [ресёрче](../../research/README.md): [bb](../../research/bb.md), [DeepSeek Harness](../../research/deepseek-harness.md), [сравнение](../../research/comparison.md) и [спайке UI](../../05-verification/spike-iframe-ui.md).

## Decision Drivers

- Плагин рисует только у себя; каркас окна появляется до кода плагинов ([SAD, 3.8](../design/sad.md#38-изоляция-рендера)).
- Системное сочетание срабатывает одинаково из любого места окна, включая терминал; конфликт сочетаний виден при загрузке ([SAD, 3.9](../design/sad.md#39-системные-клавиши-и-события)). В Cyborg список занятых сочетаний вёлся вручную и не знал акселераторов меню (D-27 фичи 12 корпуса Cyborg).
- Версия UI-фреймворка не должна становиться частью API плагинов.
- Образцы: слоты, где компонент не получает контекст (dsh), граница ошибок на слот и эксклюзивные слоты с запасным вариантом (bb) ([bb 5.5](../../research/bb.md), [dsh 7](../../research/deepseek-harness.md)).

## Context

[Спайк UI](../../05-verification/spike-iframe-ui.md) (Linux): свой origin - свой процесс рендера, +13 МБ PSS на фрейм; граница фрейма не добавляет задержки (p50 0,12 мс); `before-input-event` гасит сочетание при фокусе во фрейме; HTML5-перетаскивание между фреймами разных процессов Chromium блокирует.

## Decision

1. **Ядро знает только роды областей.** Боковая колонка с заголовком, основная область с группой документов, панель инструментов основной области, всплывающий слой, слой замка (`overlay`, только с правом `ui.lock`). Плагин объявляет в манифесте виды и типы документов с родом области и `order`. Предустановленного лаяута нет: расстановка - манифесты плюс изменения пользователя в `state`; закрепить её для команды можно сохранением в `config` воркспейса. Роды областей в манифесте: `sidebar`, `main`, `toolbar`, `popup` (`ui.views.<имя>.area`, `documents.<тип>.area`), `order` - число; ядро отдаёт упорядоченный снимок `Kernel.layout` (по `order`, при равенстве по id плагина), приложение рисует области по нему и плагины по именам не выбирает. Проверка: `core/test/semver-manifest.test.ts` («вид: неизвестная область и нечисловой order…»), `core/test/loader.test.ts` («раскладка: …»), `playground/test/plugins-model.test.ts` («в renderer нет строковых имён плагинов…»).
2. **Вид плагина - свой `<iframe>` с origin группы рендера `cyborg-plugin://<группа>/` и CSP.** Свой DOM, CSS и `window` не дают дотянуться до UI другой группы. Группу рекомендует автор в манифесте (`ui.group`), владелец переопределяет в `plugins.uiGroups` файла пользователя (поле воркспейса не действует, [ADR-CH-0015](ADR-CH-0015-workspace-trust.md), п. K-04); плагин без группы получает группу со своим id; сторонний плагин всегда один в своей группе, из любого слоя (общую группу ему даст этап 2 вместе с окном согласия), и его origin - `cyborg-plugin://solo_<id>`, пространство имён вне групп поставки, чтобы веб-хранилище не переходило между ними от загрузки к загрузке: просьба о группе с другими не исполняется, ядро пишет `group-isolated`, а «Плагины Cyborg» предупреждают в строке плагина. Внутри группы изоляции DOM нет: правило «не трогать чужой DOM» проверяется статически. CSP по умолчанию - `default-src 'none'; script-src 'self'; style-src 'self' 'unsafe-inline'; connect-src 'self'; img-src 'self' data:`: встроенный скрипт не выполняется, интернет и другие origin закрыты, `parent.document` и мост оболочки недоступны ([ресёрч-2](../../research/sad2-validation.md)). Модуль вида задан в манифесте (`ui.views`) путём внутри каталога плагина. Мост - preload в подфреймах: адрес кадра - `cyborg-plugin://<группа>/<плагин>/`, главный процесс узнаёт группу по origin фрейма-отправителя, плагин - по первому сегменту пути его адреса, и признаёт плагин, только если тот состоит в группе кадра; слова вида в счёт не идут. Плагины одной группы для моста подменяют друг друга, поэтому граница доверия моста - группа. Проверка: `core/test/ui-shell.test.ts` («манифест ui.views: путь модуля только вниз от каталога плагина…»), `core/test/loader.test.ts` («группы рендера…»), `electron/test/view-files.test.ts` («вид: origin называет группу…», «вид: адрес обслуживается, только если плагин состоит в группе…»), `electron/test/view-frames.test.ts`, дымовой тест («группы рендера…»), `electron/test/plugins.test.ts` («виды: … команда и контракт из вида - только свои»).
3. **Вид монтируется функцией: `mount(root, ctx)` отдаёт `Disposable` или ничего.** `ctx` вида (`UiContext`) - команды, контракты, клавиши, слой диалогов, тема, свой `state`, документы и терминал по билету; `ctx.os` в виде нет. Скрытая область не отмонтируется: вид получает `onVisibilityChange`; `dispose` - только при выключении плагина или закрытии документа. Проверка: `core/test/ui-shell.test.ts` («mountModule: модуль без mount отклонён…», «connectView: тема на :root до mount и при смене, видимость без повторов…», «connectView: команда и контракт идут мостом…»).
4. **Общего UI-фреймворка нет; ядро даёт токены темы и элементы ядра.** Токены `--cy-*` (цвета, шрифты, отступы, радиусы) приходят в каждый фрейм до `mount` и при смене темы. Элементы ядра - веб-компоненты `cy-button`, `cy-field`, `cy-list`, `cy-tree`, `cy-tabs`, `cy-empty`, `cy-spinner`; их определяет оболочка вида до `mount`, так что имя `cy-*` плагину не занять. Набор версионируется вместе с API плагинов ([ADR-CH-0002](ADR-CH-0002-manifest-and-compatibility.md), п. 3). Проверка: `core/test/elements.test.ts`, `core/test/ui-shell.test.ts` (тема), `electron/test/view-files.test.ts` («тема: одинаковый набор токенов у светлой и тёмной схемы…»).
5. **Чужой UI в свой не встраивается - «задача, а не виджет».** Плагин не монтирует вид другого плагина: нужен чужой UI - вызывает команду или член контракта владельца, и владелец сам показывает свой документ или диалог и возвращает данные. Проверка: оболочка фрейма грузит только модуль из манифеста плагина своего origin - `electron/test/view-files.test.ts`.
6. **За прямоугольник фрейма - только через слой ядра.** Диалоги и меню - `ctx.dialogs.show` (`ask`, `menu`), ядро разбирает описание и показывает по одному поверх всех фреймов. Перетаскивание между видами ведёт ядро. Порядок фокуса между областями - команды окна `cyborg.window.focus-next` (`F6`) и `cyborg.window.focus-prev` (`Shift+F6`) у ядра. Проверка: `core/test/window.test.ts` («parseDialog…», «слой окна: диалоги по одному и по порядку…», «команды окна: F6 и Shift+F6 у ядра…», «keepFocus…»), `electron/test/view-drag.test.ts`.
7. **Сбой вида виден на его месте.** Пока хост перезапускается, вид стоит под плашкой ядра «Перезапуск» и не принимает ввод (`inert`). Плагин выключен или не поднялся - ядро ставит на место вида заглушку с причиной из журнала, «Включить снова» и «Журнал». Проверка: дымовой тест окна (`npm run smoke`); `electron/test/plugins.test.ts` («виды: адрес у плагина с ui в манифесте и у снятого…»).
8. **Сочетания объявляются в манифесте и перехватываются ядром до страницы.** Привязка - к своей команде без обязательных аргументов. Ядро ловит объявленные сочетания в главном процессе (`before-input-event`), поэтому они срабатывают одинаково из каркаса и из любого `<iframe>`; остальные клавиши идут в фокус. Конфликт виден при загрузке, в журнале и в «Плагины Cyborg»: сочетание достаётся встроенному плагину, между равными - первому по id; выгруженный победитель отдаёт сочетание окну, а не проигравшему. Человек переназначает сочетание в `plugins.keybindings`. Меню окна - вид ядра: плагин вкладывает пункты объявлением `contributes.menus` (меню из закрытого списка `workspace`, `view`, `tools`, `window`; `enabled` и `checked` - булев член контракта; пункт неработающего плагина остаётся недоступным), акселераторы пунктов идут в тот же реестр с приоритетом меню над манифестом ([SAD, 3.9](../design/sad.md#вклады-в-меню-окна)). Сочетания, которые задаёт человек во время работы (кнопки-команды), плагин регистрирует через `ctx.keys.register({ key, command, args?, when? })` в тот же реестр: человек (`plugins.keybindings`, он может забрать или освободить и сочетание окна или меню) старше окна и меню, они старше манифеста, манифест старше динамического; `when` - закрытый список `repeat`, `dialog`, `visible`, `input`, регистрации снимаются с плагином ([SAD, 3.9](../design/sad.md#39-системные-клавиши-и-события)). Проверка: `core/test/lifecycle.test.ts` («манифест: сочетание - на свою команду без обязательных аргументов», «конфликт сочетаний: встроенный побеждает сторонний…», «plugins.keybindings: выбор пользователя перекрывает манифесты…»), `electron/test/plugins.test.ts` («служба окна: сочетания с конфликтом, перехват нажатия…»), `core/test/keys-registry.test.ts` (динамические), дымовой тест.
9. **Документы восстанавливаются через ядро.** Тип документа объявлен в манифесте; `restorable` - документ переживает перезапуск окна. Данные документа владелец отдаёт сам, когда они меняются (`ctx.documents.save`); после перезапуска получает их из `ctx.documents.list()`; поставщика нет - вкладка недоступна, а не пропадает. Проверка: `core/test/documents.test.ts`.
10. **Замок окна: механизм в ядре, политика в плагине.** `ctx.os.ui.lock` - только с правом `ui.lock` и экраном `ui.overlay`. Под замком чужие фреймы скрыты и `inert`, работают только сочетания владельца, выключить владельца нельзя; снять замок может только поставивший. Проверка: `core/test/window.test.ts` («замок окна: только с правом…», «манифест: ui.lock только с ui.overlay…», «lock.onStart…»).
11. **Код вида - браузерный бандл без Node.** npm-пакеты в виде разрешены, встроенные модули Node и `electron` - нет. Проверка: `core/test/plugin-imports.test.ts` (каталог `ui/` плагина).

## Consequences

- Positive: плагин не трогает чужой DOM физически, а не по правилу; Monaco и xterm работают во фрейме как на обычной странице; сочетания одинаковы во всём окне, конфликт «сочетание занято» закрыт ядром; плагин пишет UI на чём угодно.
- Negative: процесс рендера на каждую группу (+13 МБ PSS на процесс); внутри группы изоляции DOM нет, и плагины одной группы для моста неразличимы; меню, диалоги и перетаскивание за пределы фрейма - только средствами ядра; составной экран из карточек разных плагинов не собрать.
- Risks: «задача, а не виджет» не покроет составные экраны - встраиваемые виды станут отдельным решением, когда появится такой случай; набор элементов ядра становится API и держится минимальным ([SAD, раздел 9](../design/sad.md#9-риски)).

## Alternatives Considered

- **Слоты на общем DOM окна (`strip.action`, `sidebar.tab`, `session.view`, `panel`, `terminal.footer`), граница ошибок на слот, эксклюзивные слоты с запасной реализацией ядра; стили с префиксом `.p-<id>-` и запрет `innerHTML` тестом (первая редакция).** Why rejected: слоты повторяют разрез одного приложения и делают его API ядра; на общем DOM изоляция держится правилами, которые надо проверять, а `<iframe>` даёт её даром ([SAD, раздел 7](../design/sad.md#7-расхождения-с-первой-редакцией-пакета)). Заглушку на месте упавшего вида ядро ставит по-прежнему (пункт 7).
- **Изолированное окно только для сторонних плагинов, встроенные - на общем DOM (первая редакция).** Why rejected: два способа писать UI; переход стороннего плагина во встроенный и обратно требовал бы переписывания. `<iframe>` - и для встроенных; общий origin встроенных, который [спайк UI](../../05-verification/spike-iframe-ui.md#запасной-путь-общий-origin-для-встроенных) держал запасным путём, стал частным случаем групп рендера (пункт 2).
- **Origin на плагин для всех (редакция 2026-11-05).** Cons: свой процесс рендера на каждый плагин (+13 МБ PSS на Linux, около 17 против 3 МБ на macOS); десять кадров с xterm - 335 МБ против 106 МБ на общем origin. Why rejected: близким по смыслу плагинам граница не нужна; владелец разводит их по группам.
- **Origin по классу: `builtin` для всех встроенных, свой у стороннего.** Cons: класс не отражает смысл, владелец не может развести встроенные. Why rejected: заменён группами.
- **Мост без preload (`MessageChannelMain`, порт через страницу оболочки, круг 45 мкс).** Cons: порт, переданный через документ окна, не говорит главному процессу, чей это кадр. Why rejected: preload с проверкой origin отправителя говорит.
- **`sandbox` без `allow-same-origin` для всех.** Pros: изоляция DOM по цене общего origin. Cons: нет хранилищ origin, с Monaco не проверено (открытый вопрос 11 [SAD](../design/sad.md#8-открытые-вопросы)). Why rejected пока.
- **React или другой общий фреймворк.** Cons: его версия стала бы частью API плагинов, мажорное обновление сломало бы всех сторонних; каждый фрейм всё равно грузит свою копию. Why rejected.
- **Web Components отклонить (первая редакция).** Пересмотрено: элементы ядра - веб-компоненты с Shadow DOM на токенах темы; переменные `--cy-*` проходят внутрь, и элемент работает из любого фреймворка (пункт 4).
- **Сочетания в каждом плагине без общей таблицы.** Why rejected: так возник D-27; конфликт находится только нажатием.

## Расхождения с текущим кодом

- Пункт 1: расстановка видов, изменённая человеком, в `state` не сохраняется (род области и `order` из манифеста - сделаны, K-03).
- Пункт 2: CSP вида - `default-src 'self'` (`VIEW_CSP` в `electron/src/view-files.ts`), а не `'none'` с явными источниками.
- Пункт 4: CSP вида разрешает инлайн-стили всем видам, а нужны они только видам с xterm и Monaco ([дорожная карта, раздел 13](../../06-plans/roadmap.md#13-стенд-playground)).
