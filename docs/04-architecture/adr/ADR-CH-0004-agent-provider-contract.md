# ADR-CH-0004 Агент - обычный плагин, поставщик контракта `cyborg.agent`: описывает запуск и переводит следы в события, pty запускает потребитель

> Решение составителя по запросу владельца, не согласовано; ждёт приёмки. Редакция 2026-11-05 записывает решение, принятое в [SAD](../design/sad.md#5-пример-базовая-часть) и реализованное в `contracts/agent.ts` и playground; решение первой редакции (2026-11-02) - в рассмотренных вариантах. Номера пунктов сохранены: на п. 6 ссылается `contracts/index.ts`. Основано на [ресёрче](../../research/README.md): [bb](../../research/bb.md), [DeepSeek Harness](../../research/deepseek-harness.md), [сравнение](../../research/comparison.md).

## Decision Drivers

- Продуктовая идея Cyborg: настоящий интерактивный `claude` в pty, человек работает в терминале; сессия не подменяется (ADR-0003 корпуса Cyborg).
- Другой агент подключается плагином, без правок ядра и `sessions`.
- В ядре нет предметной области ([ADR-CH-0001](ADR-CH-0001-core-and-plugins.md)): ядро не знает, что pty - агент.
- Образцы подключают агентов структурным протоколом и строят таймлайн сами; интерактивный CLI в pty не встраивает никто ([comparison](../../research/comparison.md)).

## Context

bb: провайдер - плагин; мост по JSON-RPC (stdio) с рукопожатием, дельтами, типизированными подсказками восстановления; Claude Code подключён через Agent SDK. dsh: `SubagentProvider.start()` даёт один терминальный результат; Claude Code - неинтерактивный субагент через SDK ([bb 5.6](../../research/bb.md), [dsh 8](../../research/deepseek-harness.md)).

## Decision

1. **Агент - обычный плагин, поставщик контракта `cyborg.agent` (кратность many).** Члены: `facts`, `launch`, `watch`, `ended`, `history`; типы - `contracts/agent.ts`. Потребитель - плагин `sessions`; особого места в ядре у агента нет. Проверка: `playground/test/agents.test.ts` («cyborg.agent, общий набор: факты, запуск через потребителя по его праву pty, причина выхода, история») - один набор для каждого поставщика.
2. **Поставщик описывает запуск, процесс запускает потребитель.** `launch` возвращает `LaunchSpec` (программа, аргументы, cwd, окружение) - готовый вход `ctx.os.pty.spawn`. Потребитель запускает pty по своему праву `pty` и передаёт `describedBy`; ядро сверяет описание и с правом `pty` потребителя, и с правом `launch` поставщика - права пересекаются. Поставщик процессов не создаёт, право `launch` члена в `ctx.os` не даёт ([SAD, 3.6](../design/sad.md#36-ресурсы-дольше-плагина-pty)). Проверка: `core/test/pty.test.ts` («pty.spawn с describedBy: описание поставщика проходит, только если подходит и под его launch (confused deputy)»).
3. **Факты, а не обещания.** `facts()` сообщает, найдена ли программа там, где её запустит `launch`, версию и `capabilities` (`resume`, `history`, `events`). Потребитель не зовёт того, чего нет в `capabilities`. Проверка: `playground/test/agents.test.ts` (общий набор).
4. **События нормализуются поставщиком.** `watch(sessionId, listener)` даёт `cwd`, `session` (id сессии агента для `resume`), `activity`, `prompt`, `turnEnd`, `waiting`. У Claude Code источник - хуки и файл событий сессии в `plugin-data`; агент без следов остаётся с запуском и выводом, подписка молчит. Проверка: `playground/test/agents.test.ts` («agent-claude-code: хуки в события контракта…», «agent-claude-code: «ждёт» после Stop…»).
5. **Восстановление типизировано.** `ended(sessionId, exit)` убирает файлы поставщика и называет причину по коду выхода (`notFound`, `authRequired`, `rateLimited`, `resumeFailed`), без разбора текста ошибок. Продолжение сессии - `launch({ resumeId })` при `capabilities.resume`. Проверка: `playground/test/agents.test.ts` (общий набор - причина выхода; «sessions: восстановленная сессия claude продолжается через resume поставщика»).
6. **Вклад в системный промпт - контракт `cyborg.session-prompt` (кратность many).** Потребитель собирает фрагменты всех поставщиков по порядку id и передаёт их в `launch({ promptFragments })`. Изоляция сессий и кнопки следующих шагов - отдельные плагины-поставщики (`session-isolation`, `next-actions`). Фрагмент читает агент, поэтому поставщик действует с правами агента: сторонний плагин такого контракта не отдаёт ([SAD 3.7](../design/sad.md#агент-в-модели-доверия)). Проверка: `playground/test/agents.test.ts` (общий набор: фрагмент `session-isolation` доходит до аргументов `claude`).
7. **Первый поставщик `agent-claude-code` запускает `claude` так же, как сегодняшний Cyborg** - через оболочку входа и `--settings` с хуками. **Второй поставщик обязателен до стабилизации контракта**, чтобы контракт не выточился под один агент; сегодня это `agent-shell` - агент без следов. Проверка: `playground/test/agents.test.ts` («agent-claude-code: запуск как в Cyborg - оболочка входа, --settings с хуками, порядок аргументов»; общий набор проходит оба поставщика).
8. **Структурные агенты (SDK, ACP) - отдельный контракт, после v1.** Claude Code через SDK основным путём не используется: одноразовый неинтерактивный режим противоречит живым сессиям. Проверка: не требуется до появления структурного агента.
9. **Инструменты агенту - контракт `cyborg.agent-tool` (кратность many), протокол MCP держит потребитель.** `sessions` по праву `serve` поднимает сервер MCP на `127.0.0.1`, токен выдаётся на сессию и уходит поставщику агента в `launch({ tools })`; поставщик передаёт его агенту через окружение, а не argv. Агент зовёт инструменты сервера без вопроса (`allow: ["mcp__cyborg"]` в `--settings` `agent-claude-code`), потому что сервер отдаёт только инструменты плагинов поставки; сторонний `cyborg.agent-tool` отклонён графом (K-15), а сервер MCP стороннего плагина в `allow` не входит ([SAD 3.7](../design/sad.md#агент-в-модели-доверия)). Проверка: `playground/test/agents.test.ts` («sessions + next-actions…», «sessions: инструменты поставщиков - по id плагина…»), `core/test/serve.test.ts`.

## Consequences

- Positive: Claude Code не особый случай ни в ядре, ни в `sessions`; новый агент - плагин; история, продолжение, изоляция и кнопки - возможности поставщиков; сторонний поставщик агента не получает права потребителя.
- Negative: контракт описывает меньше, чем у образцов (нет таймлайна, нет дельт): таймлайн строит сам агент в терминале.
- Risks: события агентов без хуков окажутся эвристикой; смена формата `resume` у Claude Code ломает восстановление - сбой показывается вкладкой с причиной, а не теряет её ([SAD, раздел 9](../design/sad.md#9-риски)).

## Alternatives Considered

- **Точка расширения «провайдер агента» в ядре, `AgentProvider` с `handshake`, `launch`, `attach`, `history`, `recover`; ядро само исполняет `LaunchSpec` (первая редакция).** Why rejected: агент - предметная область, ей не место в ядре; ядро держит только pty как ресурс дольше плагина, а запуск по описанию делает потребитель по своему праву ([SAD, раздел 7](../design/sad.md#7-расхождения-с-первой-редакцией-пакета)). `attach` стал общим членом `ctx.os.pty`, `recover` - членом `ended`.
- **Waterfall-событие `session.prompt` для вклада в промпт (первая редакция, п. 6).** Why rejected: шины событий в ядре нет ([ADR-CH-0005](ADR-CH-0005-plugin-interaction.md)), а контракт кратности many даёт тот же сбор без нового механизма.
- **Только Agent SDK.** Pros: структурные события, как у образцов. Cons: нативный интерактивный терминал пропадает; противоречит сути продукта. Why rejected.
- **ACP как основа.** Pros: стандарт, много агентов. Cons: интерактивный pty тоже не получить; Claude Code в ACP - через мост. Why rejected для v1; остаётся отдельным контрактом позже (пункт 8).
