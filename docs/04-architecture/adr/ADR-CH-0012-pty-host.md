# ADR-CH-0012 pty держит ядро в отдельном pty-хосте; вывод к виду идёт мимо хоста плагина

> Решение составителя по запросу владельца, не согласовано; ждёт приёмки. Записывает решение [SAD, 3.6](../design/sad.md#36-ресурсы-дольше-плагина-pty), проверенное [ресёрчем-2](../../research/sad2-validation.md). Редакция 2026-11-06: хосты плагинов и сторож, которые первая редакция этого ADR тоже описывала, записаны в [ADR-CH-0003](ADR-CH-0003-trust-and-isolation.md), пп. 2-4; здесь остался только pty.

## Decision Drivers

- Процесс агента должен пережить перезапуск плагина, хоста и окна.
- Зависание или падение нативного `node-pty` не должно замораживать окно.
- Ядро не знает, что в pty агент: для него это программа из права плагина ([ADR-CH-0004](ADR-CH-0004-agent-provider-contract.md)).

## Context

Ресурс ОС, который переживает владельца, по критерию компактности держит ядро: плагин не гарантирует, что процесс переживёт его перезапуск ([ADR-CH-0001](ADR-CH-0001-core-and-plugins.md), п. 2). В VS Code терминал живёт в отдельном `ptyHost` по той же причине, что и здесь: нативный модуль в главном процессе замораживает окно ([ресёрч-2, 4.1](../../research/sad2-validation.md#41-vs-code)). `node-pty` в `utilityProcess` загружается (проверено).

## Decision

1. **Плагин решает, что запустить, ядро держит процесс.** `ctx.os.pty.spawn` по праву `pty`; `persist` - pty переживает падение хоста и ждёт `attach` вернувшегося плагина; `list` и `attach` видят только pty своего плагина, чужой - `NotFound`. Проверка: `core/test/pty.test.ts` («pty.spawn: программа, окружение и cwd по праву…», «pty: чужие не видны и не трогаются…», «падение хоста: pty с persist живёт и копит вывод…»).
2. **Хвост вывода копит ядро, и при живом владельце тоже.** Буфер кольцевой, размер - настройка ядра. После `attach` ядро шлёт `resize`, и TUI перерисовывает себя по `SIGWINCH`; сырой хвост или снимок экрана (headless-xterm) - решает спайк с настоящим `claude` (открытый вопрос 14 [SAD](../design/sad.md#8-открытые-вопросы)). Проверка: `core/test/pty.test.ts` («pty завершился без владельца: list показывает выход, attach отдаёт хвост…»).
3. **Выключение плагина с живыми pty спрашивает человека.** Оставленные pty ждут `attach`, как `persist` после падения хоста; удаление плагина, закрытие воркспейса и выход из приложения процессы завершают. Проверка: `core/test/pty.test.ts` («выключение: preview называет живые pty; keepPty…»).
4. **Держит pty не главный процесс, а pty-хост** - отдельный `utilityProcess` ядра, не плагин и не общий хост плагинов. Сторож ([ADR-CH-0003](ADR-CH-0003-trust-and-isolation.md), п. 4) следит и за ним; перезапуск pty-хоста теряет процессы pty, плагины получают это как завершение. Проверка: нет - pty-хоста в коде нет, см. расхождения.
5. **Вывод к виду идёт мимо хоста плагина.** Главная часть выдаёт своему виду одноразовый билет `pty.share()`, вид открывает его через `ctx.terminal.open`; поток идёт из pty-хоста во фрейм по `MessagePort` (около 1,9 ГБ/с, круг 45 мкс), главный процесс только раздаёт концы порта. Хост плагина может зависнуть - терминал работает. Ввод и размер принимаются только от открывшего фрейма. Проверка: `core/test/pty.test.ts` («share: билет одноразовый и только для своего UI…», «share: просроченный билет не открывается»), `playground/src/main/view-terminals.test.ts` («терминалы вида: вывод - в открывший фрейм…»), дымовой тест останавливает хост `echo` через `SIGSTOP` и печатает в его вид.
6. **Осиротевший pty завершается по льготному времени** - плагин не вернулся после перезапуска хоста; значение - настройка ядра. Проверка: нет - не реализовано.

## Consequences

- Positive: процессы агентов переживают перезапуск хоста, плагина и окна; зависание `node-pty` не трогает окно; путь вывода к виду не дороже пути через главный процесс.
- Negative: ещё один вид процесса ядра и протокол к нему; буфер вывода на каждый pty.
- Risks: перерисовка TUI `claude` после `attach` не проверена; у сторожа нет прецедента для pty-хоста.

## Alternatives Considered

- **pty в главном процессе.** Pros: проще, без протокола. Cons: зависание нативного модуля замораживает окно; падение главного процесса теряет все сессии. Why rejected: прямой путь из pty-хоста к виду не медленнее.
- **pty в плагине `sessions` или агента.** Cons: перезапуск владельца убивает процесс. Why rejected: не проходит критерий компактности ([ADR-CH-0001](ADR-CH-0001-core-and-plugins.md), п. 2).
- **Вывод через хост плагина.** Cons: зависший хост останавливает терминал. Why rejected: билет и порт дают тот же контроль доступа без хоста на пути.

## Расхождения с текущим кодом

- Пункт 4: pty-хоста нет - playground держит `node-pty` и таблицу pty в главном процессе (`PtyBackend` в `core/src/pty.ts` даёт приложение).
- Пункт 5: вывод к зрителям идёт через главный процесс (`playground/src/main/view-terminals.ts`), а не по `MessagePort` из pty-хоста; хост плагина на пути всё равно не стоит.
- Пункт 6: льготного времени нет. `pty` на Windows не проверялся.
