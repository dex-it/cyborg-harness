# Плагин падает, приложение продолжает работать

- **Актор:** человек в окне; автор плагина, разбирающий сбой.
- **Цель:** сбой одного плагина не мешает остальным, причина видна.
- **Требования:** BR-CH-006 ([BRD](../../01-product/brd.md)). Устройство - SAD [3.2](../../04-architecture/design/sad.md#32-загрузка-плагинов), [3.5](../../04-architecture/design/sad.md#35-изоляция-сбоев-хосты-и-сторож), [3.6](../../04-architecture/design/sad.md#36-ресурсы-дольше-плагина-pty).

## Основной ход

1. Плагин бросает исключение при активации (в playground так делает `flaky` при первом запуске в хосте).
2. Исключение ловит хост: отказывает только этот плагин, в журнале - запись `failed` с хостом и ошибкой. Соседи по хосту и другие хосты работают.
3. Потребители через `requires` не запускаются с записью «поставщик не активен»; потребители через `optional` работают без него.
4. Ядро снимает виды плагина и ставит на их место заглушку: имя, причина из журнала, «Включить снова» и «Журнал».
5. Человек открывает «Плагины Cyborg» и видит состояние плагина и причину словами.
6. Человек нажимает «Включить снова»: ядро активирует плагин, а следом - потребителей, которые не запустились из-за него.

## Расширения

- **1а. Плагин завис.** Сторож пингует хост раз в 1 с; нет ответа 5 с - хост перезапускается. Пока он перезапускается, виды его плагинов стоят под плашкой «Перезапуск» и не принимают ввод. Плагины хоста активируются заново; потребители из других хостов узнают о пропаже и возврате поставщика из `ctx.contracts.onChange`. pty, запущенные с `persist`, живы и ждут `attach`, терминал сессии продолжает работать: вывод идёт из ядра во фрейм мимо хоста. Вернувшийся владелец находит свои pty через `ctx.os.pty.list()` и `attach`, получает снимок экрана терминала: содержимое, курсор и режимы, которые программа включила один раз, - альтернативный экран, bracketed paste, мышь. Сырого хвоста мало: в сессии длиннее него эти режимы выпадают, и `claude` по смене размера их не повторяет ([спайк](../../05-verification/spike-pty-restore.md)). Сейчас ядро отдаёт хвост и шагает размером; снимок приходит с pty-хостом ([ADR-CH-0012](../../04-architecture/adr/ADR-CH-0012-pty-host.md), п. 2).
- **1а1. Тот же плагин зависает три раза подряд.** Ядро выключает его с записью, кто брал его контракты, и ставит заглушку, как в шаге 4.
- **1а2. Промис плагина отклонён без обработчика.** Хост не падает: в журнале `unhandled-rejection` на плагин, с чьего входа началась цепочка, и страйк ему; соседи по хосту работают без перезапуска. Третий сбой подряд выключает только этот плагин, как в 1а1.
- **1б. Хост упал.** Тот же путь, что при зависании: виновник - плагин, чей код завершил процесс (`process.exit`, необработанное исключение в его цепочке); хост виновника не назвал, например процесс убит сигналом, - плагин первого вызова, принятого после последнего отвеченного пинга ([SAD 3.5](../../04-architecture/design/sad.md#35-изоляция-сбоев-хосты-и-сторож)). Хост, который падает без виновника три раза подряд, больше не перезапускается, его плагины выключаются.
- **1в. Упал pty-хост ядра.** Процессы pty теряются, владельцы получают это как завершение; сторож перезапускает pty-хост, окно и хосты плагинов не замирают ([ADR-CH-0012](../../04-architecture/adr/ADR-CH-0012-pty-host.md)). В playground pty-хоста ещё нет: `node-pty` работает в главном процессе.
- **4а. У плагина нет видов.** Ядро показывает одно уведомление с перечнем плагинов, которые брали его контракты.
- **6а. Сбой повторяется на каждом старте.** Безопасный режим выключает все плагины без исключений; окно без плагинов работает, в нём доступно управление плагинами. Человек запускает приложение с `--safe-mode` или выбирает в окне «Перезапустить в безопасном режиме»; окно показывает плашку режима и у каждого плагина причину «безопасный режим: код плагинов не запускается». Выход - пункт «Выйти из безопасного режима».

## Постусловия

Окно и процессы агентов живы; состояние и причина каждого плагина - в журнале и в «Плагины Cyborg».
