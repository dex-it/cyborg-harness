# Автор создаёт плагин вне поставки

- **Актор:** автор плагина вне поставки - человек со своим плагином или сторонний автор.
- **Цель:** от пустого каталога до работающего плагина в окне; всё нужное автор берёт из руководства, шаблона и тест-кита и не открывает код ядра.
- **Предусловия:** этап 1 - установки нет, плагин кладётся в каталог плагинов пользователя (`plugins/` в каталоге данных приложения; у playground на Linux - `~/.config/Cyborg Playground/plugins`). Этот каталог по умолчанию выключен ([SAD, 6.1](../../04-architecture/design/sad.md#61-этап-1-ядро-без-изоляции-доступа)): автор запускает приложение с флагом `--user-plugins`, иначе плагин не читается. Установка с окном согласия - этап 2, сценарий [установка стороннего плагина](../security-trust/UC-SECURITY-TRUST-3001-third-party-install-permissions.md).
- **Требования:** BR-CH-004, BR-CH-010 ([BRD](../../01-product/brd.md)). Нормы набора автора - [FR-CH-1013](../../03-requirements/07-author-kit/srs.md#fr-ch-1013-набор-автора-плагина), [NFR-CH-1008](../../03-requirements/07-author-kit/srs.md#nfr-ch-1008-набор-автора). Устройство - SAD [3.2](../../04-architecture/design/sad.md#32-загрузка-плагинов), [3.5](../../04-architecture/design/sad.md#35-изоляция-сбоев-хосты-и-сторож), [3.7](../../04-architecture/design/sad.md#37-безопасность-данных-и-контроль-плагинов), [3.8](../../04-architecture/design/sad.md#38-изоляция-рендера), [раздел 4](../../04-architecture/design/sad.md#4-взаимодействие-плагинов); план набора автора - [дорожная карта, раздел 10](../../06-plans/roadmap.md#10-опыт-автора-плагина).
- **Состояние (BR-CH-010):** есть руководство в `docs/guide/authors/`, пакет объявлений, примеры плагинов `cyborg-plugin check` и `build` (P-09, P-06), тест-кит и общий набор тестов `cyborg.agent` (P-08). Ещё нет: шаблона плагина (P-05), публикации пакетов (P-10), рабочих общих наборов для остальных контрактов, руководства под API 1.0 (P-04, после K-21). Шаг 1 (шаблон) описывает целевое поведение.

## Основной ход

1. Автор создаёт каталог плагина из шаблона: в нём `manifest.json`, главная часть и минимальный пример с видом, командой, контрактом и разделом `config`. Без шаблона автор создаёт каталог сам: `manifest.json` и главную часть `index.ts` (или `index.mjs`, `index.js`), которая экспортирует `PluginModule` с `activate(ctx)`.
2. В манифесте объявляет `id`, `version`, `engines.cyborg`, контракты (`provides`, `requires`, `optional`, `consumes`), команды со схемой аргументов, сочетания, права (`permissions`) и виды (`ui.views`).
3. Типы берёт из `@cyborg-harness/contracts`. Свой контракт называет по автору (`acme.*`) и дополняет карту `Contracts` своим пакетом объявлений ([контракты](../../../contracts/README.md#сторонние-контракты)).
4. Пишет главную часть только против `ctx`: к ОС - через `ctx.os` по объявленным правам. Вид - браузерный модуль с `mount(root, ctx)` в своём `<iframe>`, на токенах темы и элементах ядра `cy-*`.
5. Пишет тесты плагина на тест-ките: ядро поднимается в процессе теста без Electron, плагин проверяется общим набором тестов каждого контракта `cyborg.*`, который он даёт, и тестами своей логики.
6. Собирает плагин: сборка кладёт npm-зависимости внутрь бандла и проверяет его состав.
7. Запускает `checkPlugin` на каталоге плагина вне репозитория ядра; он проверяет манифест, `engines.cyborg`, правило импортов и выводит права словами.
8. Кладёт каталог в каталог плагинов пользователя, добавляет `id` в `plugins.enabled` и перезапускает приложение с флагом `--user-plugins`.
9. Ядро проверяет манифест, совместимость и граф контрактов до запуска кода, даёт плагину отдельный хост, пишет в журнал `third-party` и активирует его. Виды появляются в каркасе; строка плагина в «Плагины Cyborg» помечена «сторонний» с предупреждением, права словами - под ней; над списком плашка о флаге.

## Расширения

- **1а. Автору нужен ответ, которого нет в руководстве и справочниках: он есть только в коде ядра.** Это дефект руководства, а не повод читать код: мера BR-CH-010 - вопросов с ответом только в коде ядра ноль. Ответ дописывается в руководство; канал, по которому автор сообщает о таком вопросе, не определён (вопрос 1). Возврат к шагу, на котором автор остановился.
- **2а. Манифест с ошибками.** Плагин не загружается, журнал перечисляет ошибки. `checkPlugin` показывает их раньше, на шаге 7.
- **2б. Несовместимый `engines.cyborg`.** Плагин не загружается, код не выполнялся.
- **2в. Граф не сходится: нет поставщика из `requires`, два поставщика при кратности `one` или цикл.** Плагин не загружается, причина в журнале.
- **2г. Сочетание уже занято.** Оно достаётся встроенному плагину, между равными - первому по `id`; конфликт виден в журнале и в «Плагины Cyborg». Человек переназначает сочетание в `plugins.keybindings`.
- **4а. Вызов к ОС без права в манифесте.** `PermissionDenied` и запись `denied` в журнале.
- **4б. Плагин импортирует `node:*`, `electron` или чужой модуль.** В первом этапе хост этому не мешает. Статическую проверку импортов автор запускает сам: `cyborg-plugin check <каталог>` (`checkPlugin`, `core/src/plugin-check.ts`, шаг 7) называет файл и строку, а сборка (шаг 6) проверяет состав бандла; на плагинах репозитория то же правило гоняет `core/test/plugin-imports.test.ts`. Это дисциплина, а не защита: динамику вроде `globalThis.process` проверка не видит, пока нет `Compartment` второго этапа. Поэтому каталог пользователя выключен по умолчанию, а метка «сторонний» - предупреждение, а не защита.
- **5а. Общий набор тестов контракта падает: поставщик не выполняет контракт.** Автор правит главную часть до сборки. Возврат к шагу 4.
- **5б. Для контракта общего набора нет.** Он есть у `cyborg.agent` (`agentContractSuite` пакета `@cyborg-harness/testing`); для остальных - каркасы, рабочими станут с типами контрактов ([открытый вопрос 10 SAD](../../04-architecture/design/sad.md#8-открытые-вопросы)). Автор проверяет поставщика через своего потребителя на поднятом ядре. Возврат к шагу 6.
- **6а. Состав бандла нарушает правила: в нём `node:*`, `electron` или чужой плагин.** Сборка падает с перечнем нарушений, бандл не создаётся. Возврат к шагу 4. Плагин с npm-зависимостью без бандла не загрузится вовсе.
- **7а. `checkPlugin` находит нарушения.** Автор правит манифест (возврат к шагу 2) или код (возврат к шагу 4).
- **8а. Приложение не перезапускали.** Плагина не было в графе при запуске: в журнале запись «включатся после перезапуска».
- **8б. Приложение запущено без `--user-plugins`.** Каталог пользователя не читается: плагин не найден, `id` из `plugins.enabled` получает в журнале `not-found`, в лог идёт строка с названием флага. Плагин появится после перезапуска с флагом.
- **9а. Человек назвал плагин в группе хостов с другими.** Ядро всё равно даёт ему отдельный хост и пишет `host-isolated`; «Плагины Cyborg» показывают предупреждение.

## Постусловия

Плагин работает в своём хосте; его данные - в `plugin-data`, секреты - в хранилище ядра под его `id`. Автор прошёл путь от шаблона до окна по руководству, не открывая код ядра.

## Открытые вопросы

1. **Канал для вопросов автора (1а).** Мера BR-CH-010 считает вопросы, на которые ответ только в коде, но не говорит, куда автор их несёт и кто их считает. Предлагаю завести для них метку в трекере репозитория: счёт мере нужен, а метка ничего не стоит.
