# ST-2004 Слой окна: диалоги, замок, уведомления

Как человек, работающий в окне, я хочу, чтобы диалоги, замок и уведомления плагинов шли через ядро, чтобы вид не перекрыл чужое окно.

Нормы: FR-CH-2004, FR-CH-2006, FR-CH-2028, FR-CH-2031. Сценарии: UC-SECURITY-TRUST-3001. SRS - [srs.md](../srs.md).

## Критерии приёмки

1. [FR-CH-2006]
   - Дано плагин вызвал `ctx.dialogs.show` с `menu` из 13 пунктов и подписью в 81 символ
   - Когда ядро разбирает описание
   - Тогда описание ограничено (до 12 пунктов, подпись до 80 символов); показывается один диалог поверх всех фреймов, остальные ждут по порядку, в очереди плагина не больше 8
2. [FR-CH-2006]
   - Дано диалог `ask` открыт и плагин выгружен
   - Когда диалог ещё не закрыт
   - Тогда выгрузка закрывает диалоги плагина; Escape и клик мимо меню дают `undefined`; ответ - `id` пункта
3. [FR-CH-2006] [UC-SECURITY-TRUST-3001#6]
   - Дано плагин с правом `ui.lock` и экраном `ui.overlay` поставил замок
   - Когда человек работает в окне
   - Тогда чужие фреймы скрыты и `inert`, работают только сочетания владельцев замка, чужие диалоги ждут; владельца замка выключить нельзя; снять замок может только поставивший; `lock.onStart` закрывает окно до активации
4. [FR-CH-2028] [FR-CH-2004]
   - Дано уведомление плагина с командой
   - Когда человек кликает по уведомлению
   - Тогда уведомление закрыто, вызвана названная плагином команда своего плагина (`Kernel.runOwn`); заголовок окна плагин задаёт через ядро
5. [FR-CH-2031] [UC-SECURITY-TRUST-3001#3]
   - Дано манифест, объявляющий себя поставкой
   - Когда ядро определяет признак «из поставки»
   - Тогда признак берётся из каталога установки, манифест его не задаёт
