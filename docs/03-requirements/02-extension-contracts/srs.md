# SRS фичи 02 - контракты, команды и UI плагинов

## 1. SRS overview

Как плагины связываются и показывают себя: контракты в манифесте, события подпиской, команды и сочетания, виды и документы в `<iframe>`, слой окна, контракт агента и плагин `agent-claude-code`, доступность элементов ядра. Закрывает BR-CH-001, BR-CH-003. Сценарии - [второй агент](../../02-use-cases/extension-contracts/UC-EXTENSION-CONTRACTS-2002-second-agent.md), [автор встроенного плагина](../../02-use-cases/extension-contracts/UC-EXTENSION-CONTRACTS-2001-maintainer-adds-feature.md), расширение 4а сценария [сбой плагина](../../02-use-cases/plugin-host/UC-PLUGIN-HOST-1001-plugin-failure-isolated.md). Устройство - [SAD](../../04-architecture/design/sad.md), цели 3.4, 3.8, 3.9, разделы 4 и 5; типы - пакет `@cyborg-harness/contracts` (`contracts/`). Метод проверки называет тест ядра (`core/test`), тест playground (`playground/test`, `playground/src/main/*.test.ts`) или дымовой тест окна (`playground/scripts/smoke.mjs`, `npm run smoke`). Что не сделано - помечено «Ещё нет» или «Отложено», остаток - [дорожная карта](../../06-plans/roadmap.md). Раскладка норм по фичам - [03-requirements](../README.md).

## 2. Требования

### FR-CH-2001 Контракты в манифесте

- **Требование:** плагин отдаёт контракт (`provides`) и берёт чужой (`requires`, `optional`, `consumes`) только по объявлению в манифесте; необъявленное не отдаётся и не берётся. Кратность объявляет потребитель: `requires` и `optional` - ровно один поставщик, `consumes` - все поставщики списком. Тип контракта выводится из имени и мажорной версии по карте `Contracts` пакета `@cyborg-harness/contracts`; потребитель получает `Remote<T>` с асинхронными методами. Контракт из `requires`, который поставщик не отдал, - `Unavailable`; `optional` без поставщика - `undefined`. Метод контракта зовёт только связанный графом потребитель из своего хоста. Поставщик не знает потребителей, потребитель не знает поставщика.
- **traced from:** BR-CH-001.
- **источник:** [SAD, 3.4](../../04-architecture/design/sad.md#34-связь-между-плагинами), [SAD, раздел 4](../../04-architecture/design/sad.md#4-взаимодействие-плагинов); `core/src/registry.ts`.
- **verification:** испытание - `core/test/registry.test.ts`, `core/test/trust.test.ts` («invoke: метод контракта зовёт только связанный графом потребитель из своего хоста», «provide и section.write: хост не отдаёт необъявленное…»), `core/test/contracts-types.ts` (`npm run typecheck`).
- **класс:** Functions.

### FR-CH-2002 События без шины

- **Требование:** общей шины событий нет. Событие предмета - часть контракта его владельца (`sessions.onChange`); обратный вызов - только подписка с `Disposable`. Колбэк остаётся в хосте потребителя, через границу идёт его номер. Подписку ядро снимает при выгрузке или падении любой из сторон и отбрасывает вызов колбэка от хоста, который подписку не обслуживает. Функция в аргументах или результате вне подписки - `NotCloneable`. События окна и системы - фокус окна, сон и пробуждение, блокировка экрана, простой, завершение приложения - плагин получает подпиской `ctx.window` и `ctx.system`; упавший слушатель не мешает соседу, `onBeforeQuit` ядро ждёт не дольше бюджета.
- **traced from:** BR-CH-001, BR-CH-006.
- **источник:** [SAD, раздел 4](../../04-architecture/design/sad.md#4-взаимодействие-плагинов) (п. 4-6), [SAD, 3.9](../../04-architecture/design/sad.md#39-системные-клавиши-и-события).
- **verification:** испытание - `core/test/subscriptions.test.ts`, `core/test/rpc.test.ts` («функция не проходит границу…»), `core/test/loader.test.ts` («функция в результате контракта - NotCloneable у вызывающего»), `core/test/trust.test.ts` («emit и release: чужой хост не стреляет в чужую подписку…»), `core/test/events.test.ts`.
- **класс:** Functions.

### FR-CH-2004 Команды и сочетания

- **Требование:** команды объявляются в манифесте исполнителя вместе со схемой аргументов; ядро сверяет аргументы до обработчика, откуда бы ни пришла команда. Необъявленная команда отклоняется, чужой хост команду не перехватит; команду, объявленную манифестами двух плагинов (`a` и `a.b` оба объявили `a.b.run`), ядро не отдаёт ни одному, кроме встроенного: сторонний отвергается при загрузке (`rejected`, причина `command`), а вид и клик по уведомлению запускают только команду своего плагина (`Kernel.runOwn`). Сочетания объявляются в манифесте и привязаны к своей команде без обязательных аргументов. Ядро перехватывает их в главном процессе до страницы, поэтому они срабатывают одинаково из каркаса и из любого `<iframe>`. Конфликт двух плагинов на одно сочетание виден при загрузке (`key-conflict`): побеждает встроенный, между равными - первый по id; победитель выгружен - сочетание идёт окну. Человек переназначает сочетания записью `plugins.keybindings`: запись воркспейса побеждает запись пользователя, `null` отдаёт сочетание окну. Команды окна `cyborg.window.focus-next` (`F6`) и `cyborg.window.focus-prev` (`Shift+F6`) принадлежат ядру. Плагин может и во время работы зарегистрировать сочетание, `ctx.keys.register({ key, command, args?, when? })`: своя объявленная команда с аргументами (до 4 КиБ, сверяются со схемой сразу), условия `when` - закрытый список `repeat`, `dialog`, `visible`, `input`; не больше 128 регистраций на плагин, регистрации снимаются при выгрузке, падении хоста и откате активации. Старшинство в одном реестре: человек, затем окно и меню приложения (их динамически занять нельзя - `CommandConflict`), манифесты, динамические по порядку; проигравший динамический получает `active: false` и победителя, а в журнале - `key-conflict`.
- **traced from:** BR-CH-001.
- **источник:** [SAD, 3.9](../../04-architecture/design/sad.md#39-системные-клавиши-и-события), [SAD, раздел 4](../../04-architecture/design/sad.md#4-взаимодействие-плагинов) (п. 10); `core/src/keys.ts`, `core/src/keybindings.ts`.
- **verification:** испытание - `core/test/lifecycle.test.ts` (сочетания, `plugins.keybindings`, конфликт), `core/test/keys-registry.test.ts` (keys.register и keys.unregister: условия, старшинство, снятие при выгрузке, откате и падении хоста), `core/test/semver-manifest.test.ts` (команды и их аргументы), `core/test/trust.test.ts` («register…», «run: ядро сверяет аргументы со схемой манифеста…»), `core/test/loader.test.ts` («команды: … необъявленная команда отклоняется»), `core/test/window.test.ts` («команды окна: F6 и Shift+F6 у ядра…»), `core/test/graph.test.ts` («команда в двух манифестах…»), `core/test/command-callers.test.ts` («команда в двух манифестах: …runOwn…»), `core/test/keys-menu-parity.test.ts` (реестр с акселераторами меню Cyborg ловит всё из `RESERVED_MAC`/`RESERVED_OTHER` и то, чего в списке нет; PL-03), `electron/test/plugins.test.ts` («menuKeys приложения…»), `electron/test/key-route.test.ts` (решение по нажатию не зависит от кадра), `playground/test/pilot-keys.test.ts` (пилот `keys-pilot` на хосте-процессе); дымовой тест - «перехват клавиш, конфликт…» и «акселераторы меню окна … в едином реестре ядра».
- **класс:** Functions.

### FR-CH-2005 Виды и документы плагина

- **Требование:** ядро знает только роды областей: боковая колонка, основная область с группой документов, панель инструментов, всплывающий слой, слой замка. Плагин объявляет виды и типы документов в манифесте с родом области (`sidebar`, `main`, `toolbar`, `popup`) и `order` (краткая запись пути модуля остаётся допустимой), неизвестная область или нечисловой `order` отвергают манифест с именем поля; ядро отдаёт приложению упорядоченный снимок раскладки (`Kernel.layout`: по `order`, при равенстве по id плагина, не включённые, выключенные и вне графа помечены по-разному), и каркас окна рисуется по манифестам до кода плагинов, без выбора плагина по имени. Каждый вид живёт в своём `<iframe>` по адресу `cyborg-plugin://<группа>/<плагин>/` и под CSP; origin задаёт группа рендера ([FR-CH-3013](../03-security-trust/srs.md#fr-ch-3013-группа-рендера)), кадры одной группы делят процесс рендера; модуль вида экспортирует `mount(root, ctx)` и возвращает `Disposable`. `UiContext` даёт команды, контракты от имени плагина вида, тему, видимость, память вида, диалоги, сочетания своих команд и терминал по билету; `ctx.os` у вида нет. Мост узнаёт плагин по группе из origin фрейма и плагину из пути его адреса (плагин обязан состоять в группе кадра), а не со слов вида; граница доверия - группа; каналы окна принимают сообщения только от главного фрейма, страница чужого происхождения во фрейме вида мост не получает. Скрытый вид не размонтируется. Пока хост перезапускается, вид стоит под плашкой без ввода; плагин выключен - на месте вида заглушка с причиной, «Включить снова» и «Журнал». Чужой UI в свой вид не встраивается: плагин зовёт команду или контракт владельца. Документ типа с `restorable` переживает перезапуск окна: данные отдаёт владелец (`ctx.documents.save`), без владельца вкладка показывается недоступной, а не пропадает.
- **traced from:** BR-CH-001, BR-CH-006.
- **источник:** [SAD, 3.8](../../04-architecture/design/sad.md#38-изоляция-рендера); У-22 ([модель угроз, 5.3](../../04-architecture/design/threat-model.md), закрыто); `core/src/ui-shell.ts`, `core/src/documents.ts`, `core/src/layout.ts`.
- **verification:** испытание - `core/test/ui-shell.test.ts`, `core/test/documents.test.ts`, `core/test/semver-manifest.test.ts` («вид: …», «документ: area и order…»), `core/test/loader.test.ts` («раскладка: …»), `playground/test/plugins-model.test.ts`, `electron/test/view-files.test.ts` («вид: origin называет группу…», «вид: адрес обслуживается, только если плагин состоит в группе…»), `electron/test/view-frames.test.ts`; дымовой тест - «виды во фреймах: свой мост, лента плагина, чужая команда отклонена», «перезапуск хоста: вид под плашкой без ввода…», «окно: заглушка с причиной…», «документы: вкладка сессии в окне…», «оба вида panels показаны, каждый со своим именем» (шаг раздела «виды во фреймах…»), «panels: два вида во фреймах со своими ?view=, независимая свёртка, меню у фрейма своего вида» (T-14), «группы рендера: alice и bob в одном процессе рендера…». Род области и порядок - [FR-CH-2022](#fr-ch-2022-род-области-и-порядок-вида). Группа рендера - [FR-CH-3013](../03-security-trust/srs.md#fr-ch-3013-группа-рендера) (фича 03).
- **класс:** Functions.

### FR-CH-2006 Слой окна: диалоги и замок

- **Требование:** диалог плагина - `ctx.dialogs.show`: `ask` (заголовок, текст, кнопки) или `menu` (пункты в точке фрейма). Ядро разбирает описание и ограничивает его (до 12 пунктов, подпись до 80 символов), показывает один диалог поверх всех фреймов, остальные ждут по порядку, у плагина в очереди не больше 8. Слой поверх фреймов принадлежит только ядру и владельцу замка, вид рисует лишь внутри своего прямоугольника. Ответ - `id` пункта; Escape и клик мимо меню - `undefined`; выгрузка плагина закрывает его диалоги. Замок окна - `ctx.os.ui.lock` по праву `ui.lock` с экраном `ui.overlay`: чужие фреймы скрыты и `inert`, работают только сочетания владельцев замка, чужие диалоги ждут в очереди, выключить владельца замка нельзя. Снять замок может только тот, кто его поставил; главные части и pty работают. `lock.onStart` закрывает окно до активации.
- **traced from:** BR-CH-001, BR-CH-005.
- **источник:** [SAD, 3.8](../../04-architecture/design/sad.md#38-изоляция-рендера), [SAD, 5.4](../../04-architecture/design/sad.md#54-пример-узкого-плагина-блокировка-по-пину); У-24 (частично), У-25 (закрыто), У-26 (принято: замок не защищает данные) - [модель угроз, 5.3](../../04-architecture/design/threat-model.md); `core/src/window-layer.ts`.
- **verification:** испытание - `core/test/window.test.ts`; дымовой тест - «слой окна: ask и menu вида поверх фреймов, ответ и отмена, ctx.keys.of», «замок: виды скрыты, экран замка, чужие сочетания не перехвачены, открытие по PIN». Ещё нет (У-24): внутри своего прямоугольника вид рисует что угодно, в том числе подделку диалога или замка; мера против этого - окно согласия этапа 2 ([FR-CH-2012](../03-security-trust/srs.md#fr-ch-2012-права-в-манифесте-и-этапы-изоляции)).
- **класс:** Functions.

### FR-CH-2009 Контракт агента `cyborg.agent`

- **Требование:** агент - обычный плагин, поставщик контракта `cyborg.agent` (`contracts/agent.ts`); регистрации агента в ядре нет. Члены: `facts` (найдена ли программа, версия, `capabilities`: `resume`, `history`, `events`), `launch` (готовый вход `ctx.os.pty.spawn`), `watch` (события `cwd`, `session`, `activity`, `prompt`, `turnEnd`, `waiting`), `ended` (уборка и причина выхода), `history`. Поставщик процессов не создаёт: pty запускает потребитель по своему праву `pty`, а `describedBy` сверяет описание ещё и с правом `launch` поставщика - права пересекаются. Продолжение сессии через `resumeId` потребитель просит, только если поставщик объявил `capabilities.resume`. Фрагменты системного промпта - контракт `cyborg.session-prompt`, инструменты агенту по MCP - `cyborg.agent-tool`, оба кратности many.
- **traced from:** BR-CH-003.
- **источник:** [SAD, раздел 5](../../04-architecture/design/sad.md#5-пример-базовая-часть), [SAD, 5.3](../../04-architecture/design/sad.md#53-восстановление-сессий); [ADR-CH-0004](../../04-architecture/adr/ADR-CH-0004-agent-provider-contract.md) (поставщик не создаёт процессов).
- **verification:** испытание - `playground/test/agents.test.ts` («cyborg.agent, общий набор…» для `agent-claude-code` и `agent-shell`, «sessions: восстановленная сессия claude продолжается через resume поставщика», «sessions + next-actions…»), `core/test/pty.test.ts` («pty.spawn с describedBy…»); дымовой тест - «cyborg.agent: два поставщика…».

### FR-CH-2010 Плагин `agent-claude-code`

- **Требование:** `agent-claude-code` - поставщик `cyborg.agent` для Claude Code. Запуск - `$SHELL -lc 'exec claude --settings "$CYBORG_SETTINGS" "$@"'` по праву `launch`. Хуки `SessionStart`, `UserPromptSubmit`, `PostToolUse`, `Stop`, `Notification` пишут JSON в файл сессии в `plugin-data`; `watch` следит за каталогом сессий через `fs.watch` и дочитывает файл через `fs.readSlice`. «Ждёт» после `Stop` - только если ход закончен без фоновой работы и сессия молчит 30 с. `history` - интерактивные сессии каталога и его worktree из `~/.claude/projects`. `resumeId` - `session_id` хука `SessionStart`. Токен сервера MCP передаётся переменной `CYBORG_MCP_TOKEN` и файлом `--mcp-config`, а не в argv. Настройки `--settings` разрешают без вопроса ровно сервер `cyborg` (`permissions.allow: ["mcp__cyborg"]`), режим разрешений не задают и флагов режима не передают; в `--mcp-config` попадает один сервер - `cyborg`. Сервер MCP стороннего плагина по объявлению в манифесте и право «пишет агенту» - **Ещё нет**: форма поля и срок - этап 2 ([SAD, вопрос 17](../../04-architecture/design/sad.md#8-открытые-вопросы)).
- **traced from:** BR-CH-003, BR-CH-005.
- **источник:** [SAD, раздел 5](../../04-architecture/design/sad.md#5-пример-базовая-часть), [SAD, 3.7](../../04-architecture/design/sad.md#агент-в-модели-доверия); `playground/plugins/agent-claude-code`.
- **verification:** испытание - `playground/test/agents.test.ts` («agent-claude-code: запуск…», «… режим разрешений человека не меняется…», «… хуки в события контракта…», «… «ждёт» после Stop…», «… история…», «сторонний плагин: текст и инструменты агенту…»); дымовой тест с `CYBORG_SMOKE_CLAUDE=1` - живой `claude` по праву `launch`.
- **класс:** Functions.

## 3. Открытые вопросы

Решает владелец (D-00) или постановщик. Нормы выше выбранного варианта не содержат.

1. **Род области и диапазоны `order` (FR-CH-2022; D-00, строка 2).** Решено 2026-11-08 по предложению D-00 и влито с K-03 (PR #110): один числовой `order`, сравнение внутри своей области; плагины из поставки занимают 0-1000 с шагом 100, не объявившие и сторонние идут после, при равенстве - по id плагина ([SAD, 3.8](../../04-architecture/design/sad.md#38-изоляция-рендера)).
2. **Просмотр файла: превью или вкладка (FR-CH-2022; D-00, строка 1; держит PL-08).** Принято исполнителем K-03 по предложению D-00, подтверждено владельцем 2026-11-11 (вопрос 1 SAD; файл открывается вкладкой рядом с терминалом): превью на месте терминала, как в Cyborg сейчас; отдельной области под вкладку-просмотр ядро не заводит, `viewer` ставит свой вид в `main`. Прежнее предложение этого документа - вкладка в группе документов, переживающая перезапуск ([FR-CH-2005](#fr-ch-2005-виды-и-документы-плагина)) - с принятым расходится; выбирает владелец.
3. **Форма `ctx.keys.register` (FR-CH-2024; D-00, строка 8).** Решено 2026-11-08 и влито с K-07 (PR #121): `ctx.keys.register({ key, command, args?, when? }): Promise<KeyRegistration>`, `when` - закрытый список флагов `repeat`, `dialog`, `visible`, `input`, проверяет ядро без вызова через границу ([SAD, 3.9](../../04-architecture/design/sad.md#39-системные-клавиши-и-события)).
4. **Форма отмены запроса (FR-CH-2026; D-00, строка 8; держит K-09, PL-07).** Решено 2026-11-08 исполнителем K-09 в D-00 (форма минимально обратимая, подтверждено владельцем 2026-11-11): `AbortSignal` последним аргументом вызова члена контракта, `commands.run` и `kernel.run`, поставщик получает сигнал на то же место. Реализовано и влито в PR #122.
5. **Форма вклада в меню (FR-CH-2025; D-00, строка 8; K-08).** Решено 2026-11-10 исполнителем K-08 (принято по поручению владельца, подтверждено владельцем 2026-11-11): источник `enabled` и `checked` - `{ contract, major, member }`, булев член контракта, который плагин получает (`requires`, `optional`) или отдаёт (`provides`); выгруженный владелец - пункт недоступен, а не пропадает, как предлагал этот вопрос ([FR-CH-2005](#fr-ch-2005-виды-и-документы-плагина) так же держит вкладки) ([SAD, 3.9](../../04-architecture/design/sad.md#вклады-в-меню-окна)).
6. **Канал «главная часть - вид» (FR-CH-2027; K-13, K-07 влит - PR #121).** Вопрос: новый канал или команды и подписки существующего моста. Предлагаю канал поверх команд и подписок с `Disposable`: нового вида границы тогда не появляется. Решено 2026-11-10 по поручению владельца и реализовано: канал по имени вида с `post` и `onMessage` (`Disposable`) в обе стороны, поверх моста хоста и вида.
7. **Порог контраста темы (FR-CH-2038, K-32).** Число сверх источника: норма говорит «контраст», не число. Предлагаю WCAG 2.2 AA (4,5:1 для текста, 3:1 для крупного и элементов управления): стандарт, который проверяют готовые средства.

### Находки

- **FR-CH-2005 заявлял роды областей, а манифест их не знает.** Исправлено: добавлено «Ещё нет» (K-03, K-04). С K-03 (PR #110) роды и `order` есть в манифесте, K-04 влит вместе с группами рендера (PR #142): «Ещё нет» нет.
- **K-15 и K-23.** Формулировки: K-15 «пространство контрактов `cyborg.*` только для встроенных плагинов»; K-23 «инструменты стороннего плагина по умолчанию агенту не показываются, пока человек их не включил», по решению владельца (2026-11-08) - сторонний инструмент в сервер `cyborg` не попадает, сторонний плагин даёт его своим сервером MCP, объявленным в манифесте. Так обе формулировки выполнимы; выбор - [вопрос 14 фичи 03](../03-security-trust/srs.md#3-открытые-вопросы).
- **K-22.** Умолчание `user` ломает межплагинный вызов команды без пометки: встроенные манифесты с межплагинными командами меняются одним ходом с ядром ([вопрос 4 фичи 03](../03-security-trust/srs.md#3-открытые-вопросы)).
- **Агент под инъекцией (У-30).** `agent-claude-code` сегодня пишет `permissions.allow: ["mcp__cyborg"]` (`playground/plugins/agent-claude-code/index.ts`, строка 112) - все инструменты сервера разрешены без вопроса. По FR-CH-3018 (фича 03) это верно: сервер `cyborg` отдаёт только инструменты встроенных плагинов, они проверены в поставке (решение владельца, 2026-11-08). Сервер MCP стороннего плагина виден агенту, только если объявлен в манифесте, и в `allow` не попадает (FR-CH-3017; K-23 влит PR #101, объявление сервера в манифесте - этап 2, вопрос 17 SAD).
