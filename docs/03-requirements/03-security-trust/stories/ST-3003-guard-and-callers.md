# ST-3003 Права не передаются через чужие контракты и команды

Как разработчик поставки, я хочу, чтобы плагин без права на путь не получил путь руками другого плагина, чтобы контракт и команда не обходили шлюз.

Нормы: FR-CH-3008, FR-CH-3009, FR-CH-3010. Сценарии: UC-EXTENSION-CONTRACTS-2001. SRS - [srs.md](../srs.md).

## Критерии приёмки

1. [FR-CH-3008] [UC-EXTENSION-CONTRACTS-2001#2б]
   - Дано поставщик объявил `guard` для члена контракта, работающего с путём
   - Когда вызывающий без права на путь зовёт член
   - Тогда ядро сверяет аргумент с правом вызывающего до передачи вызова поставщику; действует пересечение прав; отказ - `via-contract`, запись `denied`
2. [FR-CH-3008]
   - Дано член контракта и команда с аргументом-путём без `guard`
   - Когда автор запускает `checkPlugin`
   - Тогда проверка предупреждает о таком члене и такой команде
3. [FR-CH-3009]
   - Дано команда плагина без `callers`
   - Когда чужая главная часть вызывает команду
   - Тогда `PermissionDenied` и запись `denied`; команда по умолчанию открыта человеку: палитре, клавишам, меню и виду своего плагина; плагин без права `pty` не запускает агента командой `sessions.new`
4. [FR-CH-3009]
   - Дано команда с `callers`, открытая плагинам, и аргументом-путём
   - Когда чужая главная часть вызывает её
   - Тогда аргумент-путь сверяется с правом вызывающего через `guard`
5. [FR-CH-3010]
   - Дано сторонний плагин отдаёт контракт `cyborg.*` или носит `id` с префиксом `cyborg.`
   - Когда ядро загружает плагин
   - Тогда плагин не загружается, причина в журнале называет имя и пространство; брать контракты `cyborg.*` стороннему можно; признак поставки - каталог установки, не манифест
