# ST-3005 Вид изолирован: группа рендера, закрытая CSP, окно остаётся на своих адресах

Как человек, открывающий вид стороннего плагина, я хочу, чтобы вид не выполнял чужой код, не читал соседей и не уводил окно, чтобы страница плагина не стала дырой в окне.

Нормы: FR-CH-3013, FR-CH-3014, FR-CH-3015, FR-CH-3016, NFR-CH-2002. Сценарии: UC-AUTHOR-KIT-7001. SRS - [srs.md](../srs.md).

## Критерии приёмки

1. [FR-CH-3013]
   - Дано два плагина просят общую группу рендера `ui.group`, один из них сторонний
   - Когда ядро выдаёт группы
   - Тогда сторонний всегда один в своей группе, origin `cyborg-plugin://solo_<id>`; просьба отклонена записью `group-isolated` и предупреждением в строке плагина; группа поставки с таким же именем его веб-хранилище не наследует; `plugins.uiGroups` читается из файла пользователя
2. [FR-CH-3013] [FR-CH-3014]
   - Дано кадр вида и вложенная в него чужая страница
   - Когда кадр обращается к мосту
   - Тогда мост выдаётся по origin документа: вид получает свой, окно свой, чужая страница внутри вида моста не получает; плагин узнаётся по первому сегменту пути; каналы окна принимает только главный фрейм
3. [FR-CH-3014]
   - Дано имя файла, вывод команды и markdown плагина с разметкой `<img onerror=…>`
   - Когда окно и элементы ядра выводят данные плагина
   - Тогда данные выведены текстом, а не разметкой; вхождений `innerHTML` с данными плагинов в `core/`, `electron/src` и `playground/src` нет; вид - браузерный бандл без `node:*` и `electron`
4. [FR-CH-3015] [UC-AUTHOR-KIT-7001#4]
   - Дано CSP вида
   - Когда вид загружается
   - Тогда `default-src 'none'` и явные источники: скрипты, стили, соединения `'self'`, изображения `'self'` и `data:`, шрифты `'self'`, `base-uri 'none'`, `form-action 'none'`; встроенный скрипт не выполняется, запрос на чужой origin и в интернет блокируется
5. [FR-CH-3015]
   - Дано манифест без `ui.inlineStyles`, затем с `ui.inlineStyles: true`
   - Когда вид вставляет `<style>` и атрибут `style`
   - Тогда без флага инлайн-стили не применяются, элементы `cy-*` работают через `adoptedStyleSheets`; с флагом `style-src 'self' 'unsafe-inline'` - для xterm и Monaco
6. [FR-CH-3016]
   - Дано вид вызывает `window.open` и меняет адрес фрейма на внешний
   - Когда вид пытается уйти
   - Тогда `window.open` отклонён; навигация разрешена только на `cyborg-plugin://` и страницу окна
7. [целевое поведение] [NFR-CH-2002]
   - Дано проверочные попытки из вида: скрипт не с его origin, соединение за пределы origin, чтение DOM соседей и моста оболочки
   - Когда попытки выполняются
   - Тогда успешных - 0
8. [FR-CH-3013] [FR-CH-3014]
   - Дано вид группы меняет адрес своего кадра через `history.pushState` на путь соседа по группе, плагина другой группы или корень
   - Когда вид просит команду через мост
   - Тогда плагин кадра прежний: он привязан к кадру при создании документа (`frameTreeNodeId`), а не к текущему адресу; команда соседа - «не команда плагина <свой>»; номер кадра не меняется ни от `pushState`, ни от перезагрузки документа, а новый документ привязывается заново
9. [FR-CH-3014] [FR-CH-3016]
   - Дано проверочные попытки вида на настоящем Electron: вложенный фрейм с адресом другой группы, внешним адресом и `data:`, `srcdoc`, уход самого фрейма на чужие адреса, обход моста (Node, `ipcRenderer`, мост окна, DOM окна и соседней группы, `window.open`, `fetch` мимо origin)
   - Когда попытки выполняются
   - Тогда вложенные фреймы заблокированы CSP (документ - страница ошибки без origin и без моста), у `srcdoc` моста и Node нет, уход фрейма отклонён и записан в журнал плагина, у вида нет Node, `ipcRenderer`, моста окна, DOM окна и соседней группы, новых окон нет
