# ST-3008 Безопасный режим, значения не из репозитория и учёт угроз

Как человек, открывший чужой репозиторий или получивший плагин, который падает на каждом старте, я хочу выключить все плагины и быть уверенным, что файл воркспейса не расширит права, чтобы вернуть управление и не пустить чужое.

Нормы: FR-CH-1009, FR-CH-3020, NFR-CH-2003. Сценарии: UC-PLUGIN-HOST-1001, UC-SECURITY-TRUST-3001. SRS - [srs.md](../srs.md).

## Критерии приёмки

1. [FR-CH-1009] [UC-SECURITY-TRUST-3001#1а] [UC-PLUGIN-HOST-1001#6а]
   - Дано плагин падает на каждом старте
   - Когда человек запускает с `--safe-mode` или выбирает «Перезапустить в безопасном режиме»
   - Тогда хосты не запускаются, каждый плагин получает запись `safe-mode`, замок `lock.onStart` не ставится, включить плагин нельзя (`Unavailable`); окно без плагинов и управление ими работают, у плагина причина «безопасный режим: код плагинов не запускается»
2. [FR-CH-3020]
   - Дано файл воркспейса из репозитория команды с `net`-хостом `config:baseUrl` и `plugins.uiGroups`
   - Когда ядро собирает права
   - Тогда хосты `config:<поле>` и группы рендера берутся только из слоя пользователя; поле `plugins.uiGroups` воркспейса не действует и названо в `Workspace.problems`; группа хостов и группа рендера стороннему права не расширяют
3. [NFR-CH-2003]
   - Дано возможность, которая даёт право, открывает канал между плагинами или принимает данные извне
   - Когда проверяется заморозка API 1.0
   - Тогда у неё есть строка в модели угроз со статусом и задачей; у угроз этапа 1 нет статуса «открыто» - только закрыто, принято владельцем или вынесено в этап 2
