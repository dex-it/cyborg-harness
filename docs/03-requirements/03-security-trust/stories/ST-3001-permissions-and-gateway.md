# ST-3001 Права плагина проверяет шлюз ctx.os, у каждого отказа есть запись

Как человек, ставящий чужой плагин, я хочу, чтобы плагин делал с ОС только то, что объявил в манифесте, чтобы выход за права кончался отказом и записью в журнале.

Нормы: FR-CH-2007, FR-CH-2012, FR-CH-3001, FR-CH-3007, NFR-CH-3001. Сценарии: UC-AUTHOR-KIT-7001, UC-SECURITY-TRUST-3001. SRS - [srs.md](../srs.md).

## Критерии приёмки

1. [FR-CH-2007] [UC-SECURITY-TRUST-3001#6] [UC-SECURITY-TRUST-3001#7] [UC-AUTHOR-KIT-7001#4а]
   - Дано плагин с пустыми `permissions` вызывает членов `ctx.os` в обход (прямой RPC хоста) по списку
   - Когда вызывается каждый член, которому нужно право
   - Тогда результат каждого - `PermissionDenied` и запись `denied`; без права члена в `ctx.os` нет
2. [FR-CH-2007] [UC-SECURITY-TRUST-3001#6]
   - Дано путь вне области права и путь через ссылку, ведущую наружу
   - Когда плагин читает путь
   - Тогда проверка идёт после `realpath`; ответ `PermissionDenied`, а не `NotFound`; данные приложения, файл воркспейса и замок, каталоги других плагинов и запись в `.git` (кроме области `workspace.git`) закрыты всегда
3. [FR-CH-2007]
   - Дано `secrets` и `dialog` в манифесте не объявлены, `fs.watch` объявлен через право чтения
   - Когда плагин вызывает `ctx.os.secrets`, `ctx.os.dialog`, `ctx.os.fs.watch`
   - Тогда свои секреты и диалог доступны без права, `fs.watch` идёт по праву чтения
4. [FR-CH-3001]
   - Дано защищённый файл воркспейса и его соседи `<файл>.corrupt-*`, `<файл>.bak`, временный файл записи
   - Когда плагин с правом чтения всего каталога читает или пишет соседа
   - Тогда `PermissionDenied` и запись `denied` при любом праве
5. [FR-CH-3007]
   - Дано плагин без права `fs.read` вызвал `ctx.os.dialog.open`, человек выбрал каталог
   - Когда плагин читает выбранный каталог
   - Тогда путь после `realpath` стал областью `granted` этого плагина; доступ даёт право `fs.read: ["granted"]`; выбор другого плагина не право; выбор переживает перезапуск в `$granted` state воркспейса
6. [FR-CH-3007]
   - Дано файл воркспейса с относительным путём и путём с NUL в `$granted`; окно под замком; сбой записи выбора
   - Когда выбор читается и записывается
   - Тогда берутся только абсолютные пути без NUL; диалог чужого плагина под замком - `Unavailable`; сбой записи выбор не отменяет; битый файл воркспейса другие разделы не стирает
7. [FR-CH-2012]
   - Дано манифест с правом `fs.reed` и правом `net` неверной формы
   - Когда ядро разбирает манифест
   - Тогда неизвестное право и неверная форма - ошибка манифеста; плагин не загружается
8. [FR-CH-2012] [UC-SECURITY-TRUST-3001#3]
   - Дано плагин с правами `process` и `pty` в окне «Плагины Cyborg»
   - Когда человек открывает строку плагина
   - Тогда права показаны словами «полный доступ через программу»; те же строки потом войдут в окно согласия
9. [FR-CH-2012]
   - Дано сторонний плагин в этапе 1
   - Когда ядро проверяет импорты и сообщения хоста
   - Тогда главной части разрешены только `@cyborg-harness/contracts` и свои модули, виду ещё npm-пакеты, без `node:*` и `electron`; сообщение принимается только из хоста названного плагина; значения `config`, из которых выводится право, берутся только из слоя пользователя
10. [целевое поведение] [NFR-CH-3001]
   - Дано плагин с пустыми `permissions` вызывает членов `ctx.os` в обход (прямой RPC хоста), перебор по списку всех членов
   - Когда вызывается каждый член, которому нужно право
   - Тогда членов без `PermissionDenied` и записи `denied` - 0 из общего числа; результат, успех операции или иной код ошибки - неуспех
