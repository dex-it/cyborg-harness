# ST-3004 Секреты не утекают, удаление плагина стирает его данные

Как человек, пользующийся плагином с ключами, я хочу, чтобы секрет не попадал в файлы и журнал, а удаление плагина стирало его данные, чтобы новый плагин с тем же именем ничего не унаследовал.

Нормы: FR-CH-2014, FR-CH-3011, FR-CH-3012, NFR-CH-4002. Сценарии: нет (несценарная ветка). SRS - [srs.md](../srs.md).

## Критерии приёмки

1. [FR-CH-2014]
   - Дано плагин сохранил секрет `token`
   - Когда другой плагин читает `ctx.os.secrets`
   - Тогда ключ хранится как `<плагин>/token`, каждый плагин видит только свои; без шифрования ОС вызов получает `Unavailable`, открытым текстом не пишется
2. [FR-CH-2014]
   - Дано в `config` записана ссылка `{ "$secret": "token" }` и ссылка со схемой `vault:`
   - Когда ядро разрешает ссылки
   - Тогда ссылка без схемы идёт из хранилища вызывающего; со схемой - по праву `secrets.ref` вызывающего у поставщика `cyborg.secret-source` этой схемы; значение в `config`, `state` и журнал не пишется, ядро его не кэширует
3. [FR-CH-3011] [NFR-CH-4002]
   - Дано значение секрета выдано плагину
   - Когда плагин пишет `ctx.log` и человек выгружает диагностику
   - Тогда значения нет ни в журнале ядра, ни в выгрузке
4. [FR-CH-3012] [FR-CH-2014]
   - Дано у плагина есть секреты `<плагин>/*`, данные в `plugin-data` и выбор `granted`
   - Когда плагин удалён (`Kernel.uninstall`), затем поставлен плагин с тем же `id`
   - Тогда секреты, `plugin-data` и `granted` стёрты, новый плагин ничего не наследует; обычное выключение плагина ничего из этого не стирает; шифрование ОС для стирания секретов не нужно
5. [FR-CH-3011]
   - Дано плагин сам пишет выданное ему значение секрета в `ctx.log`
   - Когда строка попадает в журнал плагина
   - Тогда значение из хранилища вычёркнуто меткой `[секрет]`; значения короче 4 символов не вычёркиваются; строка, записанная плагином, в меру NFR-CH-4002 не входит
