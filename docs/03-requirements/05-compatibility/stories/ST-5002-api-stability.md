# ST-5002 Публичный API стабилен в пределах мажорной версии

Как автор плагина, я хочу, чтобы плагин, собранный под API 1.x, работал на ядре 1.y без пересборки, чтобы обновление ядра не ломало выпущенные плагины.

Нормы: FR-CH-1012, FR-CH-5002, FR-CH-5003, FR-CH-5004, FR-CH-5006, NFR-CH-1006. Сценарии: UC-COMPATIBILITY-5002, UC-EXTENSION-CONTRACTS-2001. SRS - [srs.md](../srs.md).

## Критерии приёмки

1. [FR-CH-1012] [NFR-CH-1006] [UC-COMPATIBILITY-5002#4]
   - Дано члены `ctx`, элементы ядра и контракты минорного выпуска 1.y против 1.x
   - Когда ядро обновляется
   - Тогда элемент не удалён и не сменил атрибуты в пределах мажорной версии, плагин работает как до обновления; минорная версия контракта добавляет только необязательное, мажорная - новый тип в карте `Contracts`
2. [FR-CH-1012] [UC-EXTENSION-CONTRACTS-2001#3а]
   - Дано контракт, где поставщик даёт две мажорные версии, и потребитель, просящий версию вне диапазона манифеста
   - Когда потребитель вызывает `get` и `all`
   - Тогда каждый потребитель получает ту версию, что просил; версия вне диапазона даёт `NotDeclared`; член с `@deprecated` живёт минимум до следующей мажорной версии
3. [FR-CH-5003] [UC-COMPATIBILITY-5002#4а]
   - Дано разработчик ядра удаляет член `PluginContext`, меняет его атрибуты и добавляет обязательное поле манифеста в минорном выпуске
   - Когда CI сверяет публичный API со снимком в репозитории
   - Тогда сборка падает; добавление необязательного члена проходит после дополнения снимка; в снимок входят `PluginContext`, `UiContext`, `PluginPermissions`, поля манифеста, теги `cy-*`, коды `CoreErrorCode`, карта `Contracts`
4. [FR-CH-5004] [NFR-CH-1006] [UC-COMPATIBILITY-5002#4б]
   - Дано изменение прошло снимок, но сменило поведение члена; плагин прошлого минорного выпуска собран под API 1.x
   - Когда CI запускает его тесты на текущем ядре без пересборки
   - Тогда упавший тест роняет сборку так же, как расхождение со снимком; плагинов прошлых минорных выпусков, не прошедших тесты, - 0
5. [FR-CH-5002] [UC-COMPATIBILITY-5002#4]
   - Дано пакет `@cyborg-harness/contracts` и демо-контракты примеров
   - Когда проверяется состав пакета и снимок
   - Тогда в пакете только контракты с гарантиями FR-CH-1012; демо-контракты лежат вне него и в снимок не попадают
6. [FR-CH-1012] [UC-COMPATIBILITY-5002#4в]
   - Дано ломающее изменение всё же дошло до пользователя, плагин упал в вызове
   - Когда плагин отказывает
   - Тогда отказывает только он, окно и соседи работают, причина в журнале (дефект выпуска разбирается отдельно)
7. [FR-CH-5006] [UC-COMPATIBILITY-5002#9]
   - Дано выпуск пакета объявлений, у которого снимок API изменился
   - Когда готовится выпуск
   - Тогда запись изменений несёт, что добавлено, что объявлено `@deprecated`, что удалено в мажорной версии; плагин под 2.0, где нет вызова удалённого члена, загружается
