# ST-5001 Несовместимый плагин не загружается, остальные работают

Как пользователь, обновивший приложение, я хочу, чтобы плагин под другой API отказывал до запуска кода с понятной причиной, чтобы остальные плагины продолжали работать.

Нормы: FR-CH-1002, FR-CH-5001, FR-CH-5008. Сценарии: UC-AUTHOR-KIT-7001, UC-COMPATIBILITY-5001, UC-COMPATIBILITY-5002, UC-DELIVERY-6001. SRS - [srs.md](../srs.md).

## Критерии приёмки

1. [FR-CH-1002] [UC-COMPATIBILITY-5001#2] [UC-COMPATIBILITY-5002#1] [UC-COMPATIBILITY-5002#2] [UC-COMPATIBILITY-5002#3]
   - Дано плагин с `engines.cyborg: ^1.3` на ядре с API 1.4
   - Когда ядро сверяет плагин до запуска кода
   - Тогда плагин проходит и загружается без пересборки
2. [FR-CH-1002] [UC-COMPATIBILITY-5001#2а] [UC-COMPATIBILITY-5002#3а] [UC-COMPATIBILITY-5002#8а] [UC-AUTHOR-KIT-7001#2б] [UC-DELIVERY-6001#3а]
   - Дано плагин с `engines.cyborg: ^1.0`, ядро сменило мажорную версию на 2
   - Когда ядро сверяет плагин
   - Тогда плагин не загружается, код не выполнялся; причина «нужен API Cyborg <диапазон>, есть <версия>» в журнале и в «Плагины Cyborg»; потребители через `requires` не загружаются каскадом, через `optional` остаются; остальные плагины работают
3. [FR-CH-1002] [UC-COMPATIBILITY-5002#3б]
   - Дано плагин с `^1.5` на ядре 1.3
   - Когда ядро сверяет плагин
   - Тогда тот же отказ с той же причиной, что и при другой мажорной версии; диапазон `^1` такого отказа не даёт
4. [FR-CH-5008] [UC-COMPATIBILITY-5001#3а] [UC-COMPATIBILITY-5002#4г]
   - Дано потребитель просит мажорную версию 1 контракта, поставщик даёт только 2; рядом поставщик, дающий обе
   - Когда ядро разрешает граф
   - Тогда для потребителя первый поставщик - как отсутствие: через `requires` потребитель не загружается, причина называет контракт и диапазон; через `optional` работает без поставщика; поставщик с двумя версиями обслуживает потребителя
5. [FR-CH-5001] [UC-COMPATIBILITY-5002#3]
   - Дано код ядра, приложения и проверки плагина вне репозитория
   - Когда ищется литерал версии API
   - Тогда версия определена в одном месте (`PLUGIN_API_VERSION` в `core/src/api-version.ts`), второго литерала нет
