# ST-5004 Разделы config и state переживают обновление

Как пользователь, обновивший плагин, я хочу, чтобы его настройки и данные остались и были переведены в новый формат, чтобы ничего не терялось и не перезаписывалось без моего решения.

Нормы: FR-CH-2008, FR-CH-5007, FR-CH-5009, FR-CH-5010, NFR-CH-5001. Сценарии: UC-COMPATIBILITY-5001, UC-DELIVERY-6001. SRS - [srs.md](../srs.md).

## Критерии приёмки

1. [FR-CH-2008] [UC-COMPATIBILITY-5001#4] [UC-COMPATIBILITY-5001#5] [UC-DELIVERY-6001#9б]
   - Дано раздел `config` версии 1, плагин версии 2 с `migrate(fromVersion, data)`
   - Когда ядро активирует плагин
   - Тогда `migrate` вызван до активации, итог записан; ядро проверяет раздел по схеме - подмножеству JSON Schema - до активации
2. [FR-CH-2008] [UC-COMPATIBILITY-5001#4а]
   - Дано раздел версии 3, плагин версии 2 (плагин откатили)
   - Когда ядро активирует плагин
   - Тогда плагин не активируется, данные не тронуты, причина в журнале
3. [FR-CH-2008] [UC-COMPATIBILITY-5001#5а]
   - Дано файл `config` отредактирован руками: значение не по схеме; затем исправлен во время работы
   - Когда ядро проверяет раздел
   - Тогда отказ только владельцу раздела; значение остаётся прежним; при правке во время работы отказ в журнале; плагин видит только свой раздел, чужой хост не пишет; воркспейс перекрывает слой пользователя; ключ вне подмножества схемы - ошибка схемы
4. [FR-CH-5007] [UC-COMPATIBILITY-5001#4б]
   - Дано `migrate` бросил исключение, вернул не объект, либо не объявлен
   - Когда ядро мигрирует раздел
   - Тогда плагин не активируется, ни один слой раздела не записывается, запись `migrate-error` со слоем, исходной версией и причиной; остальные плагины работают
5. [FR-CH-5009] [UC-COMPATIBILITY-5001#1а]
   - Дано файл воркспейса `{projects, lastProjectId}` с лишним полем верхнего уровня
   - Когда хук приложения переводит формат
   - Тогда лишнее поле осталось в переведённом файле; `<файл>.v1.bak` хранит прежний файл без изменений; повторное открытие перевод не повторяет
6. [FR-CH-5010]
   - Дано плагин удаляется, затем появляется плагин с тем же `id`; в другом случае плагин только выключен
   - Когда ядро удаляет плагин
   - Тогда `state` в открытом воркспейсе стёрт, новый плагин начинает с `defaults`; `config` слоёв остаётся и назван в `left` и в журнале; выключение разделы не стирает
7. [NFR-CH-5001] [UC-COMPATIBILITY-5001#4] [UC-COMPATIBILITY-5001#4а] [UC-COMPATIBILITY-5001#4б] [UC-COMPATIBILITY-5001#5а]
   - Дано файлы слоёв и `state` до запуска и после запуска плюс повторного, в сценариях: миграция, откат версии плагина, сбой `migrate`, отказ по схеме, правка файла извне, битый файл
   - Когда запуски проходят
   - Тогда потерянных или перезаписанных без решения человека разделов - 0; раздел плагина, которого исход не касается, после запуска такой же
