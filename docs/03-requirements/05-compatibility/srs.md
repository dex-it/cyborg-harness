# SRS фичи 05 - совместимость, версии и данные

## 1. SRS overview

Как обновление ядра и плагина не ломает соседей и не теряет данные: проверка `engines.cyborg` до запуска кода, версии API и контрактов, устаревание членов контракта, разделы `config` и `state` с миграциями и их сохранность, снимок публичного API. Закрывает BR-CH-002, BR-CH-008. Сценарии - [пользователь после обновления](../../02-use-cases/user-after-upgrade/scenario.md), [плагин переживает обновление ядра](../../02-use-cases/plugin-survives-core-upgrade/scenario.md). Устройство - [SAD](../../04-architecture/design/sad.md), 3.3 и 3.10; правила контрактов - `contracts/README.md`. Метод проверки называет тест ядра (`core/test`), тест playground (`playground/test`, `playground/src/main/*.test.ts`) или дымовой тест окна (`playground/scripts/smoke.mjs`, `npm run smoke`). Что не сделано - помечено «Ещё нет» или «Отложено», остаток - [дорожная карта](../../06-plans/roadmap.md). Раскладка норм по фичам - [03-requirements](../README.md).

Что лежит в соседних фичах. Воркспейс, замок, «Недавние», битый файл целиком, второй запуск - FR-CH-1014; граф и каскад отказа - FR-CH-1004; правка файла руками и угроза У-41 - FR-CH-1021; журнал и окно «Плагины Cyborg» - FR-CH-1010; выгрузка диагностики - NFR-CH-1005; восстановление документов и сессий (шаги 6-7 сценария «после обновления») - FR-CH-2005, FR-CH-2009; стирание секретов и `granted` при удалении плагина - FR-CH-2014 и фича 03. Здесь они берутся ссылкой на ID.

## 2. Требования

### FR-CH-1002 Проверка совместимости до запуска кода

- **Требование:** до запуска кода `engines.cyborg` плагина сверяется с версией API плагинов (`ctx` и элементы ядра). Несовместимый плагин не загружается: отказ графа с причиной «нужен API Cyborg <диапазон>, есть <версия>». Диапазон, нижняя граница которого выше версии API ядра (`^1.5` на ядре 1.3), отклоняется так же, как диапазон другой мажорной версии. Отказ каскадирует на тех, кто требует плагин через `requires`; потребитель через `optional` остаётся.
- **traced from:** BR-CH-002, BR-CH-006, BR-CH-008; `user-after-upgrade`, шаг 2, расширение 2а; `plugin-survives-core-upgrade`, шаг 3, расширения 3а, 3б.
- **источник:** [SAD, 3.3](../../04-architecture/design/sad.md#33-версии-и-миграции); `core/src/graph.ts`, `core/src/semver.ts`.
- **verification:** испытание - `core/test/graph.test.ts` («отказ по engines каскадирует на зависимых, optional переживает»), `core/test/semver-manifest.test.ts` («диапазоны: каретка, тильда, префикс и звезда» - `^1.4` не принимает 1.3.9; «манифест под другой API…» - `^1.3` на 1.2.0).
- **класс:** Functions.

### FR-CH-1012 Версии API плагинов и контрактов

- **Требование:** API плагинов (`ctx` и элементы ядра) и контракты версионируются семантически. Элемент ядра не удаляется и не меняет атрибуты в пределах мажорной версии. Минорная версия контракта добавляет только необязательное; мажорная - новый тип в карте `Contracts`. Поставщик может давать две мажорные версии контракта сразу, каждый потребитель получает ту, что просил. Мажорная версия в `get` и `all` должна лежать в диапазоне манифеста потребителя, иначе `NotDeclared`. Член с `@deprecated` живёт минимум до следующей мажорной версии; запись его вызовов - FR-CH-5005.
- **traced from:** BR-CH-001, BR-CH-002, BR-CH-008; `plugin-survives-core-upgrade`, шаг 4, расширение 4г.
- **источник:** [SAD, 3.3](../../04-architecture/design/sad.md#33-версии-и-миграции); `contracts/README.md`.
- **verification:** испытание - `core/test/graph.test.ts` («поставщик с двумя мажорными версиями обслуживает старого и нового потребителя», «несовместимая мажорная версия поставщика - как отсутствие»), `core/test/registry.test.ts` («потребитель получает свою мажорную версию…», «мажорная версия в get и all должна лежать в диапазоне манифеста»), `core/test/contracts-types.ts` (`npm run typecheck`). Стабильность `ctx` и элементов ядра в пределах мажорной версии автоматически не проверяется - FR-CH-5003.
- **класс:** Functions.

### FR-CH-2008 Разделы `config` и `state`

- **Требование:** плагин видит только свой раздел `config` (`ctx.config`) и `state` (`ctx.state`); чужой раздел хост не пишет. `config` - слои пользователя и воркспейса, воркспейс перекрывает; `state` лежит в каталоге приложения по ключу воркспейса. Манифест объявляет версию и схему раздела. Ядро проверяет раздел по схеме - подмножеству JSON Schema, где ключ вне подмножества - ошибка схемы, - до активации и при правке файла извне. Версия раздела ниже версии плагина - ядро до активации вызывает `migrate` и записывает итог (сбой `migrate` - FR-CH-5007); выше - плагин не активируется, данные не трогаются, причина в журнале; раздел не по схеме - отказ только этому плагину. Правка файла извне доходит до `ctx.config.onChange`; не прошедшая проверку оставляет прежнее значение. Значений секретов в `config` и `state` нет, только ссылка `$secret`. Документ воркспейса без поля `cyborg` переводит хук приложения `migrate` при открытии; ядро записывает итог один раз и оставляет копию `.v1.bak` (поля вне списка переноса - FR-CH-5009).
- **traced from:** BR-CH-002; `user-after-upgrade`, шаги 4-5, расширения 1а, 4а, 5а.
- **источник:** [SAD, 3.3](../../04-architecture/design/sad.md#33-версии-и-миграции), [SAD, 3.10](../../04-architecture/design/sad.md#310-главный-конфиг-и-состояние); `core/src/config.ts`, `core/src/json-schema.ts`.
- **verification:** испытание - `core/test/config.test.ts`, `core/test/json-schema.test.ts`, `core/test/loader.test.ts` («откат версии плагина…», «миграция config идёт в хосте…», «схема раздела из манифеста…»), `core/test/workspace.test.ts` («перенос старого формата хуком приложения…», «правка файла извне доходит до ctx.config.onChange…»), `playground/src/main/legacy-workspace.test.ts` («перенос {projects, lastProjectId}…»), `core/test/trust.test.ts` («provide и section.write…»), `playground/src/main/plugins.test.ts` («схема раздела: файл из каталога плагина…»).
- **класс:** Functions.

### FR-CH-5001 Одно место версии API

- **Требование:** версия API плагинов определена в одном месте; ядро, приложение и проверка плагина вне репозитория берут её оттуда, второго литерала версии в исходниках нет.
- **traced from:** BR-CH-008; `plugin-survives-core-upgrade`, шаг 3.
- **источник:** задача T-03 (#51, PR #72); `core/src/api-version.ts` (`PLUGIN_API_VERSION`).
- **verification:** испытание - `core/test/api-version.test.ts` («мажор PLUGIN_API_VERSION равен мажору @cyborg-harness/contracts»); осмотр - литерал версии только в `core/src/api-version.ts`. Ещё нет: теста, который ищет второй литерал версии API в исходниках. Связь версии API с версиями пакетов - вопрос 5.
- **класс:** Maintainability.

### FR-CH-5002 Демо-контракты вне боевого пакета

- **Требование:** пакет `@cyborg-harness/contracts` содержит только контракты, на которые действуют гарантии FR-CH-1012; демо-контракты примеров лежат вне него и в снимок API (FR-CH-5003) не попадают.
- **traced from:** BR-CH-008; `plugin-survives-core-upgrade`, расширение 4а.
- **источник:** задача T-03 (#51, PR #72); карта `Contracts` в `contracts/index.ts`, демо-контракты `demo.*` - `core/examples/contracts.ts`.
- **verification:** осмотр - в `contracts/index.ts` нет демо-контрактов, они дополняют карту из `core/examples/contracts.ts`. Ещё нет: теста, который сверяет ключи карты `Contracts` с перечнем поставляемых контрактов.
- **класс:** Compatibility.

### FR-CH-5003 Снимок публичного API

- **Требование:** публичный API - `PluginContext`, `UiContext`, `PluginPermissions`, поля манифеста, теги `cy-*`, коды `CoreErrorCode`, карта `Contracts` - зафиксирован снимком в репозитории. Удаление члена, смена его атрибутов и новое обязательное поле в пределах мажорной версии роняют сборку; добавление необязательного члена проходит после дополнения снимка.
- **traced from:** BR-CH-008; `plugin-survives-core-upgrade`, расширение 4а.
- **источник:** задачи T-06 (#12), K-21 (#62: эталон снимка - API 1.0 на момент заморозки); [ADR-CH-0002, «Расхождения с текущим кодом»](../../04-architecture/adr/ADR-CH-0002-manifest-and-compatibility.md#расхождения-с-текущим-кодом), п. 3; MOE BR-CH-008.
- **verification:** Ещё нет: T-06; эталон принимает K-21 после K-03, K-06, K-07, K-08, K-09, K-12, K-13 (состав эталона - вопрос 6). Испытание - тест извлекает поверхность и сверяет со снимком: удаление члена даёт падение, добавление необязательного - нет. Сейчас `core/test/contracts-types.ts` проверяет типы карты, но не сверяет их со снимком.
- **класс:** Compatibility.

### FR-CH-5004 Плагин прошлого минорного выпуска на текущем ядре

- **Требование:** плагин, собранный под API предыдущего минорного выпуска, проходит свои тесты на текущем ядре без пересборки; упавший тест роняет сборку так же, как расхождение со снимком.
- **traced from:** BR-CH-008; `plugin-survives-core-upgrade`, шаг 2, расширение 4б.
- **источник:** сценарий `plugin-survives-core-upgrade`, 4б; NFR-CH-1006. Задачи в реестре эпика нет.
- **verification:** Ещё нет. Испытание - CI гоняет тесты плагинов прошлого минорного выпуска на ядре текущего (состав набора - вопрос 7).
- **класс:** Compatibility.

### FR-CH-5005 Журнал вызовов устаревших членов

- **Требование:** плагин, обратившийся к члену контракта с `@deprecated`, попадает в журнал: запись называет контракт, член и вызывающий плагин; вызов выполняется как раньше. Автор видит запись в окне «Плагины Cyborg» (FR-CH-1010) и в выгруженной диагностике (NFR-CH-1005).
- **traced from:** BR-CH-008; `plugin-survives-core-upgrade`, шаги 5-7, расширения 5а, 6а, 7а.
- **источник:** [SAD, 3.3](../../04-architecture/design/sad.md#33-версии-и-миграции), «Устаревание»; [ADR-CH-0002](../../04-architecture/adr/ADR-CH-0002-manifest-and-compatibility.md), п. 5; задача K-06 (#41), ждёт D-00, строка 10 (открыта); MOE BR-CH-008: у каждого члена с `@deprecated` есть запись о вызывающих.
- **verification:** Ещё нет: K-06. Испытание - плагин A вызывает помеченный член плагина B: вызов вернул результат, в журнале запись с A, контрактом и членом. Откуда ядро берёт пометку и как пишутся повторные вызовы - вопросы 1, 2; видит ли запись тест-кит автора - вопрос 4. Запись в трассу операций - NFR-CH-1004 (фича 04).
- **класс:** Functions.

### FR-CH-5006 Журнал изменений API

- **Требование:** выпуск пакета объявлений, у которого снимок API изменился, несёт запись изменений: что добавлено, что объявлено `@deprecated`, что удалено в мажорной версии.
- **traced from:** BR-CH-008; `plugin-survives-core-upgrade`, шаги 7-8.
- **источник:** задача P-01 (#29); [дорожная карта, раздел 6](../../06-plans/roadmap.md#6-совместимость-и-версии). Публикация пакета - фича 06.
- **verification:** Ещё нет: P-01. Осмотр - запись на каждый выпуск, чей снимок (FR-CH-5003) изменился.
- **класс:** Maintainability.

### FR-CH-5007 Сбой миграции раздела

- **Требование:** раздел `config` или `state` с версией ниже версии плагина не мигрирует, если `migrate` бросил исключение, вернул не объект или не объявлен: плагин не активируется, ни один слой раздела не записывается, в журнал идёт запись `migrate-error` со слоем, исходной версией и причиной. Остальные плагины работают.
- **traced from:** BR-CH-002; `user-after-upgrade`, расширение 4б.
- **источник:** [SAD, 3.3](../../04-architecture/design/sad.md#33-версии-и-миграции), «Разделы config и state»; `core/src/config.ts` (`resolveSection`).
- **verification:** испытание - `core/test/config.test.ts` («сбой migrate и отказ validate различаются»), `core/test/stress-sections.test.ts` («migrate бросает не Error - причина читаема…»). Ещё нет: теста, что после сбоя файлы слоёв не изменены и плагин не активен. Изоляция отказа от соседей - FR-CH-1005.
- **класс:** Reliability.

### FR-CH-5008 Поставщик контракта не на просимой мажорной версии

- **Требование:** поставщик, не дающий мажорную версию контракта, которую просит потребитель, для этого потребителя - как отсутствие: потребитель через `requires` не загружается, причина в журнале называет контракт и диапазон; потребитель через `optional` работает без поставщика.
- **traced from:** BR-CH-008, BR-CH-001; `user-after-upgrade`, расширение 3а; `plugin-survives-core-upgrade`, расширение 4г.
- **источник:** [SAD, 3.3](../../04-architecture/design/sad.md#33-версии-и-миграции), «Переход между мажорными версиями»; `core/src/graph.ts`. Граф и каскад - FR-CH-1004.
- **verification:** испытание - `core/test/graph.test.ts` («несовместимая мажорная версия поставщика - как отсутствие» - `requires`; «отказ по engines каскадирует на зависимых, optional переживает» - то же состояние `missing` для `optional`). Ещё нет: отдельного теста `optional` при чужой мажорной версии.
- **класс:** Functions.

### FR-CH-5009 Перевод старого формата не теряет поля

- **Требование:** при переводе старого формата воркспейса `{projects, lastProjectId}` поля верхнего уровня, которых нет в списке переноса, остаются в переведённом файле; копия `<файл>.v1.bak` хранит прежний файл без изменений; повторное открытие перевод не повторяет.
- **traced from:** BR-CH-002; `user-after-upgrade`, расширение 1а.
- **источник:** [SAD, 3.10](../../04-architecture/design/sad.md#310-главный-конфиг-и-состояние); задача PL-06 (#28); [инвентарь Cyborg, пилот P6](../../research/cyborg-migration-inventory.md); хук приложения `playground/src/main/legacy-workspace.ts` (`migrateLegacyWorkspace`), механизм копии и однократности - `core/src/workspace.ts`.
- **verification:** испытание - `playground/src/main/legacy-workspace.test.ts` («перенос {projects, lastProjectId}: …копия старого файла»), `core/test/workspace.test.ts` («перенос старого формата хуком приложения: копия .v1.bak, … повтор не идёт»). Ещё нет: теста с полями вне списка (`commands`, неизвестные); переноса ключей `localStorage` Cyborg в `state` (PL-06, вопрос 10).
- **класс:** Reliability.

### FR-CH-5010 Удаление плагина стирает его разделы

- **Требование:** удаление плагина стирает его разделы: `config` в слое пользователя и в слое открытого воркспейса, `state` открытого воркспейса. Плагин с тем же `id`, появившийся после удаления, начинает со значений `defaults`. Выключение плагина его разделы не стирает.
- **traced from:** BR-CH-002, BR-CH-005; угроза У-18.
- **источник:** [модель угроз, У-18](../../04-architecture/design/threat-model.md#52-плагин-против-плагина) (открыта); задача K-10 (#47); SAD 3.7. Секреты и `granted` при удалении - FR-CH-2014 и фича 03.
- **verification:** Ещё нет: K-10. Испытание - тест: у плагина разделы в обоих слоях и в `state`; удаление убирает их из файлов; плагин с тем же `id` читает `defaults`; выключение оставляет разделы на месте. Область стирания вне открытого воркспейса - вопрос 8.
- **класс:** Security.

### NFR-CH-1006 Совместимость API

- **Требование:** ломающих изменений публичного API ядра и контрактов `@cyborg-harness/contracts` в минорных выпусках - 0. Плагин, собранный под API 1.x, загружается и проходит свои тесты на ядре 1.y при y не меньше x: плагинов прошлых минорных выпусков, не прошедших свои тесты на текущем ядре, - 0. Замер: CI на каждом выпуске 1.y против снимка (FR-CH-5003) и набора плагинов прошлого минорного выпуска (FR-CH-5004); неуспех - расхождение снимка без повышения мажорной версии либо упавший тест плагина. Версия API записана в одном месте (FR-CH-5001).
- **traced from:** BR-CH-008.
- **источник:** [SAD, 3.3](../../04-architecture/design/sad.md#33-версии-и-миграции); FR-CH-1012; MOE BR-CH-008.
- **verification:** испытание - `core/test/semver-manifest.test.ts` (`engines.cyborg`), `core/test/graph.test.ts` (две мажорные версии поставщика). Ещё нет: снимок API в CI (FR-CH-5003, T-06), плагин прошлого минорного выпуска на текущем ядре (FR-CH-5004).
- **класс:** Compatibility.

### NFR-CH-5001 Сохранность разделов

- **Требование:** разделов `config` и `state`, потерянных или перезаписанных без решения человека, - 0 при каждом исходе: миграция раздела, откат версии плагина, сбой `migrate`, отказ по схеме, правка файла извне, битый файл. Раздел плагина, которого исход не касается, после запуска такой же, как до него. Замер: содержимое файлов слоёв и `state` до запуска и после, один запуск плюс повторный; неуспех - раздел исчез или изменился, хотя не мигрировался (FR-CH-2008) и не записан самим плагином.
- **traced from:** BR-CH-002 (MOE: потерянных разделов - 0).
- **источник:** MOE BR-CH-002; [SAD, 3.3](../../04-architecture/design/sad.md#33-версии-и-миграции); FR-CH-1014, FR-CH-1021, FR-CH-5007.
- **verification:** испытание - `core/test/loader.test.ts` («откат версии плагина: раздел config новее манифеста - … данные целы»), `core/test/workspace.test.ts` («битый файл пользователя не роняет открытие: … файл не перезаписан»), `core/test/config.test.ts` («хранилище: мигрированный слой записывается сразу, чужие разделы не трогаются»), `playground/src/main/plugins.test.ts` («старт: … раздел plugins не теряется»). Ещё нет: теста на сбой `migrate` (FR-CH-5007).
- **класс:** Reliability.

## 3. Открытые вопросы

Решения за владельца не принимаются; после каждого вопроса - предложение составителя.

1. **Откуда ядру знать об `@deprecated` при выполнении.** Пометка живёт в типах, ядро их не видит. Варианты: (а) аннотация в манифесте поставщика рядом с `guard`; (б) генерация из типов `@cyborg-harness/contracts`; (в) отдельная машинерия. Держат: D-00, строка 10 (аннотация прав на членах контракта), [SAD, раздел 8, вопрос 6](../../04-architecture/design/sad.md#8-открытые-вопросы), сценарий `plugin-survives-core-upgrade` (6а, вопрос 1); блокирует K-06, FR-CH-5005. Предложение: решить вместе с правами, (а) или (б): одна аннотация на члене, из неё берутся право и признак устаревания.
2. **Как пишутся повторные вызовы устаревшего члена.** Варианты: каждый вызов; одна запись на пару «член, вызывающий» со счётчиком и временем последнего; одна запись за запуск. Держит сценарий `plugin-survives-core-upgrade` (5а, вопрос 2). Предложение: запись на пару со счётчиком, как для `denied`: шумный плагин не вытесняет чужие записи.
3. **Нижняя граница `engines.cyborg`.** BR-CH-008 обещает «не ниже x», руководство учит `^1`, и такой диапазон пускает плагин, собранный под 1.5, на ядро 1.3. Ядро нижнюю границу проверяет (FR-CH-1002); объявить её может только автор. Допустимый синтаксис ядра - `^1.5`; запись `>=1.5 <2` не разбирается (`isValidRange('>=1')` ложно). Держит сценарий `plugin-survives-core-upgrade` (3б, вопрос 3). Предложение: руководство и сборка автора (фича 07) ставят нижней границей минорную версию, под которую собран плагин (`^1.5`).
4. **Видит ли тест-кит автора устаревшие вызовы.** Держит сценарий `plugin-survives-core-upgrade` (7а, вопрос 4); норма лежит в фиче 07. Предложение: тест-кит показывает те же записи, что окно.
5. **Связь версии API с версиями пакетов.** Варианты: (а) версия API равна версии `@cyborg-harness/contracts`; (б) независимы, связь только в журнале изменений. Руководство ([версии](../../guide/features/versions.md)) говорит «связана», код этого не держит. Держат: T-03, P-01 (ждёт D-00). Предложение: (а) для API плагинов и контрактов - снимок покрывает оба, и `engines.cyborg` называет версию одного пакета.
6. **Состав эталона снимка 1.0 (K-21).** Эталон нельзя принять, пока открыты строки D-00 1, 2 (K-03), 8 (K-07, K-08, K-09), 9 (K-21), 10 (K-06). Варианты: заморозить после закрытия всех; заморозить сейчас и расширять только дополнением. Предложение: снимок T-06 завести сразу, запрет на удаление и смену атрибутов включить заморозкой K-21.
7. **Из чего набор плагинов «прошлого минорного выпуска» (FR-CH-5004).** Варианты: встроенные плагины и их тесты на теге прошлого выпуска; плюс шаблон плагина (фича 07). Предложение: встроенные плагины на теге прошлого минорного выпуска.
8. **Область стирания при удалении плагина (FR-CH-5010).** Варианты: (а) только слой пользователя и открытый воркспейс; (б) ещё `state` всех воркспейсов каталога приложения; (в) ещё файлы `config` других воркспейсов. Держат: У-18, K-10 (без D-00). Предложение: (б) - `state` лежит в каталоге приложения, и без него плагин с тем же `id` в другом воркспейсе унаследует память; файлы `config` воркспейсов - файлы человека, их ядро молча не правит.
9. **Копия повреждённого файла `<файл>.corrupt-<время>`.** Варианты: делать (как в Cyborg, FR-1026); не делать - файл не перезаписывается и так (FR-CH-1014). Держат: K-18 (в), [спорный пункт 17](../../04-architecture/design/sad2-disputed-points.md); приёмка K-18 - тест или явная запись «не делаем». Предложение: не делать, пока ядро не заменяет битый файл.
10. **Кто переносит ключи `localStorage` Cyborg в `state`.** Варианты: приложение один раз при первом запуске; ядро; вид плагина. Держит PL-06; SAD 3.10 допускает чужие поля только в переводе старого формата. Предложение: приложение, ядро ключей не знает.
