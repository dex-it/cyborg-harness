# BRD фичи 05 - совместимость и миграции

> Бизнес-требования фичи: что получает пользователь, автор плагина или приложение, сгруппированное по потребности, а не по компонентам [SAD](../../04-architecture/design/sad.md). Каждое выводится из BR продукта ([BRD](../../01-product/brd.md)); [нормы](srs.md) и [истории](stories/) трассируются на эти требования. Корпус писался от обратного (SAD, код, затем BRD и SRS), поэтому требования фичи выведены из уже существующих норм и сверены с BR продукта: `origin: derived`. Решение «BRD фич нет» заменено требованием раскладки `docs-layout` (принято по поручению владельца 2026-11-11). Идентификаторы `BR-CH-05NN` - блок номеров фичи.

## Бизнес-требования

### BR-CH-5001 Совместимость плагина проверена до запуска его кода

- **Требование:** плагин, которому не подходит версия ядра, API или контракта поставщика, получает отказ с причиной до запуска кода; версия API объявлена в одном месте.
- **traced from:** BR-CH-008.
- **rationale:** reason - сторонний автор не следит за ядром и узнаёт о поломке от пользователя.
- **MOE:** плагинов с несовместимой версией, запущенных, - 0; отказ называет требуемую и фактическую версию.

### BR-CH-5002 Ломающее изменение API не выходит минорной версией

- **Требование:** снимок публичного API, журнал изменений и проверка плагина прошлого минорного выпуска ловят ломающее изменение до выпуска; демо-контракты не попадают в боевой пакет.
- **traced from:** BR-CH-008.
- **rationale:** reason - обещание «1.x работает на любом 1.y не ниже x» не проверяется глазами; relationships - NFR-CH-1006.
- **MOE:** ломающих изменений публичного API в минорных выпусках - 0, ловит снимок API в CI; плагинов прошлых минорных выпусков, не прошедших свои тесты на текущем ядре, - 0.

### BR-CH-5003 Устаревшее видно до удаления

- **Требование:** устаревший член живёт мажорную версию перед удалением, а его вызовы пишутся в журнал.
- **traced from:** BR-CH-008.
- **rationale:** reason - автор плагина узнаёт об удалении заранее, не в день выпуска.
- **MOE:** у каждого члена с `@deprecated` есть запись о вызывающих.

### BR-CH-5004 Данные плагина сохраняются при обновлении и сбое миграции

- **Требование:** разделы `config` и `state` переводятся на новую схему миграцией; сбой миграции, раздел новее плагина и перевод старого формата не теряют данные и отказывают только своему плагину.
- **traced from:** BR-CH-002.
- **rationale:** reason - формат раздела меняется с версией плагина, а файл правят руками.
- **MOE:** разделов `config` и `state`, потерянных или перезаписанных без решения человека, - 0 при каждом исходе (NFR-CH-5001).

### BR-CH-5005 Удаление плагина стирает его разделы и только их

- **Требование:** удаление плагина стирает его разделы `config` и `state`, не трогая разделы соседей.
- **traced from:** BR-CH-002, BR-CH-005.
- **rationale:** reason - остаток данных удалённого плагина - утечка (BR-CH-005), а удаление чужого - потеря (BR-CH-002).
- **MOE:** разделов соседей, изменённых удалением, - 0; разделов удалённого плагина после удаления - 0.
