# ST-4005 Окно «Плагины Cyborg» объясняет состояние и ресурсы

Как человек, у которого что-то не так с плагином, я хочу открыть одно окно и увидеть состояние, причину, права и расход ресурсов, чтобы разобраться без чтения кода.

Нормы: FR-CH-1010, FR-CH-4017, FR-CH-4018. Сценарии: UC-COMPATIBILITY-5001, UC-OBSERVABILITY-4001, UC-PLUGIN-HOST-1001. SRS - [srs.md](../srs.md).

## Критерии приёмки

1. [FR-CH-1010] [UC-PLUGIN-HOST-1001#5] [UC-COMPATIBILITY-5001#7]
   - Дано плагины в разных состояниях и записи журнала `invalid`, `not-found`, `rejected`, `failed`, `denied`, `host-down`, `key-conflict`
   - Когда человек открывает окно «Плагины Cyborg»
   - Тогда у плагина состояние, причина из журнала словами, хост, время запуска, объявленные права словами и журнал плагина вместе с записями его хоста; у каждой записи описание и уровень
2. [FR-CH-1010]
   - Дано окно без включённых плагинов
   - Когда человек открывает окно
   - Тогда состояние нормальное, управление плагинами (выгрузить, загрузить, «Включить снова») доступно
3. [FR-CH-4017]
   - Дано хост с тремя плагинами и вид во фрейме
   - Когда человек смотрит ресурсы
   - Тогда у хоста и у вида показаны занятая память и загрузка процессора; для хоста с несколькими плагинами значение относится к хосту, а не делится
4. [FR-CH-4018] [UC-OBSERVABILITY-4001#4]
   - Дано плагин превысил предел частоты строк и выключен
   - Когда окно показывает строки
   - Тогда видна сводная запись со счётом пропущенных, плагин выключен записью `switched-off`

Открыто: Норма FR-CH-4017 отложена: разбивку K-28 - K-30 и K-31 в «Позже» владелец не принял (вопрос 12 SRS), критерий 3 описывает целевое поведение и станет проверяемым с задачей K-31.
