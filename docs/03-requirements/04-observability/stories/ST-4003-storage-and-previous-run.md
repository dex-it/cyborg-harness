# ST-4003 Журнал и трасса переживают закрытие: файл, ротация, причина прошлого сбоя

Как человек, у которого вчера что-то сломалось, я хочу, чтобы сегодня после перезапуска причина сбоя была видна в окне «Плагины Cyborg», чтобы не ловить сбой заново.

Нормы: FR-CH-4003, FR-CH-4012, FR-CH-4013, FR-CH-4014, NFR-CH-1005. Сценарии: UC-OBSERVABILITY-4001. SRS - [srs.md](../srs.md).

## Критерии приёмки

1. [FR-CH-4012] [UC-OBSERVABILITY-4001#4] [UC-OBSERVABILITY-4001#4в]
   - Дано журнал и трасса работают, `diagnostics.log` достиг 2 МиБ
   - Когда ядро пишет в файл в `userData`
   - Тогда файл ротируется по размеру; хранится до 5 файлов по 2 МиБ на воркспейс, срока хранения нет
2. [NFR-CH-1005] [UC-OBSERVABILITY-4001#5] [UC-OBSERVABILITY-4001#4б]
   - Дано в запуске были записи с ошибкой и записи жизненного цикла (`failed`, `host-down`, `switched-off`)
   - Когда приложение закрыто штатно, хост плагина упал, приложение убито без закрытия
   - Тогда потерянных записей с ошибкой и жизненного цикла - 0 при штатном закрытии и падении хоста; в убитом приложении теряются только обычные записи последней секунды: ошибки и жизненный цикл уходят сразу (не чаще раза в 20 мс), остальные пакетом раз в секунду
3. [FR-CH-4012] [UC-OBSERVABILITY-4001#4а]
   - Дано нет места на диске или нет прав на `userData`
   - Когда запись в файл не удаётся
   - Тогда операции не отказывают; записи остаются в кольце и пакете; на серию отказов одна запись `диагностика` уровня `error` с кодом ошибки (`ENOSPC`), без текста с путём; приложение узнаёт через `onProblem`; когда диск вернулся, накопленное уходит в файл
4. [FR-CH-4013] [UC-OBSERVABILITY-4001#5] [UC-OBSERVABILITY-4001#6]
   - Дано вчера плагин упал, сегодня приложение запущено заново
   - Когда окно «Плагины Cyborg» показывает плагин
   - Тогда причина последнего сбоя в прошлом запуске показана отдельно от состояния текущего; прошлый запуск - последний запуск воркспейса до текущего (его начало пишется записью `run`)
5. [FR-CH-4014] [UC-OBSERVABILITY-4001#6]
   - Дано в прошлом запуске плагин получил `switched-off`
   - Когда ядро выводит состояние в новом запуске
   - Тогда записи прошлого запуска состояние не меняют: оно выводится только из записей текущего
6. [FR-CH-4003] [UC-OBSERVABILITY-4001#3а]
   - Дано хост завис или упал посреди цепочки, операция не вернулась
   - Когда хост перезапущен
   - Тогда операция кончается обычной записью с `code: "HostGone"`, отдельной записи нет; виновник - в записи `host-down` журнала
