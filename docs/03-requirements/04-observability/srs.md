# SRS фичи 04 - наблюдаемость

## 1. SRS overview

Что ядро записывает и показывает: журнал и окно «Плагины Cyborg», трасса операций на границах плагинов, журнал плагина, хранение и выгрузка диагностики. Закрывает BR-CH-006 (наблюдаемость). Сценарии - [причина сбоя по трассе](../../02-use-cases/diagnose-failure-by-trace/scenario.md), [плагин падает](../../02-use-cases/plugin-failure-isolated/scenario.md). Устройство - [SAD](../../04-architecture/design/sad.md), 3.2 и 3.5; границы доверия - [модель угроз, раздел 4](../../04-architecture/design/threat-model.md#4-границы-доверия). Метод проверки называет тест ядра (`core/test`), тест playground (`playground/test`, `playground/src/main/*.test.ts`) или дымовой тест окна (`playground/scripts/smoke.mjs`, `npm run smoke`). Что не сделано - помечено «Ещё нет» или «Отложено», остаток - [дорожная карта](../../06-plans/roadmap.md). Состав: FR-CH-1010 (журнал и окно, сделано), FR-CH-4001…4008 (трасса, K-28), FR-CH-4009…4010, 4018 (`ctx.log` и вывод хоста, K-29), FR-CH-4011…4016 (хранение и выгрузка, K-30), FR-CH-4017 (ресурсы, K-31); меры NFR-CH-1004, 1005, 4001, 4002. Функции, которые раньше лежали в NFR-CH-1004 и NFR-CH-1005, вынесены в FR; в NFR остались меры. Открытые вопросы - раздел 3, покрытие сценария - раздел 4. Раскладка норм по фичам - [03-requirements](../README.md).

## 2. Требования

### FR-CH-1010 Журнал и окно «Плагины Cyborg»

- **Требование:** ядро ведёт журнал плагинов: отказы загрузки (`invalid`, `not-found`, `rejected`), ошибки активации, отказы прав `denied`, падения и перезапуски хостов, конфликты сочетаний. У каждой записи есть описание словами и уровень. Окно «Плагины Cyborg» показывает у плагина состояние, причину из журнала, хост, время запуска, объявленные права словами и журнал плагина вместе с записями его хоста; даёт выгрузить, загрузить и «Включить снова» плагин, снятый сбоем. Окно без плагинов - нормальное состояние: управление плагинами в нём доступно.
- **traced from:** BR-CH-006.
- **источник:** [SAD, 3.2](../../04-architecture/design/sad.md#32-загрузка-плагинов), [SAD, 3.5](../../04-architecture/design/sad.md#35-изоляция-сбоев-хосты-и-сторож).
- **verification:** испытание - `core/test/status.test.ts`, `playground/test/plugins-model.test.ts`, `core/test/os.test.ts` («права в манифесте: … права словами»), `playground/src/main/plugins.test.ts` («служба окна: снимок с причиной и журналом, «Включить снова»…»); дымовой тест - «окно: заглушка с причиной, журнал плагина, «Включить снова»».
- **класс:** Functions.

### FR-CH-4001 Запись операции на границе

- **Требование:** операция, прошедшая границы плагинов - сообщение хоста с главным процессом (Г1), вызов моста из вида (Г2), член контракта, команда и событие контракта (Г3), вызов `ctx.os` с решением права (Г4, Г5), - даёт в трассе одну запись, сколько бы границ она ни прошла: вызов `ctx.os` проходит Г1 и Г4, член контракта плагина другого хоста - Г1, Г3 и снова Г1. Запись несёт время, id цепочки, вызывающего, адресата (плагин, контракт с версией и член, команда либо метод шлюза), пройденные границы (последняя - та, где операция кончилась), право, которым операция допущена, длительность, размер аргументов и размер результата в байтах, итог. Поля и значения записи - английские имена в нотации кода: поля - camelCase (`durationMs`); значения закрытых наборов - kebab-case, как `kind` записей журнала: граница `host` (Г1), `bridge` (Г2), `contract` (Г3), `os` (Г4), `net` (Г5), итог `outcome` - `ok` либо `error`; код ошибки `code` - имя из `CoreErrorCode` (`PermissionDenied`), как в API; участник - `род:имя` (`plugin:jira`, `view:jira`, `command:jira.create`, `contract:sessions.current@1#active`, `os:net.fetch`); причина отказа `reason` - текстом на английском. Вызов члена с `@deprecated` записывается так же; журнал таких вызовов - FR-CH-1012.
- **traced from:** BR-CH-006; шаг 2 (`diagnose-failure-by-trace`).
- **источник:** запрос владельца (2026-11-08); одна запись на операцию с пройденными границами, английские имена полей и значений - решение владельца (2026-11-08, вопрос 13); границы - [модель угроз, раздел 4](../../04-architecture/design/threat-model.md#4-границы-доверия); [дорожная карта, раздел 4](../../06-plans/roadmap.md#4-наблюдаемость); точка записи хоста - `Endpoint` в `core/src/rpc.ts`; K-28.
- **verification:** Ещё нет: трассы в ядре нет (K-28). Испытание - тест ядра: по одной операции каждой границы дают по одной записи со всеми полями; вызов `ctx.os` и член контракта плагина другого хоста - по одной записи с перечнем пройденных границ; сообщение хоста неверной формы - запись с `boundaries: ["host"]` и `code: "Invalid"`; дымовой тест - вызов моста из вида.
- **класс:** Functions.

### FR-CH-4002 Цепочка операций

- **Требование:** первая операция цепочки - вызов моста из вида, сочетание, событие или первая операция плагина, вызванная не из другой операции - даёт цепочке идентификатор, равный id своей записи; команда, член контракта другого плагина и вызов `ctx.os`, порождённые этой операцией, несут тот же id цепочки.
- **traced from:** BR-CH-006; шаги 1, 2, 9, 10, расширение 10а (`diagnose-failure-by-trace`).
- **источник:** [дорожная карта, раздел 4](../../06-plans/roadmap.md#4-наблюдаемость) (цепочку несёт механизм, которым сторож определяет виновника: `Owner` в `core/src/rpc.ts`); K-28.
- **verification:** Ещё нет (K-28). Испытание - тест ядра: клик вида -> команда -> член контракта другого плагина -> `ctx.os` дают записи с одним id цепочки, равным id первой; цепочка от события и от сочетания строится так же.
- **класс:** Functions.

### FR-CH-4003 Итог операции

- **Требование:** итог операции записан кодом: успех (`outcome: "ok"`) либо ошибка (`outcome: "error"`) с кодом ядра в `code` (`PermissionDenied`, `Unavailable` и прочие `CoreErrorCode`); вызов `ctx.os` без права кончается записью с кодом `PermissionDenied`, и вызов не выполняется.
- **traced from:** BR-CH-006; шаг 3, расширение 3б (`diagnose-failure-by-trace`).
- **источник:** запрос владельца (2026-11-08); [SAD, 3.7](../../04-architecture/design/sad.md#37-безопасность-данных-и-контроль-плагинов); отказ в журнале - FR-CH-2007 (фича 03), отказ жизненного цикла - FR-CH-1010; K-28.
- **verification:** Ещё нет (K-28). Испытание - тест ядра: операция с исключением и вызов `ctx.os` без права дают запись с кодом; запись `denied` в журнале остаётся (`core/test/os.test.ts`, «без прав: свои каталоги работают, чужой путь - PermissionDenied и запись в журнале»).
- **класс:** Functions.

### FR-CH-4004 Содержимое в запись не попадает

- **Требование:** запись трассы несёт размеры аргументов и результата в байтах, а их содержимое в запись не попадает.
- **traced from:** BR-CH-006, BR-CH-005; расширение 7б (`diagnose-failure-by-trace`).
- **источник:** [SAD, 3.7](../../04-architecture/design/sad.md#37-безопасность-данных-и-контроль-плагинов) («ядро не логирует ни результат `resolve`, ни аргументы с ним»); У-17 ([модель угроз, 5.2](../../04-architecture/design/threat-model.md#52-плагин-против-плагина)); K-28. Запись содержимого по флагу отладки решает владелец, решения нет (вопрос 6).
- **verification:** Ещё нет (K-28). Испытание - тест ядра: операция с маркерной строкой в аргументе и в результате; запись содержит размеры и не содержит маркера. Мера - NFR-CH-4002. Для журнала отказов есть `core/test/security-gateway.test.ts` («безопасность: отказ process.run не кладёт аргументы программы … в журнал»).
- **класс:** Security.

### FR-CH-4005 Частые потоки пишутся счётчиком

- **Требование:** вывод pty и события `fs.watch` ядро не пишет записью на каждое сообщение: за интервал пишется одна запись-счётчик с числом сообщений и объёмом в байтах.
- **traced from:** BR-CH-006, BR-CH-007; расширение 2а (`diagnose-failure-by-trace`).
- **источник:** [дорожная карта, раздел 4](../../06-plans/roadmap.md#4-наблюдаемость) (частые потоки - счётчиками); NFR-CH-1001 (вывод терминала до кадра, событие `fs.watch`); K-28. Длина интервала не задана (вопрос 10).
- **verification:** Ещё нет (K-28). Испытание - тест ядра: поток из 5000 сообщений pty за интервал даёт одну запись со счётом 5000 и суммой байтов (рядом - `core/test/stress-pty.test.ts`, «вывод идёт мелкими кусками»).
- **класс:** Performance.

### FR-CH-4006 Вызывающий в общем хосте

- **Требование:** запись несёт id хоста и имя вызывающего плагина. Сторонний плагин всегда один в своём хосте, и его имя определено каналом; в хосте с несколькими плагинами имя называет отметка хоста: запись различает плагины хоста для диагностики и не доказывает, что операцию начал именно названный плагин.
- **traced from:** BR-CH-006; расширение 2б (`diagnose-failure-by-trace`).
- **источник:** [SAD, 3.5](../../04-architecture/design/sad.md#35-изоляция-сбоев-хосты-и-сторож) (граница доверия - процесс хоста, внутри хоста плагины неразличимы); FR-CH-2012 (фича 03); У-11 (ядро принимает сообщение, только если названный плагин живёт в этом хосте), У-04 (этап 2 снимет вопрос); K-28.
- **verification:** Ещё нет (K-28). Испытание - тест ядра: операция плагина из хоста с двумя плагинами несёт id хоста и имя; сверка «названный плагин живёт в этом хосте» - `core/test/trust.test.ts`. Осмотр - руководство автора называет это диагностической точностью (фича 07; вопрос 9).
- **класс:** Security.

### FR-CH-4007 Запуск программы

- **Требование:** запуск программы по праву `process` или `pty` ядро пишет записью с правом, а завершение - записью с кодом завершения; что программа делала внутри, ядро не видит и не записывает.
- **traced from:** BR-CH-006; расширение 2г (`diagnose-failure-by-trace`).
- **источник:** граница Г6 ([модель угроз, раздел 4](../../04-architecture/design/threat-model.md#4-границы-доверия)); FR-CH-2007 (фича 03); K-28.
- **verification:** Ещё нет (K-28). Испытание - тест ядра: `ctx.os.process.run` с ненулевым кодом и `pty.spawn` с выходом дают запись запуска с правом и запись завершения с кодом, без вывода программы.
- **класс:** Functions.

### FR-CH-4008 Трасса недоступна плагину

- **Требование:** ни один член `ctx` и ни один вызов моста вида не возвращает плагину записи трассы других плагинов; записи читает окно ядра.
- **traced from:** BR-CH-006, BR-CH-005; расширение 2в (`diagnose-failure-by-trace`).
- **источник:** NFR-CH-1004 (прежняя редакция: «чужие записи плагину недоступны»); А7 ([модель угроз, раздел 2](../../04-architecture/design/threat-model.md#2-активы)). Чтение плагином своих записей и отдельное право - решение владельца, решения нет (вопрос 5).
- **verification:** Ещё нет (K-28). Осмотр - в `PluginContext` (`contracts/plugin.ts`) и в мосте вида нет члена, возвращающего трассу; испытание - тест ядра, что после K-28 это остаётся так.
- **класс:** Security.

### FR-CH-4009 Строка `ctx.log`

- **Требование:** плагин пишет строку через `ctx.log` с уровнем `info`, `warn` или `error`; ядро кладёт её в журнал плагина с именем плагина, уровнем и временем, и строки двух плагинов одного хоста различимы по имени. Окно «Плагины Cyborg» показывает строки в журнале плагина.
- **traced from:** BR-CH-006; расширение 2б (`diagnose-failure-by-trace`).
- **источник:** [дорожная карта, раздел 4](../../06-plans/roadmap.md#4-наблюдаемость); `ctx.log(message)` без уровня есть в `contracts/plugin.ts`; уровни - те же, что у записей журнала (`entryLevel` в `core/src/status.ts`); K-29. Форма уровня в API - вопрос 11.
- **verification:** испытание - `core/test/loader.test.ts` («хуки: граф до кода, журнал по ходу, лог с id плагина, снятие в журнале»), `playground/src/main/plugins.test.ts` («виды: … лента вида - только свои строки …»): строка доходит с именем плагина. Ещё нет: уровень, запись в журнал плагина в окне, две строки двух плагинов одного хоста (K-29).
- **класс:** Functions.

### FR-CH-4010 Вывод хоста по плагину

- **Требование:** строки, которые хост плагинов пишет в stdout и stderr, ядро принимает в журнал; строка относится к плагину, чей код выполнялся, а если плагин определить нельзя - к хосту.
- **traced from:** BR-CH-006; расширение 2б (`diagnose-failure-by-trace`).
- **источник:** [дорожная карта, раздел 4](../../06-plans/roadmap.md#4-наблюдаемость) («Пробелы» и K-29); сейчас хост запущен с `stdio: 'inherit'` (`playground/src/main/plugin-hosts.ts`); плагин определяет `Owner` в `core/src/rpc.ts`. В общем хосте это диагностика, а не доказательство (FR-CH-4006).
- **verification:** Ещё нет (K-29). Испытание - тест playground: `console.log` из двух плагинов общего хоста дают две строки журнала с разными плагинами; строка вне вызова плагина - с хостом.
- **класс:** Supportability.

### FR-CH-4011 Кольцо в памяти

- **Требование:** журнал плагина и трасса держатся в памяти кольцом ограниченной ёмкости; при переполнении уходит старейшая запись самого шумного плагина, поэтому плагин, пишущий в цикле, не вытесняет записи соседей. Записи журнала, из которых выводится состояние плагина, из кольца не уходят.
- **traced from:** BR-CH-006, BR-CH-007; шаг 4 (`diagnose-failure-by-trace`).
- **источник:** `appendBounded` в `core/src/journal.ts` (так сейчас ограничены отказы); У-43 ([модель угроз, 5.7](../../04-architecture/design/threat-model.md#57-ресурсы-и-доступность)), У-49 ([5.8](../../04-architecture/design/threat-model.md#58-диагностика)); FR-CH-1003 (состояние выводится из журнала); K-30. Ёмкость не задана (вопрос 10).
- **verification:** испытание - `core/test/journal.test.ts` («журнал: отказов не больше предела …», «поток разных отказов одного плагина не вытесняет отказы другого», «плагин в цикле из 20 000 отказов не раздувает журнал ядра»). Ещё нет: то же для строк `ctx.log` и трассы (K-30).
- **класс:** Reliability.

### FR-CH-4012 Файл в `userData` с ротацией

- **Требование:** журнал и трасса пишутся в файл в `userData`; файл, достигший предельного размера, ротируется.
- **traced from:** BR-CH-006; шаг 4, расширение 4в (`diagnose-failure-by-trace`).
- **источник:** запрос владельца (2026-11-08); [SAD, 3.2](../../04-architecture/design/sad.md#32-загрузка-плагинов); [дорожная карта, раздел 4](../../06-plans/roadmap.md#4-наблюдаемость); K-30. Предельный размер, число файлов и срок хранения - D-00, новая строка про трассу (вопрос 4); момент записи в файл (вопрос 2) и отказ записи (вопрос 3) не решены.
- **verification:** Ещё нет (K-30). Испытание - тест ядра: записи за предел размера дают ротацию, оба файла читаются.
- **класс:** Reliability.

### FR-CH-4013 Причина сбоя прошлого запуска

- **Требование:** при старте ядро читает журнал прошлого запуска из файла, и окно «Плагины Cyborg» показывает у плагина причину его последнего сбоя в прошлом запуске, отдельно от состояния текущего.
- **traced from:** BR-CH-006; шаги 5, 6 (`diagnose-failure-by-trace`).
- **источник:** BR-CH-006 (MOE: причина сбоя прошлого запуска видна после перезапуска); [дорожная карта, раздел 4](../../06-plans/roadmap.md#4-наблюдаемость) («Пробелы»); K-30.
- **verification:** Ещё нет (K-30). Испытание - тест playground: служба окна на том же `userData` после перезапуска отдаёт причину `failed` из прошлого запуска (рядом - `playground/src/main/plugins.test.ts`, «служба окна: снимок с причиной и журналом …»); дымовой тест окна.
- **класс:** Functions.

### FR-CH-4014 Прошлый запуск не меняет состояние

- **Требование:** записи прошлого запуска не меняют состояние плагина в текущем запуске: состояние ядро выводит только из записей текущего запуска.
- **traced from:** BR-CH-006; шаг 6 (`diagnose-failure-by-trace`).
- **источник:** FR-CH-1003 (состояние выводится из журнала, `core/src/status.ts`); без правила записанный вчера `switched-off` читался бы как состояние сегодня; K-30.
- **verification:** Ещё нет (K-30). Испытание - тест ядра: журнал прошлого запуска с `switched-off` и `host-down`, плагин в текущем запуске `active`.
- **класс:** Reliability.

### FR-CH-4015 Выгрузка диагностики

- **Требование:** человек выгружает диагностику одним файлом: журнал, трасса, версии ядра и плагинов, состояние графа; записи идут в порядке времени, и запись трассы несёт id цепочки (FR-CH-4002).
- **traced from:** BR-CH-006; шаги 7, 9, 10, 11 (`diagnose-failure-by-trace`).
- **источник:** запрос владельца (2026-11-08); [дорожная карта, раздел 4](../../06-plans/roadmap.md#4-наблюдаемость); K-30. Формат, запуск и место файла (вопрос 8), состав при ротации (вопрос 4) не решены.
- **verification:** Ещё нет (K-30). Испытание - тест ядра: выгрузка после сбоя несёт запись с ошибкой, её цепочку по id, версии ядра и плагинов и граф; демонстрация - мейнтейнер называет плагин и версию, на которых оборвалась операция, только по файлу.
- **класс:** Functions.

### FR-CH-4016 Выгрузка остаётся на машине

- **Требование:** ядро не отправляет выгрузку: файл остаётся на машине, пока человек сам его не передал.
- **traced from:** BR-CH-006; шаг 8 (`diagnose-failure-by-trace`).
- **источник:** [BRD, раздел 3](../../01-product/brd.md#3-business-scope) (облака у харнеса нет); У-48 ([модель угроз, 5.8](../../04-architecture/design/threat-model.md#58-диагностика)); K-30.
- **verification:** Ещё нет (K-30). Осмотр - в модуле выгрузки нет сетевых вызовов и права `net`; испытание - тест ядра: выгрузка при заблокированной сети даёт файл.
- **класс:** Security.

### FR-CH-4017 Ресурсы хостов и видов

- **Требование:** окно «Плагины Cyborg» показывает у каждого хоста и у каждого вида занятую память и загрузку процессора; в хосте, где живут несколько плагинов, значение относится к хосту, а не делится между плагинами.
- **traced from:** BR-CH-006, BR-CH-007; цель «состояние каждого плагина видно пользователю».
- **источник:** [дорожная карта, раздел 4](../../06-plans/roadmap.md#4-наблюдаемость) («Позже», K-31); сейчас память меряют только спайки (`playground/src/main/proc-memory.ts`). Разбивку «сейчас» и «позже» владелец не принял (вопрос 12).
- **verification:** Отложено (K-31). Испытание - тест playground: снимок службы окна несёт память и процессор хоста; рядом - `playground/src/main/proc-memory.test.ts`.
- **класс:** Supportability.

### FR-CH-4018 Предел длины и частоты строк плагина

- **Требование:** строку `ctx.log` и строку вывода хоста длиннее предела ядро обрезает и помечает обрезку. Строки плагина любого уровня сверх предела частоты за интервал ядро в журнал по одной не кладёт: в конце интервала пишет одну сводную запись со счётом пропущенных, числом пропущенных строк уровня `error` и последней из них. Сводная запись состояния плагина не меняет. Плагин, превышающий предел частоты дольше 10 с подряд (значение по умолчанию), ядро выключает, как сторож после серии сбоев (FR-CH-1005 фичи 01): запись `switched-off` с причиной «поток строк», после неё строки плагина в журнал не идут, включает его снова человек. Предел считается на плагин: шумный плагин не теряет и не задерживает строки соседей по хосту.
- **traced from:** BR-CH-006, BR-CH-007; шаг 4 (`diagnose-failure-by-trace`).
- **источник:** У-49 ([модель угроз, 5.8](../../04-architecture/design/threat-model.md#58-диагностика)); [дорожная карта, раздел 4](../../06-plans/roadmap.md#4-наблюдаемость) («Пробелы»); приём счётчиком - FR-CH-4005; выключение после 10 с потока по умолчанию - решение владельца (2026-11-08); K-29. Предел длины, частоты и интервал не заданы (вопрос 10).
- **verification:** Ещё нет (K-29). Испытание - тест ядра: плагин пишет строку длиннее предела, затем поток строк `info` с одной `error` в конце, сосед в том же хосте - одну строку; второй плагин пишет поток без остановки. Точка наблюдения - журнал плагина и состояние. Неуспех - строка длиннее предела; строк за интервал больше предела плюс одна сводная; в сводной нет последней `error`; сводная меняет состояние; строка соседа потеряна; плагин с потоком без остановки не выключен через 10 с либо его строки идут в журнал после `switched-off`.
- **класс:** Reliability.

### NFR-CH-1004 Трасса операций

- **Требование:** доля операций на границах Г1-Г5, не получивших ровно одну запись в трассе, равна нулю.
- **traced from:** BR-CH-006 (MOE: «операций на границах плагинов без записи - 0»).
- **источник:** [BRD, BR-CH-006](../../01-product/brd.md#br-ch-006-наблюдаемость-и-устойчивость); функции записи - FR-CH-4001…FR-CH-4008.
- **verification:** Ещё нет (K-28). Испытание - тест ядра: по одной операции каждого рода (сообщение хоста, вызов моста, член и команда контракта, событие, вызов `ctx.os` с успехом и с отказом); точка наблюдения - трасса ядра; неуспех - операция без записи либо с двумя.
- **класс:** Supportability.

### NFR-CH-1005 Журнал плагина и хранение

- **Требование:** все записи с ошибкой и все записи жизненного цикла (`failed`, `host-down`, `switched-off`), сделанные в запуске, видны после перезапуска на том же `userData`: доля потерянных равна нулю при штатном закрытии приложения и при падении хоста плагина. Для приложения, убитого без закрытия, доля зависит от момента записи в файл (вопрос 2).
- **traced from:** BR-CH-006 (MOE: «причина сбоя прошлого запуска видна после перезапуска»).
- **источник:** [BRD, BR-CH-006](../../01-product/brd.md#br-ch-006-наблюдаемость-и-устойчивость); функции - FR-CH-4009…FR-CH-4016.
- **verification:** Ещё нет (K-30). Испытание - тест ядра: запуск пишет по одной записи каждого вида, закрывается, второй запуск на том же каталоге; точка наблюдения - журнал второго запуска; неуспех - любая запись из первого запуска не найдена. Предел размера файлов - после решения владельца (вопрос 4).
- **класс:** Reliability.

### NFR-CH-4001 Накладные расходы записи

- **Требование:** с включённой трассой вызов шлюза `ctx.os`, событие `fs.watch` и вывод терминала укладываются в бюджеты NFR-CH-1001 теми же условиями замера.
- **traced from:** BR-CH-007, BR-CH-006.
- **источник:** NFR-CH-1001 (фича 01); [дорожная карта, раздел 4](../../06-plans/roadmap.md#4-наблюдаемость) (кольцо в памяти, файл пакетами вне вызова); K-28.
- **verification:** Ещё нет (K-28). Испытание - замер шлюза `npm run spike:gateway` с выключенной и включённой трассой, на нагрузке NFR-CH-1001; неуспех - выход за бюджет с трассой при бюджете без неё.
- **класс:** Performance.

### NFR-CH-4002 Содержимое и секреты вне записей

- **Требование:** число вхождений в трассу, файлы журнала и выгрузку значения секрета из хранилища ядра и содержимого аргумента операции равно нулю. Строка, которую плагин записал через `ctx.log` сам, в меру не входит (вопрос 7).
- **traced from:** BR-CH-005, BR-CH-006 (ограничение: в записи нет содержимого аргументов и результатов).
- **источник:** У-17 ([модель угроз, 5.2](../../04-architecture/design/threat-model.md#52-плагин-против-плагина)), У-48 ([5.8](../../04-architecture/design/threat-model.md#58-диагностика)), T-05; FR-CH-2014 (фича 03).
- **verification:** Ещё нет (K-28, K-30). Испытание - тест ядра: операция с маркером в аргументе и секрет через `secrets.set` и `resolve`; поиск маркера и значения в трассе, файле и выгрузке (как `core/test/os.test.ts`, «секреты: ключи своего плагина …»); для журнала ядра - `core/test/secrets-journal.test.ts`.
- **класс:** Security.

## 3. Открытые вопросы

Нормы не выбирают за владельца. Вопросы 1-9 держит [сценарий](../../02-use-cases/diagnose-failure-by-trace/scenario.md#открытые-вопросы) (номера те же); часть из них держит новая строка D-00 про трассу ([дорожная карта, раздел 15](../../06-plans/roadmap.md#15-решения-владельца)).

1. **Операция начата и не закончена (расширение 3а).** Писать ли запись об оборванной операции. Предложение: при перезапуске хоста закрывать висящие операции записью «оборвана: хост перезапущен» с виновником из журнала сторожа. Держит сценарий, вопрос 1.
2. **Момент записи в файл (4б).** Предложение: записи с ошибкой и события жизненного цикла - сразу, остальное - пакетами вне вызова. Сценарий, вопрос 2. Влияет на NFR-CH-1005.
3. **Отказ записи в файл (4а).** Предложение: операцию не отказывать, оставить кольцо и написать в журнал одну запись. Сценарий, вопрос 3.
4. **Хранение: число файлов, срок, объём; состав выгрузки (4в, 7а).** Предложение: выгрузка включает все хранимые файлы и время самой ранней записи; ротация размером уносит и записи соседей шумного плагина, поэтому предел задать с запасом. D-00, новая строка про трассу; сценарий, вопрос 4.
5. **Кто читает трассу (2в).** Окно ядра либо ещё плагин с отдельным правом (свои записи). Предложение: только окно ядра, как в FR-CH-4008. D-00, новая строка; сценарий, вопрос 5.
6. **Содержимое аргументов по флагу отладки и маскировка (7б).** Предложение: не писать; при решении владельца - только за флагом и с маскировкой значений из хранилища секретов. D-00, новая строка; сценарий, вопрос 6.
7. **Секрет в строке `ctx.log` и в выводе хоста (7б).** BR-CH-005 и NFR-CH-4002 строку плагина не покрывают. Предложение: ядро вычёркивает из строк значения, лежащие в хранилище секретов; остальное - ответственность автора, правило в руководство. Мера - здесь либо в FR-CH-2014 (фича 03, правит другой аналитик). Сценарий, вопрос 7.
8. **Выгрузка: формат, запуск, место (7, 11).** Предложение: запуск из окна «Плагины Cyborg», текстовый формат, читаемый без инструментов. Сценарий, вопрос 8.
9. **Вызывающий в общем хосте (2б).** FR-CH-4006 уже различает канал и отметку хоста по SAD 3.5. Осталось подтвердить формулировку «диагностическая точность» и внести её в руководство (фича 07). Сценарий, вопрос 9.
10. **Параметры.** Интервал счётчика (FR-CH-4005) и ёмкость кольца (FR-CH-4011) не заданы. Предложение: интервал 1 с, ёмкость - по числу записей, значение выбрать замером NFR-CH-4001. Предел длины строки и частоты строк плагина (FR-CH-4018) тоже не заданы. Предложение: длина 8 КиБ, частота 100 строк в секунду на плагин, сводная запись - раз в интервал счётчика FR-CH-4005. Держит эта фича.
11. **Форма уровня в `ctx.log`.** Предложение: второй необязательный параметр, по умолчанию `info`, - дополнение API без поломки существующих плагинов; решить до заморозки 1.0 (K-21). Держит K-29.
12. **Разбивка «сейчас» и «позже».** Владелец не принял K-28 - K-30 в эпик и K-31 в «Позже» (D-00, новая строка про разбивку); пока FR-CH-4017 отложена, остальные - «Ещё нет».
13. **Операция на нескольких границах.** Решено: одна запись на операцию с перечнем пройденных границ, поля и значения - английские имена в нотации кода (решение владельца, 2026-11-08); FR-CH-4001, FR-CH-4003, сценарий, шаг 2.
