# SRS фичи 04 - наблюдаемость

## 1. SRS overview

Что ядро записывает и показывает: журнал и окно «Плагины Cyborg», трасса операций на границах плагинов, журнал плагина, хранение и выгрузка диагностики. Закрывает BR-CH-006 (наблюдаемость). Сценарии - [причина сбоя по трассе](../../02-use-cases/observability/UC-OBSERVABILITY-4001-diagnose-failure-by-trace.md), [плагин падает](../../02-use-cases/plugin-host/UC-PLUGIN-HOST-1001-plugin-failure-isolated.md). Устройство - [SAD](../../04-architecture/design/sad.md), 3.2 и 3.5; границы доверия - [модель угроз, раздел 4](../../04-architecture/design/threat-model.md#4-границы-доверия). Метод проверки называет тест ядра (`core/test`), тест playground (`playground/test`, `playground/src/main/*.test.ts`) или дымовой тест окна (`playground/scripts/smoke.mjs`, `npm run smoke`). Что не сделано - помечено «Ещё нет» или «Отложено», остаток - [дорожная карта](../../06-plans/roadmap.md). Состав: FR-CH-1010 (журнал и окно, сделано), FR-CH-4001…4008 (трасса, K-28, сделано в ядре: запись отдаёт `LoadOptions.onTrace`, хранит и показывает K-30; аргументы операций по флагу запуска `--trace-args` - K-33), FR-CH-4009…4010, 4018 (`ctx.log` и вывод хоста, K-29), FR-CH-4011…4016 (хранение и выгрузка, K-30, сделано в ядре и адаптере Electron: `core/src/diagnostics*.ts`, `electron/src/diagnostics-file.ts`), FR-CH-4017 (ресурсы, K-31); меры NFR-CH-1004, 1005, 4001, 4002. Функции, которые раньше лежали в NFR-CH-1004 и NFR-CH-1005, вынесены в FR; в NFR остались меры. Открытые вопросы - раздел 3, покрытие сценария - раздел 4. Раскладка норм по фичам - [03-requirements](../README.md).

## 2. Требования

### FR-CH-1010 Журнал и окно «Плагины Cyborg»

- **Требование:** ядро ведёт журнал плагинов: отказы загрузки (`invalid`, `not-found`, `rejected`), ошибки активации, отказы прав `denied`, падения и перезапуски хостов, конфликты сочетаний. У каждой записи есть описание словами и уровень. Окно «Плагины Cyborg» показывает у плагина состояние, причину из журнала, хост, время запуска, объявленные права словами и журнал плагина вместе с записями его хоста; даёт выгрузить, загрузить и «Включить снова» плагин, снятый сбоем. Окно без плагинов - нормальное состояние: управление плагинами в нём доступно.
- **traced from:** BR-CH-006.
- **источник:** [SAD, 3.2](../../04-architecture/design/sad.md#32-загрузка-плагинов), [SAD, 3.5](../../04-architecture/design/sad.md#35-изоляция-сбоев-хосты-и-сторож).
- **verification:** испытание - `core/test/status.test.ts`, `playground/test/plugins-model.test.ts`, `core/test/os.test.ts` («права в манифесте: … права словами»), `electron/test/plugins.test.ts` («служба окна: снимок с причиной и журналом, «Включить снова»…»); дымовой тест - «окно: заглушка с причиной, журнал плагина, «Включить снова»».
- **класс:** Functions.

### FR-CH-4001 Запись операции на границе

- **Требование:** операция, прошедшая границы плагинов - сообщение хоста с главным процессом (Г1), вызов моста из вида (Г2), член контракта, команда и событие контракта (Г3), вызов `ctx.os` с решением права (Г4, Г5), - даёт в трассе одну запись, сколько бы границ она ни прошла: вызов `ctx.os` проходит Г1 и Г4, член контракта плагина другого хоста - Г1, Г3 и снова Г1. Запись несёт время, id цепочки, вызывающего, адресата (плагин, контракт с версией и член, команда либо метод шлюза), пройденные границы (последняя - та, где операция кончилась), право, которым операция допущена, длительность, размер аргументов и размер результата в байтах, итог. Поля и значения записи - английские имена в нотации кода: поля - camelCase (`durationMs`); значения закрытых наборов - kebab-case, как `kind` записей журнала: граница `host` (Г1), `bridge` (Г2), `contract` (Г3), `os` (Г4), `net` (Г5), итог `outcome` - `ok` либо `error`; код ошибки `code` - имя из `CoreErrorCode` (`PermissionDenied`), как в API; участник - `род:имя` (`plugin:jira`, `view:jira`, `command:jira.create`, `contract:sessions.current@1#active`, `os:net.fetch`); причина отказа `reason` - текстом на английском. Вызов члена с `@deprecated` записывается так же; журнал таких вызовов - FR-CH-1012.
- **traced from:** BR-CH-006; шаг 2 (`UC-OBSERVABILITY-4001`).
- **источник:** запрос владельца (2026-11-08); одна запись на операцию с пройденными границами, английские имена полей и значений - решение владельца (2026-11-08, вопрос 13); границы - [модель угроз, раздел 4](../../04-architecture/design/threat-model.md#4-границы-доверия); [дорожная карта, раздел 4](../../06-plans/roadmap.md#4-наблюдаемость); точка записи хоста - `Endpoint` в `core/src/rpc.ts`; K-28.
- **verification:** `core/test/trace.test.ts` («трасса: вызов ctx.os, член контракта, команда и вызов моста дают по одной записи …», «сообщение хоста неверной формы и подмена имени плагина …», «цепочка: событие контракта …»), `electron/test/plugins.test.ts` («старт: onTrace доходит до ядра …»). Испытание - тест ядра: по одной операции каждой границы дают по одной записи со всеми полями; вызов `ctx.os` и член контракта плагина другого хоста - по одной записи с перечнем пройденных границ; сообщение хоста неверной формы - запись с `boundaries: ["host"]` и `code: "Invalid"`. Запись отдаёт `LoadOptions.onTrace` (`TraceRecord`: `operation`, `stream`, `exit`); точки записи - `core/src/trace.ts` (запись и цепочка), `core/src/host-bridge.ts` (Г1: каждый запрос хоста), `core/src/kernel-api.ts` (Г2: вызовы моста вида), `core/src/contract-calls.ts` и `core/src/commands.ts` (Г3), `core/src/os-requests.ts` (Г4, Г5). Ещё нет: дымовой тест вызова моста из вида в окне - запись Г2 делает ядро при вызове `Kernel.callAs` и `Kernel.runOwn`, которые зовёт адаптер.
- **класс:** Functions.

### FR-CH-4002 Цепочка операций

- **Требование:** первая операция цепочки - вызов моста из вида, сочетание, событие или первая операция плагина, вызванная не из другой операции - даёт цепочке идентификатор, равный id своей записи; команда, член контракта другого плагина и вызов `ctx.os`, порождённые этой операцией, несут тот же id цепочки.
- **traced from:** BR-CH-006; шаги 1, 2, 9, 10, расширение 10а (`UC-OBSERVABILITY-4001`).
- **источник:** [дорожная карта, раздел 4](../../06-plans/roadmap.md#4-наблюдаемость) (цепочку несёт механизм, которым сторож определяет виновника: `Owner` в `core/src/rpc.ts`); K-28.
- **verification:** `core/test/trace.test.ts` («цепочка: клик вида -> команда -> член контракта другого плагина -> ctx.os …», «цепочка: событие контракта начинает цепочку …»), `core/test/rpc.test.ts` («цепочка: запрос и уведомление несут номер цепочки Owner …»). Испытание - тест ядра: клик вида -> команда -> член контракта другого плагина -> `ctx.os` дают записи с одним id цепочки, равным id первой; цепочка от события и от сочетания строится так же. Номер цепочки идёт в сообщении хоста (поле `c`) и держится в `AsyncLocalStorage` хоста и ядра; номер от хоста ядро не сверяет с цепочками, идущими сейчас: запись - диагностика, а не доказательство (FR-CH-4006).
- **класс:** Functions.

### FR-CH-4003 Итог операции

- **Требование:** итог операции записан кодом: успех (`outcome: "ok"`) либо ошибка (`outcome: "error"`) с кодом ядра в `code` (`PermissionDenied`, `Unavailable` и прочие `CoreErrorCode`); вызов `ctx.os` без права кончается записью с кодом `PermissionDenied`, и вызов не выполняется.
- **traced from:** BR-CH-006; шаг 3, расширение 3б (`UC-OBSERVABILITY-4001`).
- **источник:** запрос владельца (2026-11-08); [SAD, 3.7](../../04-architecture/design/sad.md#37-безопасность-данных-и-контроль-плагинов); отказ в журнале - FR-CH-2007 (фича 03), отказ жизненного цикла - FR-CH-1010; K-28.
- **verification:** `core/test/trace.test.ts` («итог: исключение поставщика, команда без владельца и вызов ctx.os без права …»). Испытание - тест ядра: операция с исключением и вызов `ctx.os` без права дают запись с кодом; запись `denied` в журнале остаётся (`core/test/os.test.ts`, «без прав: свои каталоги работают, чужой путь - PermissionDenied и запись в журнале»). `reason` - фиксированный английский текст по коду (`REASONS` в `core/src/trace-record.ts`), текст исключения в запись не идёт: в нём бывают пути и значения аргументов.
- **класс:** Functions.

### FR-CH-4004 Содержимое в запись не попадает

- **Требование:** запись трассы несёт размеры аргументов и результата в байтах. Содержимое результата в запись не попадает никогда. Содержимое аргументов не попадает, пока приложение не запущено с флагом `--trace-args` (K-33, решение владельца 2026-11-11, вопрос 6): флаг включает только командная строка, не config и не файл воркспейса; тогда запись несёт аргументы вызова (член контракта, команда, вызов `ctx.os`) текстом не длиннее `LIMITS.traceArgsBytes` (4 КиБ, остаток отрезается с пометкой), значения секретов, прошедшие через шлюз в этом запуске, вычёркиваются так же, как в строках `ctx.log` (FR-CH-4018). Включённый флаг виден в окне и в журнале, выгрузка диагностики предупреждает, что в файле есть аргументы (FR-CH-4015).
- **traced from:** BR-CH-006, BR-CH-005; расширение 7б (`UC-OBSERVABILITY-4001`).
- **источник:** [SAD, 3.7](../../04-architecture/design/sad.md#37-безопасность-данных-и-контроль-плагинов) («ядро не логирует ни результат `resolve`, ни аргументы с ним»); У-17 ([модель угроз, 5.2](../../04-architecture/design/threat-model.md#52-плагин-против-плагина)); K-28. Запись содержимого по флагу отладки - решение владельца 2026-11-11 (вопрос 6), [K-33 #224](https://github.com/dex-it/cyborg-harness/issues/224); `--user-plugins` устроен так же (SAD 6.1).
- **verification:** `core/test/trace.test.ts` («содержимое: маркер в аргументе и в результате, значение секрета и путь в записи не попадают …»; с флагом - «без флага запись не несёт поля args …», «с флагом запись несёт аргументы …», «предел: длинные аргументы обрезаны по LIMITS.traceArgsBytes …», «секрет: значение, полученное плагином через шлюз, вычёркнуто из аргументов …», «журнал: с флагом при запуске есть запись trace-args …»), `core/test/trace-args.test.ts` (текст, предел, секреты на границе предела), `core/test/trace-size.test.ts`; флаг только из командной строки - `electron/test/trace-args.test.ts` («без StartOptions.traceArgs записи не несут аргументов, даже если файлы пользователя и воркспейса просят их …»), `playground/test/trace-args-flag.test.ts`, дымовой тест `traceArgsWindow` (`playground/scripts/smoke.mjs`); плашка - `playground/test/plugins-model.test.ts`. Испытание - тест ядра: операция с маркерной строкой в аргументе и в результате; запись содержит размеры и не содержит маркера. Мера - NFR-CH-4002. Размер - оценка снизу (`bytesOf`, `core/src/trace-size.ts`): строки в UTF-8, буферы, ключи и значения объектов до 1000 узлов и глубины 8. Для журнала отказов есть `core/test/security-gateway.test.ts` («безопасность: отказ process.run не кладёт аргументы программы … в журнал»).
- **класс:** Security.

### FR-CH-4005 Частые потоки пишутся счётчиком

- **Требование:** вывод pty и события `fs.watch` ядро не пишет записью на каждое сообщение: за интервал пишется одна запись-счётчик с числом сообщений и объёмом в байтах.
- **traced from:** BR-CH-006, BR-CH-007; расширение 2а (`UC-OBSERVABILITY-4001`).
- **источник:** [дорожная карта, раздел 4](../../06-plans/roadmap.md#4-наблюдаемость) (частые потоки - счётчиками); NFR-CH-1001 (вывод терминала до кадра, событие `fs.watch`); K-28. Длина интервала не задана (вопрос 10).
- **verification:** `core/test/trace.test.ts` («поток: 5000 сообщений pty за интервал …», «поток: счётчик закрывается по истечении интервала …», «поток: события fs.watch …»). Испытание - тест ядра: поток из 5000 сообщений pty за интервал даёт одну запись со счётом 5000 и суммой байтов (рядом - `core/test/stress-pty.test.ts`, «вывод идёт мелкими кусками»). Интервал - `LIMITS.traceStreamMs`, 1 с (предложение вопроса 10, принято по поручению владельца 2026-11-10); считаются сообщения, дошедшие до плагина, то есть после склейки вывода pty (`ptyFlushMs`) и событий `fs.watch` (50 мс).
- **класс:** Performance.

### FR-CH-4006 Вызывающий в общем хосте

- **Требование:** запись несёт id хоста и имя вызывающего плагина. Сторонний плагин всегда один в своём хосте, и его имя определено каналом; в хосте с несколькими плагинами имя называет отметка хоста: запись различает плагины хоста для диагностики и не доказывает, что операцию начал именно названный плагин.
- **traced from:** BR-CH-006; расширение 2б (`UC-OBSERVABILITY-4001`).
- **источник:** [SAD, 3.5](../../04-architecture/design/sad.md#35-изоляция-сбоев-хосты-и-сторож) (граница доверия - процесс хоста, внутри хоста плагины неразличимы); FR-CH-2012 (фича 03); У-11 (ядро принимает сообщение, только если названный плагин живёт в этом хосте), У-04 (этап 2 снимет вопрос); K-28.
- **verification:** `core/test/trace.test.ts` («вызывающий в общем хосте: …», «сообщение хоста неверной формы и подмена имени плагина …»). Испытание - тест ядра: операция плагина из хоста с двумя плагинами несёт id хоста и имя; сверка «названный плагин живёт в этом хосте» - `core/test/trust.test.ts`. Имя в запись берётся из сообщения хоста до сверки: подмена имени видна как заявленное имя с отказом `Unavailable`. Осмотр - руководство автора называет это диагностической точностью (фича 07; вопрос 9).
- **класс:** Security.

### FR-CH-4007 Запуск программы

- **Требование:** запуск программы по праву `process` или `pty` ядро пишет записью с правом, а завершение - записью с кодом завершения; что программа делала внутри, ядро не видит и не записывает.
- **traced from:** BR-CH-006; расширение 2г (`UC-OBSERVABILITY-4001`).
- **источник:** граница Г6 ([модель угроз, раздел 4](../../04-architecture/design/threat-model.md#4-границы-доверия)); FR-CH-2007 (фича 03); K-28.
- **verification:** `core/test/trace.test.ts` («запуск программы: process.run даёт запись с правом и запись выхода с кодом …»). Испытание - тест ядра: `ctx.os.process.run` с ненулевым кодом и `pty.spawn` с выходом дают запись запуска с правом и запись завершения с кодом, без вывода программы. Запись запуска - обычная запись операции (`right: "process"` либо `"pty"`), завершение - запись `exit` с `code`; имя программы и аргументы в записи нет (У-48).
- **класс:** Functions.

### FR-CH-4008 Трасса недоступна плагину

- **Требование:** ни один член `ctx` и ни один вызов моста вида не возвращает плагину записи трассы других плагинов; записи читает окно ядра.
- **traced from:** BR-CH-006, BR-CH-005; расширение 2в (`UC-OBSERVABILITY-4001`).
- **источник:** NFR-CH-1004 (прежняя редакция: «чужие записи плагину недоступны»); А7 ([модель угроз, раздел 2](../../04-architecture/design/threat-model.md#2-активы)). Чтение плагином своих записей и отдельное право - решение владельца, решения нет (вопрос 5).
- **verification:** `core/test/trace.test.ts` («трасса недоступна плагину: …»). Осмотр - в `PluginContext` (`contracts/plugin.ts`) и в мосте вида нет члена, возвращающего трассу; испытание - тест ядра: в `ctx` нет члена про трассу, а сообщения ядра хостам не несут записей (в сообщении есть только номер цепочки `c`). Записи получает приложение через `LoadOptions.onTrace`; окно «Плагины Cyborg» покажет их в K-30.
- **класс:** Security.

### FR-CH-4009 Строка `ctx.log`

- **Требование:** плагин пишет строку через `ctx.log` с уровнем `info`, `warn` или `error`; ядро кладёт её в журнал плагина с именем плагина, уровнем и временем, и строки двух плагинов одного хоста различимы по имени. Окно «Плагины Cyborg» показывает строки в журнале плагина.
- **traced from:** BR-CH-006; расширение 2б (`UC-OBSERVABILITY-4001`).
- **источник:** [дорожная карта, раздел 4](../../06-plans/roadmap.md#4-наблюдаемость); `ctx.log(message, level?)` в `contracts/plugin.ts` (K-29); уровни - те же, что у записей журнала (`entryLevel` в `core/src/status.ts`). Форма уровня в API - вопрос 11: принята исполнителем K-29, подтверждена владельцем 2026-11-11.
- **verification:** испытание - `core/test/loader.test.ts` («хуки: граф до кода, журнал по ходу, лог с id плагина, снятие в журнале»), `electron/test/plugins.test.ts` («виды: … лента вида - только свои строки …»): строка доходит с именем плагина; `core/test/plugin-log.test.ts` («ctx.log: без уровня - info, с уровнем - он …»), `core/test/host-output.test.ts` («console.log двух плагинов одного хоста разобран по плагинам …»): уровень, id плагина, две строки двух плагинов одного хоста; `electron/test/plugins.test.ts` («старт: включённый плагин активен …»): уровень доходит до приложения. Строка уходит в `LoadOptions.onLog` с уровнем. Ещё нет: запись в журнал плагина и показ строк в окне «Плагины Cyborg» (K-30).
- **класс:** Functions.

### FR-CH-4010 Вывод хоста по плагину

### FR-CH-4018 Предел длины и частоты строк плагина

- **Требование:** строку `ctx.log` и строку вывода хоста длиннее предела ядро обрезает и помечает обрезку. Строки плагина любого уровня сверх предела частоты за интервал ядро в журнал по одной не кладёт: в конце интервала пишет одну сводную запись со счётом пропущенных, числом пропущенных строк уровня `error` и последней из них. Сводная запись состояния плагина не меняет. Строка самого ядра о хосте (отказ по заметке хоста, сбой перезапуска) идёт тем же путём с меткой хоста, а не прямо в `onLog`: в ней может быть текст с провода. Плагин, превышающий предел частоты дольше 10 с подряд (значение по умолчанию), ядро выключает, как сторож после серии сбоев (FR-CH-1005 фичи 01): запись `switched-off` с причиной «поток строк», после неё строки плагина в журнал не идут, включает его снова человек. «Подряд» значит без паузы: интервал сверх предела продолжает поток, только если начался не позже чем через `окно / предел` (время одной строки на пределе; 10 мс при 100 строках за 1 с) после конца предыдущего такого интервала, иначе счёт срока начинается заново; так всплеск в предел плюс одна строка раз в два окна (в среднем вдвое ниже предела) плагин не выключает. Предел считается на плагин: шумный плагин не теряет и не задерживает строки соседей по хосту.
- **traced from:** BR-CH-006, BR-CH-007; шаг 4 (`UC-OBSERVABILITY-4001`).
- **источник:** У-49 ([модель угроз, 5.8](../../04-architecture/design/threat-model.md#58-диагностика)); [дорожная карта, раздел 4](../../06-plans/roadmap.md#4-наблюдаемость) («Пробелы»); приём счётчиком - FR-CH-4005; выключение после 10 с потока по умолчанию - решение владельца (2026-11-08); K-29. Предел длины, частоты и интервал - предложение вопроса 10, принято исполнителем K-29, подтверждено владельцем 2026-11-11 (`LIMITS`: `logLineBytes`, `logRate`, `logWindowMs`, `logFloodMs`).
- **verification:** `core/test/plugin-log.test.ts` («длина: …», «частота: строк сверх предела за интервал в журнал по одной не идёт, в конце интервала - одна сводная с последней error; сосед и состояние целы», «частота: сводная запись не меняет состояние плагина …», «поток: плагин выше предела частоты дольше срока выключается (switched-off, log-flood) …», «поток: всплески выше предела с паузами дольше интервала плагин не выключают», «поток: всплески через паузу короче окна, но с частотой в среднем ниже предела, потоком не считаются …», «поток: плагин снят до срока - счёт потока начат заново …»), `core/test/trust.test.ts` («output: поток строк хоста без плагина …», «output: сводная строка хоста … при выгрузке ядра», «log: отказ ядра по заметке хоста идёт под теми же пределами …»). Испытание - тест ядра: плагин пишет строку длиннее предела, затем поток строк `info` с одной `error` в конце, сосед в том же хосте - одну строку; второй плагин пишет поток без остановки. Неуспех - строка длиннее предела; строк за интервал больше предела плюс одна сводная; в сводной нет последней `error`; сводная меняет состояние; строка соседа потеряна; плагин с потоком без остановки не выключен через 10 с либо его строки идут в журнал после `switched-off`.
- **класс:** Reliability.

### NFR-CH-4002 Содержимое и секреты вне записей

- **Требование:** число вхождений в трассу, файлы журнала и выгрузку значения секрета из хранилища ядра равно нулю; содержимого аргумента операции - равно нулю, пока приложение не запущено с `--trace-args` (FR-CH-4004). Строка, которую плагин записал через `ctx.log` сам, в меру не входит (вопрос 7).
- **traced from:** BR-CH-005, BR-CH-006 (ограничение: в записи нет содержимого аргументов и результатов).
- **источник:** У-17 ([модель угроз, 5.2](../../04-architecture/design/threat-model.md#52-плагин-против-плагина)), У-48 ([5.8](../../04-architecture/design/threat-model.md#58-диагностика)), T-05; FR-CH-2014 (фича 03).
- **verification:** трасса - `core/test/trace.test.ts` («содержимое: …»); файл и выгрузка - `core/test/diagnostics.test.ts` («выгрузка: маркера аргумента, значения секрета и текста исключения поставщика нет ни в файле хранилища, ни в выгрузке»). Испытание - тест ядра: операция с маркером в аргументе и секрет через `secrets.set` и `resolve`; поиск маркера и значения в трассе, файле и выгрузке (как `core/test/os.test.ts`, «секреты: ключи своего плагина …»); для журнала ядра - `core/test/secrets-journal.test.ts`.
- **класс:** Security.

## 3. Открытые вопросы

Нормы не выбирают за владельца. Вопросы 1-9 держит [сценарий](../../02-use-cases/observability/UC-OBSERVABILITY-4001-diagnose-failure-by-trace.md#открытые-вопросы) (номера те же); часть из них держит новая строка D-00 про трассу ([дорожная карта, раздел 15](../../06-plans/roadmap.md#15-решения-владельца)).

1. **Операция начата и не закончена (расширение 3а).** Писать ли запись об оборванной операции. Предложение: при перезапуске хоста закрывать висящие операции записью «оборвана: хост перезапущен» с виновником из журнала сторожа. Держит сценарий, вопрос 1. Решено в K-28 (принято по поручению владельца 2026-11-10): отдельной записи нет, оборванная падением хоста операция кончается обычной записью с `code: "HostGone"` - вызывающий получает тот же отказ; операцию, которую исполнял сам упавший хост, закрывает отказ вызывающего. Виновник - в записи `host-down` журнала.
2. **Момент записи в файл (4б).** Предложение: записи с ошибкой и события жизненного цикла - сразу, остальное - пакетами вне вызова. Сценарий, вопрос 2. Влияет на NFR-CH-1005. Решено в K-30 (принято по поручению владельца 2026-11-10) по предложению: сразу пишутся записи журнала жизненного цикла и с ошибкой, строки `error` и операции трассы с отказом; остальное копится в пакет и уходит в файл через 1 с (`flushMs`) вне вызова. Срочная запись не чаще раза в 20 мс (`urgentGapMs`): поток операций с отказом иначе превратил бы каждый вызов шлюза в запись на диск; ошибки внутри окна уходят в файл в конце окна. Убитое приложение теряет только обычные записи последней секунды.
3. **Отказ записи в файл (4а).** Предложение: операцию не отказывать, оставить кольцо и написать в журнал одну запись. Сценарий, вопрос 3. Решено в K-30 (принято по поручению владельца 2026-11-10) по предложению: отказ записи (нет места, нет прав) операцию не отказывает; записи остаются в кольце и в пакете (не больше ёмкости кольца), на серию отказов в кольцо и в пакет идёт одна запись `диагностика` уровня `error` с кодом ошибки (`ENOSPC`), а не с текстом: в сообщении файловой системы лежит путь к `userData`. Приложение узнаёт об отказе через `onProblem`, окно показывает его в строке «Диагностика». Повтор записи раз в секунду; когда диск вернулся, накопленное уходит в файл, а не записанное входит в выгрузку.
4. **Хранение: число файлов, срок, объём; состав выгрузки (4в, 7а).** Предложение: выгрузка включает все хранимые файлы и время самой ранней записи; ротация размером уносит и записи соседей шумного плагина, поэтому предел задать с запасом. D-00, новая строка про трассу; сценарий, вопрос 4. Решено в K-30 (принято по поручению владельца 2026-11-10): до 5 файлов по 2 МиБ на воркспейс (текущий `diagnostics.log` и `diagnostics.1.log`…`diagnostics.4.log`), то есть до 10 МиБ или около 30 тысяч записей трассы по ~340 Б; срока хранения нет, ротация только по размеру: срок требовал бы часов и чистки по времени, а предел объёма уже ограничивает диск. Запас выбран как предложение: рядом с потоком строк одного плагина (FR-CH-4018 и выключение за поток через 10 с) 10 МиБ переживают минуты шума, а не секунды; остаточный риск - поток длиннее вынесет из файлов потока и записи сбоев соседей: закрыто в #180, уходящий файл отдаёт записи жизненного цикла файлу `diagnostics.keep.log` (до 256 КиБ), поэтому предел всего на диске - 10 МиБ потока и 256 КиБ записей сбоев. Выгрузка включает все хранимые файлы и время самой ранней записи; файлы сверх нынешнего предела числа убираются при старте. Файлы лежат в `<userData>/diagnostics/<ключ воркспейса>/`: у каждого воркспейса свои, потому что в одном `userData` работают несколько процессов (K-20), а «прошлый запуск» и ротация считаются на воркспейс. Права `0600`.
5. **Кто читает трассу (2в).** Окно ядра либо ещё плагин с отдельным правом (свои записи). Предложение: только окно ядра, как в FR-CH-4008. D-00, новая строка; сценарий, вопрос 5. Решено в K-28 (принято по поручению владельца 2026-11-10) по предложению: только окно ядра; `ctx` и мост вида записей не отдают (FR-CH-4008). Чтение плагином своих записей и право на него - не делается, вернуться к вопросу можно без поломки API: член добавляется в `ctx`.
6. **Содержимое аргументов по флагу отладки и маскировка (7б).** Предложение: не писать; при решении владельца - только за флагом и с маскировкой значений из хранилища секретов. D-00, новая строка; сценарий, вопрос 6. Решено в K-28 (принято по поручению владельца 2026-11-10) по предложению: содержимое не пишется, флага отладки нет; в записи только размеры. Владелец 2026-11-11 решил иначе: при отладке аргументы пишутся - флаг запуска `--trace-args` (только командная строка), обрезка по длине, вычёркивание секретов, как у строк `ctx.log`; без флага - как сейчас. Сделано в [K-33 #224](https://github.com/dex-it/cyborg-harness/issues/224) (принято по поручению владельца 2026-11-12): предел - `LIMITS.traceArgsBytes`, 4 КиБ на запись (предложение задачи); секреты вычёркиваются для вызывающего и адресата записи значениями, прошедшими через шлюз (токен, собранный плагином самим, не вычёркивается); предупреждение выгрузки выводится из записей файла, а не из флага запуска, поэтому аргументы прошлого запуска в файле тоже предупреждены. Тесты - в FR-CH-4004.
7. **Секрет в строке `ctx.log` и в выводе хоста (7б).** BR-CH-005 и NFR-CH-4002 строку плагина не покрывают. Предложение: ядро вычёркивает из строк значения, лежащие в хранилище секретов; остальное - ответственность автора, правило в руководство. Мера - здесь либо в FR-CH-2014 (фича 03, правит другой аналитик). Сценарий, вопрос 7. Принято исполнителем K-29, подтверждено владельцем 2026-11-11: вычёркиваются значения, прошедшие через шлюз в этом запуске (`secrets.get`, `set`, `resolve`; хранилище значений списком не отдаёт), для строки плагина - его значения, для строки хоста - значения плагинов этого хоста, чужой плагин чужую диагностику не портит; значения после `delete` и перезаписи помнятся до конца запуска, при `uninstall` забываются; значения короче 4 символов не вычёркиваются; метка `[секрет]`. Тесты - `core/test/plugin-log.test.ts` («секреты: …»).
8. **Выгрузка: формат, запуск, место (7, 11).** Предложение: запуск из окна «Плагины Cyborg», текстовый формат, читаемый без инструментов. Сценарий, вопрос 8. Решено в K-30 (принято по поручению владельца 2026-11-10) по предложению: запуск кнопкой «Выгрузить диагностику…» окна «Плагины Cyborg»; место называет человек в системном диалоге «Сохранить как» (имя по умолчанию `cyborg-diagnostics-<время>.txt`); формат - текст в кодировке UTF-8: заголовок (приложение, API плагинов, число записей, самая ранняя запись, пределы хранения, запуски), плагины с версиями и состоянием, граф контрактов, затем по строке на запись в порядке времени; запись трассы несёт `цепочка N`, перевод строки в строке плагина заменяется на `⏎`. Файл `0600`.
9. **Вызывающий в общем хосте (2б).** FR-CH-4006 уже различает канал и отметку хоста по SAD 3.5. Осталось подтвердить формулировку «диагностическая точность» и внести её в руководство (фича 07). Сценарий, вопрос 9.
10. **Параметры.** Интервал счётчика (FR-CH-4005) и ёмкость кольца (FR-CH-4011) не заданы. Предложение: интервал 1 с, ёмкость - по числу записей, значение выбрать замером NFR-CH-4001. Предел длины строки и частоты строк плагина (FR-CH-4018) тоже не заданы. Предложение: длина 8 КиБ, частота 100 строк в секунду на плагин, сводная запись - раз в интервал счётчика FR-CH-4005. Держит эта фича. Предел длины, частоты и срок потока приняты исполнителем K-29 по предложению (8 КиБ, 100 строк за 1 с, 10 с), подтверждены владельцем 2026-11-11; интервал сводной записи - 1 с, он же окно счёта. Интервал счётчика потока - 1 с (`LIMITS.traceStreamMs`), принят в K-28 (по поручению владельца 2026-11-10). Ёмкость кольца выбрана в K-30 замером (принято по поручению владельца 2026-11-10): 5000 записей в кольце, не больше 1250 записей одного плагина без жизненного цикла; кольцо держит около 2,5 МиБ, запись стоит 1-5 мкс ([замер](../../05-verification/spike-gateway.md#хранение-диагностики-k-30)).
11. **Форма уровня в `ctx.log`.** Предложение: второй необязательный параметр, по умолчанию `info`, - дополнение API без поломки существующих плагинов; решить до заморозки 1.0 (K-21). Держит K-29: сделано (`LogLevel`, `ctx.log(message, level?)`), подтверждено владельцем 2026-11-11.
12. **Разбивка «сейчас» и «позже».** Владелец не принял K-28 - K-30 в эпик и K-31 в «Позже» (D-00, новая строка про разбивку); пока FR-CH-4017 отложена, остальные - «Ещё нет».
13. **Операция на нескольких границах.** Решено: одна запись на операцию с перечнем пройденных границ, поля и значения - английские имена в нотации кода (решение владельца, 2026-11-08); FR-CH-4001, FR-CH-4003, сценарий, шаг 2. Границы в записи: `host`, `bridge`, `contract` (член, команда и событие), `os`, `net` (`net.fetch`); участники - `plugin:`, `view:`, `user` (палитра, сочетание, меню, клик по уведомлению), `host:` (имя плагина в сообщении не названо), `command:`, `contract:`, `event:`, `os:`, `bridge:`.
14. **Что такое «прошлый запуск» (FR-CH-4013).** Норма говорит «прошлый запуск», но не говорит, что будет с причиной, если после сбоя приложение запустили и закрыли, ничего не сделав. Решено в K-30 (принято по поручению владельца 2026-11-10): прошлый запуск - последний запуск этого воркспейса до текущего (его начало пишется записью `run` при старте, поэтому чистый запуск без сбоев тоже считается); сбой позапрошлого запуска из окна уходит, в выгрузке он остаётся, пока файл не вытеснен ротацией. Основание: окно отвечает на вопрос «что случилось в прошлый раз», а не копит историю, историю даёт выгрузка. Вернуть окну причину из любого хранимого запуска - выбор прошлого запуска в `Diagnostics`, без изменения формата файла.
