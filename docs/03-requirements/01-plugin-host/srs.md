# SRS фичи 01 - ядро и загрузчик плагинов

## 1. SRS overview

Как ядро открывает воркспейс, находит и запускает плагины и переживает их сбои: манифест, обнаружение и состояния, граф контрактов, хосты и сторож, откат регистраций, выгрузка и загрузка, ленивая активация, воркспейс, pty у ядра; накладные расходы, устойчивость, время реакции на сбой и компактность ядра; сбои хоста и слоя pty, осиротевший pty, пределы pty, правка файла воркспейса руками. Ресурсы по плагинам - [FR-CH-4017](../04-observability/srs.md#fr-ch-4017-ресурсы-хостов-и-видов). Закрывает BR-CH-001, BR-CH-002 (воркспейс), BR-CH-006 (устойчивость), BR-CH-007. Сценарии - [плагин падает](../../02-use-cases/plugin-failure-isolated/scenario.md), [автор встроенного плагина](../../02-use-cases/maintainer-adds-feature/scenario.md). Устройство - [SAD](../../04-architecture/design/sad.md), разделы 2, 3.1, 3.2, 3.5, 3.6. Метод проверки называет тест ядра (`core/test`), тест playground (`playground/test`, `playground/src/main/*.test.ts`) или дымовой тест окна (`playground/scripts/smoke.mjs`, `npm run smoke`). Что не сделано - помечено «Ещё нет» или «Отложено», остаток - [дорожная карта](../../06-plans/roadmap.md). Раскладка норм по фичам - [03-requirements](../README.md).

## 2. Требования

### FR-CH-1001 Манифест плагина

- **Требование:** манифест - JSON-объект, который ядро разбирает до запуска кода плагина; приложение читает его из `manifest.json` в каталоге плагина. Обязательны `id` (имя вида `pin-lock` или `cyborg.files`), `version` (`x.y.z`) и `engines.cyborg` (диапазон версий). Необязательны `provides`, `requires`, `optional`, `consumes`, `commands`, `keybindings`, `config`, `state`, `permissions`, `host`, `activation`, `ui`, `lock`, `documents`. Ошибки собираются все сразу, `id` сохраняется для журнала. Включённый плагин с ошибками в манифесте получает запись `invalid`, его код не запускается. `id`, в пространстве которого лежат команды окна и ядра (`cyborg`, `cyborg.window`, `cyborg.workspace`), занят ядром.
- **traced from:** BR-CH-001.
- **источник:** [SAD, 3.2](../../04-architecture/design/sad.md#32-загрузка-плагинов), [SAD, 3.3](../../04-architecture/design/sad.md#33-версии-и-миграции); `core/src/manifest.ts`.
- **verification:** испытание - `core/test/semver-manifest.test.ts` (минимальный манифест, все ошибки сразу, `many` не может быть `one`), `core/test/loader.test.ts` («журнал: невалидный…», «битый манифест невключённого плагина - disabled, а не invalid»), `core/test/window.test.ts` («манифест: id, в пространстве которого лежат команды окна, занят»).
- **класс:** Functions.

### FR-CH-1003 Обнаружение и состояния

- **Требование:** плагины ищутся в каталоге поставки и в каталоге плагинов пользователя; встроенные раньше пользовательских, повтор `id` - отказ второму. Признак поставки - каталог, а не манифест. Загружаются только плагины из `plugins.enabled`. Состояние плагина ядро выводит из журнала: `active`, `waiting` (ждёт ленивой активации), `restarting` (хост перезапускается), `stopped` (снят отказом, сбоем или человеком), `disabled` (не включён в настройках).
- **traced from:** BR-CH-006.
- **источник:** [SAD, 3.2](../../04-architecture/design/sad.md#32-загрузка-плагинов), [SAD, 3.5](../../04-architecture/design/sad.md#35-изоляция-сбоев-хосты-и-сторож); `core/src/status.ts`, `playground/src/main/plugins.ts`.
- **verification:** испытание - `playground/src/main/plugins.test.ts` («поиск: встроенные раньше пользовательских, повтор id…»), `core/test/graph.test.ts` («повтор id - отказ второму»), `core/test/status.test.ts`, `playground/src/main/plugins.test.ts` («старт: плагин из каталога пользователя - сторонний и не попадает в общую группу хоста»). Ещё нет: политики загрузки из каталога пользователя на этапе 1 (У-38, K-17; ждёт D-00, строки 13 и 14 - вопрос 3 раздела 3).
- **класс:** Functions.

### FR-CH-1004 Граф контрактов до запуска кода

- **Требование:** ядро разрешает граф `provides` / `requires` / `optional` / `consumes` по манифестам до запуска кода. Нет поставщика из `requires`, два поставщика при кратности `one`, цикл - плагин не загружается, причина в журнале называет контракт, поставщиков или участников цикла. Отказ каскадирует на зависящих через `requires`. Несовместимая мажорная версия поставщика - как его отсутствие. `consumes` ребра не создаёт: встречные `consumes` допустимы. Сторонний плагин, который отдаёт контракт `cyborg.*` или носит `id` из `cyborg.`, не загружается, причина называет имя и пространство; брать `cyborg.*` ему можно. Активация идёт в порядке графа: поставщик раньше потребителя.
- **traced from:** BR-CH-006.
- **источник:** [SAD, 3.2](../../04-architecture/design/sad.md#32-загрузка-плагинов), [SAD, раздел 4](../../04-architecture/design/sad.md#4-взаимодействие-плагинов); dsh 11 (молчаливый PENDING как слабость).
- **verification:** испытание - `core/test/graph.test.ts` (порядок, отсутствие, два поставщика `one`, цикл, `consumes`, мажорная версия, пространство поставки), `core/test/loader.test.ts` («пространство поставки: …»), `core/test/status.test.ts` (причина словами).
- **класс:** Functions.

### FR-CH-1005 Изоляция сбоя: хосты и сторож

- **Требование:** главные части плагинов работают в хостах `utilityProcess`, не в главном процессе. Исключение при активации или в вызове ловит хост: отказывает только этот плагин, с записью в журнале. Сторож проверяет хост раз в 1 с; нет ответа 5 с - хост перезапускается, виновник - при зависании плагин, чей код хост выполнял (хост называет плагин ядру до входа в его код: вызов, событие, таймер, продолжение после ответа ядра), при падении - плагин, чей код завершил процесс (`process.exit`, необработанное исключение в его асинхронной цепочке); хост виновника не назвал, например процесс убит сигналом, - плагин первого вызова, принятого после последнего отвеченного пинга. Необработанное отклонение промиса плагина хост не роняет: запись `unhandled-rejection` на виновника и страйк. Виновник ошибки - плагин, с чьего входа началась цепочка, а не вошедший последним; ошибка вне цепочки плагина - сбой кода хоста без виновника. После трёх сбоев подряд (зависание, падение, отклонение) виновник выключается с записью `switched-off`; выключенный отклонением снимается с живого хоста, без перезапуска соседей. Падение хоста идёт тем же путём. Перезапуск не трогает другие хосты, окно и pty; потребители из других хостов узнают о пропаже и возврате поставщика из `ctx.contracts.onChange`. Плагины из поставки идут в хост `builtin` или в группы `plugins.hosts`; сторонний плагин всегда один в своём хосте, а попытка сгруппировать его даёт запись `host-isolated`.
- **traced from:** BR-CH-005, BR-CH-006.
- **источник:** [SAD, 3.5](../../04-architecture/design/sad.md#35-изоляция-сбоев-хосты-и-сторож); пороги - [замер хостов](../../05-verification/spike-hosts.md).
- **verification:** испытание - `core/test/hosts.test.ts` (зависание, падение, выключение после N сбоев; виновник в общем хосте - таймер, слушатель, продолжение после ответа, падение в таймере, убийство снаружи, прежнее правило без отметки хоста, ответ на пинг вместе с уведомлением о коде; необработанное отклонение, отклонение после `await`, исключение в `queueMicrotask` и `process.nextTick`, три отклонения подряд, ошибка вне цепочки плагина), `playground/test/host-electron.test.ts` («хост на рантайме Electron…»), `core/test/loader.test.ts` («сбой активации снимает уже отданное плагином», «хост упал без виновника…», «хосты: из поставки - по группам, сторонний всегда один в своём хосте»); дымовой тест - «падение и зависание хоста: сторож перезапускает».
- **класс:** Functions.

### FR-CH-1006 Откат регистраций

- **Требование:** всё, что плагин отдал ядру, - контракты, команды, подписки, наблюдения `fs.watch`, серверы `serve`, диалоги, незавершённые `process.run` с их потомками и запросы `net.fetch` - снимается при выгрузке, падении хоста и сбое активации. Подписка привязана к вызывающему: ядро снимает её при уходе любой из сторон. После выгрузки в реестрах ядра нет записей плагина.
- **traced from:** BR-CH-001, BR-CH-006.
- **источник:** [SAD, 3.2](../../04-architecture/design/sad.md#32-загрузка-плагинов), [SAD, раздел 4](../../04-architecture/design/sad.md#4-взаимодействие-плагинов) (п. 6); dsh 2 (эффекты с откатом).
- **verification:** испытание - `core/test/loader.test.ts` («активация по графу… снятие в обратном порядке», «сбой активации снимает уже отданное плагином»), `core/test/subscriptions.test.ts`, `core/test/os.test.ts` («fs.watch: … выгрузка закрывают наблюдение»), `core/test/serve.test.ts` («… dispose и выгрузка закрывают»), `core/test/window.test.ts` («диалог вида: … выключение плагина закрывает…»), `core/test/os-lifetime.test.ts` («process.run: выключение плагина и выгрузка ядра завершают программу вместе с её потомками», «net.fetch: зависший сервер - … выгрузка плагина обрывает запрос»).
- **класс:** Functions.

### FR-CH-1007 Выгрузка, загрузка и каскад зависимых

- **Требование:** выгрузка и загрузка плагина идут без перезапуска окна. Выгрузка снимает плагин и тех, кто требует его через `requires`, в обратном порядке активации; потребители через `optional` и `consumes` остаются и получают `onChange`. Хост, где не осталось плагинов, гасится, поэтому загрузка поднимает код в новом процессе. Плагин, выгруженный человеком, не поднимают ни сторож, ни включение соседа. Смена `plugins.enabled` в файле без перезапуска выключает убранные плагины и включает вернувшиеся; плагин, которого не было в графе при запуске, ждёт перезапуска с записью в окне.
- **traced from:** BR-CH-006.
- **источник:** [SAD, 3.1](../../04-architecture/design/sad.md#31-воркспейс-как-главная-сессия), [SAD, 3.2](../../04-architecture/design/sad.md#32-загрузка-плагинов).
- **verification:** испытание - `core/test/lifecycle.test.ts` («disable: требующие выгружаются вместе с поставщиком, необязательный остаётся; enable поднимает…», «disable: выключенного человеком enable соседа не поднимает»), `playground/src/main/plugins.test.ts` («plugins.enabled из файла воркспейса без перезапуска…»); дымовой тест - «выгрузка с зависимыми, загрузка в новый процесс, переподписка». Ещё нет: включение без перезапуска плагина, которого не было в графе при запуске.
- **класс:** Functions.

### FR-CH-1008 Ленивая активация

- **Требование:** плагин с `"activation": "lazy"` при старте получает состояние `waiting`. Будят его первая команда, его сочетание, показ его вида и активация потребителя его контракта. Поставщиков из `requires` и `optional` ядро поднимает до потребителя, поставщиков `consumes` - без ожидания. Выключенный человеком ленивый плагин команда не будит. Плагин без `activation` активируется при старте; `lock.onStart` активирует плагин сразу, даже ленивый.
- **traced from:** BR-CH-007.
- **источник:** [SAD, 3.2](../../04-architecture/design/sad.md#32-загрузка-плагинов).
- **verification:** испытание - `core/test/events.test.ts` («activation lazy: ждёт; будит команда, сочетание, wake и потребитель контракта…»), `core/test/window.test.ts` («lock.onStart: … ленивый плагин замка активируется сразу…»); дымовой тест - «ленивая активация по команде».
- **класс:** Functions.

### FR-CH-1014 Воркспейс как главная сессия

- **Требование:** один экземпляр - один воркспейс - одно окно. Воркспейс открывается флагом `--workspace=<файл>` или из «Недавних»; ядро берёт замок `<файл>.lock` с pid и забирает замок умершего процесса. Второй запуск приложения переводит фокус на открытое окно и завершается. `state` воркспейса лежит по ключу от `realpath` файла. `config` - слои пользователя и воркспейса, `plugins.enabled` воркспейса перекрывает пользовательский. Битый файл не роняет открытие и не перезаписывается; рядом ложится копия `<файл>.corrupt-<время>` с исходным содержимым, одна на одно содержимое. Показать файл воркспейса - команда ядра `cyborg.workspace.reveal`, плагину она недоступна. Документ без поля `cyborg` ядро один раз отдаёт хуку приложения `migrate` и записывает его итог с копией `<файл>.v1.bak`. «Недавние» - до 10 воркспейсов, последний первым, без повторов по `realpath`, пропавший файл не показывается. Закрытие окна или смена воркспейса выключает плагины и снимает замок; при живых pty окно сначала спрашивает человека.
- **traced from:** BR-CH-002.
- **источник:** [SAD, 3.1](../../04-architecture/design/sad.md#31-воркспейс-как-главная-сессия); `core/src/workspace.ts`, `core/src/recent.ts`.
- **verification:** испытание - `core/test/workspace.test.ts` (замок, ключ `state`, слои, битый файл и его копия, перенос хуком, «Недавние»), `core/test/os.test.ts` («команда ядра cyborg.workspace.reveal…»), `playground/src/main/plugins.test.ts` («воркспейс: битый cyborg.json - жалоба, а не отказ…»); дымовой тест - «воркспейс: замок с pid, второй запуск отдаёт фокус первому и уходит, открытый - в «Недавних»», «окно без воркспейса…». Ещё нет: несколько воркспейсов и экземпляров при общем `userData` (K-20; D-00, строка 5 открыта - вопрос 2 раздела 3); сейчас норма - один экземпляр, один воркспейс.
- **класс:** Functions.

### FR-CH-1015 Процессы дольше плагина: pty

- **Требование:** pty держит ядро в главном процессе; плагин решает, что запустить, по праву `pty`. Перезапуск хоста или окна pty не завершает: pty с `persist` ждёт владельца, тот возвращается через `ctx.os.pty.list()` и `attach` и получает хвост вывода; не взятый за льготное время (по умолчанию 60 с) завершается с записью `pty-expired`. Оставленный человеком при выключении ждёт без срока, пока плагин выключен, а после активации плагина получает тот же срок. Оставленные процессы ядро отдаёт приложению списком, и человек может завершить любой. Чужой pty для плагина не существует (`NotFound`). Выключение плагина с живыми pty спрашивает человека: оставить процессы ждать возврата плагина или завершить; выход из приложения завершает все. Вид плагина видит вывод и пишет ввод по одноразовому билету `share()` своей главной части, мимо хоста: зависший хост терминал не останавливает. Короткие процессы `ctx.os.process` при падении хоста завершаются.
- **traced from:** BR-CH-006.
- **источник:** [SAD, 3.6](../../04-architecture/design/sad.md#36-ресурсы-дольше-плагина-pty); `core/src/pty.ts`.
- **verification:** испытание - `core/test/pty.test.ts` (предел ввода и числа pty, `COLORTERM`), `core/test/stress-pty.test.ts` (склейка вывода), `playground/src/main/view-terminals.test.ts`; замер - `npm run spike:pty` ([итоги](../../05-verification/spike-pty.md)); дымовой тест - «терминал вида: билет share(), вывод и ввод мимо хоста…», «выключение спрашивает о pty: оставленный процесс виден в строке плагина…». Ещё нет: проверки pty на Windows (D-00, строка 7 - вопрос 7 раздела 3); снимка экрана после `attach` - спайк SP-01 выбрал снимок headless-xterm вместо сырого хвоста ([итоги](../../05-verification/spike-pty-restore.md)), снимок вводит K-01 вместе с pty-хостом (ADR-CH-0012, п. 2). Сбой слоя pty - FR-CH-1018, осиротевший pty - FR-CH-1019, пределы - FR-CH-1023.
- **класс:** Functions.

### FR-CH-1016 «Включить снова» после сбоя

- **Требование:** «Включить снова» поднимает плагин, снятый сбоем при активации, и следом потребителей через `requires`, которые не запустились из-за него. Плагин, выключенный сторожем после трёх зависаний подряд, включается тем же вызовом. Включение несуществующего плагина - отказ с причиной.
- **traced from:** BR-CH-006; плагин падает (`plugin-failure-isolated`, шаг 6).
- **источник:** [SAD, 3.2](../../04-architecture/design/sad.md#32-загрузка-плагинов), [SAD, 3.5](../../04-architecture/design/sad.md#35-изоляция-сбоев-хосты-и-сторож); `core/src/lifecycle.ts` (`enable`).
- **verification:** испытание - `core/test/loader.test.ts` (««Включить снова»: не поднявшийся плагин и потребитель следом, затем выключенный сторожем»), `playground/src/main/plugins.test.ts` («служба окна: … «Включить снова» поднимает не поднявшийся плагин»). Кнопка и заглушка вида - FR-CH-1010 и FR-CH-2005.
- **класс:** Reliability.

### FR-CH-1017 Хост, падающий без виновника

- **Требование:** хост, упавший без названного виновника, ядро поднимает заново; в журнале запись называет потребителей через `consumes`, которых задело падение. После лимита падений подряд без виновника (по умолчанию три) хост больше не перезапускается, его плагины выключаются с записью `host-abandoned`. Остальные хосты и окно работают.
- **traced from:** BR-CH-006; плагин падает (`plugin-failure-isolated`, расширение 1б).
- **источник:** [SAD, 3.5](../../04-architecture/design/sad.md#35-изоляция-сбоев-хосты-и-сторож); `core/src/host-pool.ts` (`watchdog.strikes`), `core/src/lifecycle.ts`, `core/src/status.ts`.
- **verification:** испытание - `core/test/loader.test.ts` («хост упал без виновника: журнал называет задетых через consumes, хост поднимается, после лимита брошен»).
- **класс:** Reliability.

### FR-CH-1018 Сбой слоя pty не замораживает окно

- **Требование:** падение или зависание слоя, который держит процессы pty, не замораживает окно и не трогает хосты плагинов. Процессы pty при этом теряются, владельцы получают это как завершение процесса, слой pty поднимается заново.
- **traced from:** BR-CH-006; плагин падает (`plugin-failure-isolated`, расширение 1в).
- **источник:** [ADR-CH-0012](../../04-architecture/adr/ADR-CH-0012-pty-host.md) (`proposed`), п. 4; [SAD, 3.6](../../04-architecture/design/sad.md#36-ресурсы-дольше-плагина-pty), риск раздела 9; задача K-01; D-00, строка 21 (открыта).
- **verification:** Ещё нет. Сегодня `node-pty` и таблица pty живут в главном процессе (`PtyBackend` в `core/src/pty.ts` даёт приложение), и зависание нативного модуля замораживает окно. Испытание после K-01 - тест ядра и дымовой тест: слой pty убит при трёх живых pty, окно отвечает, хосты плагинов живы, владельцы получили завершение. Где и как слой живёт - вопрос 1 раздела 3.
- **класс:** Reliability.

### FR-CH-1019 Осиротевший pty завершается по льготному времени

- **Требование:** pty с `persist`, чей владелец не вернулся через `attach` за льготное время после перезапуска хоста, ядро завершает; в журнале причина и срок. Владелец, вернувшийся раньше срока, забирает pty и хвост вывода как прежде (FR-CH-1015). Значение льготного времени - настройка ядра `ptyOrphanGrace`, по умолчанию 60 с.
- **traced from:** BR-CH-006; плагин падает (`plugin-failure-isolated`, расширение 1а: pty с `persist` ждут `attach`).
- **источник:** [SAD, 3.6](../../04-architecture/design/sad.md#36-ресурсы-дольше-плагина-pty), [ADR-CH-0012](../../04-architecture/adr/ADR-CH-0012-pty-host.md), п. 6; задача K-02.
- **verification:** испытание - `core/test/stress-pty.test.ts` («сирота: pty с persist без attach завершается по сроку; attach, release и park срок снимают»), `core/test/pty.test.ts` («сирота: плагин вернулся после падения хоста, но не взял pty за срок - процесс завершён, журнал называет срок», «оставленный: ждёт без срока, пока плагин выключен…»).
- **класс:** Reliability.

### FR-CH-1020 Свой хост плагина поставки

- **Требование:** плагин поставки с `"host": "own"` в манифесте получает отдельный хост, а не общий `builtin`. Значение `host`, кроме `own`, - ошибка манифеста. Если человек назвал такой плагин в группе `plugins.hosts`, действует группа; есть у него в группе соседи - ядро пишет в журнал `host-own-grouped` с их списком, и «Плагины Cyborg» показывают предупреждение. Группа из него одного или со сторонним плагином, который всё равно уходит в свой хост, предупреждения не даёт.
- **traced from:** BR-CH-001; автор встроенного плагина (`maintainer-adds-feature`, расширение 2в).
- **источник:** [SAD, 3.5](../../04-architecture/design/sad.md#35-изоляция-сбоев-хосты-и-сторож); `core/src/host-pool.ts` (`assignHosts`), `core/src/manifest.ts`.
- **verification:** испытание - `core/test/loader.test.ts` («хосты: host own у плагина поставки - свой хост без группы; в группе с соседом - хост группы и предупреждение host-own-grouped»).
- **класс:** Functions.

### FR-CH-1021 Правка файла руками не ломает права и разделы

- **Требование:** раздел `config` или `state`, правленный руками и не прошедший проверку по схеме, отклоняется с записью в журнале, значение раздела остаётся прежним, остальные разделы файла не меняются. В `granted` принимаются только абсолютные пути без NUL; прочие записи отсеиваются при следующем сохранении.
- **traced from:** BR-CH-002; угроза У-41 (закрыта).
- **источник:** [модель угроз, У-41](../../04-architecture/design/threat-model.md#56-загрузка-воркспейс-жизненный-цикл); [SAD, 3.1](../../04-architecture/design/sad.md#31-воркспейс-как-главная-сессия); `core/src/config.ts`. Файл целиком - FR-CH-1014, схемы и миграции разделов - FR-CH-2008.
- **verification:** испытание - `core/test/config.test.ts` («хранилище: мигрированный слой записывается сразу, чужие разделы не трогаются»), `core/test/workspace.test.ts` («правка файла извне доходит до ctx.config.onChange; не прошедшая проверку - запись в журнале, значение прежнее; …»), `core/test/loader.test.ts` («схема раздела из манифеста: … правка извне не по схеме - значение прежнее»), `core/test/os.test.ts` («granted: … кривые записи и сбой записи не мешают»).
- **класс:** Reliability.

### FR-CH-1023 Пределы pty

- **Требование:** ядро хранит хвост вывода каждого pty не больше 256 КиБ (по умолчанию; настройка ядра), вывод сверх предела вытесняет старое. Вывод pty, на который плагин не подписан, в хосте не копится. Ввод в pty за один вызов не больше 1 МиБ, больше - отказ.
- **traced from:** BR-CH-006; угроза У-43.
- **источник:** [SAD, 3.6](../../04-architecture/design/sad.md#36-ресурсы-дольше-плагина-pty); [модель угроз, У-43](../../04-architecture/design/threat-model.md#57-ресурсы-и-доступность); `core/src/pty.ts` (`BACKLOG_LIMIT`); задача K-14.
- **verification:** испытание - `core/test/stress-pty.test.ts` («кольцевой буфер - 5 МБ мелкими кусками не выходит за предел…», «плагин spawn-ит pty и не подписывается на вывод - хост не копит вывод без предела»). `core/test/pty.test.ts` («пределы pty: ввод больше предела - Invalid, pty жив и принимает следующий…»), `core/test/stress-pty.test.ts` («10 000 мелких кусков - хосту и зрителю уходят десятки пачек…», «пачка уходит по размеру, не дожидаясь интервала»). Пределы шлюза `ctx.os` вне pty - фича 03.
- **класс:** Reliability.

### FR-CH-1024 Модуль вида без `mount`

- **Требование:** модуль вида без `mount` оболочка вида отклоняет с причиной; вид не открывается, окно и другие виды работают.
- **traced from:** BR-CH-006.
- **источник:** [SAD, 3.8](../../04-architecture/design/sad.md#38-изоляция-рендера); `core/src/ui-shell.ts`. Вынесено из NFR-CH-1002.
- **verification:** испытание - `core/test/ui-shell.test.ts` («mountModule: модуль без mount отклонён с причиной…»).
- **класс:** Reliability.

### NFR-CH-1001 Накладные расходы

- **Требование:** время старта, память на хост и на `<iframe>`, задержка вызова через шлюз и вывода терминала укладываются в бюджет. Принято владельцем 2026-11-07 ([D-00](https://github.com/dex-it/cyborg-harness/issues/21), строка 6): вызов шлюза `ctx.os` до 64 КиБ - цена шлюза p99 не больше 1 мс, где цена - время вызова из плагина минус то же действие без шлюза, как её считает `npm run spike:gateway`; событие `fs.watch` - p99 не позже 5 мс после склейки 50 мс; вывод терминала - не больше 16 мс до кадра; мера - медиана трёх прогонов. Бюджеты старта окна и памяти не заданы - [открытый вопрос 9 SAD](../../04-architecture/design/sad.md#8-открытые-вопросы). Замерено на Linux: первый хост ~56 МБ PSS, каждый следующий ~34 МБ; вид со своим origin +13 МБ PSS; вызов p50 0,07-0,3 мс; p99 на вызов до 64 КиБ - 0,64 мс из главного процесса в хост и до 1,41 мс между хостами (вызов контракта, два перехода через главный процесс); перезапуск хоста 70 мс; вывод терминала от программы до хоста p99 0,5 мс под нагрузкой при склейке 4 мс ([замер pty](../../05-verification/spike-pty.md)). Цена шлюза `ctx.os` по медиане трёх прогонов - p50 до 0,4 мс, p99 до 0,7 мс на вызов до 64 КиБ; `fs.watch` сверх склейки 50 мс - 0,9 мс на p99 ([замер шлюза](../../05-verification/spike-gateway.md)).
- **traced from:** BR-CH-007.
- **источник:** [SAD, раздел 2](../../04-architecture/design/sad.md#2-что-есть-ядро); [замер хостов](../../05-verification/spike-hosts.md), [замер шлюза](../../05-verification/spike-gateway.md), [замер pty](../../05-verification/spike-pty.md), [спайк UI](../../05-verification/spike-iframe-ui.md).
- **verification:** испытание - замеры `npm run spike:hosts` (`playground/scripts/spike-hosts.mjs`), `npm run spike:gateway` (`playground/scripts/spike-gateway.mjs`) и `npm run spike` (`playground/scripts/spike-iframe.mjs`); сверка с бюджетом шлюза - код выхода `spike-gateway.mjs`: медиана p99 цены за три прогона против порогов `--budget` и `--watch-budget`. Ещё нет: замер вывода терминала до кадра; проверка бюджетов в CI (P-10); бюджеты старта и памяти (D-00, строка 6, остаток - вопрос 4 раздела 3; база Cyborg снята в PL-09, PR #108: [cyborg-baseline](../../05-verification/cyborg-baseline.md)).
- **класс:** Performance.

### NFR-CH-1002 Устойчивость

- **Требование:** в каждом из тестов отказов - исключение при активации, в вызове, в слушателе события, в виде, зависание хоста, падение хоста - главный процесс и окно живы, другие хосты отвечают, pty с `persist` живы; необработанное отклонение промиса плагина вне вызова не завершает и его хост: соседи по хосту работают без перезапуска; случаев, когда отказ одного плагина остановил окно или чужой хост, - 0. Поведение сторожа - FR-CH-1005 и FR-CH-1017, модуль вида без `mount` - FR-CH-1024.
- **traced from:** BR-CH-006 (MOE: тесты отказов).
- **verification:** испытание - `core/test/hosts.test.ts` («сторож: необработанное отклонение плагина - запись на него, хост и сосед живут» и др.), `core/test/events.test.ts` («… упавший слушатель не мешает соседу…»), `core/test/pty.test.ts` («падение хоста: pty с persist живёт и копит вывод…»); дымовой тест - «падение и зависание хоста: сторож перезапускает». Неуспех - любой из названных отказов, после которого окно, чужой хост или pty с `persist` не отвечают.
- **класс:** Reliability.

### NFR-CH-1003 Компактность ядра

- **Требование:** задача попадает в ядро, только если она нужна всем плагинам или окну без плагинов и плагин не может решить её сам, не нарушив гарантию остальным. В ядре нет предметной области (агентов, сессий, файлов, проектов, трекеров, источников секретов), общей шины событий, реестра сервисов по ключам и `inject`. В коде ядра нет имён плагинов; перенос старого формата воркспейса - хук приложения `migrate`.
- **traced from:** BR-CH-001.
- **источник:** [SAD, раздел 2](../../04-architecture/design/sad.md#2-что-есть-ядро).
- **verification:** осмотр - новая задача ядра сверяется с критерием SAD, раздел 2; испытание - `core/test/purity.test.ts` (предметные слова, импорты и зависимости `core/src`).
- **класс:** Maintainability.

### NFR-CH-1010 Время до перезапуска зависшего хоста

- **Требование:** зависший хост обнаруживается и его перезапуск начинается не позже 6 с после последнего ответа хоста: порог 5 с без ответа плюс интервал проверки 1 с (значения по умолчанию, FR-CH-1005). Неуспех - перезапуск позже 6 с при значениях по умолчанию.
- **traced from:** BR-CH-006.
- **источник:** [SAD, 3.5](../../04-architecture/design/sad.md#35-изоляция-сбоев-хосты-и-сторож); [замер хостов](../../05-verification/spike-hosts.md), [проверка на macOS](../../05-verification/macos-check.md) (зависание обнаружено за 5417-5423 мс, падение за 5 мс, хост поднят за 84-85 мс).
- **verification:** испытание - `npm run spike:hosts` (`playground/scripts/spike-hosts.mjs`) на значениях по умолчанию, хост без нагрузки. Ещё нет: теста в `core/test` на значениях по умолчанию (`core/test/hosts.test.ts` идёт с интервалом 50 мс и порогом 400 мс) и проверки порога в CI.
- **класс:** Reliability.

## 3. Открытые вопросы

Нормы выше не выбирают вариант там, где решение за владельцем. После каждого вопроса - предложение составителя.

1. **Где живёт слой pty (FR-CH-1018, K-01).** Варианты: (а) отдельный `utilityProcess` ядра по ADR-CH-0012; (б) `node-pty` остаётся в главном процессе. ADR в статусе `proposed`, приёмка - D-00, строка 21 (открыта); держат сценарий `plugin-failure-isolated` (1в) и риск SAD 9. Предлагаю (а): зависание нативного модуля иначе замораживает окно со всеми сессиями.
2. **Один процесс - один воркспейс или N процессов с общим `userData` (FR-CH-1014, K-20).** D-00, строка 5 (открыта). Предлагаю оставить один процесс - один воркспейс: замок и согласованное состояние уже стоят на этом (SAD 3.1), N процессов требуют общего `userData` с блокировками.
3. **Политика каталога пользователя на этапе 1 (FR-CH-1003, У-38, K-17).** Варианты: (а) грузить только плагины, включённые человеком, каждый в своём хосте (как сейчас); (б) не грузить каталог пользователя вовсе до этапа 2. D-00, строки 13 и 14 (открыты). Предлагаю (а) с записью в журнале о загрузке из каталога пользователя.
4. **Бюджеты старта окна и памяти на хост и вид (NFR-CH-1001).** D-00, строка 6, остаток (открыт). База Cyborg снята в PL-09 (PR #108): [cyborg-baseline](../../05-verification/cyborg-baseline.md), медиана пяти прогонов на macOS, бюджеты там - предложение. Выбор бюджета - за владельцем. Предлагаю правило из той же записи: «не хуже базы Cyborg на 10%» по медиане.
5. **Сырой хвост pty или снимок экрана после `attach` (FR-CH-1015, SP-01).** Решено спайком SP-01 (PR #91): снимок headless-xterm, сырой хвост - запасной вариант для бэкенда без эмулятора ([итоги](../../05-verification/spike-pty-restore.md), вопрос 14 SAD). Снимок вводит K-01 вместе с pty-хостом.
6. **Значение льготного времени осиротевшего pty (FR-CH-1019, K-02).** Решено слиянием PR #90: настройка ядра `ptyOrphanGrace`, по умолчанию 60 с ([SAD, 3.6](../../04-architecture/design/sad.md#36-ресурсы-дольше-плагина-pty), ADR-CH-0012, п. 6).
7. **Windows и pty на ней (FR-CH-1015).** D-00, строка 7 (открыта), вопрос 12 SAD; норма платформ - NFR-CH-1009 в [фиче 06](../06-delivery/srs.md). Предлагаю не писать норму для Windows, пока владелец не включит её в v1.
