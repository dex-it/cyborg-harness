# ST-1009 Ядро остаётся компактным: функция добавляется плагином

Как разработчик поставки, я хочу добавлять функции плагином, не трогая ядро, чтобы ядро не обрастало предметной областью.

Нормы: NFR-CH-1003. Сценарии: UC-EXTENSION-CONTRACTS-2001. SRS - [srs.md](../srs.md).

## Критерии приёмки

1. [NFR-CH-1003] [UC-EXTENSION-CONTRACTS-2001#7]
   - Дано новая функция приложения, оформленная плагином
   - Когда разработчик проходит гейты репозитория
   - Тогда в коде ядра нет имён плагинов, предметной области (агентов, сессий, файлов, проектов, трекеров, источников секретов), общей шины событий, реестра сервисов по ключам и `inject`
2. [NFR-CH-1003] [UC-EXTENSION-CONTRACTS-2001#7а]
   - Дано задача не нужна всем плагинам или окну без плагинов, плагин решает её сам
   - Когда разработчик решает, где её делать
   - Тогда задача идёт в плагин; в ядро попадает только то, что нужно всем и чего плагин не может сделать, не нарушив гарантию остальным; перенос старого формата воркспейса остаётся хуком приложения `migrate`
