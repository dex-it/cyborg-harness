# ST-1007 Воркспейс как главная сессия: замок, «Недавние», битый файл

Как человек, открывающий воркспейс, я хочу, чтобы одно окно держало один воркспейс, а испорченный файл не терялся, чтобы настройки и данные не пропадали при втором запуске и правке руками.

Нормы: FR-CH-1014, FR-CH-1021. Сценарии: UC-COMPATIBILITY-5001. SRS - [srs.md](../srs.md).

## Критерии приёмки

1. [FR-CH-1014] [UC-COMPATIBILITY-5001#1] [UC-COMPATIBILITY-5001#1б]
   - Дано воркспейс открыт процессом с замком `<файл>.lock` с pid
   - Когда запускается второй экземпляр с тем же файлом
   - Тогда второй переводит фокус на открытое окно и завершается; замок умершего процесса забирается; другой воркспейс с тем же `userData` открывается своим процессом
2. [FR-CH-1014]
   - Дано контроль экземпляров не заработал (каталог адреса чужой или не создаётся)
   - Когда процесс открывает воркспейс
   - Тогда окно открыто без адреса, причина названа человеку, данные держит замок воркспейса; владелец, не ответивший в срок, - отдельный исход с сообщением и кодом выхода 3
3. [FR-CH-1014]
   - Дано `plugins.enabled` в файле пользователя и в файле воркспейса
   - Когда ядро собирает `config`
   - Тогда слой воркспейса перекрывает пользовательский; `state` лежит по ключу от `realpath` файла
4. [FR-CH-1014]
   - Дано файл воркспейса не разбирается
   - Когда ядро открывает воркспейс
   - Тогда открытие не падает, файл не перезаписывается, рядом лежит копия `<файл>.corrupt-<время>` с исходным содержимым, одна на одно содержимое
5. [FR-CH-1014] [UC-COMPATIBILITY-5001#1а]
   - Дано документ воркспейса без поля `cyborg`
   - Когда ядро открывает воркспейс
   - Тогда документ один раз отдан хуку приложения `migrate`, итог записан, рядом копия `<файл>.v1.bak`
6. [FR-CH-1014]
   - Дано двенадцать воркспейсов в «Недавних», один файл повторён по `realpath`, один удалён
   - Когда человек открывает список
   - Тогда в списке не больше 10 воркспейсов, последний первым, без повторов, пропавший файл не показан
7. [FR-CH-1014]
   - Дано окно закрывается или воркспейс меняется при живых pty
   - Когда человек закрывает окно
   - Тогда плагины выключены и замок снят, но сначала окно спрашивает человека о pty
8. [FR-CH-1021] [UC-COMPATIBILITY-5001#5а]
   - Дано раздел `config` или `state`, правленный руками и не прошедший схему
   - Когда ядро читает файл
   - Тогда раздел отклонён с записью в журнале, значение осталось прежним, остальные разделы файла не изменены
9. [FR-CH-1021]
   - Дано в `granted` относительный путь и путь с NUL
   - Когда ядро сохраняет разрешения
   - Тогда принимаются только абсолютные пути без NUL, прочие отсеяны при следующем сохранении
