# ST-1003 Сбой плагина остаётся у плагина: хосты и сторож

Как человек, работающий в приложении, я хочу, чтобы исключение, зависание или падение одного плагина не останавливало окно и чужие плагины, чтобы работа продолжалась.

Нормы: FR-CH-1005, FR-CH-1017, FR-CH-1024, NFR-CH-1002, NFR-CH-1010. Сценарии: UC-AUTHOR-KIT-7001, UC-COMPATIBILITY-5002, UC-PLUGIN-HOST-1001, UC-SECURITY-TRUST-3001. SRS - [srs.md](../srs.md).

## Критерии приёмки

1. [FR-CH-1005] [NFR-CH-1002] [UC-PLUGIN-HOST-1001#1] [UC-PLUGIN-HOST-1001#2] [UC-COMPATIBILITY-5002#4в]
   - Дано два плагина в одном хосте, при активации первого брошено исключение
   - Когда хост ловит исключение
   - Тогда в журнале запись `failed` с хостом и ошибкой, отказал только первый плагин; сосед по хосту, другие хосты, главный процесс и окно живы
2. [FR-CH-1005] [NFR-CH-1002] [UC-AUTHOR-KIT-7001#9а] [UC-SECURITY-TRUST-3001#5а]
   - Дано главные части плагинов
   - Когда ядро запускает плагины
   - Тогда они работают в хостах `utilityProcess`, а не в главном процессе; сторонний плагин всегда один в своём хосте, попытка сгруппировать его даёт запись `host-isolated`
3. [FR-CH-1005] [NFR-CH-1002] [NFR-CH-1010] [UC-PLUGIN-HOST-1001#1а]
   - Дано плагин завис: хост не отвечает на проверку сторожа
   - Когда проходит 5 с без ответа при проверке раз в 1 с
   - Тогда хост перезапускается не позже чем через 6 с после последнего ответа; виновник - плагин, чей код хост выполнял; соседние хосты, окно и pty с `persist` не затронуты; потребители из других хостов узнают о пропаже и возврате из `ctx.contracts.onChange`
4. [FR-CH-1005] [UC-PLUGIN-HOST-1001#1а1]
   - Дано один и тот же плагин зависает три раза подряд
   - Когда происходит третье зависание
   - Тогда виновник выключается с записью `switched-off` и именем тех, кто брал его контракты; остальные плагины продолжают работать
5. [FR-CH-1005] [NFR-CH-1002] [UC-PLUGIN-HOST-1001#1а2]
   - Дано плагин оставил промис без обработчика
   - Когда промис отклонён вне вызова
   - Тогда хост не падает: запись `unhandled-rejection` на плагин, с чьего входа началась цепочка, и страйк ему; соседи по хосту работают без перезапуска; третий отказ подряд выключает только этот плагин
6. [FR-CH-1005] [NFR-CH-1002] [UC-PLUGIN-HOST-1001#1б]
   - Дано хост упал: код плагина вызвал `process.exit`
   - Когда процесс хоста завершается
   - Тогда виновником назван плагин, чей код завершил процесс; хост перезапущен, остальные хосты и окно работают; процесс, убитый сигналом без названного виновника, ставится на плагин первого вызова после последнего отвеченного пинга
7. [FR-CH-1017] [UC-PLUGIN-HOST-1001#1б]
   - Дано хост упал без названного виновника три раза подряд (лимит по умолчанию)
   - Когда хост падает в третий раз
   - Тогда хост больше не перезапускается, его плагины выключены с записью `host-abandoned`; до лимита хост поднимается заново, и запись называет потребителей через `consumes`, которых задело падение
8. [FR-CH-1024] [NFR-CH-1002]
   - Дано модуль вида без `mount`
   - Когда оболочка вида загружает модуль
   - Тогда вид отклонён с причиной и не открывается; окно и другие виды работают
