# ST-1002 Граф контрактов разрешается до запуска кода

Как человек, запускающий приложение, я хочу, чтобы несовместимые связи плагинов находились до выполнения их кода, чтобы отказ был понятным и не задевал независимых.

Нормы: FR-CH-1004. Сценарии: UC-AUTHOR-KIT-7001, UC-COMPATIBILITY-5001. SRS - [srs.md](../srs.md).

## Критерии приёмки

1. [FR-CH-1004] [UC-AUTHOR-KIT-7001#2в]
   - Дано плагин с `requires` на контракт, которого никто не даёт
   - Когда ядро разрешает граф
   - Тогда плагин не загружается, причина в журнале называет контракт; независимые плагины активны
2. [FR-CH-1004]
   - Дано два поставщика контракта с кратностью `one`
   - Когда ядро разрешает граф
   - Тогда плагин-потребитель не загружается, причина называет обоих поставщиков
3. [FR-CH-1004]
   - Дано цикл `requires` между тремя плагинами
   - Когда ядро разрешает граф
   - Тогда участники цикла не загружаются, причина называет их всех
4. [FR-CH-1004]
   - Дано цепочка A требует B, B требует C, у C ошибка
   - Когда ядро разрешает граф
   - Тогда отказ каскадирует на B и A; потребитель через `optional` остаётся; несовместимая мажорная версия поставщика считается его отсутствием
5. [FR-CH-1004]
   - Дано два плагина с встречными `consumes`
   - Когда ядро разрешает граф
   - Тогда оба загружаются: `consumes` ребра не создаёт
6. [FR-CH-1004] [UC-AUTHOR-KIT-7001#2]
   - Дано сторонний плагин, который отдаёт контракт `cyborg.*` или носит `id` с префиксом `cyborg.`
   - Когда ядро разрешает граф
   - Тогда плагин не загружается, причина называет имя и пространство; брать `cyborg.*` стороннему плагину можно
7. [FR-CH-1004] [UC-COMPATIBILITY-5001#3]
   - Дано поставщик и два потребителя в графе
   - Когда ядро активирует плагины
   - Тогда поставщик активируется раньше потребителей
