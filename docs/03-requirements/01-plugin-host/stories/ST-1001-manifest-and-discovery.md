# ST-1001 Манифест и обнаружение: плагин с ошибками не запускается, остальные работают

Как автор плагина, я хочу, чтобы ядро разбирало манифест и находило плагины до запуска кода, чтобы ошибка в одном манифесте не мешала остальным и была названа в журнале.

Нормы: FR-CH-1001, FR-CH-1003, FR-CH-1020. Сценарии: UC-AUTHOR-KIT-7001, UC-EXTENSION-CONTRACTS-2001. SRS - [srs.md](../srs.md).

## Критерии приёмки

1. [FR-CH-1001] [UC-EXTENSION-CONTRACTS-2001#1] [UC-AUTHOR-KIT-7001#2а]
   - Дано каталог плагина с `manifest.json` без `engines.cyborg` и с `version` не вида `x.y.z`
   - Когда ядро разбирает манифест
   - Тогда в журнале одна запись `invalid` со всеми ошибками сразу, `id` сохранён, код плагина не запущен
2. [FR-CH-1001]
   - Дано манифест с `id` `cyborg.window` (пространство занято командами окна и ядра)
   - Когда ядро разбирает манифест
   - Тогда плагин отвергнут как `invalid`, остальные плагины загружены
3. [FR-CH-1001]
   - Дано манифест с необязательными разделами (`provides`, `commands`, `config`, `ui`, `lock` и другие)
   - Когда ядро разбирает манифест
   - Тогда плагин принят, разделы доступны ядру
4. [FR-CH-1003] [UC-AUTHOR-KIT-7001#8б]
   - Дано плагин лежит в каталоге пользователя, приложение запущено без `--user-plugins`
   - Когда ядро ищет плагины
   - Тогда каталог пользователя не читается; с флагом `--user-plugins` плагин находится после встроенных
5. [FR-CH-1003]
   - Дано два каталога с манифестами одного `id`
   - Когда ядро ищет плагины
   - Тогда действует первый каталог (встроенные раньше пользовательских), второй манифест попадает в `problems` и лог строкой «повтор id X в <каталог>: действует <каталог первого>»; два манифеста с одним `id`, доставленные ядру напрямую, отвергаются оба
6. [FR-CH-1003]
   - Дано встроенный плагин без `index.mjs`
   - Когда ядро активирует плагин
   - Тогда активация получает отказ с причиной в журнале; расхождение файлов с `delivery.json` само в отказ не превращается, а пишется в лог и `problems`
7. [FR-CH-1003] [UC-AUTHOR-KIT-7001#9]
   - Дано плагин не из списка поставки `bundled` и плагин, не названный в `plugins.enabled`
   - Когда ядро загружает плагины
   - Тогда сторонний получает в журнале `third-party`, окно помечает его «сторонний» и показывает права словами; не названный в `plugins.enabled` не загружается и показан как `disabled`
8. [FR-CH-1003]
   - Дано плагины в разных состояниях: активирован, ленивый до первого вызова, хост перезапускается, снят отказом, не включён
   - Когда окно «Плагины Cyborg» запрашивает состояние
   - Тогда состояния выведены из журнала и равны `active`, `waiting`, `restarting`, `stopped`, `disabled`
9. [FR-CH-1020]
   - Дано плагин поставки с `"host": "own"` в манифесте
   - Когда ядро раскладывает плагины по хостам
   - Тогда плагин получает отдельный хост, а не `builtin`; значение `host`, кроме `own`, - ошибка манифеста
10. [FR-CH-1020] [UC-EXTENSION-CONTRACTS-2001#2] [UC-EXTENSION-CONTRACTS-2001#2в]
   - Дано плагин с `"host": "own"` назван человеком в группе `plugins.hosts` вместе с соседями
   - Когда ядро раскладывает плагины по хостам
   - Тогда действует группа; в журнале `host-own-grouped` со списком соседей, «Плагины Cyborg» показывают предупреждение; группа из него одного предупреждения не даёт
