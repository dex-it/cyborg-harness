# ST-6001 Приложение подключает ядро пакетами и задаёт поставку списком

Как разработчик приложения, я хочу подключить ядро тремя пакетами и описать поставку списком плагинов, чтобы не копировать файлы из репозитория харнеса.

Нормы: FR-CH-1001, FR-CH-1002, FR-CH-1003, FR-CH-1004, FR-CH-1005, FR-CH-6001, FR-CH-6002, FR-CH-6003, NFR-CH-1007. Сценарии: UC-DELIVERY-6001. SRS - [srs.md](../srs.md).

## Критерии приёмки

1. [FR-CH-6001] [NFR-CH-1007] [UC-DELIVERY-6001#1] [UC-DELIVERY-6001#2] [UC-DELIVERY-6001#2а]
   - Дано пример приложения, собранный из опубликованных пакетов `@cyborg-harness/core`, `@cyborg-harness/contracts`, `@cyborg-harness/electron`
   - Когда проверяется состав и импорты
   - Тогда у каждого пакета семантическая версия, подключение идёт через публичный экспорт, без импорта файлов `core/src` и `playground`; скопированных из `playground` и `core/src` файлов - 0
2. [FR-CH-6001] [UC-DELIVERY-6001#2б]
   - Дано приложению нужно то, чего нет в публичном экспорте
   - Когда разработчик просит доступ
   - Тогда доступно только расширение экспорта новой версией пакета, обход экспорта совместимости не получает
3. [FR-CH-6002] [UC-DELIVERY-6001#3] [UC-DELIVERY-6001#5]
   - Дано поставка - список каталогов плагинов с манифестом и кодом, включённых в `plugins.enabled`
   - Когда упакованное приложение запускается
   - Тогда плагин поставки определён каталогом, а не манифестом; встроенные идут раньше пользовательских; больше поставка ничего не содержит
4. [FR-CH-6002] [FR-CH-1003] [FR-CH-1005] [UC-DELIVERY-6001#3б] [UC-DELIVERY-6001#5б]
   - Дано пользовательский плагин с `id` встроенного, в другом случае - со своим `id` в каталоге плагинов пользователя
   - Когда ядро ищет плагины
   - Тогда при повторе `id` отказ получает пользовательский; свой плагин пользователя получает отдельный хост
5. [FR-CH-6002] [UC-DELIVERY-6001#5а]
   - Дано каталог поставки пуст или недоступен
   - Когда приложение запускается
   - Тогда окно без плагинов, управление плагинами работает, ошибки запуска нет
6. [FR-CH-6003] [UC-DELIVERY-6001#4] [UC-DELIVERY-6001#4а] [UC-DELIVERY-6001#6] [UC-DELIVERY-6001#7]
   - Дано упакованное приложение (asar, `node-pty`) и плагин с npm-зависимостью без бандла
   - Когда приложение запускается
   - Тогда плагины поставки грузятся из каталога поставки, хосты запускаются; сломанный упаковкой плагин получает отказ загрузки с причиной в журнале и в «Плагины Cyborg»; приложение и остальные плагины работают; разработчик видит каждый загруженный плагин активным или ждущим ленивой активации, а отказанный - с причиной
7. [FR-CH-1001] [FR-CH-1002] [FR-CH-1004] [UC-DELIVERY-6001#3а]
   - Дано плагин поставки с ошибкой манифеста, несовместимым `engines.cyborg` или без поставщика из `requires`
   - Когда ядро читает манифесты
   - Тогда плагин не загружается, причина в журнале и в «Плагины Cyborg», приложение и остальные плагины работают

Открыто: [UC-DELIVERY-6001#1а] правила совместимости версий трёх пакетов норма не задаёт (вопрос 1 сценария; предложение: адаптер объявляет допустимый диапазон ядра и контрактов зависимостью); критерий появится с решением.
