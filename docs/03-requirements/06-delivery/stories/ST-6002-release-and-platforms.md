# ST-6002 Выпуск пакетов проверен сборкой примера, ОС ведут себя одинаково

Как разработчик приложения, я хочу, чтобы выпуск пакета нёс версию и журнал изменений и проверялся сборкой примера, а Linux и macOS вели себя одинаково, чтобы обновление ядра не ломало приложение.

Нормы: FR-CH-6004, FR-CH-6005, FR-CH-6006, NFR-CH-1009. Сценарии: UC-DELIVERY-6001. SRS - [srs.md](../srs.md).

## Критерии приёмки

1. [FR-CH-6004] [UC-DELIVERY-6001#8] [UC-DELIVERY-6001#8а]
   - Дано выпуск пакета `@cyborg-harness/*` с ломающим изменением публичного экспорта и выпуск с изменением поведения, видимым автору плагина
   - Когда выпуск готовится
   - Тогда ломающее изменение выходит только мажорной версией; запись в журнале изменений есть в обоих выпусках; плагины поставки при мажорном ядре пересобираются вместе (3а сценария обновления)
2. [FR-CH-6004] [UC-DELIVERY-6001#8] [UC-DELIVERY-6001#9] [UC-DELIVERY-6001#9а]
   - Дано минорное обновление ядра
   - Когда разработчик меняет номера версий и пересобирает приложение
   - Тогда плагины поставки в пределах той же мажорной версии не пересобираются; поломка от минорного обновления - дефект выпуска, который снимок API в CI ядра не должен пропустить
3. [FR-CH-6005] [UC-DELIVERY-6001#10] [UC-DELIVERY-6001#10а]
   - Дано CI репозитория собирает пример приложения из опубликованных пакетов и прогоняет дымовой тест упакованной сборки
   - Когда дымовой тест красный
   - Тогда пакеты не публикуются, сборка приложения не выпускается
4. [FR-CH-6006] [NFR-CH-1009]
   - Дано Linux и macOS
   - Когда CI гоняет сборку, типы, линтер, тесты, дымовой тест и бюджеты NFR-CH-1001
   - Тогда системное сочетание срабатывает из любого `<iframe>`, pty переживает перезапуск хоста и окна, единый реестр сочетаний на macOS работает так же; тестов, зелёных на одной ОС и красных на другой, - 0
