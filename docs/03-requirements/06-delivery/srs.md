# SRS фичи 06 - поставка и платформы

## 1. SRS overview

Как ядро доходит до приложения и на каких ОС работает: пакеты `@cyborg-harness/*`, публичный экспорт, список встроенных плагинов, упакованная сборка с каталогом поставки, выпуск пакетов, платформы. Закрывает BR-CH-009 и ограничение 6 BRD. Сценарий - [приложение подключает ядро пакетами](../../02-use-cases/app-embeds-core/scenario.md). Устройство - [SAD](../../04-architecture/design/sad.md), раздел 2; [проверка на macOS](../../05-verification/macos-check.md). Метод проверки называет тест ядра (`core/test`), тест playground (`playground/test`, `playground/src/main/*.test.ts`) или дымовой тест окна (`playground/scripts/smoke.mjs`, `npm run smoke`). Что не сделано - помечено «Ещё нет» или «Отложено», остаток - [дорожная карта](../../06-plans/roadmap.md). Раскладка норм по фичам - [03-requirements](../README.md).

Функции поставки - FR-CH-6001…6006, меры - NFR-CH-1007 и NFR-CH-1009. Поведение ядра при загрузке плагинов поставки (поиск, порядок, граф, хост `builtin`) лежит в [фиче 01](../01-plugin-host/srs.md): FR-CH-1003, FR-CH-1004, FR-CH-1005; совместимость версий плагина и ядра - [фича 05](../05-compatibility/srs.md): FR-CH-1002, NFR-CH-1006.

## 2. Требования

### FR-CH-6001 Пакеты и публичный экспорт

- **Требование:** ядро, контракты и адаптер Electron публикуются тремя пакетами `@cyborg-harness/core`, `@cyborg-harness/contracts` и `@cyborg-harness/electron`. Приложение подключает ядро и адаптер через публичный экспорт пакетов, без импорта файлов `core/src` и `playground`. Приложению, которому нужно то, чего нет в публичном экспорте, доступно только расширение экспорта новой версией пакета.
- **traced from:** BR-CH-009; приложение подключает ядро (`app-embeds-core`, шаги 1-2, расширения 2а, 2б).
- **источник:** [SAD, раздел 2](../../04-architecture/design/sad.md#2-что-есть-ядро); задачи P-02, P-03, T-09, P-01; D-00, строка 3: scope `@cyborg-harness` принят, ядро - пакет (решено при P-02), адаптер - пакет `@cyborg-harness/electron` в этом репозитории (решено при P-03).
- **verification:** частично. Пакет ядра `@cyborg-harness/core` 0.1.0 (P-02, PR #103; `private` до P-10) с точками входа: основная, `/host`, `/host-entry`, `/keys`, `/ui-shell`, `/elements`; испытание - `core/test/package.test.ts` («playground берёт ядро через пакет: ни импортов, ни строковых путей (new URL, fork, readFile) в core/src и core/elements», «npm pack: в архиве dist, package.json и README, без исходников и тестов»). Пакет контрактов собирается в декларации и не `private` (P-01, PR #102; `contracts/test/package.test.ts`). Пакет адаптера `@cyborg-harness/electron` (P-03, PR #115; `electron/test/package.test.ts`, `consumer.test.ts`) и граница экспорта ядра (T-09, PR #113; `core/test/public-api.test.ts`, `electron/test/public-api.test.ts`) влиты. Ещё нет: публикации - P-10. Испытание после неё - сборка примера приложения только из пакетов (FR-CH-6005). Состав экспорта и раскладка адаптера - вопросы 2 и 4 раздела 3.
- **класс:** Portability.

### FR-CH-6002 Поставка - список встроенных плагинов

- **Требование:** приложение задаёт поставку списком каталогов встроенных плагинов с манифестом и кодом и включает их в `plugins.enabled`; ничего другого поставка не содержит. Плагин поставки определяется каталогом, а не манифестом, встроенный раньше пользовательского, при повторе `id` отказ получает пользовательский. Пустой или недоступный каталог поставки - окно без плагинов с работающим управлением плагинами, а не ошибка запуска.
- **traced from:** BR-CH-009; приложение подключает ядро (`app-embeds-core`, шаги 3, 5, расширения 3б, 5а).
- **источник:** [SAD, раздел 2](../../04-architecture/design/sad.md#2-что-есть-ядро) («Поставка Cyborg - это список встроенных плагинов и больше ничего»); задача P-07. Поиск и порядок - FR-CH-1003, окно без плагинов - FR-CH-1010, отсутствие имён плагинов в ядре - NFR-CH-1003.
- **verification:** испытание - `electron/test/plugins.test.ts` («поиск: встроенные раньше пользовательских, повтор id - второму не достаётся точка входа…»). Ещё нет: задания каталога поставки приложением через публичный экспорт (P-07, T-09); теста пустого каталога поставки (`startPlugins` с несуществующим `builtinDir` в `plugins.test.ts` стартует, но поведение не утверждает). Форма списка - вопрос 2 раздела 3.
- **класс:** Portability.

### FR-CH-6003 Упакованная сборка загружает плагины поставки

- **Требование:** упакованное приложение (asar, `node-pty`) загружает плагины поставки из каталога поставки и запускает хосты. Плагин, который упаковка сломала (npm-зависимость без бандла, каталог поставки не попал в сборку), получает отказ загрузки с причиной в журнале и в «Плагины Cyborg»; приложение и остальные плагины работают.
- **traced from:** BR-CH-009; приложение подключает ядро (`app-embeds-core`, шаги 4-6, расширение 4а).
- **источник:** [SAD, раздел 2](../../04-architecture/design/sad.md#2-что-есть-ядро); [дорожная карта, раздел 9](../../06-plans/roadmap.md#9-встраиваемость-и-поставка) («упаковка не проверена»); задачи P-07, T-10, P-06 (бандл главной части - [фича 07](../07-author-kit/srs.md)).
- **verification:** Ещё нет. Упаковка (asar, подпись, `node-pty`) не проверена: собранное приложение может не запустить плагины. Испытание после P-07 и T-10 - дымовой тест упакованной сборки: плагины поставки активны, плагин с npm-зависимостью без бандла отказан с причиной. Где лежит каталог поставки и что остаётся вне asar - вопрос 3 раздела 3.
- **класс:** Portability.

### FR-CH-6004 Выпуск пакета: версия и журнал изменений

- **Требование:** каждый выпуск пакета `@cyborg-harness/*` несёт семантическую версию и запись в журнале изменений. Ломающее изменение публичного экспорта выходит только мажорной версией. Выпуск, в котором изменилось поведение, видимое автору плагина, содержит запись об этом в журнале изменений.
- **traced from:** BR-CH-009; приложение подключает ядро (`app-embeds-core`, шаги 8-9, расширения 8а, 9а).
- **источник:** [эпик, раздел 7](../../06-plans/epic-microkernel.md#7-правила-для-всех-задач-эпика), п. 3; задачи P-01, P-10; BR-CH-008 (мера - снимок API, [фича 05](../05-compatibility/srs.md), NFR-CH-1006).
- **verification:** частично: у пакета контрактов журнал изменений `contracts/CHANGELOG.md`, а `npm run check:contracts` в CI красит правку деклараций без новой версии и снимка (P-01, PR #102). Ещё нет: журнала изменений ядра и адаптера, публикации (P-10), сверки рода изменения с версией (T-06). Осмотр - выпуск пакета без записи в журнале изменений не проходит CI; анализ - сверка версии пакета с изменением снимка API (T-06).
- **класс:** Supportability.

### FR-CH-6005 Проверка выпуска в CI

- **Требование:** CI репозитория собирает пример приложения из опубликованных пакетов и прогоняет дымовой тест его упакованной сборки; пакеты не публикуются, если сборка примера или дымовой тест красные.
- **traced from:** BR-CH-009; приложение подключает ядро (`app-embeds-core`, шаг 10, расширение 10а).
- **источник:** [NFR-CH-1007](#nfr-ch-1007-поставка-пакетами), метод проверки; задача P-10; `.github/workflows/ci.yml`.
- **verification:** Ещё нет. Сегодня CI собирает пакет ядра и стенд, сверяет снимок деклараций контрактов, гоняет типы, линтер, тесты и smoke на macOS и Linux; примера приложения из пакетов нет. Испытание после P-10 (P-02 и P-03 влиты) - красный дымовой тест примера останавливает публикацию. Приложения вне репозитория CI ядра не проверяет - вопрос 5 раздела 3.
- **класс:** Supportability.

### FR-CH-6006 Системное сочетание и pty на поддерживаемых ОС

- **Требование:** на Linux и macOS системное сочетание срабатывает из любого `<iframe>`, а pty переживает перезапуск хоста и окна. Единый реестр сочетаний на macOS работает так же, как на Linux.
- **traced from:** BR-CH-001; ограничение 6 BRD.
- **источник:** [проверка на macOS](../../05-verification/macos-check.md); [открытый вопрос 12 SAD](../../04-architecture/design/sad.md#8-открытые-вопросы). Вынесено из NFR-CH-1009; сочетания - FR-CH-2004, pty - FR-CH-1015.
- **verification:** испытание - дымовой тест окна на macOS и Linux в CI (`.github/workflows/ci.yml`); осмотр - [проверка на macOS](../../05-verification/macos-check.md) (`Cmd+Shift+A`, `F2`, `Cmd+Shift+B`, `F6` проверены; буквы в поле вида, `Cmd+C`/`Cmd+V`, замок, терминал человеком - нет). Ещё нет: единого реестра сочетаний на macOS (PL-03, после K-08; K-07 влит, PR #121).
- **класс:** Portability.

### NFR-CH-1007 Поставка пакетами

- **Требование:** в примере приложения, собранном из опубликованных пакетов, файлов, скопированных из `playground` и `core/src`, - 0; у каждого из трёх пакетов есть семантическая версия. Функции поставки - FR-CH-6001…6006.
- **traced from:** BR-CH-009 (MOE: скопированных из `playground` файлов в приложении - 0).
- **источник:** [SAD, раздел 2](../../04-architecture/design/sad.md#2-что-есть-ядро); scope - [D-00](https://github.com/dex-it/cyborg-harness/issues/21), строка 3.
- **verification:** анализ - поиск файлов `playground` и `core/src` в исходниках и сборке примера приложения; неуспех - любой найденный файл. Ещё нет: примера приложения только из пакетов и публикации (P-10); пакеты ядра, контрактов и адаптера собираются (P-01, P-02, P-03). Что приложения вне репозитория не измеряются - вопрос 5 раздела 3.
- **класс:** Portability.

### NFR-CH-1009 Платформы

- **Требование:** на каждой из двух ОС, Linux и macOS, все шаги CI - сборка, типы, линтер, тесты, дымовой тест - зелёные, а бюджеты NFR-CH-1001 выдерживаются; тестов, зелёных на одной ОС и красных на другой, - 0. Поведение на ОС - FR-CH-6006. Windows - по решению владельца ([D-00](https://github.com/dex-it/cyborg-harness/issues/21), строка 7; вопрос 6 раздела 3).
- **traced from:** BR-CH-001; ограничение 6 BRD.
- **источник:** [открытый вопрос 12 SAD](../../04-architecture/design/sad.md#8-открытые-вопросы); [проверка на macOS](../../05-verification/macos-check.md).
- **verification:** испытание - CI на macOS и Linux (`.github/workflows/ci.yml`: сборка, типы, линтер, тесты, smoke); замеры `npm run spike:hosts` и `npm run spike` на обеих ОС. Память на macOS (footprint) и на Linux (PSS) - разные меры, сравнение порядком величины ([проверка на macOS](../../05-verification/macos-check.md)). Ещё нет: проверки бюджетов NFR-CH-1001 в CI (P-10); нестабильного локального smoke на macOS (причина падений на шаге выключения `echo` не выяснена); Windows.
- **класс:** Portability.

## 3. Открытые вопросы

Нормы выше не выбирают вариант там, где решение за владельцем. После каждого вопроса - предложение составителя.

1. **Связь версий трёх пакетов (`app-embeds-core`, расширение 1а и вопрос 1; нормы нет: варианты отсекают друг друга, соседняя норма - FR-CH-6004).** Варианты: (а) адаптер объявляет допустимый диапазон ядра и контрактов зависимостью; (б) три пакета выходят одной версией. Предлагаю (а): несовместимая пара не ставится, а не ломается при запуске.
2. **Состав публичного экспорта и форма списка встроенных плагинов (FR-CH-6001, FR-CH-6002; сценарий, вопрос 2).** Задачи T-09 и P-07. Точки входа пакета ядра заданы при P-02 (PR #103): основная, `/host`, `/host-entry`, `/keys`, `/ui-shell`, `/elements`; границу экспорта провёл T-09 (PR #113; `core/test/public-api.test.ts`: перечни входов под тестом). Предлагаю снять состав снимком API (T-06) после T-09; до этого в норме имён экспорта нет.
3. **Каталог поставки в упакованном приложении и что остаётся вне asar (FR-CH-6003; сценарий, вопрос 3).** Задачи P-07 и T-10. Предлагаю решить по результату упаковки примера: `node-pty` и код хостов - вне asar, каталог поставки - рядом с ресурсами приложения.
4. **Где живут адаптер Electron и встроенные плагины (FR-CH-6001; сценарий, вопрос 4).** D-00, строка 3. Адаптер решён 2026-11-08 при P-03 по предложению: пакет `@cyborg-harness/electron` в этом репозитории, каталог `electron/` (влито, PR #115). Открыто, где живут встроенные плагины Cyborg; держит P-11. Варианты: (а) в репозитории харнеса; (б) в репозитории Cyborg. Предлагаю (б): BR-CH-009 - поставка приложения есть его список.
5. **Как проверяется «скопированных файлов - 0» (NFR-CH-1007; сценарий, вопрос 5).** Предлагаю принять проверкой примера приложения в репозитории и не измерять чужие приложения.
6. **Windows (NFR-CH-1009).** D-00, строка 7 (открыта), вопрос 12 SAD; pty на Windows не проверялся. Предлагаю не писать норму для Windows, пока владелец не включит её в v1.
