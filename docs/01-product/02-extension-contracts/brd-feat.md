# BRD фичи 02 - контракты, доступ и UI плагинов

Источник: запрос владельца (2026-11-02), [ресёрч](../../research/comparison.md) и [SAD](../../03-architecture/design/sad.md), цели 3.4, 3.7-3.10 и разделы 4-5. Родитель - [BRD продукта](../brd.md): BR-CH-001, BR-CH-002, BR-CH-003, BR-CH-004, BR-CH-005.

## 1. BRS overview

Плагин полезен ровно настолько, насколько ему есть куда подключиться. Образцы показали две крайности: у bb контракты интерфейса на 6000 строк и сотни `experimental_`-членов, у dsh 108 классифицированных сервисов. Мы не задаём набор точек расширения: плагины связываются контрактами, которые объявляют в манифесте, а ядро проверяет граф до запуска кода. Доступ к ОС идёт только через шлюз `ctx.os` по правам манифеста, UI плагина живёт в своём `<iframe>`, агент - обычный плагин, поставщик `cyborg.agent` ([SAD, раздел 7](../../03-architecture/design/sad.md#7-расхождения-с-первой-редакцией-пакета)).

## 2. Business purpose

Дать плагинам общий способ связи, доступа к ОС и показа UI, чтобы встроенные и сторонние плагины подключались одинаково, другие агенты - без правок ядра, а права плагина были видны и проверялись на каждом вызове.

## 3. Business scope

Внутри: контракты в манифесте с кратностью и версиями; события как подписки в контракте владельца, события окна и системы; команды с аргументами по схеме, системные сочетания и их переназначение; виды в `<iframe>` с `mount`, документы, слой окна (диалоги и замок); шлюз `ctx.os` с правами по манифесту и `via-contract`; хранилище секретов и ссылки `$secret`; разделы `config` и `state`; контракт `cyborg.agent` и плагин `agent-claude-code`; права словами и два этапа изоляции.

`non-goals`:

- структурные агенты (SDK, ACP): отдельный контракт позже;
- общая шина событий, реестр сервисов по ключам, `inject`, waterfall-события ([SAD, раздел 2](../../03-architecture/design/sad.md#2-что-есть-ядро));
- встраивание чужого UI в свой вид - «задача, а не виджет» ([SAD, 3.8](../../03-architecture/design/sad.md#38-изоляция-рендера));
- общий фреймворк UI для плагинов;
- источник секретов `cyborg.secret-source` до первого источника; `Compartment`, окна согласия и установка - этап 2.

## 4. Стороны и сценарии

Мейнтейнер, автор плагина, автор агента, пользователь. Сценарии: [второй агент](../../02-use-cases/second-agent/scenario.md), [установка стороннего плагина](../../02-use-cases/third-party-install-permissions/scenario.md), [мейнтейнер добавляет функцию](../../02-use-cases/maintainer-adds-feature/scenario.md).

## 5. Меры эффективности

| MOE | Значение |
|---|---|
| Второй поставщик агента написан без правок ядра | `agent-shell` проходит общий набор `cyborg.agent` (`playground/test/agents.test.ts`) |
| Вызов `ctx.os` без права отклоняется шлюзом с записью в журнале | 100% в тестах отказов (`core/test/os.test.ts`) |
| Право не передаётся через чужой контракт | 100% членов с `guard` (`core/test/via-contract.test.ts`) |
| Конфликт сочетаний виден при загрузке | 100% конфликтов (`core/test/lifecycle.test.ts`) |
| Плагин видит только свой раздел `config` и `state` | 0 записей в чужой раздел (`core/test/trust.test.ts`) |
