# SRS фичи 01 - ядро и загрузчик плагинов

## 1. SRS overview

Требования к ядру и загрузчику: воркспейс, манифест, совместимость, граф, активация, хосты и сторож, pty, выгрузка, безопасный режим, журнал, версии, набор автора. Контракты, доступ к ОС и UI плагинов - [фича 02](../02-extension-contracts/srs.md). Устройство - [SAD](../../03-architecture/design/sad.md), разделы 2, 3.1-3.6 и 6. Ядро реализовано в `core/`; метод проверки называет тест ядра (`core/test`), тест playground (`playground/test`, `playground/src/main/*.test.ts`) или дымовой тест окна (`playground/scripts/smoke.mjs`, `npm run smoke`). Что не сделано - помечено «Ещё нет», остаток - [дорожная карта](../../05-plans/roadmap.md).

## 2. Требования

### FR-CH-1001 Манифест плагина

- **Требование:** манифест - JSON-объект, который ядро разбирает до запуска кода плагина; приложение читает его из `manifest.json` в каталоге плагина. Обязательны `id` (имя вида `pin-lock` или `cyborg.files`), `version` (`x.y.z`) и `engines.cyborg` (диапазон версий). Необязательны `provides`, `requires`, `optional`, `consumes`, `commands`, `keybindings`, `config`, `state`, `permissions`, `host`, `activation`, `ui`, `lock`, `documents`. Ошибки собираются все сразу, `id` сохраняется для журнала. Включённый плагин с ошибками в манифесте получает запись `invalid`, его код не запускается. `id`, в пространстве которого лежат команды окна и ядра (`cyborg`, `cyborg.window`, `cyborg.workspace`), занят ядром.
- **traced from:** BR-CH-001.
- **источник:** [SAD, 3.2](../../03-architecture/design/sad.md#32-загрузка-плагинов), [SAD, 3.3](../../03-architecture/design/sad.md#33-версии-и-миграции); `core/src/manifest.ts`.
- **verification:** испытание - `core/test/semver-manifest.test.ts` (минимальный манифест, все ошибки сразу, `many` не может быть `one`), `core/test/loader.test.ts` («журнал: невалидный…», «битый манифест невключённого плагина - disabled, а не invalid»), `core/test/window.test.ts` («манифест: id, в пространстве которого лежат команды окна, занят»).
- **класс:** Functions.

### FR-CH-1002 Проверка совместимости до запуска кода

- **Требование:** до запуска кода `engines.cyborg` плагина сверяется с версией API плагинов (`ctx` и элементы ядра). Несовместимый плагин не загружается: отказ графа с причиной «нужен API Cyborg <диапазон>, есть <версия>». Отказ каскадирует на тех, кто требует плагин через `requires`; потребитель через `optional` остаётся.
- **traced from:** BR-CH-002, BR-CH-006.
- **источник:** [SAD, 3.3](../../03-architecture/design/sad.md#33-версии-и-миграции); `core/src/graph.ts`.
- **verification:** испытание - `core/test/graph.test.ts` («отказ по engines каскадирует на зависимых, optional переживает»).
- **класс:** Functions.

### FR-CH-1003 Обнаружение и состояния

- **Требование:** плагины ищутся в каталоге поставки и в каталоге плагинов пользователя; встроенные раньше пользовательских, повтор `id` - отказ второму. Признак поставки - каталог, а не манифест. Загружаются только плагины из `plugins.enabled`. Состояние плагина ядро выводит из журнала: `active`, `waiting` (ждёт ленивой активации), `restarting` (хост перезапускается), `stopped` (снят отказом, сбоем или человеком), `disabled` (не включён в настройках).
- **traced from:** BR-CH-006.
- **источник:** [SAD, 3.2](../../03-architecture/design/sad.md#32-загрузка-плагинов), [SAD, 3.5](../../03-architecture/design/sad.md#35-изоляция-сбоев-хосты-и-сторож); `core/src/status.ts`, `electron/src/plugins.ts`.
- **verification:** испытание - `electron/test/plugins.test.ts` («поиск: встроенные раньше пользовательских, повтор id…»), `core/test/graph.test.ts` («повтор id - отказ второму»), `core/test/status.test.ts`.
- **класс:** Functions.

### FR-CH-1004 Граф контрактов до запуска кода

- **Требование:** ядро разрешает граф `provides` / `requires` / `optional` / `consumes` по манифестам до запуска кода. Нет поставщика из `requires`, два поставщика при кратности `one`, цикл - плагин не загружается, причина в журнале называет контракт, поставщиков или участников цикла. Отказ каскадирует на зависящих через `requires`. Несовместимая мажорная версия поставщика - как его отсутствие. `consumes` ребра не создаёт: встречные `consumes` допустимы. Сторонний плагин, который отдаёт контракт `cyborg.*` или носит `id` из `cyborg.`, не загружается, причина называет имя и пространство; брать `cyborg.*` ему можно. Активация идёт в порядке графа: поставщик раньше потребителя.
- **traced from:** BR-CH-006.
- **источник:** [SAD, 3.2](../../03-architecture/design/sad.md#32-загрузка-плагинов), [SAD, раздел 4](../../03-architecture/design/sad.md#4-взаимодействие-плагинов); dsh 11 (молчаливый PENDING как слабость).
- **verification:** испытание - `core/test/graph.test.ts` (порядок, отсутствие, два поставщика `one`, цикл, `consumes`, мажорная версия, пространство поставки), `core/test/loader.test.ts` («пространство поставки: …»), `core/test/status.test.ts` (причина словами).
- **класс:** Functions.

### FR-CH-1005 Изоляция сбоя: хосты и сторож

- **Требование:** главные части плагинов работают в хостах `utilityProcess`, не в главном процессе. Исключение при активации или в вызове ловит хост: отказывает только этот плагин, с записью в журнале. Сторож проверяет хост раз в 1 с; нет ответа 5 с - хост перезапускается, виновник - при зависании плагин, чей код хост выполнял (хост называет плагин ядру до входа в его код: вызов, событие, таймер, продолжение после ответа ядра), при падении - плагин, чей код завершил процесс (`process.exit`, необработанное исключение в его асинхронной цепочке); хост виновника не назвал, например процесс убит сигналом, - плагин первого вызова, принятого после последнего отвеченного пинга. Необработанное отклонение промиса плагина хост не роняет: запись `unhandled-rejection` на виновника и страйк. Виновник ошибки - плагин, с чьего входа началась цепочка, а не вошедший последним; ошибка вне цепочки плагина - сбой кода хоста без виновника. После трёх сбоев подряд (зависание, падение, отклонение) виновник выключается с записью `switched-off`; выключенный отклонением снимается с живого хоста, без перезапуска соседей. Падение хоста идёт тем же путём. Перезапуск не трогает другие хосты, окно и pty; потребители из других хостов узнают о пропаже и возврате поставщика из `ctx.contracts.onChange`. Плагины из поставки идут в хост `builtin` или в группы `plugins.hosts`; сторонний плагин всегда один в своём хосте, а попытка сгруппировать его даёт запись `host-isolated`.
- **traced from:** BR-CH-005, BR-CH-006.
- **источник:** [SAD, 3.5](../../03-architecture/design/sad.md#35-изоляция-сбоев-хосты-и-сторож); пороги - [замер хостов](../../04-verification/spike-hosts.md).
- **verification:** испытание - `core/test/hosts.test.ts` (зависание, падение, выключение после N сбоев; виновник в общем хосте - таймер, слушатель, продолжение после ответа, падение в таймере, убийство снаружи, прежнее правило без отметки хоста, ответ на пинг вместе с уведомлением о коде; необработанное отклонение, отклонение после `await`, исключение в `queueMicrotask` и `process.nextTick`, три отклонения подряд, ошибка вне цепочки плагина), `playground/test/host-electron.test.ts` («хост на рантайме Electron…»), `core/test/loader.test.ts` («сбой активации снимает уже отданное плагином», «хост упал без виновника…», «хосты: из поставки - по группам, сторонний всегда один в своём хосте»); дымовой тест - «падение и зависание хоста: сторож перезапускает».
- **класс:** Functions.

### FR-CH-1006 Откат регистраций

- **Требование:** всё, что плагин отдал ядру, - контракты, команды, подписки, наблюдения `fs.watch`, серверы `serve`, диалоги, незавершённые `process.run` с их потомками и запросы `net.fetch` - снимается при выгрузке, падении хоста и сбое активации. Подписка привязана к вызывающему: ядро снимает её при уходе любой из сторон. После выгрузки в реестрах ядра нет записей плагина.
- **traced from:** BR-CH-001, BR-CH-006.
- **источник:** [SAD, 3.2](../../03-architecture/design/sad.md#32-загрузка-плагинов), [SAD, раздел 4](../../03-architecture/design/sad.md#4-взаимодействие-плагинов) (п. 6); dsh 2 (эффекты с откатом).
- **verification:** испытание - `core/test/loader.test.ts` («активация по графу… снятие в обратном порядке», «сбой активации снимает уже отданное плагином»), `core/test/subscriptions.test.ts`, `core/test/os.test.ts` («fs.watch: … выгрузка закрывают наблюдение»), `core/test/serve.test.ts` («… dispose и выгрузка закрывают»), `core/test/window.test.ts` («диалог вида: … выключение плагина закрывает…»), `core/test/os-lifetime.test.ts` («process.run: выключение плагина и выгрузка ядра завершают программу вместе с её потомками», «net.fetch: зависший сервер - … выгрузка плагина обрывает запрос»).
- **класс:** Functions.

### FR-CH-1007 Выгрузка, загрузка и каскад зависимых

- **Требование:** выгрузка и загрузка плагина идут без перезапуска окна. Выгрузка снимает плагин и тех, кто требует его через `requires`, в обратном порядке активации; потребители через `optional` и `consumes` остаются и получают `onChange`. Хост, где не осталось плагинов, гасится, поэтому загрузка поднимает код в новом процессе. Плагин, выгруженный человеком, не поднимают ни сторож, ни включение соседа. Смена `plugins.enabled` в файле без перезапуска выключает убранные плагины и включает вернувшиеся; плагин, которого не было в графе при запуске, ждёт перезапуска с записью в окне.
- **traced from:** BR-CH-006.
- **источник:** [SAD, 3.1](../../03-architecture/design/sad.md#31-воркспейс-как-главная-сессия), [SAD, 3.2](../../03-architecture/design/sad.md#32-загрузка-плагинов).
- **verification:** испытание - `core/test/lifecycle.test.ts` («disable: требующие выгружаются вместе с поставщиком, необязательный остаётся; enable поднимает…», «disable: выключенного человеком enable соседа не поднимает»), `electron/test/plugins.test.ts` («plugins.enabled из файла воркспейса без перезапуска…»); дымовой тест - «выгрузка с зависимыми, загрузка в новый процесс, переподписка». Ещё нет: включение без перезапуска плагина, которого не было в графе при запуске.
- **класс:** Functions.

### FR-CH-1008 Ленивая активация

- **Требование:** плагин с `"activation": "lazy"` при старте получает состояние `waiting`. Будят его первая команда, его сочетание, показ его вида и активация потребителя его контракта. Поставщиков из `requires` и `optional` ядро поднимает до потребителя, поставщиков `consumes` - без ожидания. Выключенный человеком ленивый плагин команда не будит. Плагин без `activation` активируется при старте; `lock.onStart` активирует плагин сразу, даже ленивый.
- **traced from:** BR-CH-007.
- **источник:** [SAD, 3.2](../../03-architecture/design/sad.md#32-загрузка-плагинов).
- **verification:** испытание - `core/test/events.test.ts` («activation lazy: ждёт; будит команда, сочетание, wake и потребитель контракта…»), `core/test/window.test.ts` («lock.onStart: … ленивый плагин замка активируется сразу…»); дымовой тест - «ленивая активация по команде».
- **класс:** Functions.

### FR-CH-1009 Безопасный режим

- **Требование:** безопасный режим выключает все плагины без исключений: хосты не запускаются, каждый плагин получает запись `safe-mode`, замок `lock.onStart` не ставится, включить плагин нельзя (`Unavailable`). Окно и управление плагинами работают.
- **traced from:** BR-CH-005.
- **источник:** [SAD, 3.2](../../03-architecture/design/sad.md#32-загрузка-плагинов); bb 5.4 (`safe-mode`).
- **verification:** испытание - `core/test/loader.test.ts` («безопасный режим не запускает хосты»), `core/test/window.test.ts` («lock.onStart: … безопасный…»); приложение - `playground/scripts/smoke.mjs` (запуск с `--safe-mode`: записи `safe-mode`, хосты не подняты, окно не закрыто `lock.onStart`, «Включить» - отказ; пункты окна перезапускают с флагом и без него).
- **класс:** Functions.

### FR-CH-1010 Журнал и окно «Плагины Cyborg»

- **Требование:** ядро ведёт журнал плагинов: отказы загрузки (`invalid`, `not-found`, `rejected`), ошибки активации, отказы прав `denied`, падения и перезапуски хостов, конфликты сочетаний. У каждой записи есть описание словами и уровень. Окно «Плагины Cyborg» показывает у плагина состояние, причину из журнала, хост, время запуска, объявленные права словами и журнал плагина вместе с записями его хоста; даёт выгрузить, загрузить и «Включить снова» плагин, снятый сбоем. Окно без плагинов - нормальное состояние: управление плагинами в нём доступно.
- **traced from:** BR-CH-006.
- **источник:** [SAD, 3.2](../../03-architecture/design/sad.md#32-загрузка-плагинов), [SAD, 3.5](../../03-architecture/design/sad.md#35-изоляция-сбоев-хосты-и-сторож).
- **verification:** испытание - `core/test/status.test.ts`, `playground/test/plugins-model.test.ts`, `core/test/os.test.ts` («права в манифесте: … права словами»), `electron/test/plugins.test.ts` («служба окна: снимок с причиной и журналом, «Включить снова»…»); дымовой тест - «окно: заглушка с причиной, журнал плагина, «Включить снова»».
- **класс:** Functions.

### FR-CH-1012 Версии API плагинов и контрактов

- **Требование:** API плагинов (`ctx` и элементы ядра) и контракты версионируются семантически. Элемент ядра не удаляется и не меняет атрибуты в пределах мажорной версии. Минорная версия контракта добавляет только необязательное; мажорная - новый тип в карте `Contracts`. Поставщик может давать две мажорные версии контракта сразу, каждый потребитель получает ту, что просил. Мажорная версия в `get` и `all` должна лежать в диапазоне манифеста потребителя, иначе `NotDeclared`. Член с `@deprecated` живёт минимум до следующей мажорной версии, ядро пишет в журнал, кто его вызывает (пометка - в манифесте поставщика, `provides.<контракт>.deprecated`).
- **traced from:** BR-CH-001, BR-CH-002.
- **источник:** [SAD, 3.3](../../03-architecture/design/sad.md#33-версии-и-миграции); `contracts/README.md`.
- **verification:** испытание - `core/test/graph.test.ts` («поставщик с двумя мажорными версиями обслуживает старого и нового потребителя», «несовместимая мажорная версия поставщика - как отсутствие»), `core/test/registry.test.ts` («потребитель получает свою мажорную версию…», «мажорная версия в get и all должна лежать в диапазоне манифеста»), `core/test/contracts-types.ts` (`npm run typecheck`), журнал вызовов `@deprecated` - `core/test/via-contract.test.ts` («@deprecated: …»), `core/test/journal.test.ts` («журнал: … устаревшего члена …», «журнал: записей deprecated-call не больше предела…»), `core/test/status.test.ts` («вызов устаревшего члена…»), `core/test/semver-manifest.test.ts` («манифест: deprecated у provides…»).
- **класс:** Functions.

### FR-CH-1013 Набор автора плагина

- **Требование:** автор пишет плагин на пакете объявлений `@cyborg-harness/contracts`: `PluginModule`, `PluginContext`, `UiContext` и карта `Contracts`, которую сторонний пакет дополняет через `declare module`; правила - `contracts/README.md`. Проверка импортов пропускает главной части только `@cyborg-harness/contracts`, свой пакет объявлений и свои модули; виду - ещё npm-пакеты; ни той, ни другому - `node:*` и `electron`. Примеры плагинов - `core/examples/plugins` (`npm run demo`) и `playground/plugins`. Общий набор тестов контракта, которым сторонний поставщик проверяет себя тем же, что и встроенный, есть для `cyborg.agent` (`agentContractSuite` пакета `@cyborg-harness/testing`); поднять ядро с поддельными pty и секретами в тесте плагина позволяет `startKernel` того же пакета.

### FR-CH-1014 Воркспейс как главная сессия

- **Требование:** один экземпляр - один воркспейс - одно окно. Воркспейс открывается флагом `--workspace=<файл>` или из «Недавних»; ядро берёт замок `<файл>.lock` с pid и забирает замок умершего процесса. Второй запуск приложения переводит фокус на открытое окно и завершается. `state` воркспейса лежит по ключу от `realpath` файла. `config` - слои пользователя и воркспейса, `plugins.enabled` воркспейса перекрывает пользовательский. Битый файл не роняет открытие и не перезаписывается; рядом ложится копия `<файл>.corrupt-<время>` с исходным содержимым, одна на одно содержимое. Показать файл воркспейса - команда ядра `cyborg.workspace.reveal`, плагину она недоступна. Документ без поля `cyborg` ядро один раз отдаёт хуку приложения `migrate` и записывает его итог с копией `<файл>.v1.bak`. «Недавние» - до 10 воркспейсов, последний первым, без повторов по `realpath`, пропавший файл не показывается. Закрытие окна или смена воркспейса выключает плагины и снимает замок; при живых pty окно сначала спрашивает человека.
- **traced from:** BR-CH-002.
- **источник:** [SAD, 3.1](../../03-architecture/design/sad.md#31-воркспейс-как-главная-сессия); `core/src/workspace.ts`, `core/src/recent.ts`.
- **verification:** испытание - `core/test/workspace.test.ts` (замок, ключ `state`, слои, битый файл и его копия, перенос хуком, «Недавние»), `core/test/os.test.ts` («команда ядра cyborg.workspace.reveal…»), `electron/test/plugins.test.ts` («воркспейс: битый cyborg.json - жалоба, а не отказ…»); дымовой тест - «воркспейс: замок с pid, второй запуск отдаёт фокус первому и уходит, открытый - в «Недавних»», «окно без воркспейса…».
- **класс:** Functions.

### FR-CH-1015 Процессы дольше плагина: pty

- **Требование:** pty держит ядро в главном процессе; плагин решает, что запустить, по праву `pty`. Перезапуск хоста или окна pty не завершает: pty с `persist` ждёт владельца, тот возвращается через `ctx.os.pty.list()` и `attach` и получает хвост вывода; не взятый за льготное время (по умолчанию 60 с) завершается с записью `pty-expired`. Оставленный человеком при выключении ждёт без срока, пока плагин выключен, а после активации плагина получает тот же срок. Оставленные процессы ядро отдаёт приложению списком, и человек может завершить любой. Чужой pty для плагина не существует (`NotFound`). Выключение плагина с живыми pty спрашивает человека: оставить процессы ждать возврата плагина или завершить; выход из приложения завершает все. Вид плагина видит вывод и пишет ввод по одноразовому билету `share()` своей главной части, мимо хоста: зависший хост терминал не останавливает. Короткие процессы `ctx.os.process` при падении хоста завершаются.
- **traced from:** BR-CH-006.
- **источник:** [SAD, 3.6](../../03-architecture/design/sad.md#36-ресурсы-дольше-плагина-pty); `core/src/pty.ts`.
- **verification:** испытание - `core/test/pty.test.ts` (предел ввода и числа pty, `COLORTERM`), `core/test/stress-pty.test.ts` (склейка вывода), `electron/test/view-terminals.test.ts`; замер - `npm run spike:pty` ([итоги](../../04-verification/spike-pty.md)); дымовой тест - «терминал вида: билет share(), вывод и ввод мимо хоста…», «выключение спрашивает о pty: оставленный процесс виден в строке плагина…». Ещё нет: проверки pty на Windows.
- **класс:** Functions.

### NFR-CH-1001 Накладные расходы

- **Требование:** время старта, память на хост и на `<iframe>`, задержка вызова через шлюз и вывода терминала укладываются в бюджет. Бюджет, принятый владельцем ([открытый вопрос 9 SAD](../../03-architecture/design/sad.md#8-открытые-вопросы)), - вызов через шлюз `ctx.os` не более 1 мс на p99 на вызов до 64 КиБ, событие `fs.watch` не позже 5 мс на p99 после окна склейки, вывод терминала не более 16 мс. Замерено на Linux: первый хост ~56 МБ PSS, каждый следующий ~34 МБ; вид со своим origin +13 МБ PSS; вызов p50 0,07-0,3 мс из главного процесса, p99 до 1,5 мс на вызов до 64 КиБ; перезапуск хоста 70 мс; вывод терминала от программы до хоста p99 0,5 мс под нагрузкой при склейке 4 мс ([замер pty](../../04-verification/spike-pty.md)). Цена шлюза `ctx.os` из плагина по медиане трёх прогонов - p50 до 0,4 мс, p99 до 0,7 мс на вызов до 64 КиБ; `fs.watch` сверх склейки 50 мс - 0,9 мс на p99, в пределах порога события ([замер шлюза](../../04-verification/spike-gateway.md)).
- **traced from:** BR-CH-007.
- **источник:** [SAD, раздел 2](../../03-architecture/design/sad.md#2-что-есть-ядро); [замер хостов](../../04-verification/spike-hosts.md), [замер шлюза](../../04-verification/spike-gateway.md), [замер pty](../../04-verification/spike-pty.md), [спайк UI](../../04-verification/spike-iframe-ui.md).
- **verification:** испытание - замеры `npm run spike:hosts` (`playground/scripts/spike-hosts.mjs`), `npm run spike:gateway` (`playground/scripts/spike-gateway.mjs`) и `npm run spike` (`playground/scripts/spike-iframe.mjs`); сверка с бюджетом шлюза - код выхода `spike-gateway.mjs`: медиана p99 за три прогона против порогов `--budget` и `--watch-budget`.
- **класс:** Performance.

### NFR-CH-1002 Устойчивость

- **Требование:** необработанная ошибка или зависание плагина - при активации, в вызове, в слушателе события, в виде - не завершает главный процесс и окно и не трогает другие хосты. Необработанное отклонение промиса плагина вне вызова не завершает и его хост: соседи по хосту работают без перезапуска. Модуль вида без `mount` отклоняется с причиной.
- **traced from:** BR-CH-006.
- **verification:** испытание - `core/test/hosts.test.ts` («сторож: необработанное отклонение плагина - запись на него, хост и сосед живут» и др.), `core/test/events.test.ts` («… упавший слушатель не мешает соседу…»), `core/test/ui-shell.test.ts` («mountModule: модуль без mount отклонён с причиной…»); дымовой тест - «падение и зависание хоста: сторож перезапускает».
- **класс:** Reliability.

### NFR-CH-1003 Компактность ядра

- **Требование:** задача попадает в ядро, только если она нужна всем плагинам или окну без плагинов и плагин не может решить её сам, не нарушив гарантию остальным. В ядре нет предметной области (агентов, сессий, файлов, проектов, трекеров, источников секретов), общей шины событий, реестра сервисов по ключам и `inject`. В коде ядра нет имён плагинов; перенос старого формата воркспейса - хук приложения `migrate`.
- **traced from:** BR-CH-001.
- **источник:** [SAD, раздел 2](../../03-architecture/design/sad.md#2-что-есть-ядро).
- **verification:** осмотр - новая задача ядра сверяется с критерием SAD, раздел 2; испытание - `core/test/purity.test.ts` (предметные слова, импорты и зависимости `core/src`).
- **класс:** Maintainability.
