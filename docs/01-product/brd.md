# BRD: Cyborg Harness - ядро и плагины

> Составлено по запросу владельца (2026-11-02): «сделать Cyborg таким же [как bb и DeepSeek Harness]: чтобы было ядро, чтобы были плагины, работало всё круто и качественно». 2026-11-05 сверено с [SAD](../04-architecture/design/sad.md) и кодом репозитория (`core/`, `contracts/`, `playground/`); при расхождении действует SAD. Статус `review`. Идентификаторы с префиксом `CH-` не пересекаются с корпусом приложения Cyborg.

## 1. BRS overview

Cyborg Harness - ядро плагинов для Cyborg. Ядро не знает предметной области: агенты, сессии, файлы, проекты и трекеры - плагины. Ядро открывает воркспейс, загружает плагины по манифестам, связывает их контрактами, изолирует их сбои, следит за правами и даёт им экран, клавиши и хранение ([SAD, раздел 1](../04-architecture/design/sad.md#1-общая-архитектура)). Образцы - [bb](../research/bb.md) и [DeepSeek Harness](../research/deepseek-harness.md). Документ адресован владельцу продукта и тем, кто разрабатывает ядро и плагины.

## 2. Business purpose

1. Снизить стоимость и риск добавления возможности: новая возможность - плагин, а не правка ядра.
2. Подключать других агентов, помимо Claude Code, без правок ядра.
3. Дать пользователям и командам расширять приложение своими плагинами безопасно.
4. Не терять данные пользователя при обновлении Cyborg и плагинов.

## 3. Business scope

Внутри границы: ядро по десяти целям [SAD, раздел 3](../04-architecture/design/sad.md#3-цели-ядра) - воркспейс, загрузка плагинов с проверкой графа до запуска кода, версии и миграции, контракты и команды, хосты `utilityProcess` со сторожем, pty у ядра, шлюз `ctx.os` с правами по манифесту и хранилище секретов, виды в `<iframe>` с `mount`, системные клавиши и события, `config` и `state` по разделам; пакет объявлений `@cyborg-harness/contracts`; контракт `cyborg.agent` и плагин `agent-claude-code`; окно «Плагины Cyborg»; стенд `playground`. Строится в два этапа: этап 1 - все цели, кроме гарантии доступа; этап 2 - изоляция доступа, когда для неё появится повод ([SAD, раздел 6](../04-architecture/design/sad.md#6-этапы)).

`non-goals`:

- свой цикл модели, замена Claude Code или перехват его вывода (сессия остаётся нативной);
- облако, удалённые хосты, мобильный клиент, учётные записи пользователей;
- предметная область в ядре: агенты, сессии, файлы, проекты, трекеры, источники секретов - плагины ([SAD, раздел 2](../04-architecture/design/sad.md#2-что-есть-ядро));
- общий фреймворк UI для плагинов ([SAD, 3.8](../04-architecture/design/sad.md#38-изоляция-рендера));
- структурные агенты (SDK, ACP) - отдельный контракт позже; сейчас агент - CLI в pty ([ADR-CH-0004](../04-architecture/adr/ADR-CH-0004-agent-provider-contract.md));
- каталог плагинов, установка и окна согласия до повода этапа 2 ([SAD, 6.2](../04-architecture/design/sad.md#62-этап-2-изоляция-доступа-по-поводу));
- перевод приложения Cyborg на харнес - план репозитория Cyborg, не этого;
- копирование масштаба образцов: сотни пакетов, двуязычные документы, 100% покрытие по файлам.

## 4. Стороны

| Сторона | Интерес |
|---|---|
| Пользователь Cyborg | Сбой плагина не мешает работе; видно, что плагин просит и почему он не работает |
| Владелец продукта | Управляемое развитие, предсказуемая стоимость, безопасность |
| Мейнтейнер | Добавлять возможности плагином, без правки ядра |
| Автор плагина (команда, сообщество) | Понятный API, типы контрактов, стабильная совместимость |
| Авторы агентов (Claude Code, другие CLI) | Подключение плагином, без правок ядра |

## 5. Бизнес-требования

### BR-CH-001 Модульность

- **Требование:** новая возможность добавляется как плагин без правки ядра; ядро не знает имён плагинов и не выделяет ни один из них.
- **traced from:** цель владельца «ядро и плагины».
- **rationale:** reason - плагины знают друг друга только через контракт, а в ядро попадает только то, что нужно всем плагинам и что плагин не решит сам ([SAD, раздел 2](../04-architecture/design/sad.md#2-что-есть-ядро)); relationships - BR-CH-003.
- **MOE:** правок `core/` при добавлении плагина - 0; имён плагинов в коде ядра - 0; перенос старого формата воркспейса - хук приложения ([SAD, 3.10](../04-architecture/design/sad.md#310-главный-конфиг-и-состояние)).

### BR-CH-002 Сохранность данных пользователя

- **Требование:** обновление Cyborg или плагина и правка файлов воркспейса извне не теряют данные пользователя и не ломают остальные плагины.
- **traced from:** цель ядра «обновление Cyborg или плагина не ломает остальных и не теряет данные» ([SAD, 3.3](../04-architecture/design/sad.md#33-версии-и-миграции)).
- **rationale:** reason - формат раздела меняется с версией плагина, а файл воркспейса правят руками; relationships - FR-CH-1012, FR-CH-1014, FR-CH-2008.
- **MOE:** в тестах версий и разделов: раздел новее плагина остаётся нетронутым, сбой `migrate` или раздел не по схеме отказывает только своему плагину, битый файл не перезаписывается; потерянных разделов - 0.

### BR-CH-003 Подключение других агентов

- **Требование:** новый агент подключается плагином - поставщиком контракта `cyborg.agent` - без правок ядра.
- **traced from:** цель «модульный клиент для агентов, локальных и готовых вроде Claude Code».
- **rationale:** reason - в ядре нет агента и его запуска, агент - обычный плагин ([SAD, раздел 5](../04-architecture/design/sad.md#5-пример-базовая-часть)); assumptions - агент имеет CLI, который работает в pty.
- **MOE:** второй поставщик написан без правок ядра; общий набор тестов `cyborg.agent` проходят оба (`agent-claude-code` и `agent-shell`, `playground/test/agents.test.ts`).

### BR-CH-004 Сторонние плагины

- **Требование:** автор пишет сторонний плагин на пакете объявлений `@cyborg-harness/contracts`; пользователь видит права плагина до того, как тот получит доступ; сторонний плагин не делит процесс с плагинами из поставки.
- **traced from:** цель «подключать их плагинами».
- **rationale:** reason - расширения должны появляться без правок ядра; relationships - BR-CH-005; установка и согласие - этап 2 ([SAD, 6.2](../04-architecture/design/sad.md#62-этап-2-изоляция-доступа-по-поводу)).
- **MOE:** сторонний плагин из каталога пользователя работает в своём хосте и не пишет в разделы соседа (`core/test/trust.test.ts`); проверка импортов не пускает в плагин ни чужой плагин, ни `node:*`, ни `electron` (`core/test/plugin-imports.test.ts`).

### BR-CH-005 Безопасность и доверие

- **Требование:** плагин делает только объявленное в манифесте; секреты не попадают в `config`, `state` и журнал; код плагинов не исполняется в главном процессе; есть безопасный режим.
- **traced from:** цель ядра 3.7 ([SAD, 3.7](../04-architecture/design/sad.md#37-безопасность-данных-и-контроль-плагинов)).
- **rationale:** reason - рядом работают сессии агентов с правами пользователя; образцы дают плагинам полное доверие, и это не подходит. Этап 1 делает права видимыми и проверяет каждый вызов `ctx.os`; гарантию «ничего сверх объявленного» даёт `Compartment` этапа 2 ([SAD, раздел 6](../04-architecture/design/sad.md#6-этапы)).
- **MOE:** вызов `ctx.os` без права - `PermissionDenied` и запись `denied` в 100% тестов отказов (`core/test/os.test.ts`); в безопасном режиме код плагинов не запускается.

### BR-CH-006 Наблюдаемость и устойчивость

- **Требование:** состояние каждого плагина и причина сбоя видны пользователю; зависание или падение плагина не трогает другие хосты, окно и процессы агентов. Каждая операция между плагинами, ядром, ОС и сетью записана: кто вызвал, что, по какому праву, сколько длилось и чем кончилось; записи переживают перезапуск приложения и выгружаются для отчёта о сбое.
- **traced from:** слабость молчаливого ожидания зависимостей у dsh и скрытых сбоев у bb; запрос владельца (2026-11-08): «тотальное логирование всех операций между плагинами и ядром».
- **rationale:** reason - плагины множат места отказа, а границы между плагинами видит только ядро: плагин не назовёт себя виновником зависания своего хоста и не узнает, что соседу отказал шлюз ([SAD, раздел 2](../04-architecture/design/sad.md#2-что-есть-ядро)); relationships - [SAD, 3.5](../04-architecture/design/sad.md#35-изоляция-сбоев-хосты-и-сторож), [SAD, 3.6](../04-architecture/design/sad.md#36-ресурсы-дольше-плагина-pty), NFR-CH-1004, NFR-CH-1005; constraints - в записи нет содержимого аргументов и результатов (BR-CH-005).
- **MOE:** в тестах отказов (исключение при активации, в вызове, зависание и падение хоста) окно и соседние хосты работают, pty с `persist` живы, причина видна в окне «Плагины Cyborg»; операций на границах плагинов без записи - 0; причина сбоя прошлого запуска видна после перезапуска.

### BR-CH-007 Производительность

- **Требование:** накладные расходы ядра - время старта, память на хост и на `<iframe>`, задержка вызова через шлюз и вывода терминала - укладываются в бюджет.
- **traced from:** опыт образцов (рост цены загрузки при множестве плагинов); [SAD, раздел 2](../04-architecture/design/sad.md#2-что-есть-ядро).
- **rationale:** reason - каждый хост и каждый вид - отдельный процесс; assumptions - ленивая активация; relationships - NFR-CH-1001.
- **MOE:** бюджеты приняты владельцем 2026-11-07 ([D-00](https://github.com/dex-it/cyborg-harness/issues/21), строка 6): вызов шлюза `ctx.os` до 64 КиБ - p99 не больше 1 мс, событие `fs.watch` - p99 не позже 5 мс после склейки 50 мс, вывод терминала - не больше 16 мс до кадра; мера - медиана трёх прогонов замера. Бюджеты старта окна и памяти на хост и вид не заданы: нет базы ([открытый вопрос 9 SAD](../04-architecture/design/sad.md#8-открытые-вопросы)). Замерено: хост ~34 МБ PSS сверх первого, вид +13 МБ PSS.

### BR-CH-008 Совместимость API

- **Требование:** плагин, написанный под API 1.x, работает на любом ядре 1.y не ниже x без пересборки; ломающее изменение API или контракта выходит только мажорной версией; устаревший член перед удалением живёт мажорную версию, и его вызовы видны.
- **traced from:** интерес автора плагина «стабильная совместимость» (раздел 4); цель ядра «обновление Cyborg или плагина не ломает остальных» ([SAD, 3.3](../04-architecture/design/sad.md#33-версии-и-миграции)).
- **rationale:** reason - сторонний автор не следит за ядром и узнаёт о поломке от пользователя; relationships - BR-CH-002 (данные), FR-CH-1012, NFR-CH-1006.
- **MOE:** ломающих изменений публичного API в минорных выпусках - 0, ловит снимок API в CI; у каждого члена с `@deprecated` есть запись о вызывающих.

### BR-CH-009 Ядро как зависимость

- **Требование:** приложение - Cyborg и любое другое - подключает ядро, контракты и адаптер Electron пакетами по номеру версии, а поставка приложения - список встроенных плагинов.
- **traced from:** цель «перевод приложения Cyborg на харнес - план репозитория Cyborg» (раздел 3): переносу нужен потребляемый пакет, а не копия стенда.
- **rationale:** reason - пока ядро живёт как `core/src` стенда, каждое приложение держит свою копию, и исправление ядра до него не доходит; relationships - NFR-CH-1007; constraints - ограничение 3.
- **MOE:** скопированных из `playground` файлов в приложении - 0; упакованное приложение загружает встроенные плагины из каталога поставки.

### BR-CH-010 Автор плагина без кода ядра

- **Требование:** автор плагина - встроенного или стороннего - собирает, проверяет и тестирует плагин по документации, шаблону и тест-киту, не открывая код ядра.
- **traced from:** интерес автора плагина «понятный API» (раздел 4); [сценарий автора](../02-use-cases/author-writes-plugin/scenario.md).
- **rationale:** reason - мера BR-CH-001 «плагин без правки ядра» ничего не стоит, если плагин пишет только тот, кто знает ядро; relationships - BR-CH-004, FR-CH-1013, NFR-CH-1008.
- **MOE:** человек со стороны за один заход собирает плагин с видом, командой, контрактом и разделом `config`; вопросов, на которые ответ - только в коде ядра, - 0.

## 6. Ограничения

1. Сессия агента - нативная программа в pty; вывод не подменяется.
2. Главный процесс не доверяет хостам и видам: вызывающего ядро определяет по каналу хоста или origin фрейма, а не со слов плагина; путь проверяется после `realpath`.
3. Ядро без зависимостей времени выполнения: только встроенные модули Node и `@cyborg-harness/contracts`.
4. Плагин импортирует только `@cyborg-harness/contracts` и свои модули: ни чужого плагина, ни `node:*`, ни `electron` ([SAD, 6.1](../04-architecture/design/sad.md#61-этап-1-ядро-без-изоляции-доступа)).
5. Члены контрактов асинхронные, аргументы и результаты - данные, которые переживают `structuredClone`.
6. Платформы - Linux и macOS; Windows - по решению владельца ([D-00](https://github.com/dex-it/cyborg-harness/issues/21), строка 7; [открытый вопрос 12 SAD](../04-architecture/design/sad.md#8-открытые-вопросы)). Поведение ядра на поддерживаемых ОС одно (NFR-CH-1009).
