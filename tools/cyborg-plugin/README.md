# cyborg-plugin

Инструмент автора плагина Cyborg Harness. Пакет приватный (`private: true`), в реестр не опубликован: публикация - P-10. Формат поставки - SAD, раздел 1, «Поставка плагина».

```sh
cyborg-plugin check [каталог] [--source] [--out <каталог>] [--api-version <x.y.z>] [--declarations <файл>]... [--declarations-package <имя>]...
cyborg-plugin build [каталог] [--out <каталог>] [--api-version <x.y.z>] [--declarations <файл>]... [--declarations-package <имя>]...
cyborg-plugin pack  [каталог] [--out <файл>] [--api-version <x.y.z>] [--dry-run]
```

Код возврата: 0 - нарушений нет, 1 - есть, 2 - неверный вызов. Нарушения печатаются как `файл:строка: причина`.

- `check` - манифест, `engines.cyborg` против версии API, точка входа, модули `ui.views` и `ui.overlay`, файлы схем, правило импортов (`checkPlugin` из `@cyborg-harness/core/plugin-check`). По умолчанию npm-пакеты в главной части допустимы (её соберёт `build`); `--source` - главная часть грузится как есть, пакетов в ней нет. Каталог результата (`./dist` или `--out`) как исходники не читается.
- `build` - проверка исходников, затем бандл главной части в `index.mjs` (npm-зависимости внутрь, `node:*` и `electron` запрещены, в том числе в зависимостях), сборка видов `ui/*.ts` и модулей из манифеста в ESM `ui/*.js`, копирование манифеста, схем и файлов `ui/`; рядом карты исходников. Результат - по умолчанию `dist` в каталоге плагина; чужой непустой каталог без `manifest.json` не стирается. Результат проверяется ещё раз уже после записи: отказ этой проверки оставляет в каталоге непрошедший результат.
- `pack` - проверяет собранный каталог (нет `.ts`, есть `index.mjs`, файлы из манифеста на месте) и пишет воспроизводимый `<id>-<версия>.tgz` (корень `<id>/`). Формат архива предварительный: подписи и хеша нет (этап 2, вопрос 8 SAD).

Из кода: `import { buildPlugin, packPlugin, runCli } from 'cyborg-plugin'`; `buildPlugin(dir, { main: 'source', check: false })` - режим стенда (исходники как есть, виды собираются).

Ограничения: вычисляемый `import()` внутри зависимости находит только проверка результата (сборка отказывает), вычисляемый `require()` CJS-зависимости не виден; бандл зависимости может не пройти сканер `ses` на этапе 2 (zod, marked).
