# cyborg-plugin

Инструмент автора плагина Cyborg Harness. Пакет приватный (`private: true`), в реестр не опубликован: релизный workflow P-10 его не выпускает (в задачу входят контракты, ядро и адаптер). Формат поставки - SAD, раздел 1, «Поставка плагина».

```sh
cyborg-plugin check [каталог] [--source] [--out <каталог>] [--api-version <x.y.z>] [--declarations <файл>]... [--declarations-package <имя>]...
cyborg-plugin build [каталог] [--out <каталог>] [--api-version <x.y.z>] [--declarations <файл>]... [--declarations-package <имя>]...
cyborg-plugin delivery <каталог плагина>... --out <каталог> [--api-version <x.y.z>] [--declarations <файл>]... [--declarations-package <имя>]... [--sign-key <файл> [--days <N> | --expires <дата>]]
cyborg-plugin pack  [каталог] [--out <файл>] [--api-version <x.y.z>] [--dry-run]
cyborg-plugin keygen --out <префикс>
cyborg-plugin sign [каталог] --key <файл закрытого ключа> [--days <N> | --expires <дата>]
cyborg-plugin verify <каталог или архив .tgz> --key <файл открытого ключа или ed25519:...>...
cyborg-plugin revoke --key <файл закрытого ключа поставки> --serial <N> --out <revocations.json> [--revoke-key <id>]... [--revoke-hash <sha256>]... [--reason <слова>] [--days <N>]
```

Код возврата: 0 - нарушений нет, 1 - есть, 2 - неверный вызов. Нарушения печатаются как `файл:строка: причина`.

- `check` - манифест (ошибки со строкой в `manifest.json`: `manifest.json:<строка>: причина`), `engines.cyborg` против версии API, точка входа, модули `ui.views` и `ui.overlay`, файлы схем, правило импортов (`checkPlugin` из `@cyborg-harness/core/plugin-check`). По умолчанию npm-пакеты в главной части допустимы (её соберёт `build`); `--source` - главная часть грузится как есть, пакетов в ней нет. Каталог результата (`./dist` или `--out`) как исходники не читается.
- `build` - проверка исходников, затем бандл главной части в `index.mjs` (npm-зависимости внутрь, `node:*` и `electron` запрещены, в том числе в зависимостях), сборка видов `ui/*.ts` и модулей из манифеста в ESM `ui/*.js`, копирование манифеста, схем и файлов `ui/`; рядом карты исходников. Результат - по умолчанию `dist` в каталоге плагина; стирается и заменяется только каталог, который создала сама сборка (метка `.cyborg-plugin-build`), пустой или отсутствующий; любой другой, даже с `manifest.json`, - отказ. Сборка идёт во временный каталог рядом, результат проверяется там ещё раз и переименовывается на место только целиком: при отказе прежний результат цел. Символическая ссылка в `ui/` на файл внутри плагина копируется как файл, остальные - нарушение.
- `delivery` - поставка приложения (P-07): каждый каталог плагина собирается как `build` в режиме bundle и ложится в `<out>/<id>`, затем `delivery.json` с sha256 всех файлов каждого плагина (`@cyborg-harness/core/delivery`). Всё собирается во временный каталог рядом и встаёт на место целиком: отказ любого плагина оставляет прежнюю поставку целой; `--out` обязателен и должен быть пустым, отсутствующим или прежней поставкой (есть `delivery.json`), чужой каталог не стирается. Метки сборки в поставке нет. Приложение указывает этот каталог как `builtinDir` адаптера, и при старте адаптер сверяет файлы со списком (расхождение - в лог и «Не дошло до ядра», не отказ).
- `pack` - проверяет собранный каталог (нет `.ts`, есть `index.mjs`, файлы из манифеста на месте) и пишет воспроизводимый `<id>-<версия>.tgz` (корень `<id>/`). Если в каталоге есть `integrity.json` (после `sign`), он едет в архив как обычный файл, а устаревшая подпись (файл правили после `sign`) - отказ `pack`. Источник установки (вопрос 8 SAD) формат не задаёт.
- `keygen`, `sign`, `verify`, `revoke` - происхождение пакета (TR-10, TR-11, [ADR-CH-0017](../../docs/04-architecture/adr/ADR-CH-0017-plugin-provenance.md)): `keygen` пишет пару ключей Ed25519 (`<префикс>.key` с правами 0600 - секрет, в репозиторий не класть; `<префикс>.pub` - открытый); `sign` кладёт в собранный каталог `integrity.json` (sha256 каждого файла, срок, ключ, подпись); `verify` читает каталог или архив целиком в память и проверяет так же, как ядро (изменённый и лишний файл, чужой ключ, истёкший срок - код 1); `revoke` пишет подписанный список отозванных ключей издателей и хешей для `userData/revocations.json` приложения. Порядок: `build`, `sign`, `pack`, `verify архив`. Подробно - [руководство автора](../../docs/guide/authors/signing.md).
- `delivery --sign-key` подписывает `delivery.json` ключом выпуска (TR-12); `build` и `delivery` печатают пакеты npm, вошедшие в бандл, с версиями (TR-14).

Из кода: `import { buildDelivery, buildPlugin, keygen, packPlugin, runCli, signPlugin, verifyPlugin, writeRevocations } from 'cyborg-plugin'`; `buildPlugin(dir, { main: 'source', check: false })` - режим стенда (исходники как есть, виды собираются).

Ограничения: вычисляемый `import()` внутри зависимости находит только проверка результата (сборка отказывает), вычисляемый `require()` CJS-зависимости не виден; бандл зависимости может не пройти сканер `ses` на этапе 2 (zod, marked).
