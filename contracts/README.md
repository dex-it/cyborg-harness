# @cyborg-harness/contracts

Пакет объявлений контрактов без логики. Поставщик и потребитель не знают друг друга: оба импортируют отсюда тип и называют контракт по имени и мажорной версии.

## Установка и версии

```bash
npm install --save-dev @cyborg-harness/contracts
```

Пакет состоит из деклараций (`dist/*.d.ts`) и описания в `package.json`: кода выполнения в нём нет, в `exports` только условие `types`, поэтому импорт значения не разрешится. Плагин пишет `import type { PluginModule } from '@cyborg-harness/contracts'`; потребителю не нужны ни `allowImportingTsExtensions`, ни DOM в `lib` (корень вида - параметр типа `UiModule<Root>`). Сторонний пакет объявлений дополняет карту так же, как в разделе «Сторонние контракты» ниже: `declare module '@cyborg-harness/contracts' { interface Contracts { ... } }` внутри своего пакета, не меняя этот.

**Состояние выпуска.** Пакет ещё не опубликован: версия `1.0.0-dev` - линия разработки до первого выпуска, её типы меняются без повышения версии, но снимок обновляется. Канал, имя в реестре и порядок выпуска - [SAD 3.3](../docs/03-architecture/design/sad.md#пакет-контрактов-поставка-и-версии); выпуск по тегу - задача P-10. В репозитории ядро и стенд берут пакет по `paths` из корневого `tsconfig.json`, сборка деклараций им не нужна.

### Три версии

Версий три, и они меняются независимо.

| Версия | Где записана | Что значит |
|---|---|---|
| Пакета | `version` в `package.json`, `CHANGELOG.md` | выпуск набора деклараций; по ней ставит потребитель |
| Контракта | мажорный ключ карты (`Contracts['cyborg.agent'][1]`), минорная часть - у поставщика в манифесте (`"provides": { "cyborg.agent": "1.2" }`) | форма одного контракта между плагинами |
| API плагина | `engines.cyborg` в манифесте плагина, `PLUGIN_API_VERSION` в `core/src/api-version.ts` | форма `ctx`, манифеста и элементов `cy-*` |

Мажор API плагина равен мажору пакета (держит `core/test/api-version.test.ts`): плагин собран под те типы, под которые загружается. Минор и патч у них расходятся: новый контракт повышает версию пакета, но не API плагина.

### Что повышает какую версию

| Изменение | Пакет | Контракт | API плагина (`engines.cyborg`) |
|---|---|---|---|
| Необязательный член в существующем контракте (`icon?`, как у `demo.tab` с 1.1) | минор | минор у поставщика (1.0 -> 1.1), ключ карты прежний | не меняется |
| Новый контракт в карте (`cyborg.git`: ключ `1`) | минор | появляется, мажор 1 | не меняется |
| Вторая мажорная версия контракта рядом с первой (`cyborg.agent`: ключи `1` и `2`) | минор: старый ключ остаётся | новый мажор 2 | не меняется |
| Необязательный член в `PluginContext`, `UiContext`, манифесте, новый элемент `cy-*` | минор | не меняется | минор |
| Исправление типа без смены формы (опечатка в имени параметра, уточнение `unknown` до того, что и так приходило) | патч | не меняется | не меняется |
| Пометка `@deprecated` на члене | минор (запись в `CHANGELOG.md`) | не меняется | не меняется |
| Удаление или переименование члена, обязательное поле аргумента, смена смысла | мажор | новый мажор: старый ключ карты можно оставить рядом | мажор |
| Удаление ключа карты (мажорной версии контракта) | мажор | версия снимается | мажор |

Следствие последней строки: мажор пакета равен мажору API плагина, поэтому снятие ключа карты повышает `engines.cyborg` для каждого плагина, а не только для поставщиков и потребителей этого контракта. Поэтому ключ снимают после срока `@deprecated`, а не при выходе новой мажорной версии контракта.

Правило для минорного члена то же, что в SAD 3.3: он объявляется необязательным, поставщик прежней версии продолжает подходить под тип, а потребитель проверяет, что член есть.

### Проверка в CI

`api-snapshot.txt` - собранные декларации без комментариев и с единым форматированием. Правки JSDoc и отступов снимок не меняют; правка типа, члена или ключа карты меняет.

- `npm run check:contracts` собирает декларации и сверяет их со снимком и с версией в `package.json`; расхождение - ошибка.
- `npm run check:contracts -- --base origin/master` (так CI вызывает его в PR) берёт снимок из ветки назначения: снимок изменился, а версия пакета та же - ошибка «изменено без повышения версии»; версия понижена - ошибка. Сам выбор между патчем, минором и мажором проверяет ревью по таблице выше: компилятор не отличит добавление необязательного члена от обязательного.
- Изменили декларации: повысьте версию в `package.json`, запишите строку в `CHANGELOG.md`, обновите снимок командой `npm run snapshot:contracts`. До первого выпуска (`-dev`) повышать версию не нужно, снимок обновляется всё равно.

Снимок заменяет «снимок публичного API» задачи T-06 для пакета контрактов; когда T-06 появится, сравнение деклараций переедет в него.

### Сборка и проверка пакета

- `npm run build:contracts` - декларации в `contracts/dist` (каталог не в git). `rewriteRelativeImportExtensions` правит только выпускаемый JS, а в `.d.ts` остаются пути вида `./plugin.ts`; сборка заменяет их на `./plugin.js` (`contracts/scripts/build.ts`).
- `npm pack` в каталоге `contracts` собирает декларации (`prepack`) и кладёт в tarball только `dist/*.d.ts`, `package.json`, `README.md` и `CHANGELOG.md`.
- `contracts/test/package.test.ts` упаковывает пакет, ставит tarball в пустой проект вне репозитория (`moduleResolution` NodeNext и Bundler, `lib` ES2023 без DOM, `types: []`, `skipLibCheck: false`) и собирает плагин на `PluginModule` с `declare module`.

## Карта контрактов

`Contracts` — карта «имя → мажорная версия → тип». Один тип описывает одну мажорную версию со всеми её минорными.

```ts
export interface Contracts {
  'cyborg.agent': { 1: Agent };
  'cyborg.agent-tool': { 1: AgentTool };
  'cyborg.session-prompt': { 1: SessionPrompt };
}
```

Примеры ниже берут демонстрационные контракты `demo.*` (`demo.files` с двумя мажорными версиями, `demo.tab`): они не входят в пакет и дополняют карту из `core/examples/contracts.ts` так же, как сторонний пакет объявлений.

| Правило | Почему |
|---|---|
| Член, добавленный в минорной версии, объявляется необязательным (`icon?` с 1.1) | Поставщик 1.0 удовлетворяет тому же типу, а потребитель обязан проверить, что член есть |
| Новая мажорная версия — новый ключ карты и новый тип | Поставщик может отдавать обе версии сразу, каждый потребитель получает ту, что просил |
| Методы объявляются асинхронными, аргументы и результат — данные | Вызов идёт через границу хоста; функцию, класс и `Map` RPC не передаёт |
| Подписка — единственный обратный вызов, она возвращает `Subscription` с `dispose()` | Колбэк остаётся в хосте потребителя; ядро снимает подписку при выгрузке или падении любой из сторон |

## Права вызывающего: `guard`

Поставщик, который по чужой просьбе читает или пишет путь (или разрешает ссылку на секрет), объявляет это в `provides`, иначе он посредник: вызывающий без `fs.read` прочитал бы файл его правами.

```jsonc
"provides": { "demo.files": { "version": "1.0", "guard": { "read": { "fs.read": 0 }, "open": { "fs.read": "0.path" } } } }
```

Ключ - член контракта, значение - право (`fs.read`, `fs.write`, `shell`, `secrets.ref`) и номер аргумента или `"номер.поле"`. Ядро проверяет аргумент по праву вызывающего до передачи вызова - и из главной части, и из вида; отказ - `PermissionDenied` с записью `denied` и `reason: 'via-contract'`. Дальше поставщик работает своими правами: действует пересечение. Член без `guard` ядро не проверяет.

## Устаревшие члены: `deprecated`

Член, который уйдёт в следующей мажорной версии, помечается `@deprecated` в типе контракта (для читателя и редактора), а для ядра - в `provides` поставщика: типов TypeScript ядро не видит, как и в случае с `guard`.

```jsonc
"provides": { "demo.files": { "version": ["1.4", "2.0"], "deprecated": ["list", "stat"] } }
```

Значение - список имён членов. Пометка относится к контракту целиком, а не к одной мажорной версии: член, которого в новой мажорной версии нет, там никто не вызовет. Ядро проверяет вид списка (список строк, имя члена - идентификатор: буквы, цифры, `_` и `$`, не с цифры, без повторов) и называет ошибочное поле, например `provides.demo.files.deprecated[1]`; есть ли такой член в контракте, при разборе манифеста ядро не знает - опечатку выдаст только отсутствие записей в журнале, поэтому пометку держат рядом с `@deprecated` в типах.

Когда плагин вызывает помеченный член (из главной части или из вида) и проверки вызова пройдены, ядро пишет в журнал запись `deprecated-call`: кто вызвал (`pluginId`), поставщик, контракт, член. Первый вызов пишется сразу, повторы той же четвёрки за окно 5 с склеиваются в одну запись с `repeats`. Записей `deprecated-call` в журнале не больше 1000; уходит старейшая у самого шумного вызывающего. В окне «Плагины» запись видна и у вызывающего, и у поставщика. Вызов не блокируется и не меняет состояния плагинов: это сведения поставщику о том, кто ещё зовёт старый член.

## API плагина

`PluginModule`, `PluginContext` и типы вида (`UiModule`, `UiContext`, `ThemeTokens`, `FeedLine`) объявлены здесь же: плагин импортирует только этот пакет и свои модули, а `core/test/plugin-imports.test.ts` проверяет это по каждому файлу плагинов.

Разделы `config` и `state`: манифест объявляет `"config": { "version": 2, "schema": "./config.schema.json" }`, модуль - `config: { defaults, migrate, validate }`. Схема - подмножество JSON Schema (`type`, `properties`, `required`, `additionalProperties`, `items`, `enum`, `const`, границы чисел, длины, `pattern`, `uniqueItems`); прочий ключ вроде `$ref` или `oneOf` - отказ разделу, а не пропуск. Значение не по схеме - плагин не активируется; правка файла извне не по схеме оставляет прежнее значение.

События окна и ОС - `ctx.window.onFocusChange` и `ctx.system`: `onSuspend`, `onResume`, `onScreenLock`, `onIdle(seconds, cb)` (один раз на каждый простой от `seconds`), `onBeforeQuit` (ядро ждёт асинхронного слушателя не дольше бюджета приложения). Подписки снимаются вместе с плагином; упавший слушатель пишет в журнал плагина и соседям не мешает.

Уведомления - `ctx.os.notify` с правом `notify`: `show(title, body?, { onClick: { command, args } })` отдаёт id, `close(id)` снимает своё уведомление. Заголовок до 120 символов, текст до 1000, живых уведомлений у плагина до 10: одиннадцатое закрывает старейшее. Команда клика - своя из `commands` манифеста, её аргументы сверяются со схемой при `show`, а не при клике. Клик поднимает окно, закрывает уведомление и запускает команду; под чужим замком окна команда не запускается. Выгрузка плагина закрывает его уведомления, падение хоста - нет: клик дождётся перезапуска. Заголовок окна - `ctx.window.setTitle(segment)` без права: фрагмент до 80 символов, `undefined` его снимает; окно склеивает воркспейс, фрагменты плагинов по их id и имя приложения.

Вид плагина - ES-модуль из `"ui": { "views": { "main": "./ui/ui.js" } }` с `export function mount(root, ctx: UiContext): Disposable`. `UiContext` - команды, контракты (`ctx.contracts.get` отдаёт удалённый объект: только методы, ответ - данные), токены темы `--cy-*` уже стоят на `documentElement` до `mount`, `ctx.theme.onChange`, `ctx.onVisibilityChange` (свёрнутый вид не размонтируется), лента журнала, перетаскивание и `ctx.terminal.open(ticket)` - pty по билету `PtyHandle.share()` своей главной части, вывод и ввод мимо хоста, `ctx.state` - память вида в state воркспейса (JSON до 64 КБ, готова до `mount`), `ctx.dialogs.show` - диалог `ask` или меню `menu` в слое окна поверх всех фреймов (ответ - `id` пункта или `undefined`) и `ctx.keys.of(command)` - сочетание своей команды для подсказки. Замок окна - у главной части: `ctx.os.ui.lock()` с правом `ui.lock` и экраном `ui.overlay`, снять его может только `release()` того же плагина. `ctx.os` у вида нет. Мост вида (`ViewBridge`) - внутреннее дело ядра, плагин его не видит.

`"activation": "lazy"` в манифесте откладывает активацию: плагин ждёт первой команды или сочетания, показа своего вида или потребителя своего контракта. Поставщика из `requires` и `optional` ядро поднимает до потребителя, поставщиков `consumes` будит без ожидания.

## Документы: `ctx.documents`

Вкладки плагина, которые окно показывает и переживают перезапуск. Тип документа объявлен в манифесте: `"documents": { "note": { "restorable": true } }`; без `restorable` документ живёт до закрытия окна.

- `open(type, { title, data? })` - новый документ, ответ - id. `data` - JSON до 64 КБ, `title` - непустая строка до 200 символов.
- `save(id, { title?, data? })` - владелец сам отдаёт данные, когда они меняются: ядро их не опрашивает, после падения опрашивать некого. Не названное поле не меняется, `data: undefined` его стирает.
- `close(id)`, `list()` - свои документы в порядке окна; после перезапуска `list()` отдаёт `restorable`-документы прошлого запуска, поднимает их владелец.
- `onClose(id => ...)` - вкладку закрыл человек.

Чужой документ для плагина не существует (`NotFound`), тип не из манифеста - `NotDeclared`.

## Доступ к ОС: `ctx.os`

Права - поле `permissions` манифеста; нет права - нет члена в `ctx.os`, а вызов в обход формы отклоняет шлюз ядра в главном процессе.

```jsonc
"permissions": {
  "fs.read": ["workspace", "~/notes/**", "/srv/*/logs", "granted"],  // ещё plugin-data, plugin-temp; * - сегмент, ** - глубина
  "fs.write": ["workspace", "workspace.git"],     // workspace.git - запись в .git корней воркспейса
  "shell": ["granted", "https:", "mailto:"],      // openPath по областям, openExternal по схемам; file: и javascript: нельзя
  "process": ["git", { "program": "npm", "args": ["test"], "env": ["CI"] }],  // env - что можно передать программе
  "pty": ["claude"],                              // та же форма; процесс держит ядро
  // $SHELL - оболочка входа человека, путь подставит ядро; только с закреплённым флагом и скриптом
  // "pty": [{ "program": "$SHELL", "args": ["-lc", "exec claude --settings \"$CYBORG_SETTINGS\" \"$@\"", "cyborg"] }]
  "launch": [ /* правила формы pty */ ],          // что поставщик cyborg.agent описывает потребителю; члена в ctx.os не даёт
  "net": ["api.github.com", "config:baseUrl"],    // config: - хост из своего раздела config
  "env": ["HOME"], "notify": true, "clipboard": ["read"],
  "serve": true,                                  // свой сервер HTTP на 127.0.0.1 - для программ этого компьютера
  "secrets.ref": ["vault://kv/data/jira*"]
}
```

| Член | Без права |
|---|---|
| `paths.data`, `paths.temp`, `fs.*` в них | доступны всегда; `paths.home` - домашний каталог, тот же, что `~` в правах |
| `fs.*` вне своих каталогов | `PermissionDenied` |
| `secrets.get/set/delete` | свои ключи; без шифрования ОС - `Unavailable` |
| `dialog.open({ title, directory, multiple })` | есть всегда; выбранное человеком становится областью `granted` плагина и хранится в state воркспейса |
| `process`, `pty`, `shell`, `net`, `env`, `notify`, `clipboard`, `security`, `serve` | члена нет |

Путь только абсолютный, проверяется после `realpath`: симлинк наружу области не выводит, файл воркспейса, данные приложения, каталоги других плагинов и запись в `.git` без `workspace.git` закрыты. `shell.openPath` исполняемый файл не открывает. Программа из `process` и `pty` получает только базовое окружение (PATH, HOME, локаль) и переменные, названные в `env` её правила.

Файлы: `fs.readText`, `list`, `stat`, `realpath`, `readSlice`, `watch` читают, `writeText`, `mkdir`, `remove` пишут. Нет файла внутри области чтения - `NotFound` (его же `process.run` отвечает, если программы нет), вне области - `PermissionDenied`; проверка существования - `stat` и ловля `NotFound`. `writeText` атомарна (временный файл рядом и `rename`; режим сохраняется; не обычный файл - `Invalid`); файл без права записи (0444) не заменяется - `EACCES`; если на имя временного файла права записи нет (`fs.write` называет один файл или маску под имя) или каталог цели закрыт для создания файлов, запись идёт на месте, без защиты от обрыва. `list` существующего файла - `Invalid`. Путь вне области, названный плагином, отвечает `PermissionDenied` при любой ошибке ОС, в том числе `ENOTDIR`, `ELOOP`, `EACCES` на пути; путь через ссылку внутри области ведёт себя как путь внутри и отвечает по цели ссылки (вне области есть - `PermissionDenied`, висячая - `NotFound` или ошибка операции, под закрытым снаружи каталогом - ошибка операции). `watch` файла переживает подмену файла через `rename`, в том числе при старом файле, открытом другим процессом; каталог или ссылка на месте файла закрывают наблюдение с причиной. `realpath(path)` раскрывает ссылки и нужен, чтобы сверять пути по имени: `/tmp/x` и `/private/tmp/x` - один каталог.

pty держит ядро: `ctx.os.pty.spawn({ program, args, cwd, env, cols, rows, persist })` отдаёт ручку с `onData`, `onExit`, `write`, `resize`, `kill`. С `persist: true` процесс переживает падение хоста плагина; вернувшийся плагин находит его через `list()` и забирает `attach(id)` вместе с хвостом вывода `backlog`. Каждый отказ - запись `denied` в журнале плагинов.

Пределы ресурсов плагина - `LIMITS` в `core/src/limits.ts`, приложение меняет их через `LoadOptions.limits`; превышение - `Invalid` с причиной, место освобождают завершение, выключение и выгрузка плагина. Ввод в pty - до 1 МиБ UTF-8 за вызов, из главной части и из вида; живых pty - до 32, включая ждущие `attach`; одновременных `process.run` - до 16; вывод `process.run` - до 16 МиБ на `stdout` и на `stderr` (`maxOutputBytes` - от 1 байта до 64 МиБ), сверх предела программа остановлена, а в ответе `truncated: true`; `fs.readText` - файл до 8 МиБ, крупнее читается `fs.readSlice`; подписок через контракты у потребителя - до 256; слушателей `onIdle` - до 64. Вывод pty ядро склеивает: первый кусок после затишья уходит сразу, следующие - пачкой раз в 4 мс или по 64 К символов, `exit` - после последней пачки. Терминалу ядро задаёт `COLORTERM=truecolor` рядом с `TERM=xterm-256color`; плагин с правом на переменную задаёт своё значение. Число команд и контрактов предела не требует: регистрация вне манифеста - отказ, так что их потолок - манифест. Прежние пределы: `fs.watch` 64, `fs.readSlice` до 1 МиБ, `net.fetch` до 16 МиБ, `serve` 4 сервера и тело 1 МиБ, диалогов в очереди 8, документов 200.

`ctx.secrets.resolve('token')` или `resolve({ $secret: 'token' })` берёт секрет из своего хранилища; ссылка со схемой (`vault://...`) должна подходить под маску `secrets.ref`.

`ctx.os.serve.http(handler)` поднимает сервер на `127.0.0.1` с портом от ОС и отдаёт `{ url, dispose }`; сервер держит главный процесс, запрос `{ method, path, headers, body }` уходит в хост плагина, ответ `{ status, headers?, body? }` - обратно. Ядро отвечает само, не зовя плагин: чужой `Host` - 421 (подмена DNS), заголовок `Origin` - 403 (страница в браузере), тело больше 1 МиБ - 413, нет ответа за 30 с - 504, падение или чужая форма ответа - 502. Длину тела и `connection` считает сервер, заголовок с переводом строки отброшен. До 4 серверов на плагин; выгрузка и падение хоста их закрывают. Кто звонит - ядро не знает: сервер проверяет вызывающего сам, например токеном.

## Агент: `cyborg.agent`

Кратность many, тип - `contracts/agent.ts`. Поставщик описывает запуск (`launch` отдаёт `program`, `args`, `cwd`, `env` - готовый вход `ctx.os.pty.spawn`) и переводит следы агента в события `watch`; процесс запускает потребитель по своему праву `pty`, поэтому в его манифесте - правила программ всех агентов, которые он поднимает. `facts().capabilities` говорит, что звать можно; `ended` после выхода процесса убирает файлы поставщика и называет причину по коду выхода. Событие `session` несёт id сессии самого агента: потребитель хранит его (у `sessions` - в данных документа) и после перезапуска передаёт в `launch({ resumeId })`.

Чужое описание под своим правом - confused deputy: потребитель передаёт `ctx.os.pty.spawn({ ...spec, describedBy: pluginId })`, и ядро пропускает запуск, только если он подходит и под `pty` потребителя, и под `launch` поставщика (программа, закреплённые аргументы, имена переменных). Права пересекаются: назвать чужой плагин в `describedBy` значит только сузить запуск, поэтому ядро не сверяет, кто чей поставщик. Поставщик объявляет `launch` с теми же правилами, что `pty` у потребителя; без него его описание не запустится.

Системный промпт сессии собирается из контракта `cyborg.session-prompt` (кратность many, `fragment(): string`): потребитель берёт фрагменты всех поставщиков по порядку их id, пустые и упавшие пропускает и передаёт в `launch({ promptFragments })`. В playground вклад даёт `session-isolation` - текст изоляции сегодняшнего Cyborg.

Инструменты агенту даёт контракт `cyborg.agent-tool` (кратность many): `tools()` перечисляет `{ name, description, inputSchema }`, `call(name, input, { sessionId })` отвечает `{ text, isError?, actions? }`. Потребитель - в playground `sessions` с правом `serve` - собирает их в один сервер MCP (Streamable HTTP, ответ JSON без SSE) и передаёт в `launch({ tools: { url, token } })`; токен у каждой сессии свой и называет её, поэтому поставщик передаёт его через окружение процесса - не в argv и не в файле, их видят другие пользователи машины (`agent-claude-code`: переменная `CYBORG_MCP_TOKEN`, файл `--mcp-config=<файл>` со ссылкой `${CYBORG_MCP_TOKEN}` в заголовке и разрешение `mcp__cyborg` в своих `--settings`). Имя инструмента - `[A-Za-z0-9_-]` до 64 знаков; при повторе берётся поставщик с меньшим id. `actions` - кнопки под сессией: до 6, подпись до 40 знаков, управляющие символы срезаны; новый запрос человека их снимает. В playground инструмент `suggest_actions` и фрагмент промпта, который велит его звать, даёт `next-actions` - замена комментария `cyborg-buttons` сегодняшнего Cyborg.

## Элементы ядра

Оболочка вида определяет их до `mount`: плагин пишет `document.createElement('cy-list')` без импорта и не может занять имя `cy-*` своим классом. Данные свойств и событий - `contracts/elements.ts`. Стили - на токенах `--cy-*` темы, поэтому вид не задаёт им цвета; внутренности открыты через `::part`, где это названо.

| Тег | Атрибуты и свойства | События |
|---|---|---|
| `cy-button` | `variant` (`primary`, `danger`), `disabled`; часть `button` | `click`; при `disabled` не доходит и от `host.click()` |
| `cy-field` | `label`, `placeholder`, `value`, `type` (`text`, `search`, `password`), `disabled`; свойство `value`; часть `input` | `input`, `change`, `keydown` |
| `cy-list` | свойство `items: ListItem[]`, `selected`, `label`; слот `empty` - когда пунктов нет | `cy-select`, `cy-activate` (Enter, двойной клик) |
| `cy-tree` | свойства `items: TreeItem[]`, `expanded: string[]`; `selected`, `label` | `cy-select`, `cy-activate`, `cy-toggle` |
| `cy-tabs` | свойство `tabs: TabItem[]`, `selected`, `label`; без `selected` выделена первая | `cy-select` |
| `cy-empty` | `heading`; текст - содержимое | - |
| `cy-spinner` | `label` (по умолчанию «Загрузка»), `role="status"` | - |

`id` пунктов - непустые и уникальные (в дереве - во всём дереве), иначе присваивание свойства бросает `TypeError` с местом. События всплывают и выходят из тени (`composed`), `detail` - `{ id }`, у `cy-toggle` ещё `expanded`. Программная смена `selected` событий не шлёт. Клавиши - по WAI-ARIA: стрелки, `Home`, `End`, `Enter`; в дереве вправо раскрывает ветвь и входит в неё, влево сворачивает и выходит к родителю; вкладки по стрелкам ходят по кругу. В пределах мажорной версии `engines.cyborg` тег не удаляется и не меняет атрибуты.

## Сторонние контракты

Пространство `cyborg.*` закреплено за этим пакетом. Автор контракта `acme.*` публикует свой пакет объявлений и дополняет карту, ничего здесь не меняя:

```ts
// @acme/contracts/index.ts
declare module '@cyborg-harness/contracts' {
  interface Contracts {
    'acme.clock': { 1: Clock };
  }
}

export interface Clock {
  now(): Promise<number>;
}
```

После импорта этого пакета `ctx.contracts.get('acme.clock', 1)` возвращает `Remote<Clock>`.

## Что проверяет компилятор, а что ядро

| Проверка | Кто | Когда |
|---|---|---|
| Имя контракта есть в карте | компилятор | сборка плагина |
| Версия в `provide` — `мажорная.минорная`, мажорная есть в карте, реализация подходит под её тип | компилятор | сборка плагина |
| Мажорная версия в `get` и `all` указана и есть в карте | компилятор | сборка плагина |
| Контракт объявлен в манифесте: `provides` у поставщика, `requires`, `optional` или `consumes` у потребителя | ядро | вызов |
| Версия в `provide` объявлена в `provides` | ядро | вызов |
| Мажорная версия в `get` и `all` лежит в диапазоне манифеста (`^1` не даёт мажорную версию 2) | ядро | вызов, иначе `NotDeclared` |
| Реализация — объект, имена его методов | ядро | `provide` |
| Сигнатуры методов | никто | рантайм их не видит; это обещание поставщика, закреплённое типом |

Компилятор защищает от опечаток автора, ядро — от плагина, который собран без типов или нарочно их обходит. Компиляторные проверки закреплены в `core/test/contracts-types.ts`: каждая строка под `@ts-expect-error` обязана не компилироваться.

## Remote

Потребитель получает `Remote<T>`, а не `T`: каждый метод возвращает `Promise`, даже если в типе объявлен синхронным. Поле данных приходит снимком на момент `provide`.

```ts
interface Clock { nowSync(): number }
const clock = ctx.contracts.get('demo.clock', 1);   // Remote<Clock> | undefined
const n = await clock?.nowSync();                    // number | undefined, только через await
```

## Отмена вызова

`AbortSignal` не переживает `structuredClone`, поэтому отмена едет не в данных. Контракт, который можно отменить, объявляет **последним** параметром члена `signal?: AbortSignal`; `Remote<T>` сохраняет параметр. Потребитель передаёт сигнал на этом месте, ядро шлёт поставщику сообщение `cancel`, и обработчик поставщика получает свой `AbortSignal` на том же месте. Тот же приём работает для `ctx.commands.run(name, ...args, signal)` и `ctx.os.process.run(program, args, { signal })`. Отменённый вызов отказывает кодом `Cancelled`; срок вызова (`Timeout`) отменяет запрос у поставщика тоже. Если вызывающий не передал сигнал, на его месте у поставщика `undefined`. Подробности - [SAD, раздел 4, п. 12](../docs/03-architecture/design/sad.md).

```ts
interface Search { find(query: string, signal?: AbortSignal): Promise<string[]> }
const hits = await ctx.contracts.get('acme.search', 1)?.find('main', abort.signal);   // abort.abort() -> Cancelled
```

## Полный пример

Поставщик `files` отдаёт две мажорные версии, `editor` берёт вторую, `projects` — первую. Вкладки собирает `tabs`. Код — `core/examples/plugins/*`, прогон — `npm run demo -- all`.

**Поставщик двух версий.**

```jsonc
// files/manifest.json
{ "id": "files", "version": "2.0.0", "engines": { "cyborg": "^1" },
  "provides": { "demo.files": ["1.4", "2.0"] } }
```

```ts
ctx.contracts.provide('demo.files', '1.4', {
  read: async (path: string) => disk.get(path),
  list: async () => [...disk.keys()],
});
ctx.contracts.provide('demo.files', '2.0', {
  readText: async (path: string) => {
    const text = disk.get(path);
    return text === undefined ? undefined : { path, text, size: text.length };
  },
});
```

**Потребитель второй версии — он же поставщик вкладки.**

```jsonc
// editor/manifest.json
{ "id": "editor", "version": "1.0.0", "engines": { "cyborg": "^1" },
  "provides": { "demo.tab": "1.0" }, "requires": { "demo.files": "^2" } }
```

```ts
const files = ctx.contracts.get('demo.files', 2);           // Remote<FilesV2> | undefined
if (!files) throw new Error('demo.files в requires, но его нет');
ctx.contracts.provide('demo.tab', '1.0', {
  kind: 'редактор',
  open: async (path: string) => {
    const file = await files.readText(path);                  // FileText | undefined
    return file ? `редактор: ${path}, ${file.size} симв.` : `редактор: ${path} не найден`;
  },
});
```

**Потребитель всех поставщиков и команда с аргументами.**

```jsonc
// tabs/manifest.json
{ "id": "tabs", "version": "1.0.0", "engines": { "cyborg": "^1" },
  "consumes": { "demo.tab": "^1" },
  "commands": { "tabs.open": { "args": ["string"] } } }
```

```ts
const kinds = () => ctx.contracts.all('demo.tab', 1)
  .map((p) => `${p.impl.icon ?? ''}${p.impl.kind} (${p.pluginId}@${p.version})`);
ctx.contracts.onChange('demo.tab', () => ctx.log(kinds().join(', ')));

ctx.commands.register('tabs.open', async (path) => {          // path: unknown
  if (typeof path !== 'string') throw new Error('путь не строка');
  return Promise.all(ctx.contracts.all('demo.tab', 1).map((p) => p.impl.open(path)));
});
```

Сочетание, которое плагин задаёт во время работы (горячая клавиша кнопки), регистрирует `ctx.keys.register`; манифестные `keybindings` остаются статическими:

```ts
const reg = await ctx.keys.register({ key: 'CmdOrCtrl+Shift+1', command: 'tabs.open', args: ['/a'], when: { visible: true } });
if (!reg.active) ctx.log(`сочетание держит ${reg.winner}`);   // конфликт назван и в журнале ядра (key-conflict)
```

`when` - закрытый список: `repeat`, `dialog`, `visible`, `input: 'any' | 'not-text'`; по умолчанию сочетание молчит при автоповторе, при открытом диалоге и в поле ввода (терминал полем ввода не считается). Сочетание окна и меню занять нельзя (`CommandConflict`), манифестное старше динамического; регистрации снимаются с выгрузкой плагина.

Ядро сверяет аргументы `tabs.open` со схемой манифеста до вызова обработчика, откуда бы ни пришла команда. Проверка `typeof` в обработчике остаётся: тип параметра — `unknown`, и компилятор без неё не даст передать `path` дальше.

## Схема аргументов команд

`commands` в манифесте — список имён (команды без аргументов) или объект со схемой:

```jsonc
"commands": {
  "pin-lock.lock": {},
  "pin-lock.unlock": { "args": ["string"] },
  "acme.log": { "args": ["string", "number?"] },
  "acme.trace": { "args": ["string"], "rest": "any" }
}
```

| Вид | Значение |
|---|---|
| `string`, `boolean` | значение этого типа |
| `number` | конечное число, не `NaN` |
| `array`, `strings` | массив; массив строк |
| `record` | объект, не массив и не `null` |
| `any` | что угодно, кроме `undefined` |

Суффикс `?` — необязательный аргумент, только в хвосте списка. `rest` — вид всех аргументов после перечисленных; вместе с необязательными не разрешён. Ошибка схемы — отказ манифесту при загрузке; несовпадение аргументов при вызове — `Invalid` с номером аргумента.
